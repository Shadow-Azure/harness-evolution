# 项目章程

[English](charter.en.md) | 中文

## 使命

建立一个可重复、可审计的闭环，让 harness 层能够基于评测证据持续改进，并清楚地区分"真实提升"和"偶然波动"。

## 范围

### 包含

- 系统提示、工具定义、上下文管理、重试与恢复、控制流、审批策略等 harness 层改动。
- 任务集、评分器、轨迹记录与回归检测。
- 实验编排：提案、对照运行、统计比较、采纳与回滚。

### 不包含

- 模型权重训练或微调。
- 没有评测证据的自动改代码。
- 未经人工批准的自动合并、发布或权限变更。
- 访问生产密钥、用户隐私数据或计费资源。

## 什么算"进化"

一次改动只有同时满足以下条件，才可标记为 `adopted`：

1. 主指标达到实验预设的最小提升。
2. 关键护栏指标没有超出允许的退化范围。
3. 在 holdout 任务上方向一致，不能只在调参集上有效。
4. 成本、时延和人工介入率在预算内。
5. 改动可通过版本或开关回滚。

单个样本的偶然成功不算进化；方向正确但未达阈值的改动应记录为 `rejected`，保留供后续复现。

## 安全边界

- 实验默认在隔离环境和独立分支中运行。
- 不读取或写入生产凭据；需要外部服务时使用测试账号和最小权限。
- 每次实验设置运行次数、时间和费用上限。
- 自动流程只能提出候选改动，不能绕过人类审批。
- 评测器本身的改动必须单独实验，不能与被测 harness 改动混在一起。

## 实验协议

1. 写下一个可证伪的假设。
2. 固定 baseline 的代码版本、配置、任务集和随机种子。
3. 只引入一个主要变量，并给出预期影响。
4. 在相同条件下运行 baseline 与 treatment。
5. 记录全部结果，包括失败和异常。
6. 按预设决策规则判定，不在看到结果后修改阈值。
7. 采纳时同步更新基线；拒绝时保留实验记录与回滚说明。
