# Agent Note: 进化对象表单移除启用开关

Status: implemented

[English](2026-11-26-target-enabled-switch.en.md) | 中文

## Problem

「新增/编辑进化对象」表单底部的 `启用` 开关同时表达「对象总启用」和「进入启动向导候选」两层含义；`启用` 与 `启动` 两个近义词上下叠放，用户无法判断开关是在启用对象，还是只把对象加进启动向导。核对代码后确认 `enabled` 实际影响启动向导目录、启动/探测、后台归因队列与进化对象总览，表单只描述向导候选会误导用户。先尝试改写文案（字段名「参与自进化」+ 停用影响说明），但反馈仍然偏复杂。

## Decision

- 从 `TargetFormDialog.vue` 移除 `启用` 表单项与 `ElSwitch`，表单不再暴露 `enabled`。
- 新增对象沿用 `form.enabled = props.target?.enabled ?? true`，提交 `enabled: true`；编辑对象保留当前值，不静默启用。
- 配置列表的「已启用/已停用」状态与「启用/停用」动作保持不变，作为唯一状态切换入口。
- 不修改后端、契约、数据库字段与启动/归因/总览语义；原型同步移除开关。

## Alternatives considered

- **保留开关，改写为「参与自进化 / 允许在启动向导中选择」**：仍然在配置表单里要求用户决定全局状态，且需要一段解释停用影响的文案；用户明确反馈这样更复杂。拒绝。
- **保留开关但增加 tooltip 解释全部影响**：歧义被藏进悬停层，触屏与键盘用户仍要先理解「启用」和「启动」的关系。拒绝。
- **表单永远提交 `enabled: true`**：编辑一个已停用对象时会在用户不知情的情况下重新启用它，破坏「保留配置」的承诺。拒绝。
- **新增第二个「仅隐藏向导」开关**：需要新的后端字段与语义，超出本次 UI 简化范围。拒绝。

## Consequences

- 表单更短，新增对象自动进入可用状态；需要停用时到列表操作，状态与动作在同一处可见。
- 编辑停用对象不会静默恢复启用；但表单本身不再显示状态，用户需从列表确认。
- 测试覆盖新增 `enabled: true`、编辑停用对象保持 `false`、表单无开关与旧文案；列表动作的现有测试保持不变。
- 真实浏览器冒烟覆盖新增、编辑停用与列表切换；PR 附 Before/After 截图，不提交截图到仓库。
