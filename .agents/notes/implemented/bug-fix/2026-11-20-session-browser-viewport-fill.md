# Agent Note: Session 页低内容时填满视口

Status: implemented

[English](2026-11-20-session-browser-viewport-fill.en.md) | 中文

## Problem

生产「Session 错误查看」页在一个只有 1 个用户轮次、1 条消息、0 次工具调用、0 个子 Agent、1 条 bad case 的 Session 上，出现右侧内容提前结束、下方留出大块页面背景空白的问题；同一视口的 V2 原型没有这条空白带（[GitHub #415](https://github.com/Shadow-Azure/harness-evolution/issues/415)）。

当前 main 的 Session 页壳层已经固定为 `100vh - 顶栏`，文档不滚动，问题卡列表也在右栏内部滚动，因此生产截图里的整页滚动与 300–550px 空白带无法在当前 main 的合成 Session 上复现。可复现的剩余缺口有两个：右栏 `.overview` 本身撑满，但内容少于一屏时内容仍从顶部自然结束，空白留在右栏背景；执行流是异步分片，分片未到时组件什么也不渲染，右栏先塌成只有标题的高度，此时问题列表上方没有任何占位。前者在更高的视口或执行流缺失态出现，后者在每次首屏都会短暂出现。

## Decision

Session 页自己拥有视口高度：`.session-browser` 用 `100dvh`（`100vh` 回退）减去顶栏，保持 `min-height: 0` 与 `overflow: hidden`；文档滚动继续保持禁用，左栏 `.sidebar` 和右栏 `.overview` 各自内部滚动。

右栏 `.overview` 保持块级滚动容器，`.overview-content` 改为纵向 flex 并以 `min-height: 100%` 占满可用高度，最后一个问题列表在内容不足一屏时占满剩余高度；内容超过一屏时列表保持自然高度，由 `.overview` 滚动。填充的是容器，不拉伸问题卡正文。

执行流的异步分片增加加载与失败组件，两者都保留与原型 `rf-canvas` 同量级的全高占位（桌面 720px、窄屏 420px）；执行流数据自身的加载、失败与无数据分支也使用同样的占位。这样右栏在首屏分片未到、接口失败或没有执行流时都不会提前结束内容。移动端 ≤860px 仍保持单列自然高度，不套用视口固定。

## Alternatives considered

- **全局禁用 `body` 滚动**：能掩盖所有页面的文档滚动，但会让总览、自进化等需要文档滚动的页面一起失去滚动；拒绝，只在 Session 页壳层内处理。
- **把问题列表或问题卡正文拉高**：会让单条问题卡出现大片卡内空白，和原型“问题卡按内容高度排列”不一致；拒绝，填充只作用于列表容器。
- **缩小执行流画布以塞进一屏**：会改变多 Agent Session 的默认图形尺寸，属于内容重排；拒绝，执行流保持自身高度，内容超过一屏时由右栏滚动。
- **只重部署生产、不改代码**：生产构建与当前 main 的 Session 壳层代码一致，但可复现的异步分片塌陷与低内容填空缺口仍存在，重部署不能覆盖这两种状态；拒绝。

## Consequences

- 低内容 Session 的右栏底部不再出现页面背景空白；1500×1100 视口下问题列表占满剩余高度，最后内容距视口底约 18px。
- 首屏执行流分片未到时显示全高骨架而不是空白；分片失败时显示“执行流视图加载失败”，不再静默塌陷。
- 执行流的加载占位是 720px，低内容首屏会短暂比最终布局高，加载完成后页面内部会有一次高度回缩；这是保留原型量级占位的代价。
- 生产截图中的整页滚动与 300–550px 空白带无法在当前 main 复现，本次只修复可复现的右栏塌陷与低内容填空；生产版本与构建哈希仍需在部署侧确认。
- 父级 `.workspace-main` 仍是 `100vh`；在动态工具栏且宽度 >860px 的窄带里，Session 页与壳层可能相差一条背景带。统一需要 shell 级改动，本次未扩范围。
- 移动端行为不变；问题列表的数据、筛选与卡片结构不变。
