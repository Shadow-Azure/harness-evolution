# Agent Note: 仅聚类页顶部排列与单一状态区

Status: implemented

[English](2026-11-28-cluster-preview-detail-layout.en.md) | 中文

## Problem

「自进化 → 仅聚类」准备中页面在内容很少时被纵向拉开：返回入口、标题、模式说明和准备提示之间出现大段空白，状态说明同时出现在顶部状态条和准备卡里（[GitHub #674](https://github.com/Shadow-Azure/harness-evolution/issues/674)）。

根节点 `.cluster-preview-page` 与 `.run-detail-page` 一样用 `display: grid`、`height: 100%`、`overflow-y: auto` 在固定高度的 `.workspace-main` 内承担页级滚动，但没有设置 `align-content`。网格默认值 `normal` 在自动行总高小于容器时按 `stretch` 分配剩余空间，短状态页的自动行被拉高，行内元素与间距随视口高度膨胀。浏览器实测（1366 宽）：准备态状态区高度从 114.2px 长到 176.6px，模式条从 126.5px 长到 188.9px，内容底部只剩 64px；修复后 1366×768 与 1366×1080 的差异 ≤2px。内容足够长的完成态没有剩余空间，所以症状只出现在准备中或失败等短内容状态。

状态重复来自模板结构：`status-banner` 已用「准备中」徽标 + `statusDetail` 描述流程，`preparing` 卡再以「正在准备聚类结果」和几乎相同的文案重复一次；橙色 `.banner` 用警告卡承载「仅聚类分析」这一正常模式说明，视觉权重过高。`target-chip` 未限制宽度，长对象名在窄屏会横向溢出。

## Decision

- `.cluster-preview-page` 保留 `height: 100%`、`overflow-y: auto` 和 1720px 内容列，增加 `align-content: start`：自动行按内容高度从内容盒顶部排列，剩余高度留在滚动容器底部。`.run-detail-page` 同步这一行，低内容状态下页头、信息卡与进度块也不再被拉伸。
- 状态只保留一个主体区域：标题行显示状态徽标（与运行详情一致），状态区展示真实进度 `progress.stageLabel` 与失败/阻塞原因。准备中不再渲染第二张准备卡；流程步骤说明只保留在状态副文案里，不伪造百分比或轮次。
- 模式说明收为一条中性信息条：保留「仅聚类分析、未执行 patch 生成与评测迭代」与启动按钮，去掉橙色警告底和粗体强调，颜色使用 `--border` / `--bg-panel` / `--text-dim`。
- `target-chip` 允许换行（`max-width: 100%`、`overflow-wrap: anywhere`）并通过 `title` 暴露完整值。

## Alternatives considered

- **移除 `height: 100%` 或改成 `min-height`**：页面会在壳层内重新参与文档滚动，破坏 #496 已确定的页级滚动与窗口右缘滚动条契约；拒绝。
- **只加 `align-items: start`**：能阻止单项在行内拉伸，但自动轨道仍平分剩余高度，行与行之间依旧出现空带；拒绝。
- **给状态卡写死高度**：能压矮这一种状态，但文案换行、字体缩放或错误详情变长时会截断；拒绝，尺寸继续由内容决定。
- **把准备提示卡改成更小的卡**：仍与状态条重复描述流程；拒绝，直接合并为一个状态区。
- **保留橙色模式卡只缩小内边距**：警告色仍把正常模式描述成异常；拒绝，改为中性信息条。

## Consequences

- 准备中、失败等短内容状态从顶部连续排列；1366×768 与 1366×1080 下状态卡高度与相邻间距不再随视口高度变化，剩余空白落在内容下方。
- 页面只出现一个准备状态区；模式说明与启动按钮保留，但不再占据大面积橙色警告区。
- 长对象名换行且可悬停查看完整值；多簇页面仍由根节点滚动到最后一簇，≤640px 仍由文档滚动。
- 只改两个详情页根节点的纵向对齐与仅聚类页的状态呈现，不涉及运行数据、API、契约或聚类流程。
