# Agent Note: V2 原型 UI 可读性与交互修正

Status: implemented

[English](2026-11-11-ui-prototype-v2-ui-polish.en.md) | 中文

## Problem

V2 原型在真实浏览器里暴露出几个会误导评审的可见问题：顶栏四个入口在 1408px 下从词中间折行；家族树把普通滚轮当成缩放，用户想向下看列表却把图缩到不可读；`--text-faint` 用于图表刻度和表格辅助信息，对比度只有约 2.6:1；Session 壳层按 100px 偏移计算高度，在隐藏子页签后留下 44px 空带；长会话 ID 把详情操作按钮挤到第二行；来源汇总第三列与进化对象侧卡分页也没有对齐卡片边界。

第三轮又发现状态与内容不自洽：已完成运行的拒绝轮次仍显示正向分差，测试集终评副标题保留字面量「M 轮」，问题复现率上升被着色为收益；添加成员默认授予空间管理员；空间管理列表页底部留出大块空白；1280px 下 Session 统计条末项折行。

第四轮发现默认策略在运行详情与向导里混用 `+` 与 `∪`，前者容易被读成加分或叠加；向导第 3 步内容超出 `66vh` 时依赖 macOS 的 overlay 滚动条，读者看不到可滚动提示；登录页第三条说明产生「话。」孤行，页脚仍指向旧原型路径；鉴权接入说明混用英文 `membership`；自定义策略说明写成「在默认策略上叠加规则」，与勾选规则重新组合的实现不符。

第五轮发现进化对象总览缺少对象维度的关联 Session 与来源视角，读者只能从右侧对象卡和趋势图间接推断；总览页的「启动自进化」会先把人带到自进化历史页再弹向导，多了一次无意义的整页跳转，也丢掉总览当前的时间窗与对象筛选。

第六轮发现把来源分布留在多对象趋势卡里只能给聚合视角：读者无法只盯一个对象、按版本与时间段看它的潜在 bad case 分布；版本维度在整个总览里完全缺位，只能看到 defaultRef 对应那一个版本。

第七轮细看新卡仍有版式问题：四个统计各占一格、行高偏大；筛选行与正文没有层次；两栏内容之间没有分隔，标题、图例与脚注位置零散；零数据版本与有数据版本同样醒目。

第八轮在潜在 bad case 列表上发现：触发点与 Session 详情、执行流重复且占用列宽；有归因报告的 case 看不出报告内容；点归因报告 ID 会跳到登录页；深链只按 case 定位，多对象归因时不一定选中对应那条；列表里的报告 ID 由运行期合成，点开后常常是「暂无归因」。

第九轮发现 bad case 列表里的 ID 只是标题下的副文本，不能单独点击，也没法把某条 case 直接指给别人；新增列后标题列还会重复显示 ID。

第十轮发现自进化运行详情里「来源 bad case」表的 ID 链接显式传了 `attr`，点 bad case ID 会落到归因分析页签，与「ID 看问题描述、报告 ID 看归因」的约定相反；归因报告 ID 的深链也没带对象，落地后选中的是第一条归因。

第十一轮发现工作空间切换器紧贴品牌，与导航争横向空间，而右侧顶栏（同步状态与用户菜单之间）反而是空的；「当前空间」作为页面级上下文，更适合放在右侧操作区靠近用户。

第十二轮发现进化对象侧卡按添加顺序排列，读者看不出该先处理哪个对象；卡片只给「关联 Session / 潜在 bad case」两个数字，缺少「可进化量」（是该对象问题 + 未分析）的口径。

第十三轮发现总览、自进化、空间管理三个页面的内容区分别被 1200px 与 1080px 的固定上限限制，1700px 左右的窗口下左右各浪费 250–300px，界面相对窗口显得偏小。

第十四轮发现「查看」的三个状态切换挤在筛选条最右，与时间、粒度、对象混在同一行，而趋势卡右上角又重复了一遍同样的图例；切换项本身没有数量，关闭态和开启态也不够好区分。

## Decision

在同一份 `plans/ui-prototype-v2/harness-evolution.html` 内做最小修正：顶栏入口不可收缩并保持单行，1400px 以下隐藏副标题；两个 React Flow 实例关闭滚轮缩放、允许页面滚动，`minZoom` 提到 0.5；`--text-faint` 改为 `#66707c` 并提高刻度和汇总数字字号；Session 壳层改为 `calc(100vh - 56px)`，详情头首列可收缩并省略超长 ID；来源汇总列扩到 120px；进化对象侧卡改为纵向 flex，分页贴底。每轮修复前后的截图保存在 `plans/ui-prototype-v2/_ui-review/`。

第二轮继续修交互状态：页面与工作空间写入 URL，浮层统一由外部点击/Esc/切页关闭；家族树画布在短视口自适应并把图例移入普通文档流；错误详情执行流在短视口压缩以露出问题详情；切换工作空间时关闭旧空间错误详情并刷新新空间 Session；时间线只对有真实数据的 Session 渲染，其余显示带正确标题的空态。

第三轮把拒绝轮次的候选分改成低于 current，终评副标题使用实际轮数，`evDelta` 增加 `lowerBetter` 方向；添加成员默认角色改为成员；空间管理内容卡最小高度收到 340px；运行卡百分比标注为「总进度」；Session 统计标签禁止换行并收紧内边距。

第四轮把默认策略统一为「对象自身 self 上报 或 触发点在对象触发点之后」，并给弹窗正文加 10px 常驻滚动条；登录页第三条说明显式分成两行，页脚路径改到 `plans/ui-prototype-v2/`；鉴权说明统一使用「成员关系」；自定义策略说明改为「勾选规则组合成策略」。

第五轮在趋势卡内追加两块分布：关联 Session 按对象归一、蓝色为含潜在 bad case 的 Session；来源分布按未去重条数归一并在括号内给去重后数量，去重键是 bad case ID。两块复用既有 `ov-obj-row` / `tg-source-obj` 结构与归一化柱，并共用进化对象多选与时间窗。启动入口改为浮窗优先：新增 `evWizardHost()` 按当前页选择挂载点（自进化页内仍用 `#modal-root`，其它页用全局 `#v2Modal`），点「启动自进化」只开浮窗，第 4 步确认后才写运行 hash 并调用 `V2.setPage('evo')` 整页跳转。

第六轮把来源分布移出趋势卡，新增独立的「单个进化对象分析」卡：对象下拉必选并默认第一个，空间没有启用对象时置空并给「去配置进化对象」入口；版本多选默认不选（视作最近 5 个），菜单底部固定 5 / 10 / 20 / 全部四档，卡片底部再给「展开到 10」的快捷入口；时间区间独立于总览筛选。卡内给对象级统计（关联 Session、潜在 bad case、去重后、覆盖版本）与两块分布：按版本的潜在 bad case 堆叠分布、按来源的去重数量分布。

第七轮只改版式不动口径：统计合并成一条内部分隔的统计条；筛选收进浅底工具条并把时间段推到右侧；两栏之间加 1px 分隔线与 22px 内边距，1100px 以下转单列并改为横向分隔；左栏标题右侧增加 是 / 非 / 未 汇总图例；零数据版本降到 60% 透明度并改写为「无潜在 bad case」；脚注移到底部横跨整卡。对象与版本两个下拉统一成 28px 高、8px 圆角、自绘 chevron 的控件，原生 select 关闭外观并预留 30px 箭头区，hover 与 focus 用蓝色描边加 3px 光环。

第八轮删掉触发点列，在归因报告 ID 后新增「问题现象/描述」列（取 bad case 描述，超长省略并保留 title）；`caseDeepLink` 统一补 `u=` 当前用户并支持 `obj=` 对象名，错误详情按对象名预选归因；列表的归因状态与报告 ID 改为读取该 bad case 现有的归因记录，匹配不到对象归因的行显示「未分析」。

第九轮在 bad case 列表最前面新增「ID」列，ID 用同一套深链打开 Session 错误查看 → 错误详情的对应 bad case，停在问题描述页签；标题列只保留标题，空态 colspan 同步到 8。

第十轮把该表改回默认深链（`desc`），归因报告 ID 的深链补 `obj` 参数，`evCaseLink` 统一加 `stopPropagation`，避免点 ID 时同时触发整行跳转。

第十一轮把 `#wsPicker` 从品牌与导航之间移到 `.tn-right`（数据同步之后、用户菜单之前），弹层改为右对齐展开（`right: 0`），摘要上限放宽到 240px、名称到 146px，1440 下完整显示「Harness 核心研发 · 全局管理员」，1280 下不出现横向溢出。

第十二轮把侧卡改为按「是该对象问题 + 未分析」降序（并列按潜在总数、再按对象名），分页在排序后的列表上；每项下方新增「可进化潜在 bad case 数量 N（是问题 X；未分析 Y）」，抬头写明排序依据。

第十三轮把 `.v2-page .wrap` 与 `.evo-app .wrap` 的上限一起放宽到 1720px，宽度随视口增长：1700px 视口下内容区实测 1659px（总览）与 1674px（自进化），1920px 视口下封顶 1720px 居中，1280px 下占满且无横向溢出。

第十四轮把三个状态切换从筛选条移进趋势卡（图表说明下方、分布块上方），重做成带数量的 pill chip：每项显示名称与该状态在当前筛选下的数量，开启态加蓝边与浅蓝底、关闭态整颗降透明度；同时删掉卡头重复的图例，图例由 chip 本身承担。

## Alternatives considered

- 直接修改生产 `apps/web`：会把原型评审与产品实现混在一个 PR，且当前 issue 只覆盖原型资产。
- 只在 1100px 以下隐藏副标题：1408px 下仍然折行，问题没有被解决。
- 保留滚轮缩放并把图例移到固定浮层：手势冲突仍在，用户依旧会误缩放。
- 只加深颜色不改字号：低对比度缓解了，但 9px 日期在密集周轴上仍难读。
- 保留 `+`/`∪` 作为数学记号：`+` 在进度与收益语境里会读成相加，`∪` 又依赖字体支持；统一用自然语言「或」更不容易误读。
- 依赖系统 overlay 滚动条：macOS 默认不显示滚动条，短视口下读者无法判断弹窗正文还有内容。
- 浮窗继续挂 `#modal-root` 并临时取消 `view-evo` 的 hidden：会把自进化历史页一起闪出来，挂载点也仍然绑在页面可见性上。
- 保留「先跳到自进化页再弹向导」：多一次整页切换，总览的时间窗与对象筛选上下文全部丢失。
- 来源分布只给去重数或只给未去重数：前者与列表条数对不上，后者解释不了 31 条潜在 bad case 的构成。
- 继续把来源分布留在趋势卡里再加对象筛选：趋势卡是多对象对比，塞进单对象筛选会让两个口径混在同一张卡。
- 按 Session 的版本归属切分卡片里的潜在 case：当前模型一个 Session 只对应一个版本，多数版本会没有数据。
- 默认一次展示全部版本：18 个版本会铺满两屏，违背「默认看最新 5 个」的要求。
- 只缩小四张统计卡的间距：仍然各占一格，信息密度没有提升。
- 把图例放到每行右侧：与行内明细重复，噪声更大。
- 桌面宽度也改单列：横向空间被浪费，版本分布与来源无法并读。
- 保留触发点只做列宽收窄：与 Session 详情仍然重复，收益有限。
- 深链只补 `u` 不改报告 ID 来源：点开仍是「暂无归因」，体验更差。
- 用 `at=<报告ID>` 定位：报告 ID 是运行期合成值，与 case 存储的归因 ID 对不上。
- 把标题做成链接：标题长、可点区域大，误触会把整页带走。
- 保留副文本 ID 只加点击：列宽仍被浪费，ID 和标题混排。
- ID 做成纯文本加复制按钮：多一步操作，也不能直接分享到详情。
- 保留该表的 `attr` 深链只在表头加说明：与其它列表不一致，读者仍会误判。
- 按点击位置区分列再决定页签：需要事件坐标判断，复杂且随布局变化失效。
- 保持左侧只缩小宽度：品牌区仍然拥挤，也继续和导航争空间。
- 把切换器放到导航中间：会打断「总览 / Session / 自进化 / 空间管理」的分组。
- 收进用户菜单：切换空间是高频操作，藏进二级菜单反而更难找。
- 只改排序不写说明：读者不知道依据，也无法判断并列时谁在前。
- 按潜在 bad case 总数排序：会把「非该对象问题」也算进来，与「可进化」的含义不符。
- 把可进化量放抬头汇总：每个对象的值不同，放抬头无法一一对应。
- 直接删掉宽度上限：2560 等超宽屏上正文会过空、表格被拉得过长。
- 用视口百分比（如 92vw）代替上限：仍需要极值保护，效果与「上限 + 随视口增长」等价。
- 用 `zoom` 整体放大：会连同弹层与固定像素组件一起缩放，容易错位。
- 只把切换项挪到别处但仍保留卡头图例：同一信息出现两次，读者不知道该点哪个。
- 把切换项做成纯文字按钮：与旁边的筛选控件视觉混同，也看不出各状态数量。
- 让切换项同时过滤下方三块分布：会改变汇总口径，读者无法再看到完整构成。

## Consequences

原型与生产前端的样式差异继续扩大，后续对齐时需要以本文件和截图为准。审阅截图会增加仓库体积，但能让人快速复核每轮判断。导航阈值 1400px、树图最小缩放 0.5、画布高度 clamp 都是经验值，若后续接入真实数据导致标签或节点变多，需要重新测量。URL 目前用 `replaceState`，刷新能恢复当前页面与空间；浏览器后退仍会离开原型，若需要完整 history 语义需另做 `pushState` 与 `popstate` 回放。 滚动条样式使用 `::-webkit-scrollbar`，Chrome 与 Safari 会常显；Firefox 仍回落为原生滚动条，若后续扩大浏览器支持需补 `scrollbar-color`。

第五轮让趋势卡在 1440px 下增高约 200px，三块分布的口径全写在副标题里，后续若压缩卡片高度需要连带重写这三块说明。自进化浮窗现在依赖全局 `#v2Modal`，新增全屏弹层要走同一挂载点；启动落地仍是「写 hash + `v2SetPage('evo')`」双写，引入客户端路由后要收敛成一次导航。

第六轮的总览页在 1440px 下再长高约 330px，而且版本的 commit 与时间戳是新增的 mock 数据（deep-research 18 个、code-review 12 个、Explore 9 个），与自进化向导里按 tags 展示的版本列表暂不一致，接真实版本接口时需要统一。卡片里按版本切分的潜在 case 由哈希抽样生成，同一 bad case 会出现在多个版本下，所以「潜在」会大于「去重后」；这不是缓存或重复上报，而是口径本身如此。

第七轮把卡片高度从约 430px 收到 376px（1440px 视口）。统计条与工具条引入的 `.td-*` 类只服务本卡，后续要复用得先提到通用样式层；零数据版本用透明度弱化，接入深色主题或高对比模式时要重新取值。

第八轮让列表与错误详情的归因口径一致，但概览里的「已分析 / 未分析」不再是哈希抽样，而是跟随 case 的归因记录，数量会随 mock 归因分布变化；接入真实归因接口时，这段按对象名匹配的逻辑要换成按对象版本查询。深链新增 `obj` 参数，旧链接仍可用，不带 `obj` 时回退到第一条归因。

第九轮把 ID 提到首列后，表格第一列宽度固定为单号宽度，标题列反而拿到更多横向空间；ID 深链仍在新标签打开，若希望同标签内跳转应改用 `v2OpenCase`。

第十轮之后，bad case ID 在自进化页面与总览列表里统一落到问题描述；若某张表确实希望默认跳归因，需要显式传 `tab` 并同步更新说明，否则会与全局约定冲突。

第十一轮后顶栏顺序变为 品牌 → 导航 → 数据同步 → 工作空间 → 用户；小屏下摘要仍可能截断工作空间名，需要按需隐藏角色或名称；弹层右对齐后靠右边缘展开，窄屏要保证宽度不超过视口。

第十二轮之后侧卡顺序随筛选时间窗变化，同一对象在不同时间窗下的位置会变；每项多一行，卡片高度约增加 18px/项，五个对象一页时右栏会略微变长。

第十三轮让内容区在大屏上更舒展，但很长的单行文本（如聚类描述）可读性会下降；目前靠既有的 `.cluster-desc p { max-width: 980px }` 等局部约束兜底，若后续觉得正文过宽，需要给正文区单独设上限而不是退回整页宽度。

第十四轮之后，「趋势图显示」只控制趋势图的堆叠信息，下方三块分布仍展示完整构成；chip 上的数量随筛选变化，若后续把分布块也接上同一组开关，需要同步改这三块的副标题与图例说明。
