# Agent Note: V2 原型 UI 可读性与交互修正

Status: implemented

[English](2026-11-11-ui-prototype-v2-ui-polish.en.md) | 中文

## Problem

V2 原型在真实浏览器里暴露出几个会误导评审的可见问题：顶栏四个入口在 1408px 下从词中间折行；家族树把普通滚轮当成缩放，用户想向下看列表却把图缩到不可读；`--text-faint` 用于图表刻度和表格辅助信息，对比度只有约 2.6:1；Session 壳层按 100px 偏移计算高度，在隐藏子页签后留下 44px 空带；长会话 ID 把详情操作按钮挤到第二行；来源汇总第三列与进化对象侧卡分页也没有对齐卡片边界。

第三轮又发现状态与内容不自洽：已完成运行的拒绝轮次仍显示正向分差，测试集终评副标题保留字面量「M 轮」，问题复现率上升被着色为收益；添加成员默认授予空间管理员；空间管理列表页底部留出大块空白；1280px 下 Session 统计条末项折行。

第四轮发现默认策略在运行详情与向导里混用 `+` 与 `∪`，前者容易被读成加分或叠加；向导第 3 步内容超出 `66vh` 时依赖 macOS 的 overlay 滚动条，读者看不到可滚动提示；登录页第三条说明产生「话。」孤行，页脚仍指向旧原型路径；鉴权接入说明混用英文 `membership`；自定义策略说明写成「在默认策略上叠加规则」，与勾选规则重新组合的实现不符。

## Decision

在同一份 `plans/ui-prototype-v2/harness-evolution.html` 内做最小修正：顶栏入口不可收缩并保持单行，1400px 以下隐藏副标题；两个 React Flow 实例关闭滚轮缩放、允许页面滚动，`minZoom` 提到 0.5；`--text-faint` 改为 `#66707c` 并提高刻度和汇总数字字号；Session 壳层改为 `calc(100vh - 56px)`，详情头首列可收缩并省略超长 ID；来源汇总列扩到 120px；进化对象侧卡改为纵向 flex，分页贴底。每轮修复前后的截图保存在 `plans/ui-prototype-v2/_ui-review/`。

第二轮继续修交互状态：页面与工作空间写入 URL，浮层统一由外部点击/Esc/切页关闭；家族树画布在短视口自适应并把图例移入普通文档流；错误详情执行流在短视口压缩以露出问题详情；切换工作空间时关闭旧空间错误详情并刷新新空间 Session；时间线只对有真实数据的 Session 渲染，其余显示带正确标题的空态。

第三轮把拒绝轮次的候选分改成低于 current，终评副标题使用实际轮数，`evDelta` 增加 `lowerBetter` 方向；添加成员默认角色改为成员；空间管理内容卡最小高度收到 340px；运行卡百分比标注为「总进度」；Session 统计标签禁止换行并收紧内边距。

第四轮把默认策略统一为「对象自身 self 上报 或 触发点在对象触发点之后」，并给弹窗正文加 10px 常驻滚动条；登录页第三条说明显式分成两行，页脚路径改到 `plans/ui-prototype-v2/`；鉴权说明统一使用「成员关系」；自定义策略说明改为「勾选规则组合成策略」。

## Alternatives considered

- 直接修改生产 `apps/web`：会把原型评审与产品实现混在一个 PR，且当前 issue 只覆盖原型资产。
- 只在 1100px 以下隐藏副标题：1408px 下仍然折行，问题没有被解决。
- 保留滚轮缩放并把图例移到固定浮层：手势冲突仍在，用户依旧会误缩放。
- 只加深颜色不改字号：低对比度缓解了，但 9px 日期在密集周轴上仍难读。
- 保留 `+`/`∪` 作为数学记号：`+` 在进度与收益语境里会读成相加，`∪` 又依赖字体支持；统一用自然语言「或」更不容易误读。
- 依赖系统 overlay 滚动条：macOS 默认不显示滚动条，短视口下读者无法判断弹窗正文还有内容。

## Consequences

原型与生产前端的样式差异继续扩大，后续对齐时需要以本文件和截图为准。审阅截图会增加仓库体积，但能让人快速复核每轮判断。导航阈值 1400px、树图最小缩放 0.5、画布高度 clamp 都是经验值，若后续接入真实数据导致标签或节点变多，需要重新测量。URL 目前用 `replaceState`，刷新能恢复当前页面与空间；浏览器后退仍会离开原型，若需要完整 history 语义需另做 `pushState` 与 `popstate` 回放。 滚动条样式使用 `::-webkit-scrollbar`，Chrome 与 Safari 会常显；Firefox 仍回落为原生滚动条，若后续扩大浏览器支持需补 `scrollbar-color`。
