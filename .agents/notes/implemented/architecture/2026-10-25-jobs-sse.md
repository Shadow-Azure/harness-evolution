# Agent Note: 任务执行与 SSE replay 边界

Status: implemented

[English](2026-10-25-jobs-sse.en.md) | 中文

## Problem

M1 需要先交付持久任务状态、单进程串行执行、重启恢复和页面级事件通知，同时 `evolution_run_events` 的父表与业务写入生命周期属于 m5-08。

## Decision

`job_runs` 是任务真值，`JobRunner` 用全局锁串行执行并保留 queued/running/terminal 审计；启动重新调度持久 queued，把残留 running 标为 interrupted，只有 sync 保留审计后重新入队。同一 run 的 prepare/advance/apply/finalize/retry 共用一个活跃阶段约束，不同阶段冲突返回 `RUN_BUSY`。EventBus 为每个连接维护跨授权 topic 的单个有界队列，满了丢最旧事件而不阻塞生产者。SSE 通过可注入 `RunEventReplay` 按 topic 游标分页回放 `seq > cursor`，再切到实时队列；订阅在回放前建立，游标过滤消除交接重复，重启中断通过 `RunEventRecorder` 先持久化再发布。`0003` 建立与权威字段一致的 `evolution_run_events` projection；`SqlRunEventStore` 负责真实 SQL 回放和中断记录，m5-08 创建 evolution 父表后补关系约束与资源 authorizer。

## Alternatives considered

让 M1 依赖尚不存在的 evolution 父表会使任务基座无法独立迁移，因此 event projection 先按权威列落地，m5 只负责父表、关系约束与真实资源授权。直接在 EventBus 保存全部历史会让进程重启丢事件，也无法满足 `Last-Event-ID`。每个 topic 单独队列会使多 topic 连接的顺序与清理复杂化，因此采用每连接一个队列。

## Consequences

SQL store 在迁移后即可分页回放和记录中断；表不存在时显式退化为空历史，不伪造事件。M1 的 topic authorizer 只承担注入接缝，run 存在性和完成态校验必须由 m5-08 的 authorizer 接入。`evolution_run_events.run_id` 的外键在父表出现后由 m5 迁移补齐。撤销和票据仍为进程内状态，多实例部署需要先替换为共享存储。
