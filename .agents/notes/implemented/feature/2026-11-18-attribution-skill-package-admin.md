# Agent Note: 空间归因 Skill 包与执行 revision 分层管理

Status: implemented

[English](2026-11-18-attribution-skill-package-admin.en.md) | 中文

## Problem

空间管理员需要跨对象复用含多个文件的 Skill，也需要从报告追溯每个 Badcase 的分析依据。

## Decision

空间独立存放上传包。对象配置在同一事务中写入单一绑定与后台任务意图。后台固定对象版本。每一代绑定以数据库里首次登记的 Skill 内容哈希为准，让并发启动的后台任务和向导使用相同的提示词及输出脚本。向导重算时可为本次 Run 另选空间包。历史报告保留产出时的 Skill 身份。

对象总览将按历史版本匹配的候选与已有 V2 报告按分析版本、Badcase 合并，轨迹版本缺失时仍能展示已完成报告。顶部同步面板按当前空间统计轨迹根与 Badcase，每条 Badcase 以最近一次完成的结论计数；目录采集和归一化显示平台级进度。

逐次记录 Agent 的可见交互，并用输入清单关联原始 Badcase。工作目录内可由 Skill 写入的文件不作为入库凭据；日志与正式报告分开保存。

报告按实际归因对象写入 `probe_type`。Agent 的标准值为 `agent`，旧包传入的 `agents` 在生成新报告时归一化。冻结脚本的产物先按原格式校验，原始上报对象的类型保留在 `from_bad_cases`。

归因与聚类共用 Agent 工厂和 Claude 子进程管理。绑定消费者及向导重算根据公共实例的 Skill 执行能力启用，避免出现绑定已写库却无人领取。新快照固定公共模型选择，重试沿用原快照。归因单独定义 `run_skill`，以便用冻结输入和平台脚本核验文件结果。每次调用独立保存会话、脱敏日志与用量，允许并发使用同一 Provider 实例。归因与自进化向导通过同一把缓存锁读取 Git 定义及其提交。

## Alternatives considered

空间级生效会影响无关对象。按全部历史报告计数会在重算后重复统计同一 Badcase。先按对象版本和 Badcase 取最新报告，再按 Skill 分组。

## Consequences

资源库可以列出并保护已绑定包。后台批次独立于下游聚类，重试时根据批次标识跳过已完成的 Badcase。

每代批次最多连续失败三次，前两次分别退避 30 秒和 60 秒。租约超时计入失败，正常等待 Session 轨迹独立轮询。终止后，对象配置展示失败原因。修复原因后编辑并保存相同绑定会重试这一代，保留快照并跳过已完成的 Badcase。

同一批次重试需要复现首次交给模型的输入。逐 case 清单固定脱敏提示词、Session 证据版本和 Skill 快照；同 Session 多个 Badcase 共享证据。新批次可使用补采后的轨迹，缓存复用沿用原报告。

保存 Git 对象时先固定定义原文和提交，再登记绑定批次。分析版本使用正文摘要，文件归档使用原文摘要，两者分别保留匹配语义和完整元数据。
