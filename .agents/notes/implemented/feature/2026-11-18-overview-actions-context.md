# Agent Note: 总览页 V2 工作流入口与运营上下文

Status: implemented

[English](2026-11-18-overview-actions-context.en.md) | 中文

## Problem

m8-04 交付总览时只保留了只读的统计、趋势、来源分布与列表，明确拒绝了原型右侧的额度/上报/当前空间侧栏和可展开的来源 × 时间矩阵：前者被判定为复制空间管理能力，后者被判定为 m8-03 没有对象 × 桶交叉计数字段。m12-08 的生产/原型对照又把这两处列为必须补齐的 V2 差距，并要求入口复用既有空间管理页与启动向导，不引入第二条写路径。

## Decision

- bad case 总览页头按 `canManageWorkspace(currentRole)` 渲染「上报接入」「启动自进化」；前者指向当前空间 `admin?tab=ingest`，后者打开既有 `LaunchWizard`。无管理权限时渲染「只读访问」提示而不是可绕过的空链接；启动成功后用 `router.push` 打开既有运行详情，浏览器后退仍回到原总览 URL。
- 运营上下文复用两个已有数据源：summary 的 `used/quota/sources` 与会话里的 `memberCount/spaceAdminCount/role`。上报地址由 `location.origin` + 当前空间 ID 推导为完整 URL（`POST <origin>/api/workspaces/:wid/bad-cases`），复制按钮只复制该地址；不读取、不复制凭据，也不额外请求成员或凭据接口。summary 未就绪时额度显示「—」，不以 0% 冒充未知。
- 运营上下文与趋势卡组成桌面双栏，bad case 列表横跨下一行；≤1024px 时单列并固定为「趋势 → 列表 → 运营上下文」，避免辅助信息挡在主内容前。
- 来源 × 时间矩阵保持既有 sources 端点不变：展开时按服务端实际生效的粒度把每个桶映射成闭区间，再与 summary 的当前窗口取交集；逐个读取交集窗口的来源聚合，再按来源合并。趋势首/末桶可能从周/月边界开始，不裁剪会把窗口外几天算进首列；裁剪后桶区间互不重叠且都落在当前窗口内，因此合并结果对当前窗口与来源筛选是精确的，不依赖列表当前页，也不伪造缺失桶。
- 矩阵最多处理 31 个时间桶；超过时明确提示切换为周/月粒度，而不是发出上百个聚合请求。矩阵请求按 4 个并发的有界分组执行，失败显示区块级错误与重试。
- 原有「只读视图 · 筛选条件保存在地址栏」提示被 V2 页头动作/只读提示取代；URL 仍是筛选唯一事实源，入口导航与返回不改变既有 `tab/range/grain/objects/page/type` 契约。

## Alternatives considered

- **给 sources 响应增加对象 × 桶字段**：拒绝。m12-08 的交付边界明确不新增 API；字段补丁应拆成独立子任务，本 issue 不把前端改动扩成契约与后端改动。
- **用当前页 8 条 bad case 拼矩阵**：拒绝。跨桶计数会系统性偏小且随翻页变化，这是伪造数据，不是降级。
- **每个来源调用一次 trend**：拒绝。trend 端点会读取窗口内全部行再在 Python 分桶，按来源重复调用等于多次全量读取；按桶调用 sources 聚合并裁剪到当前窗口更窄。注意页面本来就有一次整窗 SourceBars 读取，矩阵是在展开时追加的按桶聚合，而不是复用那一次结果。
- **用空间管理页的 members/credentials 接口补当前空间信息**：拒绝。总览只需要会话已有的成员计数与角色；额外拉取成员目录会复制管理能力并增加首屏请求。
- **无权限时渲染 disabled 按钮**：拒绝。原型与权限矩阵都要求隐藏写入口；disabled 按钮仍暗示存在可绕过的动作。

## Consequences

- m8-04 中「页面没有任何写操作」「SourceMatrix 不做」「保留侧栏被拒绝」等事实由本 Note 取代；m8-04 Note 保留 URL 契约与独立区块的原始决策，并回链本 Note。
- 矩阵展开的请求数等于时间桶数（默认 90 天周粒度约 13–14 个，取决于窗口起点是周几）；31 桶上限意味着 90 天日粒度需要先切换粒度。这是没有 API 字段时的明确代价，后续增加对象 × 桶字段后可直接替换为一次读取。
- 运营上下文中的成员/管理员计数来自登录时缓存的会话；成员变化后要等会话刷新才更新。它不用于权限判定，权限仍以 `workspace` 角色为准。
- 统计条、运营上下文和顶栏空间切换器都会显示额度/来源数。这是原型 V2 的信息架构，不是第二份事实源：统计条与上下文都读同一次 summary，context 的成员数来自会话缓存，顶栏 picker 的 used/quota 只是导航提示；维护者若决定收敛，只需删统计条额度格或让上下文只显示百分比。
- 只读成员仍能看到上报地址与来源分布，但看不到页头写入口和管理页请求示例；上报凭据仍只在空间管理页由有权限角色读取。
