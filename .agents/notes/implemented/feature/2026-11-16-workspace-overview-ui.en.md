# Agent Note: The workspace overview URL contract, independent blocks, and default landing

Status: implemented

English | [中文](2026-11-16-workspace-overview-ui.md)

## Problem

m8-03 exposes four read-only endpoints (summary, trend, sources, and the paged bad-case list), but the overview page still has to solve four things at once: filters must be shareable and survive a refresh; the trend and the list must not block each other (a slow or failing block must not turn the whole page into a spinner); a bad-case ID must land directly on the error detail's description tab; and `/workspaces/:wid` must move from the Session list to the overview without redirecting old Session deep links. m8-03 also only aggregates object totals and bucket totals, with no object × bucket cross-count, so the prototype's SourceMatrix has no honest data source.

## Decision

- The URL is the single source of truth for filters: `tab=cases`, `range=7|30|90|custom`, `from`/`to` (only with `range=custom`), `grain=day|week|month`, `objects` (comma-separated, de-duplicated, empty means all, multi-select is a union), `page` (written only when greater than 1), and `type` (`self|discovery`). Defaults are `range=90` and `grain=week`; invalid, out-of-range, or malformed dates fall back; on mount the page replaces a missing or non-canonical URL once, so refreshes and shares restore the same filters.
- A custom window is expressed as `from`/`to` and sends no `range`; opening "custom" prefills both boundaries from the summary window currently on screen; clicking a trend bucket switches the list window to that bucket's inclusive dates (the day itself for a day bucket, Monday through Sunday for a week bucket, the whole month for a month bucket) and returns to page one. Bucket windows use the grain the server actually returned (`grainEffective`), so when a day request is downgraded to weeks both the subtitle and the bucket click use weeks.
- Filter changes use `router.replace` (no history spam) while paging uses `router.push`; adding or removing objects, removing a chip, and clearing filters all only change the URL, so components never keep a second copy of filter state.
- `type` is an extra list filter key: the prototype stat strip is not clickable, but 08 §6.2 requires the self / discovery metrics to write a list filter and scroll to the list, so those two cells are buttons that write `type` and clear it on a second click; the "source count" cell itself focuses the source multi-select, with no separate shortcut button.
- A workspace switch is a navigation: the picker writes the default overview query (`tab=cases&range=90&grain=week`) when it opens another workspace, so the new workspace's first requests never carry the previous `range`/`objects`/`type`. The page watcher only canonicalizes the URL and does not reset on a `wid` change, so browser back restores the previous workspace's own URL and list.
- The stat strip, the trend plus source distribution, and the list are three independent request blocks: each has its own skeleton, empty state, block-level `ErrorState`, and retry; empty copy distinguishes "this workspace has no bad cases" from "the current filters match nothing", and the latter offers a clear action. An out-of-range `page` is clamped to the last valid page once the list reports `total`; before the clamp a distinct "page out of range" state keeps the pager visible. A 404 `WORKSPACE_NOT_FOUND` sends the whole page to `/workspaces?reason=forbidden`, and block errors show the real `ApiError.code` instead of a page-made code.
- The trend is hand-drawn SVG: `chartGeometry.ts` only does pure geometry (1/2/5×10ⁿ ticks, `min(28, slot*0.6)` bar width, stacked heights, shares) while the DOM owns axis labels and the tooltip; a `0` value draws no bar but keeps a clickable and focusable bucket area; more than 60 buckets switch to dense mode with sparse labels.
- Top nav items never wrap; the overview subtitle uses the prototype wording "bad case 趋势", and `tn-note` plus subtitles hide on narrow screens so the four items stay on one line at 1440px, while the mobile nav scrolls inside its own container.
- The bad-case ID is the only in-row link, with `target="_blank" rel="noopener"` pointing at `/workspaces/:wid/sessions/:sid/errors?case=<id>&tab=desc`; the row itself is not clickable.
- Only the bad-case tab ships: `tab=targets` canonicalizes back to `tab=cases` with an M11 notice, and the "evolution targets overview" button stays visible but `disabled` instead of hiding controls to pretend the capability is absent.
- The default landing moves to the overview: `DEFAULT_WORKSPACE_PATH` becomes `overview`, `/workspaces/:wid` redirects to `overview`, and login plus workspace choice share `defaultLandingPath`; `legacyWorkspaceTarget` still maps `/sessions` and `/errors` to the Session list and only `/` enters the overview; `switchableWorkspaceChild` keeps `/sessions` when switching workspaces. The overview route is lazy-loaded, and the top nav gains an overview entry before Sessions.
- No SourceMatrix in this issue: m8-03 has no per-object × bucket field, and stitching a matrix from the current eight-row page would produce wrong totals. The source distribution shows the top six plus a "remaining N sources" aggregate row that can expand to all. m12-08 later restores the matrix with per-bucket sources aggregates instead of a new API field; see [the 2026-11-18 overview actions/context note](2026-11-18-overview-actions-context.en.md).
- Contract types are re-exported from the m8-03 generated `components["schemas"]` through `packages/contracts/src/overview.ts`; this issue adds or changes no HTTP endpoint.
- At delivery the page has no write operation: filters, chart, and list are all read-only, and viewers see the same view as administrators. m12-08 later adds role-gated ingest/launch entries and operational context; see [the 2026-11-18 overview actions/context note](2026-11-18-overview-actions-context.en.md).
- The overview page's scroll container is `.overview-page`: it fills the workspace main's width and owns `overflow-y: auto`, then uses symmetric inline padding (`max(20px, calc((100% - 1180px) / 2 + 20px))`) to center the 1180px content column (including its 20px padding). The scrollbar is therefore painted at the window's right edge, matching the V2 prototype's document scrolling; the workspace main keeps `height: calc(100vh - 56px)` and `overflow: hidden`, so other pages' inner scrolling is unchanged. The 1024/640 breakpoints come from the content column reflowing on its own.

## Alternatives considered

- **Stitch an object × bucket matrix from the current page's bad cases**: rejected. The list has eight rows per page, so cross-bucket counts would be systematically low and would change with paging; that is fabricated data, not a degradation.
- **Keep sessions as the default landing and only add a nav item**: rejected. The issue requires the overview to become the workspace root; preserving the old `/sessions` mapping is enough for old links.
- **Add a third-party chart library**: rejected. The trend is just stacked bars plus axes and a tooltip; hand-drawn SVG reuses the existing tokens, adds no first-screen bundle, and avoids stacking a chart theme on top of Element Plus.
- **Keep the `type` filter in component state instead of the URL**: rejected. After a refresh or share the list and chart would silently disagree; the URL as the single source is the page's most verifiable contract.
- **Reset filters in the page watcher on a `wid` change**: rejected. The page watcher cannot distinguish a picker switch from browser back, so both rewrite the URL: going back overwrote the previous workspace's filters with defaults and rewrote that history entry. Putting the reset on the picker's navigation while the page watcher only canonicalizes satisfies both "no old filters in the new workspace's first requests" and "back restores the previous query".
- **Silently return to cases for `tab=targets`, or hide the tab**: rejected. Silent redirects look like broken links, while hiding cannot express the M11 boundary; a disabled entry plus a one-time notice is the honest option.
- **Keep the prototype's right column (quota / ingest / current workspace)**: rejected by this issue. Quota is already the sixth stat cell, and ingest plus member details belong to workspace administration; this issue neither copies admin capabilities nor introduces a second quota figure. m12-08 restores the column under the newer production/prototype comparison, reusing summary and session counts; see [the 2026-11-18 overview actions/context note](2026-11-18-overview-actions-context.en.md).
- **Use a whole-page spinner or load the four requests serially**: rejected. The matrix and the list differ in volume, and any single failure would take down the page; independent block requests are what "chart and list do not block each other" requires.

## Consequences

- The URL has one more key than the issue listed: `type`. Only the stat strip writes it and it disappears by default. Unknown source names in `objects` are passed to the API as-is (the server filters them out naturally), and a switch navigates with the default query, so filters never leak across workspaces; browser back/forward restores each workspace's own filters.
- Old `/errors` and `/sessions` links still land on the Session list; only the application root `/` moves to the overview. External bookmarks pointing at `/workspaces/:wid` without a child path now open the overview instead of the Session list, as this issue intends.
- The SourceMatrix and the object × bucket detail remain an explicit debt in this issue: m8-03 needs an object-bucketed count (or a trend reused under an object filter), and the frontend must not assemble page data. m12-08 fills it by reading the existing sources aggregate per time bucket without adding an object × bucket API field; see [the 2026-11-18 overview actions/context note](2026-11-18-overview-actions-context.en.md).
- The deferred targets tab still lacks F25; until M11, any `tab=targets` link only sees cases plus the notice.
- Dense mode compresses labels above 60 buckets; up to 60 buckets keep full labels. Every bucket keeps a clickable area whether or not it has data, the 390px page-level no-horizontal-overflow assertion still guards mobile, and the narrow top nav scrolls inside its own container.
- An out-of-range `page` first shows "page N has no data" with the pager, then clamps to the last valid page; a 404 `WORKSPACE_NOT_FOUND` no longer renders as four blocks that can never retry successfully, but returns the whole page to the workspace chooser.
- The E2E suite creates its own workspace and ingests eleven "today/yesterday" bad cases with a credential, so assertions do not depend on the fixtures' fixed historical dates; the default-landing case only checks structure on ws-default and never asserts specific counts.
- The page has no write entry in this issue, so viewer roles need no extra button-level degradation; adding ingest or launch entry points later will require a read-only state as well. m12-08 adds it: unauthorized roles see only a read-only notice, never a bypassable empty link.
- The real-browser suite now carries 36 cases after M8, so the `run-e2e` default budget is 600s and the CI step allows 12 minutes. A `HE_LOGIN_RATE_LIMIT` setting (default 10) was added and set to 100 in E2E so per-test logins do not trip 429.
- The overview scrollbar is flush with the window's right edge (at 1500×837 with always-visible scrollbars it no longer sits at the content column's right edge); the content column stays 1180px and centered. `.overview-page` remains the scroll container under its `data-testid`, so the existing E2E `scrollTop`/`scrollHeight` assertions keep working.
