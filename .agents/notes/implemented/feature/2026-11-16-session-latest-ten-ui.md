# Agent Note: Session 列表最新 10 条与回车精确查询

Status: implemented

[English](2026-11-16-session-latest-ten-ui.en.md) | 中文

## Problem

空间 Session 页在 m8-02 之后已经拿到权威的 `total` 与 `pendingSessions`，但页面仍沿用 V1 交互：首屏请求 `limit=100`，搜索框每次输入都经 300ms 防抖把原文写进 URL 并重新请求。V2 的 `q` 只做完整 root session ID 精确匹配，输入片段永远无意义；同时实时筛选会让「输入 → 请求」数量不可预测，也无法表达「未命中后清空右侧选中态」。页面需要改成：首屏只取最新 10 条，完整 ID 回车（或点搜索图标）才查询，清空再回车恢复最新 10 条，并把 `total` 与待同步角标显式呈现。

## Decision

- 列表请求固定 `limit=10`；URL 继续只承载 `q`、`status`、`sort`，不承载 `limit`。首屏、筛选、前进后退都复用同一份 URL 派生的 filters。
- 搜索框输入只更新本地 `searchInput`，不发请求、不写 URL。按 Enter 或点击搜索图标才提交；提交时 trim，值未变化则不动路由，避免重复请求。
- 提交查询会把路由切到列表路径（无 `sessionId`）并丢弃 `agent`/`evidence` 深链参数，因此查询未命中时右侧概览立即回到空态，不保留旧选中；命中时由既有「首屏无选中自动选第一条」逻辑选中唯一结果。
- 清空输入再 Enter 提交空 `q`，走同一条列表路径并清除筛选，恢复最新 10 条；空态的「恢复最新 10」按钮调用同一动作。状态与排序筛选仍保留当前选中，不因筛选排除而清空右侧（与既有行为一致）。
- 标题区显示 `最新 {items.length} / 总数 {total}`；有 `q` 时显示 `命中 {total} 个`。`total` 缺失（旧响应/测试桩）时回落为当前页条数，避免显示 `undefined`。
- `pendingSessions > 0` 时标题区追加「N 个待同步」按钮；点击展开一句说明：待同步表示 bad case 已上报但轨迹尚未归一化，列表只展示已归一化 Session。角标与 `q`/`status` 无关，搜索无结果时仍显示。
- 空态按三种来源分文案：有 `q` 时是「未找到匹配 “q” 的 Session」+ 恢复入口；仅状态筛选为空时是「没有匹配当前筛选的 session」+ 恢复入口；无筛选且 `pendingSessions>0` 时说明待同步轨迹仍在补齐；否则说明空间还没有上报 bad case。右侧空态在查询态显示「未找到该 Session」与重新查询提示，普通空态显示「未选择 Session」。
- 搜索输入框 placeholder 改为「输入 root session ID，回车查询」，下方提示「Enter 精确查询 · 清空后回车恢复最新 10 个」；搜索图标从装饰 SVG 变为可点击的提交按钮，视觉上仍与原型一致。不含输入法组合态提交（`isComposing` 时忽略 Enter）。
- 页面不新增 API、缓存键或契约字段；本 issue 只消费 m8-02 已返回的 `items/total/pendingSessions`。

## Alternatives considered

- **保留 300ms 防抖**：拒绝。V2 `q` 是完整 ID 精确匹配，逐字输入只会产生一串必然为空的请求；issue 也明确要求移除实时查询。
- **前端取 100 条再切前 10 条**：拒绝。`total` 与 `pendingSessions` 需要服务端权威口径，前端切片会让计数与列表脱节。
- **提交查询时保留当前选中**：拒绝。未命中时右侧会继续展示不在结果里的旧 Session，与设计「未命中清空右侧」冲突；命中时又会被自动选中覆盖。
- **把待同步根混进列表并置灰**：拒绝。API 明确 pending 只贡献计数、永不进入 `items`；前端伪造行会让排序、统计和「总数」口径互相矛盾。
- **用按钮替代 Enter**：拒绝。原型与设计都以 Enter 为主路径；保留图标按钮是为了可点击与可访问，不改变主交互。

## Consequences

- 输入期间没有任何列表请求；一次提交只触发一次列表请求（值未变化时零次）。E2E 通过 CDP 计数验证这一点。
- 只支持完整 root session ID；标题、仓库、ID 片段的检索在 V2 不开放，空态文案明确提示完整 ID。
- `total` 与 `pendingSessions` 不可相加：前者是当前 `q`/`status` 下已归一化根数，后者与查询/筛选无关。页面分开展示，不合成「全部上报根」。
- 搜索命中仍受当前 `status`/`sort` 影响；例如 `status=problem` 下输入一条已完成会话的 ID 会得到空结果，这是设计允许的组合语义。
- 侧栏 H1 仍是「Session 浏览器」。原型侧栏写「Session」，但该文案被应用级导航与既有 E2E 断言引用，本 issue 不改，避免让一个局部交互改动扩散到全局导航。
- 待同步说明是页面内展开文本，不是新的待同步列表页；查看待同步根仍需后续 API 或管理端能力。
- E2E 使用 `fixtures:seed` 的四个 ws-default 会话验证最新 10 条、回车命中/未命中/恢复；另建一个空间上报 pending 根验证跨空间隔离与待同步角标。
