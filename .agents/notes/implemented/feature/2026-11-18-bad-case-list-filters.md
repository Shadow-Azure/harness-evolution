# Agent Note: 总览 bad case 列表级筛选

Status: implemented

[English](2026-11-18-bad-case-list-filters.en.md) | 中文

## Problem

工作空间总览把时间范围、粒度和上报来源放在页头，只服务趋势图、来源分布和统计条。bad case 列表借用同一组参数，因此用户无法在保留图表上下文的同时单独缩小列表查询。V2 原型在列表头提供独立的开始日期、结束日期、上报来源和问题类型控件，且日期为空时不限制时间；生产页面两者都没有。

难点不在四个控件，而在“空 = 不限”：现有 `GET /workspaces/{wid}/bad-cases` 在没有任何日期参数时默认解析成最近 90 天，并在 366 天处拒绝更宽窗口。如果前端把空日期翻译成任何现有窗口，列表就不是真正不限时间，旧数据会被静默隐藏。

## Decision

- `overviewUrl.ts` 为列表增加 `listFrom`、`listTo`、`listObject`（URL 键 `lfrom`、`lto`、`lobject`），继续用既有 `page` 和 `type` 作为列表页码和类型；旧 URL 的 `page`/`type` 语义不变。
- 列表查询只读这四个列表字段：日期成对时发送 `from/to`，否则发送 `allTime=true`；来源发送 `objects=<单个>`；类型发送 `badCaseType`。趋势/统计仍读 `range`、`objects`、`grain`。
- 列表端点新增可选布尔参数 `allTime`，为真时跳过窗口解析和日期谓词，但保留来源、类型和分页。这是本切片唯一的契约扩展，没有新增端点、表或客户端全量过滤。
- 图表级筛选、清除和切换 Tab 不再重置列表页码；任一列表筛选变化把 `page` 重置为 1。点击趋势桶只写 `lfrom/lto`，不重写图表窗口。
- 开始/结束日期在组件内保留草稿：只有成对且有序时才写 URL；单边或倒置时保留上一有效结果并就地提示，不发请求。两个都清空立即恢复 `allTime`。
- 列表头保留类型 chip（只清类型）和整体重置入口；筛选无命中用“当前筛选没有命中”空态并提供清除，空间无数据仍用空间级空态。

## Alternatives considered

- **把空日期翻译成 `range=90` 或 366 天窗口**：实现最小，但“空 = 不限”名不副实，一年前的 bad case 会被隐藏；拒绝。
- **在浏览器里拉全量再过滤**：违反服务端分页与总数的既有边界，列表一大就失真；拒绝。
- **给 `range` 增加 `all` 枚举**：会让窗口解析、粒度和 422 语义全部认识一个特殊值，影响其他三个读端点；改用只作用于列表的布尔参数。
- **每个列表筛选字段都改为 `list*` 命名**：`type`/`page` 本来就只影响列表，改名只会制造 URL 迁移；保留旧键，新键只覆盖确实新增的日期和来源。
- **全局“清除筛选”连列表一起清**：两层筛选已经独立，合清会让用户丢失刚刚设置的上下文；改为各自清除。

## Consequences

- 列表默认展示空间内全部上报记录，数量很大时首屏 query 仍是 `pageSize=8` 的分页查询；`count(*)` 走 `workspace_id` 索引，代价可接受。
- `allTime` 与 `from/to/range` 同时出现时以前者为准，接口文档写明；其他总览端点不识别该参数。
- 旧 URL 仍可解析，但旧 `objects` 只再影响图表，不再隐式缩小列表；这是本切片有意改变的行为。
- 列表页码和类型键沿用 `page`/`type`，与进化对象视图共用 URL 键，切换 Tab 时仍由既有逻辑重置。
- 后续若列表需要多选来源或单边开放日期，需要新的契约讨论，不能复用本参数。
