# Agent Note: Four structural decisions for real-model self-evolution

Status: implemented

English | [中文](2026-11-22-evolution-real-ai-design.md)

## Problem

Clustering, confidence, severity, and patch generation in the self-evolution loop are placeholder implementations (lexical clustering, fixed confidence, constant formulas, placeholder patches). Wiring in real model capability forced four structural decisions: where outbound model calls converge; at which layer the model participates in clustering and how it scales with the volume of attribution reports; how structured JSON conclusions are collected reliably; and what representation edit patches use. The finalized design of 2026-11-22 ([07 §5.5.1–§5.5.4](../../../../plans/fullstack-design/07-backend-implementation.md)) locks in four answers; this note records why, and what was rejected.

## Decision

- **Outbound model calls converge on the `third_party_api/ai_agent` parent interface**: two capability faces (`analyze` / `edit_workspace`) plus a factory selecting a subclass by `AI_AGENT_PROVIDER` (currently only claude-code and fake); interfaces are split by capability, not vendor, so switching backends means adding a subclass. This is not a revival of the early "unified Provider layer" — it serves exactly one seam, model egress.
- **Clustering splits into three layers with LLM input/output decoupled from the attribution-report volume N**: a grouping layer at O(N) with no LLM (lexical first, vectorization as the upgrade slot); a review layer at O(K×s) doing merge/naming only (draft-key references plus the draft-partition integrity gate); a scoring layer at O(K×s) with direct cluster confidence and severity dimensions. Case-level confidence stays a rule-based signal — per-case blind scoring loses cross-case corroboration and costs O(N).
- **Structured collection goes through a self-built submission channel**: the agent writes `result.json5` (JSON5 lenient literal), and `submission.py` parses deterministically, validates, and retries with error feedback; no CLI-internal mechanism is relied upon (Claude Code's `--json-schema` is demoted to an optional fast path, off by default). The value of "generate JSON with JS" is distilled into lenient literals plus deterministic serialization, without executing model code.
- **Patches use SkillOpt-style Edit instructions**: after read-only exploration the agent submits an EditPlan (op/file/target/content/rationale); anchors must exist and be unique (ambiguity is fed back); `edits.py` applies deterministically with `git diff` as the single truth; `edit_budget` is enforced twice (prompt constraint plus hard truncation); `EditRequest` carries `session_id` and `EditResult` returns the plan; an eval reject ends the turn with no turn-level automatic retry, `--resume` feedback, or rejected-edit buffer (2026-11-23 decision). The agent tool surface shrinks to read-only plus writing one json5 — no file-edit permission.

## Alternatives considered

- **Per-case model confidence (before clustering)**: fits the attribution evidence cache naturally, but single-case blind scoring loses the corroboration effect and costs O(N); replaced by rule signals plus cluster-level direct scoring, with per-case model scoring kept as a budget switch.
- **Relying on the `--json-schema` native channel as the main path**: maintenance-free and reliable on Claude Code, but a CLI-internal mechanism — switching to opencode-like backends would crater layer-1 strength and require rewriting the feedback loop; demoted to an env-gated fast path.
- **Direct agent file editing with diff collection**: stronger for complex refactors, but intent is uncountable and it needs the acceptEdits permission surface; targets are skill/config documents (the instruction-style home turf), so direct editing stays a future switch.
- **Having the agent call a JS script to produce JSON**: the data still has to be hand-written by the model as arguments or files, or model code must be executed; replaced by "write a lenient literal, parse deterministically", keeping scripts only as a content-computation tool shape.

## Consequences

- The design has landed in `plans/fullstack-design` (07 §5.5.1–§5.5.4, the 04 tree and seam table); follow-up implementation issues use it as the design basis, and this note syncs status and facts as landing proceeds.
- Implementation proceeds in stages (skeleton → three clustering layers → optional vectorization → instruction-style patch), each reversible via env (fake / placeholder); the worst case equals today's behavior.
- Adds the pure-Python dependencies `json5` and `json-repair`; `edit_workspace` semantics shift from "edit directly" to "submit a plan, apply deterministically" — no in-turn trial loop, compensated by the turn-level iteration loop.
- The contrast between the declared intent (EditPlan) and the actual diff becomes a per-turn audit signal; any mismatch is a quality alarm.
- On 2026-11-22 the skeleton landed (bugfix-15): the four `ai_agent` modules, only two Settings entries, a deterministic `fake`, and a `claude-code` placeholder; the real CLI subclass and business wiring remain in follow-up issues.
- On 2026-11-22 the submission channel landed (bugfix-16): `third_party_api/ai_agent/submission.py` collects through a one-shot task directory whose sole tool whitelist is `Write(./result.json5)`; parsing runs strict JSON → JSON5 → json-repair (fallback only), the payload goes through Pydantic `model_validate`, and `feedback_prompt` feeds failures back to one bounded retry prompt.
- On 2026-11-22 the submission channel is the default and only path: `HE_AI_AGENT_NATIVE_SCHEMA` / `--json-schema` stays a design-doc fast-path option only and is deliberately not implemented, to be revisited when a real need appears; `SubmissionOutcome.parsed_by` plus the bounded `repair_log` are the layer-5 provenance fields recording which tier parsed the document and what the repairer changed; the result filename and tool whitelist are not parameterized, and reusing the channel for `edits.json5` is deferred to bugfix-21 (which needs a filename/path parameter and a backend-specific tool override).
- On 2026-11-23 the EditPlan mechanical layer landed (bugfix-20): `third_party_api/ai_agent/edits.py` defines the four ops and their cross-field rules in Pydantic (`EDIT_BUDGET=8`, 400 lines per content, canonical relative POSIX paths, `.harness-evolution/**` and `.git/**` rejection), and `apply_edit_plan` re-reads each file in order and writes atomically; the per-edit `applied / skipped_anchor_missing / error` report records a single failure and continues, since atomic replacement leaves the file at its last consistent state. `PatchBundle.sha256` equals `Patch.sha256` byte-for-byte for one file and hashes sorted `(path, content)` pairs for multiple files; `PatchSource.build_bundle()` wraps the legacy `build()/change_note()` pair as a one-file bundle, leaving placeholder and minimal-config behavior unchanged. `agent-edit` is registered as a reserved mode and the factory fails with the bugfix-21 reference; workspace `create_candidate_bundle` stages bundle files, excludes `.harness-evolution/**` by default, and returns the real `git diff` as `CandidateWorkspace.unified_diff`.
- On 2026-11-23 the three clustering layers were wired into prepare (bugfix-19): after lexical grouping, one `analyze(task="cluster.review")` call receives a roughly 60-token summary per draft, 3–5 representative samples drawn deterministically by case id, and the type/member-count/signature-overlap/time-span statistics, while the member lists stay in code and never reach a prompt (an N=200 and an N=50 run over the same three drafts produce an equal-length review prompt). The output references drafts by key (`{"from": ["D1","D2"], "title": …}`) and code expands members from `from`; the hard gate is draft-partition integrity (every key exactly once, no unknown key, no cross-type merge), and any violation degrades the whole batch back to the drafts. The scoring layer then costs exactly two batch calls covering every final cluster (`C1..Cm`): `cluster.score` (direct 0–1 rating plus `evidence_refs` restricted to the same cluster's prompt sample ids) and `severity.score` (an `overall` decision score, the five stable dimension names `impact/scope/reproducibility/evidence_directness/blast_radius`, and a CVSS 3.1 vector). The two calls are isolated, so one task failing degrades that task's values for every cluster — confidence back to `TYPE_CONFIDENCE`, severity back to `cluster_severity()` — keeping the run at exactly three bounded analyze calls (one review plus two scoring) regardless of cluster count. The formula score still lands next to the decision score as `severityFormula` in the `clusters_created` payload for comparison, and dimensions/vector stay in audit payloads while the DB columns remain `confidence/severity/rank` (zero migration). With an agent bound the algorithm identity is fixed at `hybrid-lexical-llm-v1`: the id describes the pipeline, not how much the model actually contributed, so degradation never changes it, but every fallback writes its task key into `clusters_created.payload.degraded` (the key is absent when nothing degraded) and a fully degraded run stays distinguishable from a model-assisted one. Without an agent the lexical path stays byte-for-byte `lexical-jaccard-v1`; every call records `ai_agent_call` (task/provider/model/tokens/cost/latency/outcome/sessionId, level=info) and every fallback records `degraded` (level=warn, task/reason) on the existing `String(48)` column. A merged cluster's `signatureOverlap` is recomputed as the mean pairwise Jaccard of the merged member titles, falling back to the draft weighted average only when evidence is missing; the prompt label `reportedSpanDays` makes clear the span comes from `bad_cases.created_at` (reported time). The `claude-code` placeholder still raises `NotImplementedError`, and after each layer degrades on its own the run completes as usual — the worst case equals the lexical path.
- On 2026-11-23 the real Claude Code subclass landed (bugfix-17): `third_party_api/ai_agent/claude_code.py` invokes `claude --bare -p <prompt> --output-format json --permission-mode dontAsk --allowed-tools <derived write tool>` through `create_subprocess_exec` with `start_new_session=True`; analyze adds `--no-session-persistence` and passes `--settings` only when `~/.claude/settings.json` exists, while edit keeps the session and may write only `.harness-evolution/edits.json5` (collected, not applied; bugfix-21 wires it in). Timeout/cancellation signals the process group with SIGINT first, waits a five-second grace period, then SIGKILL; exit code 143 and `cancelled` both normalize to `detail="cancelled"` with `retryable=False`. A failed submission gets exactly one stateless feedback retry: the original prompt is repeated with the `feedback_prompt` validation text and no `--resume`, because the real CLI 2.1.278 documents `--no-session-persistence` as "cannot be resumed"; a measured `--resume` against a non-persisted session exits 1 with `No conversation found with session ID`, so the issue's literal `--resume` is infeasible while the design intent (retry once with feedback) is preserved. `total_cost_usd`, `usage`, and the real CLI's camelCase `modelUsage` (entries use `inputTokens`/`outputTokens`/`costUSD`) map into `AgentUsage`; both spellings are accepted, the per-model breakdown is never added on top of the aggregate, and the model identity comes from the `modelUsage` keys (a top-level `model` wins), so tokens are not double-counted and the model is not lost. A missing `session_id` is allowed. The health probe runs `--version` with a ten-second timeout and never raises; on success it names only the credential source (`ANTHROPIC_API_KEY` or `apiKeyHelper`) or reports "no bare-mode auth configured", never reading or printing a credential value. Feature detection reads only `system/init.capabilities` into a private field: no version comparison, and no `--json-schema` fast path. `submission.prepare` gains `directory` / `filename` overrides: an explicit workspace receives the same Pydantic-derived schema inlined in the prompt instead of a written `schema.json`, and the sole write tool is derived from the filename. `SubmissionPrep.owned` separates a channel-minted directory (which `discard` may remove) from a caller directory (where `discard` is a no-op, so a symmetric `finally` cannot delete a workspace); `schema_reference` points retry feedback at `./schema.json` for a minted directory and at the inlined prompt schema for an explicit one; and the result path is checked with `Path.resolve()` containment before any unlink or read, so a symlink cannot take deletion or reading outside the submission directory. The default path (one-shot task directory + `result.json5` + `schema.json`) keeps byte-identical output. Known limits: stdout has no size ceiling (`communicate` buffers it first; only the process timeout bounds runtime); the opt-in real-CLI e2e still covers only the happy path (model identity and token assertions are tighter, the feedback retry is covered by unit tests, and no marker/lane was added); the edit iteration loop still waits on #488 — `EditRequest` has no `session_id` and `EditResult` does not return the plan, both needed for the rejected-edit buffer. `AI_AGENT_PROVIDER=claude-code` now builds the real subclass, every failure folds into `AgentProviderError`, and diagnostics pass through `sanitize_detail` with a bounded length.
- On 2026-11-23 the agent-edit patch source landed (bugfix-21): `AgentEditPatchSource` collects an `EditPlan` (`EditResult.plan` carries the intent), mirrors only the plan's target files into a temporary directory, and runs `apply_edit_plan` there, so repository bytes are never dirty before the candidate commit — an out-of-scope or failing edit cannot leak into the run branch and no `git checkout -- .` rollback is needed; a plan with no applicable edit fails the turn without a second model call. `publish` switches to `build_bundle()` + `create_candidate_bundle`: a one-file bundle keeps the `Patch.sha256` bytes and a multi-file bundle uses the sorted `(path, content)` hash; the turn `patch` JSON gains `files` / `intent` / `report` while keeping the legacy single-file keys, and `candidate_committed` records intent, the per-edit report, and a bounded `unifiedDiff` taken from the candidate commit's real git diff. The `--max-turns` constant is 40 and bounds one call together with the timeout; a retryable provider failure lands as `blocked(stage=patch)` and a non-retryable one fails terminally. Per the maintainer decision on 2026-11-23, an eval reject ends the turn: no automatic turn-level retry, `--resume` feedback, or rejected-edit buffer, avoiding cross-module changes to the turn lifecycle and progress cursor; the issue and design document are synced.
- On 2026-11-23 the observability and permanent-doc closeout landed (bugfix-22): `ai_agent_call` payloads come from `service/evolution/ai_observability.py` and now carry `totalTokens` (input plus output), `attempts`, `feedbackRetries`, `submissionRounds`, and `submissionParsedBy`/`submissionRepaired`/`submissionParseFailures`/`submissionValidationFailures`; every outbound call, including a failed one, is recorded for the three analyze tasks and agent-edit, so the submission parse failure rate is derivable from the event stream. `submissionParsedBy` names the final collection pass tier, and a failed call keeps usage/latency when a CLI result was already parsed. The new `docs/ai-agent.md` documents the outbound layer, submission channel, and event contract; `HE_PATCH_SOURCE_MODE=agent-edit` passes configuration validation.
