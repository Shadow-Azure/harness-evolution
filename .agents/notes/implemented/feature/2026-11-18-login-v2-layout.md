# Agent Note: 登录页对齐 V2 双栏信息架构

Status: implemented

[English](2026-11-18-login-v2-layout.en.md) | 中文

## Problem

生产登录页只有约 420px 的单列白卡，信息只够承载品牌、登录标题和表单；V2 原型用约 920px 的双栏卡片解释工作空间隔离、对象级归因和默认 10 个 Session。原型的右栏还有四个账号按钮，但那是打桩演示；直接复制会枚举真实账号并暗示身份切换。m12-11 要在不放宽现有认证边界的前提下，把信息层级和视觉结构对齐原型。

## Decision

- 桌面登录页使用 `min(920px, 100%)` 双栏卡片：左栏是品牌与三条静态产品事实（工作空间隔离、归因进入进化流程、默认 10 个 Session），右栏保留用户名/密码表单、内联错误、加载态和首次改密提示。
- 左栏不读取用户目录、不渲染账号/邮箱/可点选账号；登录页没有任何账号枚举请求，Tab 顺序从左栏之后直接进入用户名、密码、登录按钮。
- 桌面宽度不超过 760px 时改为单列，隐藏三条长说明与左栏页脚，保留品牌、标题和一句能力摘要；390px 下无横向溢出。
- 卡片背景、圆角、边框、间距与断点复用 `styles/tokens.css`；新增 `--shadow-auth-card` 只是把原型的大卡片阴影收进 token 层，不引入第二套视觉变量。
- 登录 API、Cookie、强制改密、权限与路由守卫不变；错误仍是内联 `role=alert` 与 `aria-live=polite`。

## Alternatives considered

- **照搬原型账号按钮**：拒绝。它会枚举真实账号并暗示一键切换身份；生产账号只能由管理员创建或 env 播种。
- **保留 420px 单列卡只改文案**：拒绝。单列卡承载不了原型的信息层级，issue 的目标就是双栏。
- **把左栏能力说明做成可点入口**：拒绝。登录前没有会话与空间上下文，链接会引入未认证路由。
- **在登录页新增一套颜色或阴影变量**：拒绝。`verify:web-style` 要求 `tokens.css` 是颜色唯一来源，视觉基线也应与主应用共享。

## Consequences

- 登录页主内容在桌面变宽为 920px，窄屏回落到单列；页面仍无顶栏，提交与回跳行为不变。
- 新增 `tests/e2e/m12-11-login-v2-layout.test.mjs`，覆盖双栏/单列、无账号枚举、键盘顺序和内联错误；`m1-shell` 的登录断言继续复用 `.auth-card` 与品牌锁排。
- `plans/fullstack-design/08-frontend-implementation.md` §4.1 的结构图同步为双栏；原型账号列表仍只是演示，不构成生产契约。
- 未来接入 SSO/OIDC 时，接入说明仍以空间管理页的「鉴权接入」为唯一事实源，登录页不新增第三个来源。
