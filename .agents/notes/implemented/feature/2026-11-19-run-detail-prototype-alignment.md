# Agent Note: 自进化运行详情页按 V2 原型重排

Status: implemented

[English](2026-11-19-run-detail-prototype-alignment.en.md) | 中文

## Problem

生产「自进化 → 运行详情」把工作区信息做成独立卡，排在「目标与输入」和「流程进度」之间，流程进度被挤到第三张卡之后；「目标与输入」显示了原型与设计文档都没有的「模型（多选）」，缺少原型里的「工作空间」「可归因 / 非该对象」、策略与缓存来源徽标；页头显示创建人 · 时间，而设计文档 08 §10.1 要求「标题 + 状态 + 空间 badge」；分布标题按「已归因结论」统计，与原型「潜在 bad case 的归因结论分布」不一致。原型自身缺少「执行日志」页签和「准备中」态，而设计文档 08 §10.2 / §10.4 明确要求这两个能力，导致同一页面无法用原型验收。问题与对照证据见 GitHub #403。

## Decision

- 详情页改为单列：页头（标题 + 状态 + 空间 badge）→ 目标与输入 → 流程进度 → 当前步骤产出；删除独立「工作区」卡，把 run 分支、基线、仓库、子目录、推送与评测状态、本地路径收进「目标与输入」底部的折叠区，分支名仍可复制。
- 「目标与输入」按原型字段集排列：进化对象 / 版本 / 时间段 / 工作空间，关联 Session、时间段内 bad case、潜在 bad case、可归因 / 非该对象；移除「模型（多选）」。分布标题统一为「潜在 bad case 的归因结论分布（N 条）」，图例补「非该对象」与「本次新增」，分母用潜在数。
- 不改 API 契约：策略与缓存开关取自已到达的 range step `condition.policy` / `condition.cacheEnabled`；非该对象、复用缓存与本次新增按 attribution step 的 rows 行级统计（`category` 为空即非该对象，`source` 区分 cached / fresh；「本次新增」只计可归因的 fresh 行，与原型一致），归因未完成时这三项显示 `—`，分布条以「未归因」余量补齐。两个 step 查询与页面已选的 step 共用 query key，同一 key 不会重复请求，日志页签不发起这两个查询。
- 保留「七步详情 / 执行日志」页签与「准备中」态，并同步补齐 V2 原型：原型增加页签、日志面板、空间 badge、工作区折叠区与一个准备中示例运行。设计文档 08 §10.1 补充分布口径与工作区折叠，§10.4 明确页签形态。

## Alternatives considered

- **保留独立「工作区」卡，只把它移到流程进度之后**：拒绝。设计要求工作区信息归属 infoPanel，且独立卡继续占用整行高度，解决不了页面层级偏差。
- **扩展 `EvolutionRunStats` 增加 `nonTarget` / `sessionsTotal`**：拒绝。issue 明确不改 API 契约；现有 attribution step 已提供精确的 `nonTarget` / `reused` / `fresh`，range step 已提供策略与缓存开关，复用读取即可。
- **用 `potential - attributed` 推导非该对象**：拒绝。准备中或归因进行中时该差值包含未归因行，会把未分析的行误标成非该对象；必须等 attribution step 到达后读 summary。
- **删掉生产页签和准备中态以贴合旧原型**：拒绝。设计文档 08 §10.2 / §10.4 要求执行日志页签与 preparing 状态，正确方向是补齐原型而不是削减生产能力。
- **保留「模型（多选）」并在原型/设计文档补回**：拒绝。模型筛选不在原型与设计文档的信息架构内，详情页也没有按模型过滤的交互；保留会让同一页出现两套字段集。

## Consequences

- 详情页首次加载会多读 range 与 attribution 两个 step（按 step 状态启用，准备中只读 range，尚未到达的 step 不请求）；与用户当前选中的 step 共用缓存，切到这些 step 时不再重复请求。
- 「关联 Session」仍显示 `已关联 / 版本未知`，因为契约没有提供时间段内 Session 总数；原型用示例数据展示 `已关联 / 总数`，生产不伪造该总数。
- 「模型（多选）」从详情页移除，run 快照与 API 字段保留，其他消费方不受影响。
- V2 原型新增日志页签、准备中示例、空间 badge 与工作区折叠区；设计文档与原型、生产实现三处字段和顺序一致。
- 覆盖组件测试（目标与输入字段、工作区位置、策略/缓存徽章、分布文案、页签与准备中态）与 E2E（页头、卡片顺序、工作区不独立成卡），Before / After 截图放 PR 描述。
