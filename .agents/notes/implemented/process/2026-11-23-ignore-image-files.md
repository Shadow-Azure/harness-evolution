# Agent Note: 默认忽略全部图片类型

Status: implemented

[English](2026-11-23-ignore-image-files.en.md) | 中文

## Problem

日常工作和 Agent 执行会在工作区留下截图、下载图片、粘贴附件等图片文件。仓库根 `.gitignore` 此前没有覆盖任何图片扩展名，这些文件会持续出现在 `git status` 里，既制造噪声，也增加误提交的可能。仓库同时跟踪 380 张文档、检视与报告配图（约 38 MB），这些历史证据必须继续可读、可修改；忽略规则只作用于未跟踪文件，不能用 `git rm --cached` 把它们移出索引。

## Decision

在仓库根 `.gitignore` 增加一组成员图片扩展名规则：`png`、`jpg`、`jpeg`、`jpe`、`jfif`、`gif`、`webp`、`avif`、`bmp`、`tif`、`tiff`、`ico`、`svg`、`heic`、`heif`、`apng`。规则作用于任意目录，不设目录例外，也不移除任何已跟踪文件。

## Alternatives considered

只忽略固定目录（例如 `reports/`）：不满足「全部图片类型」的要求，其他目录仍会冒出图片噪声。为 `docs/`、`plans/`、`reports/` 增加负向例外：能让未来截图继续被跟踪，但这三个目录恰好是图片最常出现的地方，等于把要求放空；而已跟踪图片本来就不受忽略规则影响，例外保护不了任何现有文件。把图片交给 Git LFS 管理：LFS 解决大文件存储，不解决未跟踪文件的过滤，还会引入额外远端依赖。用 `git rm --cached` 清理历史图片：会删除文档与检视记录引用的配图，破坏可读性，明确不做。

## Consequences

新产生的图片文件默认被忽略；若某次文档或检视确实要把新图纳入仓库，需要显式 `git add -f`，或先回来调整本文与忽略规则。已跟踪的 380 张图片不受影响，仍可正常修改与提交。规则按扩展名枚举，遇到新的图片格式要补一行；文件名大小写敏感的平台（如 Linux）不会自动匹配大写扩展名，本机 macOS 的大小写不敏感索引可以覆盖。仓库不会因此改变历史，也不会引入 LFS 或图床依赖。
