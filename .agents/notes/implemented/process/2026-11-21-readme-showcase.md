# Agent Note: README 作为项目入口与截图数据边界

Status: implemented

[English](2026-11-21-readme-showcase.en.md) | 中文

## Problem

根 `README.md` 长期停留在“M1 工程骨架推进中”，正文以快速开始、生产部署前置和目录结构为主。项目已经交付工作空间、轨迹归一化、多归因、七步自进化与 lane DAG，新读者从 README 既看不到产品定位，也看不到界面；而 `docs/architecture.md` 已经维护了“已具备 / 未具备”的现状，README 成为过期信息的第二份副本。

README 还需要一个产品截图，但仓库规则明确不把生产 Session 内容、截图或凭据写入仓库。若直接截生产页面，既泄露内部数据，也让截图随生产数据漂移；若只放文字，首屏又无法说明“这个工程长什么样”。同时 README 的词数预算只有 400，增加定位、能力与截图说明必然超限，需要明确预算处置。

## Decision

- README 的第一屏回答“是什么、能做什么、怎么看”：一句定位、一张关键截图、四条核心能力，然后才是快速开始、文档入口与目录结构。
- 只保留一张截图，选 Session 浏览器 + 执行流 lane DAG + 问题卡的 Session 详情页；它同时覆盖轨迹查看、执行流与证据回链，比总览或运行详情更能代表产品。
- 截图来自本地 `pnpm fixtures:seed` 的合成数据，保留“演示数据”标识，并在图注中说明“本地合成 fixtures”；不截生产页面，不加工或伪造生产数据。
- 生产部署前置从 README 移出，`docs/deployment.md` 是唯一 home；README 只链接架构、开发、部署、文档地图、开发流程与决策记录。
- `README.md` 词数预算从 400 调到 500，理由是首屏新增定位、能力与截图说明，同时移出重复的部署段；这是压缩与搬层之后仍需要的余量，不是无上限扩张。

## Alternatives considered

- **保留状态页，只在末尾追加截图。** 首屏仍然回答不了“是什么”，新读者要翻到快速开始之后才看到产品；否决。
- **直接截生产 Session 页面。** 最省事，也最能代表真实数据，但违反“生产 Session 内容、截图或凭据不入库”的边界，且截图会随生产数据变化；否决。
- **用 `plans/ui-prototype-v2` 原型截图。** 视觉更完整，但原型不是运行中的应用，会误导读者以为功能已按原型交付；否决。
- **放多张截图（总览、Session、错误详情、运行详情）。** 信息更全，但首屏变长、维护成本翻倍，且单张 Session 页已覆盖核心链路；否决。
- **维持 400 词预算并删掉结构或文档入口。** 能压到 400 附近，但 README 失去导航价值；搬层与压缩后选择提预算；否决硬压。

## Consequences

- README 与 `docs/architecture.md` 的现状描述重新对齐；部署、架构与开发细节不再在 README 复制。
- 截图是合成演示数据，不能当作生产能力或数据规模证明；UI 改版后需要重新截取并替换同一路径的图片。
- README 预算提高到 500；后续再加内容应优先搬到 `docs/`，而不是继续抬高上限。
- 中英两侧仍成对维护，截图路径在两份 README 中相同，图注按语言翻译。
