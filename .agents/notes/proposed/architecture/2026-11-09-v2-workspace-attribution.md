# Agent Note: V2 工作空间上下文与对象级归因

Status: proposed

[English](2026-11-09-v2-workspace-attribution.en.md) | 中文

## Problem

现有认证、Session 浏览、错误详情和自进化页面可以复用，但所有业务数据默认处于同一全局范围；单一归因视图也无法表达同一 bad case 与多个进化对象版本的关系。如果各页面自行增加空间筛选，或把不同对象的归因覆盖到同一记录，会造成跨空间缓存、权限判断和历史结论串用。

## Decision

- V2 在全局身份与业务页面之间引入当前工作空间上下文。生产路由以 `workspaceId` 为前缀，前端 query key、API 查询和 run 快照都包含该上下文；旧路由只在归属唯一时重定向。
- 保留登录、refresh Cookie、Bearer access token、Session 概览、执行流、问题描述和自进化对象/版本/时间窗选择。空间管理进入独立设置页，不增加核心工作流的导航负担。
- 空间角色分为空间管理员、成员和只读成员；唯一全局管理员负责创建空间，空间管理员只拥有本空间内的全部操作权限。公开注册保持关闭。
- 归因成为自进化运行的产物，以 bad case、对象身份、对象版本、策略版本和模型版本区分。非该对象问题是对象级结论，不修改 bad case 的共享事实。
- 启动预览先关联对象出现的 Session，再按默认或版本化自定义策略筛选潜在 bad case；缓存只复用相同键下最近一次成功归因。

## Alternatives considered

- 每个页面独立保存工作空间筛选：改动局部，但切换页面和深链容易丢失空间上下文；否决。
- 为每个进化对象复制 bad case：列表实现直接，却破坏问题事实唯一性并放大统计与权限同步；否决。
- 继续让归因先于自进化启动：与现有只读模型兼容，但无法表达对象关联、潜在策略与缓存命中；否决。
- 用另一套暗色或独立应用承载 V2：无法复用已验收的视觉、认证和错误详情；否决。

## Consequences

- 现有数据需要迁入明确的默认空间，所有跨域读取必须补空间约束与服务端 membership 校验。
- 错误详情需要把单条 analysis 查询升级为分页摘要与单条详情，但问题描述和执行流组件可继续使用。
- 自进化运行需要持久化潜在集、触发点证据、策略和缓存版本，历史运行才能解释与重放。
- 本决策目前只落实到 `plans/v2-ui-prototype/`；生产契约、数据库迁移和权限实现需要后续 issue。
