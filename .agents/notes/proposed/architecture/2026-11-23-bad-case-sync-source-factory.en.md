# Agent Note: Bad Case sync-source factory — base class, factory, and the ClaudeUpstream subclass

Status: proposed

English | [中文](2026-11-23-bad-case-sync-source-factory.md)

## Problem

In code, the global bad-case source line is not "one source" but the sum of two unrelated HTTP clients (`HttpBadCaseCatalogSource` for catalog paging, `HttpSessionQuerySource` for two-endpoint trace backfill), two nearly copied assembly if-blocks in `main.py`, and two almost isomorphic BFS loops inside `BadCaseRootSyncService`. This leaves three concrete gaps: `_sync_root` switches between the report/global fetch paths with an inline if/else, the global path bypasses the existing `SessionSourceFactory` / `BaseSessionSourceAdapter` projection chain entirely, and `runtime_key` falls back to the `LocalAgentPayload` default; enablement is implied by two sets of endpoint credentials, with no explicit "on when configured, off when unconfigured" switch; and the catalog sync unconditionally overwrites the 13 upstream columns of an already reported row with the same id via `ON DUPLICATE_KEY UPDATE` (including `created_at`, which the report-source selection sorts by) while counting all of them as `updated`—"an already reported case is not synced again" holds only in a half sense.

The request is a feature: turn the global line into factory + base class + subclass, route both bad-case fetching and session fetching through base-class trigger calls implemented by subclasses, enable it once `.env` is configured, encapsulate every upstream difference inside the subclass, and reuse the existing Session parsing base class/subclass for session handling while adding a new subclass implementation. The full design lives in [plans/fullstack-design/16 · bad case 同步源工厂化](../../../../plans/fullstack-design/16-bad-case-sync-source-factory.md); this Note records only the three trade-offs and the rejected alternatives.

## Decision

**Naming: code identifiers use the `BadCaseSync*` family, not `Global*`.** The new module `third_party_api/bad_case_sync_source/` has three pieces: `BaseBadCaseSyncSource` (base class with the template methods `fetch_bad_case_page` / `fetch_session`), `ClaudeUpstreamBadCaseSyncSource` (subclass), and `BadCaseSyncSourceFactory` (factory, instantiated once at assembly time from `HE_BAD_CASE_SYNC_PROVIDER`, returning `None` when unconfigured and failing at startup on unknown values). "Global" already names the DB snapshot label (`bad_case_root_sync.source_kind = "global"`) and the per-root routing state; naming the replaceable implementation after it would weld "where a root routes" to "who fetches" into one thing.

**The if/else in `_sync_root` collapses into a "frozen snapshot → unified fetcher" data mapping; the two branch skeletons are not kept.** `fetch_session(*, session_id, expected_parent_id, snapshot)` is isomorphic to the existing `SessionSourceFetcher.fetch`, and both return `SessionInfo`; the mapping has only the `"report"` / `"global"` entries, and there is a single loop body. The global subclass synthesizes a `SessionSourceEnvelope` from the two endpoints and projects it through the existing `SessionSourceFactory.create(runtime).project`—the same chain the report path uses; `_payload()` is deleted, and `runtime_key` is declared explicitly by the subclass.

**An already reported bad case is never overwritten by the catalog sync: writer ownership plus a skipped counter, over unconditional overwrite.** `bad_cases` gains `origin ∈ {report, catalog}`, fixed by the first writer; the catalog sync updates only rows with `origin = "catalog"` and skips rows with `origin = "report"` while counting them as `skipped`. The report line writes `report` on insert, and re-reporting never changes ownership.

## Alternatives considered

- **Names like `GlobalBadCaseSource` / `GlobalSourceFactory`**: matches the user's spoken wording, but "global" is already the routing-state word; once a second upstream exists, `Global` neither says "which one" nor avoids confusion with the `kind="global"` snapshot label. Rejected.
- **Keep the `_sync_report_root` / `_sync_global_root` skeletons and only move the HTTP calls into a subclass**: the smallest change, but the two BFS loops (deadline, limits, lease renewal, enqueueing) stay duplicated and a new upstream still needs a third loop; the whole value of the base-class template methods is that the service layer sees one kind of fetcher. Rejected.
- **`fetch_session` returns a `SessionTrajectory` plus a children tuple and the service layer assembles the payload**: a thinner subclass, but the service layer would then accept both `SessionInfo` (report path) and a tuple (global path), the isomorphism disappears, and the if/else merely moves. Rejected.
- **Pure insert-if-absent for the catalog sync (never update an existing row)**: protects reported rows with zero migration, but it also freezes catalog-owned rows, so upstream revisions of titles/descriptions never propagate; writer ownership costs one column and gives both writers correct update semantics. Rejected.
- **Infer the writer from `workspace_id ≠ DEFAULT_WORKSPACE_ID` or `session_source IS NOT NULL` instead of adding a column**: no migration, but a report into the default workspace without `sessionSource` is misjudged as catalog-owned, so the gap narrows without closing; cursor-based sync keeps the practical exposure of a backfill error near zero, so the explicit column is cheap. Rejected.
- **Implicitly enable the line from legacy endpoint credentials when `HE_BAD_CASE_SYNC_PROVIDER` is unset**: zero change for existing deployments, but "off when unconfigured" stops holding and the switch matrix degenerates from two states into three; instead, assembly logs a warning telling the deployment to add one line. Rejected.
- **Register a second `BaseSessionSourceAdapter` subclass with `runtime_key = "claude-code"` for the global path**: formally satisfies "add a subclass implementation", but `SessionSourceFactory.register` rejects duplicates by runtime key and one runtime should not carry two metadata schemas; the hook for a new subclass is "new runtime → new adapter", while the sync-source subclass owns envelope synthesis. Rejected.

## Consequences

- A new upstream equals one `BaseBadCaseSyncSource` subclass plus `@BadCaseSyncSourceFactory.register`; the service layer, `main.py`, and the DB are untouched. Traversal/lease/retry policy stays in `BadCaseRootSyncService`, and subclasses never see traversal.
- `SessionSourceSnapshot` needs an optional `provider` (global only): old snapshots `{"kind":"global"}` stay valid; a new snapshot carrying `provider` is rejected by `extra="forbid"` after a rollback to old code and parks with `SESSION_SOURCE_INVALID_RESPONSE`, and the startup hook `reset_deterministic_failures` clears the snapshot and re-arms.
- The global-line switch becomes explicit: a deployment that already has endpoint credentials but no `HE_BAD_CASE_SYNC_PROVIDER` has the global line off after upgrade and must add one line; assembly logs a warning for "credentials present, provider missing".
- Payload output is field-for-field identical to today's `_payload()` (main → `agent_meta=None`; subagent → `{"parentAgentId": …}`; `runtime_key="claude-code"`), and the implementation must pin this with a parity test; the error codes `SESSION_QUERY_UNAVAILABLE` / `BAD_CASE_QUERY_UNAVAILABLE` and `_NON_RETRYABLE_ERRORS` stay unchanged.
- The dialect-specific `_upsert_statement` in the catalog sync is replaced by an explicit `INSERT` plus a conditional `UPDATE … WHERE origin = "catalog"`; `PageCounts` gains `skipped`, the job result gains one field, and whether the status API exposes `skippedBadCases` is left to the implementation issue.
- The `session_query_source=` / `bad_case_catalog_source=` injection seams of `create_app` collapse into `bad_case_sync_source=`, so the related test fixtures need renaming; the `bad_cases.origin` migration and its backfill rule are in §7.4 of the design document.
- The factory layer supports one provider per deployment only (consistent with the [Git push providers](../../implemented/architecture/2026-11-21-git-push-provider.en.md) note); multiple coexisting providers and renaming the `kind="global"` label are outside this decision.
