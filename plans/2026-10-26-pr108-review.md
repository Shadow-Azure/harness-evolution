## §1 一页速览

一句话：这个 PR 把“我正在看哪个 Agent、它的哪个触发点”从易失内存搬到 URL，使刷新、分享和浏览器前后退能重建同一个执行流视图。

生活化比喻：URL 像病历上的页码和行号。用户把书签发给同事时，接收方应直接翻到同一个 Agent、同一段证据；如果那一页被折叠、编号被二次解码，或书签找不到时悄悄跳到另一本病例，都会失去深链的意义。

| 交付块 | 结论 |
|---|---|
| URL parser 与非法输入 | 基本完整；存在 path 参数二次解码 |
| Agent/evidence 树校验 | happy path 正确；折叠分支中的目标不可恢复 |
| History/刷新/新窗口 | 真实 Chrome 通过现有用例 |
| Session 回退边界 | 显式未知 Session 会被首项替换并可能携带旧 Agent |
| case/tab seam | parser 可复用，但错误地进入普通 Session 路由 |
| UI 原型 | 亮色两栏、树、选中蓝线和 evidence 高亮均无整体回退 |
| 测试 | 覆盖主路径，但未覆盖上述 4 个关键边界 |

## §2 架构导览

### 2.1 URL 是页面状态的根

`deepLink.ts:116-188` 一次解析 Session ID、Agent、evidence、case 和 tab，并输出 canonical query。`Index.vue:59-78` 只从 parser 结果派生 `selectedId`，不再保留 `activeAgentBySession` 形式的组件内存状态。

这套结构的优点是刷新、复制链接和 History 导航天然走同一条恢复路径。页面判断选中 Agent 时也只看 URL：`Index.vue:118-137` 从 query 取 `agent`，再拿 tree 响应决定它是否仍存在。

### 2.2 树响应是 Agent/evidence 的资源真相

`Index.vue:141-153` 只接受存在于当前 Session tree、且仍落在该 Agent `events[]` 范围内的 evidence。`Index.vue:327-385` 在 tree 到达后再次校验：Agent 不存在时移除 `agent/evidence`，evidence 越界时只移除 evidence。

这个分层使 parser 只负责“形状合法”，后端 tree 负责“资源存在”。它也能避免在 tree 加载前凭 URL 伪造高亮。

### 2.3 AgentTree 只渲染和定位

`AgentTree.vue:94-105` 把 `activeAgentId/activeEventIndex` 注入当前选中节点；`AgentTree.vue:164-172` 在 URL 状态变化后调用 `locateAgent()`。`locateAgent()` 只在 `graph.value.nodes` 中查找目标，见 `AgentTree.vue:215-225`。

这里隐含了一个重要前提：目标必须已经出现在当前渲染节点集合中。若它被 collapse 节点隐藏，URL 即使合法也无法定位。

### 2.4 正式错误页状态只应作为 seam

`deepLink.ts:191-214` 提供 bad-case 响应与 path session 的归属判断。m3-04 没有注册 `/sessions/:sid/errors`，真实 409 留给 m4-02，这是正确的阶段边界。

但 Session/error 两类 query 目前由一个 parser 不分路由地解析，普通 Session 页面会消费 `case/tab` 结果，见 `Index.vue:289-299`。seam 的“可复用”因此变成了“跨路由泄漏”。

## §3 数据流走查

### 场景 A：从 Session 卡进入某个折叠子 Agent

1. 用户复制 `/sessions/{sid}?agent={hidden-child}&evidence=0`。
2. `Index.vue:118-137` 从 tree 全量 Agent 里确认 child 合法，激活它。
3. 页面把 `expandedBySession[sid] ?? []` 传给 AgentTree，见 `Index.vue:115-117`。
4. `layout.ts:555-599` 在父 Agent 超过 8 个子节点且未展开时只返回一个 collapse 节点；现有布局测试明确断言此刻 child 不存在，见 `layout.test.ts:115-124`。
5. `AgentTree.vue:215-225` 在渲染节点里找不到 child，直接返回。

最终 URL 仍声称选中了 child，但画布只显示折叠入口，没有高亮或定位。这是当前深链主验收中的直接缺口。

### 场景 B：显式 Session 不存在

1. 用户打开 `/sessions/missing?agent=main`，其中 `missing` 形状合法。
2. list 请求返回真实四 Session；它们都不等于 `missing`。
3. `Index.vue:315-321` 把路由替换为列表第一项。
4. 用于替换的 query 来自 `routeWithFilters({})`，它默认保留 URL 中的 Agent/evidence，见 `Index.vue:155-175`。

最终用户没有看到 `SESSION_NOT_FOUND`，而是进入了另一个 Session；若两个 root 含有同名字符串 Agent ID，旧 Agent 甚至可能在新树中继续显示为选中。数据库身份是 `(root_session_id, agent_id)`，不能假设 agent id 全局唯一。

### 场景 C：History 恢复合法深链

1. 用户从合法 Agent/evidence 点击另一个 Agent，路由 query 清除 evidence。
2. 浏览器后退回到旧 URL。
3. parser 恢复同一 Agent/evidence；`AgentTree.vue` 重新定位选中节点。
4. E2E 在 390px 下验证 selected Agent 可见、evidence 高亮只有一处、页面不横向溢出。

该主路径通过，且亮色原型壳没有视觉回退。

## §6 讨论点

### D1 深链无法恢复被折叠的子 Agent

**位置**：`apps/web/src/pages/sessions/Index.vue:94-117,327-385`、`apps/web/src/components/agent-tree/AgentTree.vue:88-92,215-225`、`apps/web/src/components/agent-tree/layout.ts:555-599`

**现象**：父 Agent 超过 8 个子节点时，`buildGraph()` 默认只生成 collapse 节点。现有布局回归明确断言 `main-group` 存在而 `agent-a` 不存在。深链只校验 Agent 在完整 tree 中存在，没有展开目标祖先，因此 `locateAgent()` 找不到节点并静默返回。

**问题**：用户分享任意子 Agent 的深链后，在父分支默认折叠的 Session 中看不到目标；这违反“刷新/新窗口恢复同一 Agent 与证据”的核心验收。真实数据中已有一个 root 含 61 个直接或间接后代，不是只在合成大图中才会发生。

**预判**：应由页面根据 active Agent 的父链自动展开包含目标的 collapse 分支，或由 AgentTree 在渲染时强制包含 active 节点；展开状态可只保存在当前视图，不必写 URL。补一条真实 390px 折叠子 Agent 深链回归。

**结论**：已修复（2026-10-26）。Session 页面根据 active Agent 的父链展开折叠祖先；`AgentTree` 在目标节点渲染后重新定位。页面单测和真实 Chrome 折叠树 fixture 覆盖 390px 恢复。

### D2 显式 Session 丢失时会静默串到另一 Session

**位置**：`apps/web/src/pages/sessions/Index.vue:155-175,304-322`

**现象**：当 URL 的 Session ID 不在当前 list 结果中时，页面直接 `replace` 到列表第一项。替换调用使用 `routeWithFilters({})`，而该函数默认把原 URL 的 `agent/evidence` 继续带过去。

**问题**：未知 Session、过期 Session 或筛选后不在列表中的 Session 都不会显示对应错误，而会悄悄打开另一棵树；旧 Agent ID 还可能在新树中存在，形成跨 Session 的状态串用。数据库身份是 `(root_session_id, agent_id)`，不能把 agent id 当全局唯一。

**预判**：只有 `/sessions` 无选中项时自动选第一项是合理的；显式 `/sessions/:sid` 不存在时应保留 URL 并显示 detail 的 `SESSION_NOT_FOUND`，至少必须用 `preserveDeepLink=false` 清除 Agent/evidence。补“未知 sid + agent”与“筛选排除当前 sid”的页面测试。

**结论**：已修复（2026-10-26）。自动选中只发生在无 Session 的 `/sessions`；显式 Session 即使被当前筛选排除也保留 URL、overview 请求与自身 Agent 状态，不会串到列表首项。

### D3 正式 error 路由的 `case/tab` 被普通 Session 页面消费

**位置**：`apps/web/src/router/deepLink.ts:148-175`、`apps/web/src/pages/sessions/Index.vue:289-299`

**现象**：`parseSessionDeepLink()` 同时接受 `case/tab`，普通 `/sessions/:sid` 页面又把 parser 的 `canonicalQuery` 回写 URL。真实探针输入 `{ case: "case-1", tab: "attr" }` 得到 `canonicalQuery: { case: "case-1", tab: "attr" }`。

**问题**：fullstack 契约只为 `/sessions/:sid/errors?case=&tab=` 定义这组状态，普通 Session 页没有 ErrorPage 语义。现在具有正式外观的错误深链会被当成普通 Session 的合法 query 保留，既不进入错误页，也不提示路径不属于当前页面。

**预判**：把 parser 按路由上下文拆成 Session 与 Error 两个入口，或让 Session 路由明确忽略/拒绝 `case/tab`；m4 ErrorPage 才能消费错误 parser。补页面级测试，不能只测 pure parser。

**结论**：已修复（2026-10-26）。Session surface 忽略并移除 `case/tab`；仅 error surface 解析并规范化这些值，正式跨 Session 归属仍由 m4 resolver 处理。

### D4 path 参数在 Vue Router 解码后再次 URL 解码

**位置**：`apps/web/src/router/deepLink.ts:80-95`

**现象**：`route.params.sessionId` 已由 Vue Router 解码一次，但 parser 又执行 `decodeURIComponent()`。实测 `router.push("/sessions/a%2541b")` 的 param 是 `a%41b`，随后 parser 把它规范成 Session ID `aAb` 并返回合法状态。

**问题**：严格深链校验会悄悄把一种无效/双重编码的资源地址重写为另一种 ID，可能命中不同 Session；这与“非法参数不能掩盖错误”冲突。

**预判**：parser 接收的 path param 应视为已解码，只做长度、控制字符和字符集校验；若需要原始 path，应显式传入独立字段。补 `%2541` 与 `%00` 的路由级回归。

**结论**：已修复（2026-10-26）。parser 将 Vue Router path 参数视为已解码，只做长度、控制字符和字符集校验；`a%41b` 不再被二次解码。

### D5 测试只覆盖可见 Agent 和默认 Session，未覆盖关键失败路径

**位置**：`tests/e2e/m3-session-browser.test.mjs:442-651`、`apps/web/src/pages/sessions/Index.test.ts:363-489`

**现象**：E2E 会遍历四个 Session，但只选择当前已渲染且带 trigger 的 Agent；页面单测没有未知 Session、筛选排除当前 Session、或折叠子 Agent 的深链案例。布局测试虽证明 collapse 会隐藏 `agent-a`，但没有把该事实与深链连接起来。

**问题**：现有 CI 可以在上述 3 个错误路径存在时保持全绿，真实用户却复制不到同一视图或会被带到错误 Session。

**预判**：至少新增三类回归：大于 8 子 Agent 的深链自动展开并定位；显式未知 Session 保持 404 且不携带 agent/evidence；`%2541` 双重编码 path 被拒绝。测试应走真实页面/真实 Chrome，而不是只调用 parser。

**结论**：已修复（2026-10-26）。新增折叠 Agent 自动展开组件回归、真实 Chrome 折叠深链 E2E、筛选排除显式 Session、`%2541` 非法路径和 Session/error query 隔离测试。

## §9 文件级代码分析

### `apps/web/src/router/deepLink.ts`（A）

职责是把 URL 的 Session/Agent/evidence 与未来错误页 case/tab 收敛成一个稳定状态对象；它像 airport check-in 的第一道证件检查，只负责形状和明显非法值。

parser 对字符串、数组、控制字符、长度、evidence 数字边界有明确处理；`resolveBadCaseSession()` 把跨 Session 归属封装成稳定的 409 seam，避免 m3 猜测后端资源。

检视发现 D3、D4。前者来自没有路由上下文的统一 parser，后者来自对 Vue Router 已解码 param 的二次解码。未发现 secret、HTML 注入或未经校验直接请求路径的问题。

### `apps/web/src/pages/sessions/Index.vue`（M）

职责是把 route、list、detail、tree 和 Agent 交互串起来。它不再维护内存 activeAgent，而是从 URL 派生状态；节点点击写 URL，tree 到达后清理不存在的 Agent/evidence。

主路径的设计是合理的：parser 管格式，tree 管资源，AgentTree 管渲染定位。canonical query 使用 `router.replace`，不会给 History 增加无意义条目。

检视发现 D1、D2、D3。页面默认展开集合为空，无法保证 active Agent 落在渲染图中；列表回退没有区分“无选择”和“显式但缺失的 Session”；普通 Session 页把 case/tab 一并规范化。

### `apps/web/src/components/agent-tree/AgentTree.vue`（M）

职责是消费完整 tree 与 URL 选中状态，生成布局并在节点存在时居中。`activeEvidence` 仅注入当前 Agent，修复了此前多个 Agent 同下标同时高亮的问题。

`locateAgent()` 不在 render list 中时静默返回，当前组件没有“目标被 collapse 隐藏”的恢复策略，检视发现 D1。

### `apps/web/src/components/agent-tree/nodes/AgentNode.vue`（M）

职责是渲染一个 Agent 条、触发点链与 evidence 高亮。高亮同时要求 `data.active` 和 `data.activeEvidence === item.evIdx`，状态隔离正确。

未发现新的视觉或 token 问题；按钮保留唯一 Tab 停点与 `aria-pressed`。

### `apps/web/src/pages/sessions/components/SessionOverview.vue`（M）

职责是把 active Agent/evidence 从页面传给 AgentTree，不引入新请求。改动很小，保持 overview 的独立三态。

未发现单独缺陷；D1 的展开职责更适合在页面或 AgentTree 协调层解决。

### `apps/web/src/components/agent-tree/types.ts`（M）

职责仅为布局节点补 `activeEvidence` 可选字段。类型没有泄漏到 API 契约，范围正确。
