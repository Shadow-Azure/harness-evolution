## §1 一页速览

一句话：这个 PR 把外部问题数据同时挂到 Session 执行流图和问题列表上，并用真实 `badCaseId` 做了双向定位。

生活化比喻：问题卡像贴在地铁路线图上的便签。后端 `anchor` 决定便签该贴在哪条线路、哪个触发站；左栏列表是同一组便签的目录。用户点目录，地图应移到便签；点地图便签，目录应滚到对应条目。这个 PR 把“便签身份”和“贴在哪里”分开，避免用显示序号或“最后一个 Agent”猜位置。

| 交付块 | 结论 |
|---|---|
| 独立读取 summary/tree/problems | 符合设计 |
| 五态标签、摘要、metadata、降级提示 | 符合设计 |
| 真实 `badCaseId` 双向选择 | 主路径通过 |
| self-agent / self-skill / discovery / fallback 连线 | 通过，路径已按原型恢复 |
| 同锚点稳定叠卡 | 通过 |
| 不同锚点但视觉落点相同的叠卡 | **失败**，会重叠 |
| 折叠分支内问题卡的定位 | **失败**，会生成左上角无连线浮卡 |

## §2 架构导览

### 2.1 三条查询互相独立

`Index.vue:104-113` 并行创建 Session summary、tree、bad-cases 三条 query。问题请求使用 `['sessions','bad-cases',sid]`，因此既可单独重试，也能被现有 `sessions` 前缀失效一起刷新。`SessionOverview.vue:228-279` 分别渲染 tree loading/error 和 problem loading/error，任一请求失败都不会抹掉另一块。

这个拆分是必要的：问题详情来自外部只读表，可能和轨迹树有不同延迟。页面先画真实树，再补充五态与摘要，比等待所有请求一起返回更能保持原型结构。

### 2.2 树记录决定“贴在哪”，详情记录决定“写什么”

`layout.ts:285-381` 只使用 `tree.badCases` 的后端 `anchor` 计算宿主、事件下标、方向和坐标。`layout.ts:424-509` 再用完整 `BadCase[]` 覆盖 reason、五态与 degraded 文案。卡片身份始终是 `badCaseId`，没有用 `badCaseAgent` 反推位置。

这像“信封上的地址”和“信封里的正文”分开：tree 提供稳定地址，bad-cases 提供最终内容。某一侧内容晚到时，卡片仍能先保持可识别的最小形态。

### 2.3 语义边与顶部 discovery 引线

`AgentNode.vue:12-30` 为每个触发事件生成底部 `h{i}` 和顶部 `rep{i}` source handle；`AgentNode.vue:110-139` 同时渲染两类 handle 与可见引线。`layout.ts:383-415` 按锚点选择：

- self-agent / fallback：Agent 左右侧 `finding-*` handle。
- self-skill：底部 `h{i}` 到卡片顶部。
- discovery：顶部 `rep{i}` 到卡片底部。

三条边组件把统一坐标交给纯路径函数，`layout.ts:948-1023` 保留原型不同的首轴和圆角行为。Vue Flow 只负责渲染和测量，不在组件内猜布局。

### 2.4 选择通过显式回调传递

`AgentTree.vue:64-66` 通过 provide 把 `BAD_CASE_SELECT_KEY` 注入 `BadCaseNode`。`BadCaseNode.vue:12-29` 点击后停止 Vue Flow 外层冒泡，直接调用这个回调；`AgentTree.vue:58-66` 再 emit 给页面。原因是真实浏览器中自定义节点点击不能稳定依赖 DOM 冒泡，同时必须保证问题选择不会误触 Agent 选择。

`SessionOverview.vue:115-121` 收口列表与画布的同一活动 ID：先等待 `setCenter`，再滚动列表对应行。`Index.vue:368-374` 取消迟到的 Session 初始滚动恢复，防止刚定位到问题又被重置。

### 2.5 视觉与无障碍

问题列表保持原生 `<button>`，外层是 `role=list/listitem`（`BadCaseList.vue:80-134`），因此 `aria-pressed` 仍表达选中态。卡片同样使用原生按钮、完整 `title` 和前 8 位 ID（`BadCaseNode.vue:20-31`）。颜色全部来自 token，`verify:web-style` 通过。

## §3 数据流走查

### 场景 A：打开一个包含问题的 Session

1. 路由确认 `sid`，三条 query 并行发起，`Index.vue:104-137`。
2. `/tree` 返回 Agent、事件和最小 bad-case 记录；`layout.ts:519-885` 组装节点、父边、折叠节点与 anchor。
3. `/bad-cases` 返回五态与 metadata；`layout.ts:424-509` 生成问题节点。
4. Agent 与问题节点一起交给 Vue Flow；`AgentTree.vue:114-137` 只把当前 ID 标成 active。
5. `BadCaseList.vue:97-135` 按 API 顺序显示同一批问题。

### 场景 B：列表点问题，画布定位

1. 列表按钮 emit 真实 `badCaseId`。
2. `SessionOverview.vue:115-120` 设置唯一活动 ID，并调用 `AgentTree.locateBadCase()`。
3. `AgentTree.vue:265-276` 找到对应节点，用当前 zoom 与 0.85 的较大值 `setCenter`。
4. 居中完成后滚动列表行；画布卡和列表行同时显示 active。

### 场景 C：点画布问题卡，列表定位

1. `BadCaseNode` 通过注入回调发出 ID。
2. `AgentTree` emit `badcase-select`，但不 emit `node-select`。
3. 页面复用同一个 `selectBadCase()`，因此两种入口共享同一活动状态。
4. 列表行滚动到视口并显示 `aria-pressed=true`。

### 场景 D：问题位于折叠分支

1. 父 Agent 有超过 8 个子节点且未展开，`layout.ts:729-772` 只渲染一个 collapse 节点。
2. 子 Agent 的完整记录仍在 `tree.agents`，但不在本次 `nodes` 中。
3. `badCaseAnchors()` 把“宿主不在渲染节点”误判成 malformed fallback，返回 `ROOT_X/ROOT_Y`（`layout.ts:316-331`）。
4. `buildBadCaseOverlay()` 仍创建卡片，`buildGraph()` 只过滤其孤儿边（`layout.ts:895-907`）。
5. 结果：卡片出现在画布左上角，没有连线；点列表只能对这张错误位置的卡执行 `setCenter`，不会展开祖先。

本地探针结果：

```text
agents: ["main", "main-group"]
anchor: { hostAgentId: "agent-extra-1", eventIndex: -1, kind: "fallback" }
card:   { id: "case-collapsed", x: 106, y: 25 }
edge:   []
diag:   MISSING_ANCHOR_AGENT
```

### 场景 E：同一 Agent 上有多个不同锚点问题

`layout.ts:438-443` 用 `hostAgentId + eventIndex + kind + side` 分组。不同 eventIndex 的 self-skill 或 discovery 各成一组，组内 index 都从 0 开始；但它们的画布落点可能相同，或横向距离不足一张卡宽。当前后端对 self-agent 固定返回 `eventIndex=-1`（`apps/api/app/service/problems/anchor.py:53-54`），所以 self-agent 的完全重叠探针更偏契约级预防；同一 Agent 上两个相邻 skill/discovery 触发点则是实际可产生的数据。

本地探针：

```text
self-agent, same host, eventIndex 0 / 1（契约级探针）
  -> case-a { x: 363, y: 53 }
  -> case-b { x: 363, y: 53 }      完全重叠

self-skill, same host, adjacent triggers
  -> case-a { x: 101, y: 138, w: 230 }
  -> case-b { x: 216, y: 138, w: 230 }   横向重叠 115px
```

这说明“同锚点稳定叠卡”成立，但原型要求的“同宿主问题卡不互相遮挡”尚未成立。

## §6 讨论点

### D1 折叠分支中的问题卡被当成无效宿主，定位无法展开祖先

**位置**

- `apps/web/src/components/agent-tree/layout.ts:316-331`
- `apps/web/src/components/agent-tree/layout.ts:895-907`
- `apps/web/src/pages/sessions/components/SessionOverview.vue:115-121`
- `apps/web/src/pages/sessions/Index.vue:283-297,368-374`

**现象**

父 Agent 有 9 个以上子节点且未展开时，tree 只渲染 collapse 节点。锚定在隐藏子 Agent 的问题仍被创建为 fallback 卡，定位到画布左上角 `x=106,y=25`，且没有边。

**问题**

“Agent 在完整树中存在但因折叠未渲染”与“API 给出不存在的坏宿主”被当成同一种状态。前者是正常交互，应该先展开祖先再定位；当前表现会让用户把浮卡误认成真实拓扑，并让列表点击无法到达目标。

**预判**

不能只修视觉位置。选择问题时需要从 `BadCase.anchor.agentId` 找到完整 tree 中的 Agent，展开全部折叠祖先，等卡片节点出现后再 `setCenter`。布局层同时应区分“真实缺失”与“当前折叠未渲染”：后者不生成左上角 fallback，前者才保留降级卡。建议补折叠树列表定位的组件测试和真实 Chrome 回归，优先级 P1。

**结论**

待维护者拍板。

### D2 不同事件锚点落在同一视觉区域时，问题卡会重叠

**位置**

- `apps/web/src/components/agent-tree/layout.ts:359-378`
- `apps/web/src/components/agent-tree/layout.ts:424-476`

**现象**

同宿主的 self-agent 卡即使 eventIndex 不同，也会使用相同中心点；相邻 skill 触发点的卡则可能横向相交。当前分组键包含 eventIndex，因此两张卡各自被视为“组内第一张”。本地探针分别得到完全重叠和 115px 横向重叠。

**问题**

同锚点堆叠测试通过，但用户看到的是画布上的最终矩形，不会理解“锚点不同所以允许遮挡”。原型 `addSkillFindingsLeft()` 会按卡片实际右边界更新下一行的 Y；这里缺少跨锚点的位置级碰撞处理。

**预判**

分组应按最终可见落点/宿主方向聚合，而不是只按键值完全相等聚合；或先创建候选矩形，再对相交矩形做稳定下移。self-agent 可统一按宿主侧向栈处理，skill/discovery 需按 X 区间与宽度检测横向重叠。补同宿主不同 eventIndex 的纯布局测试。优先级 P1/P2，视真实外部问题密度而定。

**结论**

待维护者拍板。

### D3 画布问题卡的 state class 当前没有对应样式

**位置**

- `apps/web/src/components/agent-tree/nodes/BadCaseNode.vue:20-29`
- `apps/web/src/components/agent-tree/nodes/BadCaseNode.vue:65-125`

**现象**

节点挂着 `state-analyzed_issue_model` 等五个 class，但 scoped CSS 没有任何 `.state-*` 规则。画布上模型、prompt、错误问题都保持同一红色卡面，只有下方列表 chip 显示五态颜色。

**问题**

Issue 写有“渲染问题卡、状态色”；设计 §9 也定义了五态色。当前可能是有意让画布卡保持原型红色、由列表 chip 承担状态色，但代码保留了无效 class，验收文案没有说明这一分工。

**预判**

若产品意图是“画布结构红、列表 chip 五态”，应删除死 class，并在 Agent Note 写清分工；若要求画布也能辨认五态，应增加小状态点/边框或 chip，并补真实浏览器 computed color 断言。当前无数据错误，属于设计取舍待定。

**结论**

待维护者拍板。

### D4 固定 230px 卡宽与原型按文本动态宽度不同

**位置**

- `apps/web/src/components/agent-tree/layout.ts:50-55`
- `apps/web/src/components/agent-tree/nodes/BadCaseNode.vue:66-69`
- 原型 `plans/14-15-ui-prototype/harness-evolution.html:1422,1450,1694`

**现象**

原型 finding 卡宽度按文本计算，范围约 150–400px；当前统一 230px，超出部分只靠省略号和 tooltip。

**问题**

短卡会留白，长 reason 会截断。固定宽度让碰撞计算更简单，但视觉不再逐卡贴合内容，密集问题图上仍可能因为文本压缩而难以快速分诊。

**预判**

如果 m4-03 选择固定宽度作为可预测布局的取舍，应在 Note 记录；否则可把原型的 `textW` 与上下界移植为纯布局宽度，并让节点与碰撞检测共用同一 `w`。优先级 P2，当前有 tooltip 兜底。

**结论**

待维护者拍板。

### D5 问题 ID 深链与错误详情 CTA 仍不可用

**位置**

- `apps/web/src/components/bad-cases/BadCaseList.vue:100-134`
- `apps/web/src/pages/sessions/components/SessionOverview.vue:195-205`
- `plans/fullstack-design/02-features.md:59,123`

**现象**

问题 ID 只是文本，点击整行只做定位；顶部“打开错误详情”仍是 disabled 按钮。

**问题**

完整 F6 要求 ID 点击打开问题详情，但错误页路由和归因内容属于 F8/m4-04。若 m4-03 声称 F6 已全部完成，会产生范围误差。

**预判**

本 PR 应明确交付为“列表与画布联动 + 真实 ID 可追溯”，ID 深链和 CTA 在 m4-04 落地。下一 issue 必须保留同一 ID，不可重新引入展示序号身份。

**结论**

待维护者确认阶段边界。

## §9 文件级代码分析

### `apps/web/src/api/sessions.ts`（M）

职责：新增 `listSessionBadCases()`，复用统一 request、Bearer 与错误模型，并对路径参数编码。

实现思路：只增加一个 GET，不把问题详情塞回 tree 响应。`sessions.test.ts` 用带 `/` 和空格的 Session ID 验证编码。

检视发现：无。

### `apps/web/src/api/queryKeys.ts`（M）

职责：集中注册 Session 问题 query key。

实现思路：保留 `sessions` 前缀，使同步后的现有失效逻辑能覆盖问题列表。

检视发现：无。

### `apps/web/src/composables/useSessions.ts`（M）

职责：在无选中 Session 时禁用问题 query，并返回完整 vue-query 状态。

实现思路：与 summary/tree hook 同构，查询函数只接收非空 ID。

检视发现：无。

### `apps/web/src/pages/sessions/Index.vue`（M）

职责：并行接线三条查询，把 problem state 传给 overview，并在问题选择时取消迟到的滚动恢复。

实现思路：问题请求独立重试；`focusBadCase()` 以 sequence 失效旧 timer。列表与画布共用一个后端数据源。

检视发现：D1 的展开祖先信息在页面层已经可得，但当前回调没有接收 `badCaseId` 并驱动展开。

### `apps/web/src/pages/sessions/components/SessionOverview.vue`（M）

职责：组合 Session 概要与执行流、问题列表，维护同一个 `activeBadCaseId`。

实现思路：列表和画布都 emit 同一个选择函数；定位先等待画布，再滚动列表。

检视发现：D1；`agentTreeRef.locateBadCase()` 对折叠分支找不到节点时静默返回，页面仍显示 active 列表项，形成“看似选中、实际未定位”。

### `apps/web/src/components/bad-cases/BadCaseList.vue`（A）

职责：渲染五态问题行、独立加载/空/错误态，并提供 `scrollToProblem()`。

实现思路：原生按钮负责选择，真实 ID 放在 `data-bad-case-id` 和 full tooltip；外层真实 listitem 保留 ARIA 结构。metadata 只显示前三项。

检视发现：D5；列表定位依赖全局 `document.getElementById()`，当前单实例页面可用，但若未来同时出现多个列表应考虑根节点 scope。

### `apps/web/src/components/bad-cases/badCaseDisplay.ts`（A）

职责：集中五态 label/tone、摘要选择和 metadata facts 格式化。

实现思路：静态 UI 词典只保留一份；issue/non-issue 按判别联合取不同字段；facts 最多三条。

检视发现：无功能错误；超长字符串按 code unit 截断，极小概率拆开代理对，属于可接受的小风险。

### `apps/web/src/components/agent-tree/layout.ts`（M）

职责：把 tree 的 anchor 与完整 problem details 合成纯布局节点、边和诊断，同时保留原型路径函数。

实现思路：agent identity fail-closed；anchor 只消费后端字段；同锚点按 ID 排序；三类语义边各用纯路径生成器。

检视发现：D1、D2、D4。布局仍无 DOM 依赖，输入乱序可复现，同锚点和安全坏宿主测试有效。

### `apps/web/src/components/agent-tree/AgentTree.vue`（M）

职责：注册问题节点/边、提供选择注入、执行 viewport 定位，并把 topology fit 与 active 更新分开。

实现思路：active 状态只重算 node data，不触发 fitView；节点初始化与容器 resize 才适配画布。问题选择不污染 Agent 选择。

检视发现：D1；`locateBadCase()` 找不到折叠内节点时没有反馈或展开请求。

### `apps/web/src/components/agent-tree/interactions.ts`（A）

职责：声明 problem-card 选择的 injection key。

实现思路：用一个 Symbol 隔离注入协议，避免依赖 Vue Flow 事件冒泡。

检视发现：无。

### `apps/web/src/components/agent-tree/types.ts`（M）

职责：扩展 pure layout 输出类型，加入 bad-case node/edge、五态、degraded 与 problem details 输入。

实现思路：视图模型仍独立于 Vue Flow 实际类；边类型保持语义闭集。

检视发现：无。

### `apps/web/src/components/agent-tree/nodes/AgentNode.vue`（M）

职责：增加左右 finding source handle、每事件顶部 `rep{i}` discovery handle 和红色向上引线；底部 `h{i}` 继续服务子 Agent 与 skill 问题。

实现思路：顶部和底部 handle 共用 chain offset，视觉桩与命中点不会分成两套坐标。

检视发现：无。

### `apps/web/src/components/agent-tree/nodes/BadCaseNode.vue`（A）

职责：渲染真实 ID 短形式、reason、degraded、active 和四个方向的 target handle。

实现思路：原生按钮 + 完整 title + `aria-pressed`；点击停止冒泡，改走显式注入回调。

检视发现：D3；另外节点宽高与布局常量重复写为 230/30，修改时存在漂移风险。

### `apps/web/src/components/agent-tree/edges/BadCaseEdge.vue`（A）

职责：把 Agent 侧向到问题卡的圆角正交路径渲染为 Vue Flow edge。

检视发现：无；坐标和样式均由布局/edge props 提供。

### `apps/web/src/components/agent-tree/edges/TriggerEdge.vue`（A）

职责：渲染底部触发点到下方 skill 问题卡的横后竖圆角路径。

检视发现：无。

### `apps/web/src/components/agent-tree/edges/DiscoveryEdge.vue`（A）

职责：渲染顶部 discovery handle 到上方卡片的竖后横路径。

检视发现：无。

### `apps/web/src/test/badCases.ts`（A）

职责：构造完整 API-shaped BadCase。

实现思路：默认 skill/self/unanalyzed，overrides 可形成五态；避免每个测试重复完整字段。

检视发现：末尾使用类型断言包容 overrides，若未来 discriminated analysis 发生变化，夹具可能掩盖组合错误；当前由 typecheck 与专门测试约束。

### `apps/web/src/components/bad-cases/badCaseDisplay.test.ts`（A）

职责：表驱动验证五态 label/tone、summary 分支、三事实截断。

检视发现：无。

### `apps/web/src/components/bad-cases/BadCaseList.test.ts`（A）

检视发现：缺少“问题在同一 Agent 的不同锚点上互不遮挡”的组件级回归，这是 D2 漏出的测试缺口。

### `apps/web/src/components/agent-tree/nodes/BadCaseNode.test.ts`（A）

### `apps/web/src/components/agent-tree/nodes/AgentNode.test.ts`（M）

检视发现：无。

### `apps/web/src/components/agent-tree/layout.test.ts`（M）

职责：覆盖四类 anchor、五态 detail merge、同锚点顺序、不同锚点堆叠安全坏宿主、路径字符串。

检视发现：缺少“不同 eventIndex 但最终矩形相交”的反例；现有两条测试都只验证同锚点或直接调用 helper，因此 D2 没有变红。

### `apps/web/src/components/agent-tree/AgentTree.test.ts`（M）

### `apps/web/src/pages/sessions/Index.test.ts`（M）

检视发现：E2E mock 暴露了 `locateBadCase`，但没有模拟“目标节点尚不存在、需展开后再定位”，因此 D1 未覆盖。

### `tests/e2e/m4-problem-cards.test.mjs`（A）

职责：以四个真实 fixture Session 验证五态、ID 对齐、列表/画布双向选择、唯一 active、桌面/390 与 console。

### `tests/e2e/m3-session-browser.test.mjs`（M）

职责：Session 浏览器的 Agent 数量改数 `.rf-agent`，避免问题卡改变原有键盘与树断言。

检视发现：无。

### Issue、Agent Note 与 i18n（M）

职责：把 m4-03 状态从 backlog 推进到 in-progress，补清交付边界、验证命令、锚点降级、双向定位和 fitView/scroll 取舍；双语 hash 已重录。
