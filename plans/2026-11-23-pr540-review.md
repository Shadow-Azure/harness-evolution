## §1 一页速览

一句话：在真实生产页面的第 1 步日期输入左边放三颗「近 7 天 / 近 30 天 / 近半年」胶囊，点一下把具体起止日填进两个原生日期框，当前区间命中哪颗就把哪颗点亮。

比喻：原来的日期区间像**每次手写两张车票的日期**；三颗胶囊是**常用行程单**，点一下先替你抄好日期，想改仍然可以直接改车票。胶囊不提交「近 30 天」这种相对说法，服务端看到的仍是两个具体日期。

## §2 架构导览

### 2.1 为什么把日期计算抽成独立模块

`launchWizardRangePresets.ts` 只做四件事：把本地 `Date` 格式化成 `YYYY-MM-DD`（`localIsoDate`，第 30 行）、按日历日加减（`addCalendarDays`，第 66 行）、按自然月加减并在目标月最后一天收敛（`addCalendarMonths`，第 80 行）、把「今天 + 预设 id」翻译成闭区间并反查命中项（`presetRange` 第 101 行、`activePresetId` 第 119 行）。

抽出来的直接收益是边界可测：月末收敛、跨年、非法日期都能在 Node 里跑，不需要为了测一个日期函数启动浏览器。组件保留的只是「点哪颗、写哪两个 ref、亮哪颗」的 UI 编排。

### 2.2 组件里只有一条单向状态流

`windowFrom` / `windowTo` 仍是组件原有的两个 `ref`，没有新增表单模型。`activeRangePreset`（`LaunchWizard.vue:171`）是一个 `computed`，把两个 ref 和浏览器当天的本地日期喂给 `activePresetId`；模板只读它来决定 `active` 与 `aria-pressed`。点击 `applyRangePreset`（`LaunchWizard.vue:176`）写两个 ref 并清掉对应字段错误，Vue 的响应式更新再驱动输入框和胶囊态。

这意味着三件事同时成立：点选不重建表单（按钮 DOM 不被替换，焦点留在原按钮）、手动改日期同样走 ref 更新、命中判断永远以当前 ref 为准，不需要额外的「自定义」状态。

### 2.3 视觉与可访问性

胶囊组是 `role="group"`（`LaunchWizard.vue:1595`），每颗按钮是 `type="button"`，带 `aria-pressed`、`data-testid` 与 title；选中态是浅蓝底、蓝色文字和描边，样式在 `LaunchWizard.vue:2791` 起的 `.wz-range-*` 规则。`wz-range-row` 允许换行，窄宽度下胶囊可以落到日期输入上方；1440×1100 的截图里三者与两个日期框同一行，无横向滚动。

## §3 数据流走查

1. 打开启动向导第 1 步：`windowFrom`/`windowTo` 为空，`activeRangePreset` 返回 `null`，三颗胶囊都不高亮。
2. 点击「近 30 天」：`applyRangePreset("30")` 用浏览器本地「今天」算出 `today − 29 ~ today`，写两个 ref；`evValidate` 未参与，字段错误在写值前被清掉。
3. Vue 更新两个 `<input type="date">` 的 `value`，同时重算 `activeRangePreset`；「近 30 天」得到 `aria-pressed=true`，另外两颗为 `false`。
4. 用户把结束日改成其他值：`v-model` 更新 `windowTo`，`activeRangePreset` 重新反查，没有命中就三颗都取消高亮。
5. 点击「下一步」：`validateStep1()` 仍按原逻辑检查非空和 `from <= to`，预览请求仍只带 `from`/`to` 两个具体日期；快捷预设没有进入请求体。

## §6 讨论点

### 6.1 胶囊高亮使用「当前浏览器日期」的 computed

- **位置**：`apps/web/src/pages/evolution/components/LaunchWizard.vue:171`
- **现象**：`activeRangePreset` 在每次依赖变化时调用 `new Date()`。页面跨过午夜后，如果用户不修改日期，已选中的胶囊不会自动按新的一天重算。
- **问题**：跨午夜的长驻页面可能出现「高亮仍在、但按新一天算已不命中」的短暂不一致；下一次改日期或点胶囊会立即纠正。
- **预判**：真实使用里启动向导是短时弹窗，跨午夜概率低；若后续要求严格，可在打开弹窗时记录 `todayIso` 并在午夜刷新，但会引入定时器，收益不明显。
- **结论**：留待维护者决定；当前接受该边界。

### 6.2 e2e 里重复了一份日期公式

- **位置**：`tests/e2e/m10-05-launch-wizard.test.mjs:184`
- **现象**：跨栈测试在 Node 侧用 `addCalendarDays` / `addCalendarMonths` 算期望值，没有直接 import 生产 TS 模块。
- **问题**：如果生产公式改动，e2e 不会自动跟着变，可能出现「两边一起错」；本期靠单测锁住辅助模块，e2e 只负责浏览器链路。
- **预判**：e2e 是 `.mjs` 独立进程，直接 import TS 需要额外构建；把一个公式复制到测试里比引入构建链更轻。若后续生产公式频繁变化，可把公式下沉到可被 e2e 直接 import 的纯 JS 文件。
- **结论**：本期接受重复；单测覆盖公式，e2e 覆盖链路。

### 6.3 提示文案替换了原来的 Session 说明

- **位置**：`apps/web/src/pages/evolution/components/LaunchWizard.vue:1639`
- **现象**：第 1 步日期下方原来写「Session 的启动时间只用于展示」，现在改为「快捷项只填入日期，仍可手动微调」。
- **问题**：新用户仍可能把「时间段」误读成 Session 启动时间的过滤；不过第 2 步的预览信息会显式展示 Session 关联口径。
- **预判**：当前文案优先解释新交互，符合原型 §7.4.1；如果用户反馈混淆，可在同一句里同时保留两个信息，但会让说明变长。
- **结论**：本期保留新文案；后续按反馈决定是否合并两句。

### 6.4 窄视口只做了 CSS 换行，没有专门 e2e

- **位置**：`apps/web/src/pages/evolution/components/LaunchWizard.vue:2791`
- **现象**：`wz-range-row` 与 `wz-range-presets` 都允许 `flex-wrap`，但 e2e 只在 1440×1100 断言无横向滚动。
- **问题**：更窄的笔记本视口（如 1024）可能把胶囊换行到日期上方；这是设计允许的，但没有自动化截图。
- **预判**：设计明确「空间不足时胶囊换行到日期输入上方」，CSS 已满足；真实浏览器在 1440 下的排版已验收，窄视口属于渐进增强。
- **结论**：本期接受；若后续要覆盖，可在 e2e 增加一个 1024 视口的断言。

## §9 文件级代码分析

### 9.1 `launchWizardRangePresets.ts`（A）

职责：把「相对今天的时间段」翻译成两个具体日期，并提供反查。变更形态是新增纯函数模块。

关键依赖只有内置 `Date`：`parseIsoDate` 把 `YYYY-MM-DD` 解析成本地中午（避免夏令时把 0 点挪到前一天），`localIsoDate` 再用本地 getter 格式化回字符串，不经过 `toISOString()` 的 UTC 切换。

```ts
// 新增：从今天往前 6 天（闭区间）
date.setDate(date.getDate() + days);

// 新增：先到 1 号再加月，最后收敛到目标月最后一天
date.setDate(1);
date.setMonth(date.getMonth() + months);
const lastDay = new Date(date.getFullYear(), date.getMonth() + 1, 0).getDate();
date.setDate(Math.min(day, lastDay));
```

实现思路总结：纯函数、本地日历日、月末收敛；非法日期直接抛错，调用方只传浏览器日期控件的值或今天的值。

检视发现：无阻塞问题；`addCalendarMonths` 的月末收敛用「1 号加月 + 取月底」实现，避免 JS `setMonth` 在 31 号加月时溢出，和原型 `evWzDateAddMonths` 同构。

### 9.2 `LaunchWizard.vue`（M）

职责：第 1 步表单。变更形态是模板替换 + 两个局部函数 + 样式。

旧代码（`main@409cf259`）只有两个日期输入：

```html
<div class="f-inline wz-controls">
  <div class="wz-field"><input ... data-testid="wizard-from"></div>

```

新代码在同一行前面插入胶囊组和分隔线；`f-inline wz-controls` 原样包住两个日期输入：

```html

  <div class="wz-range-presets" role="group" aria-label="快捷时间段">
    <button ... :aria-pressed="...">近 7 天</button> ...
  </div>
  <span class="wz-range-divider" aria-hidden="true" />
  <div class="f-inline wz-controls"> ... 原日期输入 ... </div>
```

`applyRangePreset` 只写 `windowFrom`/`windowTo` 与字段错误；没有改 `validateStep1`、`buildCondition` 或请求构造。样式全部使用 token 颜色，`verify:web-style` 通过。

### 9.3 测试（A/M）
