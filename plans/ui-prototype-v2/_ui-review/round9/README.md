# Round 9 UI review

范围：确认弹窗的键盘可达性，与全站弹窗的 Esc 关闭行为。

## 修复项

| # | 问题 | 修复 | 对照 |
|---|---|---|---|
| 1 | 第 8 轮新增的确认弹窗只能点按钮取消；`Esc` 只关菜单，键盘用户无法退出弹窗 | `Esc` 优先关闭已打开的弹窗，并清空待确认动作；没有弹窗时仍关闭菜单 | `before-esc.png` → `after-esc.png` |
| 2 | 确认弹窗打开后焦点留在触发按钮，Tab 顺序从页首开始，键盘用户可能误触 | 打开时把焦点放到「取消」；`Enter` 默认取消而不是确认 | `before-esc.png` |
| 3 | 弹窗缺少对话框语义，读屏软件只把它当成普通容器 | 确认弹窗加 `role="dialog"`、`aria-modal="true"`、`aria-labelledby`；关闭按钮补 `aria-label="关闭"` | `before-esc.png` |

## 验证结果

- 打开「移除成员 王浩」确认弹窗后，焦点元素为「取消」。
- 直接按 `Enter`：弹窗关闭，王浩仍在列表，未执行移除。
- 重新打开后按 `Esc`：弹窗关闭，王浩仍在列表。
- 「添加成员」表单弹窗同样可用 `Esc` 关闭，关闭后焦点回到「＋ 添加成员」。
- 浏览器控制台无 error / warn。
- 浏览器视口：默认窗口尺寸（未强制覆盖）。

## 证据

- `before-esc.png`：确认弹窗打开，焦点在「取消」。
- `after-esc.png`：按 `Esc` 后弹窗关闭，成员列表不变。
