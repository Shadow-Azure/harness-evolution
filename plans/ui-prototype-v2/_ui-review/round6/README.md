# Round 6 UI review

范围：把「潜在 bad case 来源分布」从趋势卡里搬出，改为独立的「单个进化对象分析」卡（对象必选、版本多选、时间段独立）。

## 变更项

| # | 问题 | 修复 | 对照 |
|---|---|---|---|
| 1 | 来源分布挂在多对象趋势卡里，只能看聚合，回答不了「某个对象在某个版本、某段时间怎么样」 | 趋势卡只保留关联 Session 与潜在 bad case 两块对象汇总；来源分布移入新卡 | `before-targets.png` → `after-targets.png` |
| 2 | 新卡需要独立筛选：对象必选并默认选中、版本可多选、时间段独立 | 新增「单个进化对象分析」卡：对象下拉（默认第一个；空间没有启用对象时置空并提示）、版本多选、起止时间 | `after-targets.png` |
| 3 | 版本多时默认只看最新 5 个，但要能扩到 10、20 | 版本菜单底部固定「默认显示最近 5 / 10 / 20 / 全部」，卡片底部给出「当前查看最近 N 个 · 展开到 10」入口 | `after-version-menu.png` → `after-version-20.png` |
| 4 | 不选版本时要能看到多版本信息 | 未选版本时按版本逐行给出潜在 bad case 堆叠分布（是 / 非 / 未），并配对象级统计：关联 Session、潜在 bad case、去重后、覆盖版本 | `after-targets.png` |
| 5 | 空间没有启用对象时卡片不应空白 | 置空对象选择并显示提示与「去配置进化对象 →」入口 | `after-empty.png` |

## 数据口径

- 关联 Session：对象在该时间窗内出现的 Session 数，对象级，不随版本选择变化。
- 潜在 bad case：当前所选（或可见）版本下的行数；同一 bad case 在多个版本下会重复计数。
- 去重后：按 bad case ID 去重，与趋势卡中该对象的潜在 bad case 数一致（deep-research 为 13）。
- 来源分布：所选版本集合内的上报来源，括号内为去重后数量。
