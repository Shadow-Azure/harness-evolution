### 2. 双 ID 体系与数据串联

ID 设计（确定性生成，两侧共用同一套函数）：

- **问题 ID**：`I-<会话ID前4位大写>-<编号>`，如 `I-050B-03` —— session 错误详情里的每个问题（finding）都有。
- **报告 ID**：`R-<会话ID前4位大写>-<编号>`，如 `R-050B-03` —— 归因结论为「是问题」（错误 / prompt 缺失 / 模型问题）时产出的问题报告，与其来源问题同编号、一一对应。

先用 Node 复算了 v2 的 `buildGraph` + `analysisFor`，拿到 4 个 session 实际生成的 **12 个问题**，其中 **7 个归因为「是问题」**，据此建立了共享注册表 `REPORTS`（7 份报告，含来源 session、模型、现象、归因类型），自进化侧三个 run 的聚类全部改为引用该注册表：

| 报告 ID | 问题 | 归因类型 | 来源 session |
|---|---|---|---|
| R-CB81-02 | 检索结果反序列化失败 | 是问题-错误 | AI agent + 视频播放结合… |
| R-CB81-03 | 执行时间过长 | 是问题-模型问题 | 同上 |
| R-2F5E-01 | 会话快照读取越界 | 是问题-prompt缺失 | 学习 DeepSeek Harness 源码… |
| R-2F5E-02 | 执行时间过长 | 是问题-模型问题 | 同上 |
| R-050B-03 | 检索索引读取失败 | 是问题-错误 | 研究"用户数据驱动自进化"… |
| R-050B-04 | 执行时间过长 | 是问题-模型问题 | 同上 |
| R-3F8E-01 | 插件清单解析失败 | 是问题-错误 | Obsidian 插件机制分析… |

run 的统计数字也同步对齐真实数据（如 run1：4 session / 12 报告 / 已分析 9 / 非问题 2 / 用于进化 7），时间段与模型筛选条件同样对齐（glm-5.3 / glm-5.3-flash，2026-08-20 ~ 09-10）。

### 3. 点击跳转（新窗口）

所有 ID 均为可点击链接，`target="_blank"` 打开新窗口，URL 形如：

```
harness-evolution.html?page=session&view=errors&sid=<会话ID>&issue=I-050B-03&dtab=attr|desc
```

落地后自动：切到「Session 错误查看」→ 打开该 session 的错误详情 → **默认选中对应错误** → tab 按来源落位：

- 点 **报告 ID（R-）** → 落在 **归因分析** tab；
- 点 **问题 ID（I-）** → 落在 **问题描述** tab。

挂接位置：

- 自进化 · 详情页第 1 步「筛选输入」表格：报告 ID + 来源问题 ID 两列链接；
- 自进化 · 详情页第 2 步「问题聚类」与第 5 步「迭代优化」的簇展开：来源问题报告表（含现象、来源 session、模型、归因类型 + 双 ID 链接）；
- 自进化 · 「仅聚类分析」结果页：同上；
- 自进化 · 已接纳 commit 块中的 `reports:` 列表：报告 ID 可点击；
- 自进化 · 启动向导筛选结果：前 7 份真实报告双 ID 可点击；
- Session 侧 ID 上屏：问题列表卡（I- 芯片，点击新窗口打开问题描述）、错误详情左侧错误卡（I- + R- 徽章）、错误详情头部（I-/R- 链接）、归因分析 tab 顶部（问题报告 ID + 来源问题 ID 双链接）、左侧栏 session ID。

### 4. 启动向导筛选结果分页

筛选条件确认后点「查询匹配报告」，下方展示完整命中列表（不再只预览 8 份）：

- 每页 8 份，底部分页条：**上一页 / 下一页** + `第 X / Y 页 · 共 Z 份 · 当前第 A–B 份`；
- 翻页有状态保持，修改筛选条件或重新查询时自动回到第 1 页；
- 前 7 份为关联 session 的真实报告（ID 可点击溯源），其余为打桩凑数行（灰显、注明未关联）。
