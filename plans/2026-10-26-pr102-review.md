## §1 一页速览

一句话：这个 PR 把 M2 已落库的真实 Session 行变成原型中的两栏分诊器，左栏负责“先看谁”，右栏负责“选中的会话有多大、失败多密”。

生活化比喻：左栏像医院分诊台，白卡上的状态点、失败密度和问题密度先决定谁值得优先查看；右栏像选中病人的摘要单，只有点击某张卡后才展开详细统计。URL 是病历号，刷新或返回时必须还能找到同一张摘要。

| 交付块 | 结论 |
|---|---|
| Session API client/query | 基本正确；筛选交给后端，问题数使用真实 `badCases` |
| URL 状态与深链 | 主路径正确；存在防抖定时器覆盖历史返回的边界 |
| Session 卡 | 结构与视觉接近原型；空 `short` 未回退 `title` |
| Session 概览 | 使用独立 detail 响应；fail 状态视觉有冲突 |
| 三态与响应式 | 列表/概览独立，390px 单列通过 |
| 边界控制 | 未请求 `/tree`，未实现 m4 错误详情，无假数据 |
| 测试 | Web 122 passed、真实 Chrome E2E 6/6；关键边界仍缺测试 |

## §2 架构导览

### 2.1 路由决定页面状态

`apps/web/src/router/index.ts:27-35` 注册 `/sessions` 与 `/sessions/:sessionId`，二者共用同一页面。选中项不是 Pinia 状态，而是路由参数；`Index.vue:51-53` 每次从 `route.params` 派生，因此刷新和直接深链不会依赖组件内存。

筛选值也来自 URL：`Index.vue:34-48` 把合法 `q/status/sort` 转成查询参数，并固定当前页上限 100。非法值是 fail-safe 地回退到默认值，不会把任意 URL 字符串直接传给 API。

### 2.2 列表与概览是两个真相入口

`useSessions.ts:12-33` 建立两个独立 query。列表 query key 包含 filters，详情 key 包含 session id；选中 session 改变时，详情缓存自动分离。

`Index.vue:60-73` 先拿列表项定位当前卡片，而右栏优先使用 detail 数据：

```text
list response  → 左侧卡片集合
detail response→ 右侧概览
detail 未到    → 可先保留当前列表项作为兼容承接
detail 失败    → 仅右栏 ErrorState，不阻断左侧
```

这样列表和详情短暂不同版本时，右栏不会永久使用列表的旧标题/统计。

### 2.3 页面主干与滚动边界

`App.vue:15,59-64,110-115` 用 `meta.workspace` 给 Session 路由切换成全宽 workspace。页面本身在 `Index.vue:210-225` 建立 `360px + minmax(0,1fr)` 两列，左右独立滚动；侧栏画浅灰面板，右侧保留原型白底工作区。

`Index.vue:274-291` 在 860px 以下改为单列，列表限高 58vh，概览顺势排在下方。E2E 在 390px 验证了横向不溢出与四卡仍存在。

### 2.4 纯展示基元

`DensityBar.vue:1-40` 只负责把后端密度换成条宽和文本；`StatStrip.vue:14-25` 只渲染 label/value/tone。两者没有业务数据请求，后续错误详情或进化页面可复用。

## §3 数据流走查

### 场景 A：首次打开 `/sessions`

1. 路由进入受保护 Session 页面，`Index.vue:55-58` 发起列表查询；无 sid 时详情 query 禁用。
2. 列表成功后 `Index.vue:129-147` 发现当前 URL 无选中项，取服务端排序第一项，通过 `replace` 写入 `/sessions/:id`，保留现有 query。
3. 详情 query 因 sid 变化启动；`SessionOverview.vue:63-73` 先显示概览骨架，失败则在该区域显示重试。

这条路径把“首屏必须先看到卡片集合”和“右栏可延迟加载详情”分开，避免详情慢拖住整个页面。

### 场景 B：输入搜索并切换状态/排序

1. `SearchBox.vue:27-34` 向上发出输入文本。
2. `Index.vue:99-105` 更新本地输入，重置 300ms timer；到期后把 trim 后的 q 写入 URL。
3. `Index.vue:107-113` 的状态/排序变更同样写 URL。
4. filters query key 变化，列表重新请求；服务端保持稳定排序，前端不二次排序。

URL 是搜索、筛选、排序的唯一稳定状态。页面没有额外维护一份“已提交 filters”，因此刷新与前进后退可以重新推导查询。

### 场景 C：点击其他 Session

1. `SessionCard.vue:23-36` 点击或 Enter/Space 发出 session id。
2. `Index.vue:115-120` push `/sessions/:id`，并保留当前 q/status/sort。
3. `selectedId` 改变，左卡选中边界从路由派生，右详情 query 也随 key 切换。
4. 如新列表不再包含该 id，`Index.vue:129-147` 会替换为当前列表首项，避免永远显示不属于筛选结果的概览。

### 场景 D：列表或概览失败

1. 列表失败由 `SessionList.vue:50-54` 渲染独立 ErrorState，重试只调用 list query。
2. 概览失败由 `SessionOverview.vue:68-72` 渲染独立 ErrorState，重试只调用 detail query。
3. 左侧仍有数据时右侧失败不会破坏列表；两边的加载/错误状态互不覆盖。

## §6 讨论点

### D1 空 `short` 会让 Session 卡失去标题

**位置**：`apps/web/src/pages/sessions/components/SessionCard.vue:37-45`

**现象**：卡片直接渲染 `item.short`，没有回退到 `item.title`。

**问题**：接口设计明确允许 `short` 为空，并要求前端回退到完整标题（`plans/fullstack-design/05-api-design.md:86`）。真实上游或后续解析器只要给出空短标题，左栏就会出现一张无标题卡，用户无法在列表中辨认或点击目标。

**预判**：这是列表主数据的展示缺陷，应修复。最小实现是用 `item.short || item.title`；补一条组件/E2E 断言，覆盖 `short: ""`、`title: "完整标题"`。

**结论**：已修复（2026-10-26）。卡片使用 `short || title`，并由页面测试覆盖空 `short` 的完整标题回退。

### D2 未完成的搜索 timer 可以覆盖浏览器“后退”

**位置**：`apps/web/src/pages/sessions/Index.vue:99-105,122-127`

**现象**：输入变化后 timer 会延迟执行 `updateFilter`；但 `route.query.q` 的 watcher 只同步输入框值，没有清除尚未执行的 timer。若用户在 300ms 内触发一个会改变 `q` 的历史导航，旧 timer 仍会稍后 push 新位置。

**问题**：用户按后退回到旧搜索条件后，页面可能马上又被未完成输入拉回新条件，URL 历史也会多出一条；这与“刷新和前进后退可恢复筛选”的验收冲突。现有 E2E 只在搜索已稳定并产生 URL 后才执行 back/forward，未覆盖此边界。

**预判**：应修复 handler 生命周期：route q 外部变化时先 `clearTimeout(searchTimer)`，再同步 `searchInput`；或者把 debounce 放在受控 watcher 中并以提交序号丢弃过期回调。补一条“输入但未满 300ms 时后退”的组件测试。

**结论**：已修复（2026-10-26）。路由 query 外部变化会递增搜索版本并清除 timer，延迟回调同时校验版本；新增“输入未满 300ms 即导航”的回归。

### D3 `role="listbox"` 的条件与键盘行为不完整

**位置**：`apps/web/src/pages/sessions/components/SessionList.vue:32-72`、`SessionCard.vue:23-36`

**现象**：容器始终是 `role="listbox"`，但 loading、error、empty 分支放入的是 skeleton、ErrorState 按钮或普通提示；卡片仅支持 Tab、Enter、Space，没有 listbox 约定的 ArrowUp/ArrowDown/Home/End，且所有 option 都保留 `tabindex="0"`。

**问题**：有数据时，键盘用户需要在每个卡片间逐个 Tab；没有数据或加载失败时，listbox 的直接子内容又不再是 option/group，屏幕阅读器会读到不完整的复合控件语义。原型的鼠标分诊体验可用，但这套 ARIA 还没有形成一致的可访问交互。

**预判**：应在有 options 时才赋予 listbox 语义，并实现 roving tabindex + 方向键/Home/End；加载、空、错误态用独立的 status/region 容器，避免把按钮塞进 listbox。若团队暂时不承担完整 listbox 模式，可改用语义 button 列表并保留 `aria-current`，比不完整 listbox 更可靠。

**结论**：已修复（2026-10-26）。仅 option 态启用 listbox；加载、空和错误态使用独立语义。卡片采用 roving tabindex，并支持 ArrowUp/ArrowDown/Home/End 与焦点移动。

### D4 卡片密度、时长与 Token 格式偏离原型展示

**位置**：`apps/web/src/components/ui/DensityBar.vue:22-40`、`apps/web/src/utils/sessionDisplay.ts:6-24`

**现象**：

- 密度值复用 `formatTokens`，`0.0/50.0` 会显示成 `0/50`，原型固定一位小数并带 `/百步` 单位。
- 时长超过 10 小时后当前只显示整数小时，如 17h37m 会显示成 18h；原型保留分段。
- Token ≥1M 时当前保留最多两位小数，如 `1.25M`；原型固定一位小数，如 `1.3M`。

**问题**：状态判断数值仍有，但用户无法从卡片密度看出设计约定的“每百消息”口径；长会话的时长也会丢失关键分钟信息。这不是数据正确性问题，但会直接影响原型验收和跨会话比较。

**预判**：将展示格式拆成三个明确函数/规则：密度固定一位小数并补单位，时长按小时+分钟、分钟、秒分段，Token 使用原型的一位 M/整数 k 规则。格式化函数应有边界测试（0、3、17h37m、1.25M）。

**结论**：已修复（2026-10-26）。密度固定一位小数并显示 `/百消息`，长时长保留小时和分钟，Token 使用一位 `M`/紧凑 `k`；对应格式边界纳入测试。

### D5 `fail` 概览徽章仍使用橙色“有失败”

**位置**：`apps/web/src/pages/sessions/components/SessionOverview.vue:33-35,87-90,203-211`

**现象**：状态点按 `ok/partial/fail` 区分绿/橙/红，但徽章把所有非 `ok` 状态都投到 `problem` 类，CSS 只有橙色；整体失败的会话因此同时出现红点和橙底徽章。

**问题**：原型的 Session 状态色语义和 API 的 `partial`（局部失败）/`fail`（整体失败）是两档；一个红点配橙徽章会让用户误判严重程度。当前现网四会话恰好都是 partial，测试也主要使用 partial，所以没有暴露。

**预判**：概览徽章至少为 `partial` 使用橙、`fail` 使用红；文案可继续是“有失败”，也可按产品语义区分为“部分失败/失败”。补一个 fail fixture 的组件测试和 computed-color 断言。

**结论**：已修复（2026-10-26）。`fail` 徽章使用红色 token，`partial` 保持橙色；页面测试同时覆盖徽章 class 与文字。

### D6 `?status=partial|fail` 深链没有对应激活 chip

**位置**：`apps/web/src/pages/sessions/Index.vue:20-49,174-188`、`StatusChips.vue:15-19`

**现象**：页面接受 URL 中的 `partial` 与 `fail` 作为服务端筛选值，但 UI 只有 `all/ok/problem` 三个 chip。手动打开这类深链时列表确实被筛到 partial/fail，屏幕上却没有任何 chip 处于选中态。

**问题**：API 允许这些 status 值是合理的，但页面状态表达出现“筛选已生效、控件却不解释”的空档。外部旧链接或手工 URL 会看到不完整的选择状态。

**预判**：加载时把 `partial/fail` 规范化显示为“有失败”选中态；若还要保留具体子类型，可以增加一行可选子筛选，但这超出本 PR。最低限度应让 chip 高亮与当前结果一致。

**结论**：已修复（2026-10-26）。`partial`/`fail` 在 UI 中归一显示为“有失败”激活态，URL 与后端筛选值保持不变。

## §9 文件级代码分析

### `apps/web/src/App.vue`（M）

职责：在全局壳层为 Session workspace 提供无外层卡片的全宽容器。

旧代码将每个页面限制在 1280px；新代码在 `App.vue:15,59-64` 读取路由 `workspace` meta，对 Session 路由使用 `main.workspace-main`。`App.vue:110-115` 让容器占满顶栏以下高度并消除页面 padding。代价是其他页面仍沿用普通文档流，因此后续若新增图编辑类 workspace，需要同样设置 meta。

检视发现：无新增阻断；D2/D3 在页面内部。

### `apps/web/src/api/sessions.ts`（A）

职责：把页面 filters 编码成 Session REST 请求，并读取单会话概览。

实现使用 `URLSearchParams`，避免 q 中 `&`、空格等破坏查询；详情 id 使用 `encodeURIComponent`。这部分没有前端排序，保持“列表顺序是服务端结果”的契约。

检视发现：无。

### `apps/web/src/composables/useSessions.ts`（A）

职责：封装 Vue Query 的 list/detail 生命周期。

query key 包含 filters 或 session id，缓存不会把不同筛选条件下的列表串用。当前 queryFn 没有接收 query context signal，因此快速切换筛选时浏览器请求不会被主动取消；Vue Query 会忽略过期响应，当前数据正确，代价是服务器可能多做短暂请求，列为优化项而非缺陷。

### `apps/web/src/pages/sessions/Index.vue`（A）

职责：URL 状态、自动选中、列表/详情 query 和两栏编排。

核心机制是把 `route.query` 当输入，把 `router.push/replace` 当输出；没有额外 Pinia 选中态。`Index.vue:55-73` 将详情响应放在概览优先位置，修复了“列表 detail 两套数据”的早期设计缺口。

检视发现：D1 的空 short 不在此文件；D2 的防抖 timer 和 D6 的 status 深链归一化在此编排处。

### `apps/web/src/pages/sessions/components/SearchBox.vue`（A）

职责：受控搜索输入和图标。

输入通过 v-model 事件上抛，页面层负责 300ms debounce，因此组件本身无 timer 泄漏。`aria-label` 与占位文案让无可见 label 的搜索仍可被读屏识别。

检视发现：无。

### `apps/web/src/pages/sessions/components/StatusChips.vue`（A）

职责：三态单选按钮组。

按钮用 `aria-pressed` 表达当前选中，视觉选择来自原型。API 虽允许 partial/fail 单值，但 UI 只定义三档；需要页面把这两档归一为 `problem`，对应 D6。

### `apps/web/src/pages/sessions/components/SortSelect.vue`（A）

职责：原生 select 的四档后端排序。

option 值与 API sort 名称一致，没有前端排序；`aria-label` 让 select 可读。无发现。

### `apps/web/src/pages/sessions/components/SessionList.vue`（A）

职责：列表容器、四卡 skeleton、empty/error 和卡片循环。

加载时固定四张骨架，符合原型保持布局稳定的策略。错误和空态都提供明确动作/说明。

检视发现：D3。`role=listbox` 被无条件套在所有状态上，键盘交互只由子卡实现 Enter/Space；错误态的按钮不符合 listbox 子项语义。

### `apps/web/src/pages/sessions/components/SessionCard.vue`（A）

职责：一张可在左栏分诊的 Session 卡。

卡片完整呈现状态点、标题、时间、repo、时长、工具数、子 Agent 和五项统计；`aria-selected`、Enter/Space 和 `sr-only` 状态文本让鼠标之外的用户也能选择。样式使用共享 token，没有硬编码颜色。

检视发现：D1 的 `short` 未回退 title；D3 的键盘行为只有单卡级别，缺完整 listbox 方向键。

### `apps/web/src/pages/sessions/components/SessionOverview.vue`（A）

职责：当前选中 Session 的标题、meta、九项统计、错误详情 CTA 和执行流占位。

概览显式区分 loading、error、empty 和 data；CTA 在 m4 页面存在前禁用，避免制造假链接。占位面板保留 720px 高度，后续图组件可以直接替换内容而不改变页面密度。

检视发现：D5 的 fail 状态徽章类过于粗糙。

### `apps/web/src/components/ui/StatStrip.vue`（A）

职责：无业务语义的统计条。

以 `<dl>` 表达指标和值，颜色 tone 仅作为可选样式；适合后续复用。无发现。

### `apps/web/src/components/ui/DensityBar.vue`（A）

职责：后端密度的可视化。

宽度由共享 `densityWidth` 统一截断，颜色只来自 token。当前值文本复用 Token 格式化，导致 D4 的小数/单位偏离原型。

### `apps/web/src/utils/sessionDisplay.ts`（A）

职责：UI 展示格式集中处。

集中格式化避免了多个卡片重复实现，但当前格式策略没有按原型保留长时长分钟、密度一位小数和固定 Token 精度，对应 D4。

### `apps/web/src/router/index.ts`（M）

职责：新增 `/sessions/:sessionId` 深链。

两个路由指向同一页面，route guard 仍统一保护登录与强制改密。详情请求只在有 sid 时启用，不存在空 id 请求。

### `packages/contracts/src/index.ts`（M）

职责：导出 FastAPI 生成的 Session DTO。

只增加类型别名/JSDoc，不手工复制字段。`contract:check` 已独立通过。

### `scripts/run-e2e.mjs`（M）

职责：支持按 test title 选择 E2E 文件。

现在先筛文件再交给 Node test，避免所有 E2E 文件都启动；零匹配快速退出。`timeout` 与 SIGTERM 仍在，属于有效的门禁加固。无发现。

### `scripts/gates.spec.mjs`（M）

职责：钉住 E2E 过滤和 m3 测试接线。

增加的是脚本行为断言而非常量输出，能防止 route/test 静默丢失。无发现。

### `tests/e2e/m3-session-browser.test.mjs`（A）

职责：真实 Chrome 下验证四个 canonical Session、原型尺寸和 URL history。

测试从真实 fixture seed 启动 API/Vite，经登录后读取 computed style；不是前端 mock 截图。它已在 1408px 与 390px 间切换，并验证 `/tree` 零请求。

检视发现：D2 的“未满 300ms 就后退”和 D6 的 partial/fail 深链未覆盖；D1/D4/D5 需要对应 fixture 才能暴露。
