## §1 一页速览

一句话：把 m7-05 已有的空间/成员/凭据 API 变成空间管理页，并让“谁能看到写入口”和“凭据只能看一次”在前端与后端边界上同时成立。

一个比喻：管理页像一栋只有四间办公室的楼——空间与额度、成员、上报、鉴权。楼里的门禁（角色）由服务端发卡；前端只决定把哪些门牌挂出来。凭据像一次性钥匙：前台递给你时能看，收回去（关闭弹窗）后只剩钥匙编号（prefix）。

## §2 架构导览

### 2.1 入口与角色可见性

`router/index.ts:84` 把 `admin` 加进空间壳 children；`Admin.vue` 不自己判断“能否进入”，而是从 `auth.workspaceById(wid).role` 推出 `canManage`（`Admin.vue:58-59`）。顶栏 `#tn-admin` 与切换器「空间设置 →」只在 `canManageWorkspace(role)` 为真时渲染（`TopNav.vue:350`、`WorkspacePicker.vue:131`）。成员与 viewer 仍能直接输入 URL 进入页面，但页面头显示「只读」badge，写入口隐藏。

这意味着“入口可见性”和“服务端授权”是两层：前端不是权限系统，只是体验护栏；直接调 API 仍由 m7-05 的 `require_workspace_role` 返回 403/404。

### 2.2 四 Tab 的数据边界

`Admin.vue` 只负责页面级 `GET /api/workspaces`（额度/管理员/成员数的权威快照）与弹窗编排；每个 Tab 各自取数：

- `SpacesTab`：全局管理员渲染全部空间表；空间管理员/viewer 渲染当前空间额度卡。数据来自页面级查询，不额外请求。
- `MembersTab`：`useWorkspaceMembers`；viewer 因服务端要求 `member` 及以上，直接关闭查询并渲染只读说明（`MembersTab.vue:38-42`）。
- `IngestTab`：`useWorkspaceCredentials` 只在 `canManage` 时启用；viewer 只看地址与权限说明。
- `AuthTab`：纯静态契约说明，不请求后端。

### 2.3 一次性凭据的状态生命周期

`IngestTab.vue:38` 的 `createdCredential` 是组件局部 `ref`，不是 Pinia 或 query cache。轮换成功写入它（`IngestTab.vue:71`），弹窗用 `:model-value="createdCredential !== null"` 打开；关闭时 `closeCredentialDialog` 置空（`IngestTab.vue:100-101`），模板同时用 `v-if="createdCredential"` 移除明文节点（`IngestTab.vue:333-367`）。列表查询只返回 prefix，不返回明文。

这样做的代价是：用户如果没复制就关闭，明文不可恢复，只能再轮换一次。这是有意的安全取舍。

### 2.4 缓存与失效

管理相关的 key 全部挂在 `["ws", wid, "admin", …]` 下（`queryKeys.ts:16-23`）。成员/空间写操作失效 admin 前缀、`["ws"]` 与 `["auth","session"]`，并在 `refreshAuthSession` 中重取 `GET /auth/session`（`useWorkspaces.ts:38-64`），让空间切换器和成员数跟上；凭据轮换只失效 credentials 前缀。

`["ws"]` 是空间列表与所有空间缓存的共同前缀，因此成员变更会让当前空间其他查询也失效。这是设计 §2.4 的明确要求（“建/改空间、成员变更失效 `["ws"]`”），代价是切回旧页面时会重新拉取，而不是复用旧缓存。

## §6 讨论点

### 6.1 viewer 的成员列表：隐藏还是只读展示？

- **位置**：`apps/web/src/pages/workspaces/components/MembersTab.vue:38-42`
- **现象**：viewer 打开成员 Tab 时不请求 `GET /members`，只显示“只读成员不能查看成员列表”。
- **问题**：原型把成员列表视为管理页的一部分；当前后端要求 `member` 及以上，viewer 无法读取。产品上是否希望 viewer 能看到“谁在空间里”？
- **预判**：当前实现优先遵守服务端权限，避免无意义 403；如果产品要求 viewer 可读，应放宽 API 到 `viewer` 并同步契约与测试，而不是前端绕过。
- **结论**：待维护者拍板。

### 6.2 创建空间的用户候选没有分页

- **位置**：`apps/web/src/pages/workspaces/components/WorkspaceFormDialog.vue:34-40`、`api/users.ts`
- **现象**：创建弹窗依赖 `GET /api/users` 返回全部账号。
- **问题**：账号规模很大时首屏会变慢，且没有搜索。
- **预判**：当前 m7 阶段账号量小，可接受；后续需要服务端搜索/分页或复用候选接口。
- **结论**：待维护者拍板是否在本 milestone 内补分页。

### 6.3 成员变更失效整个 `["ws"]` 前缀

- **位置**：`apps/web/src/composables/useWorkspaces.ts:47-64`
- **现象**：加/改/移成员后，除 admin 前缀外还失效 `["ws"]` 与 auth/session。
- **问题**：同一空间其他业务查询（Session、bad case、run）会被一起标脏，切回页面时重新请求。
- **预判**：这是设计 §2.4 的统一失效规则，换来成员数/空间列表/额度的一致性；数据量不大时可接受。
- **结论**：待维护者确认是否保留。

### 6.4 凭据轮换不自动撤销旧凭据

- **位置**：`apps/web/src/pages/workspaces/components/IngestTab.vue:67-98`
- **现象**：轮换只创建新凭据并展示明文，旧凭据由用户手动撤销。
- **问题**：如果用户忘记撤销，可能同时存在多个有效凭据（上限 3）。
- **预判**：这是设计要求的“先切换上游、再撤销旧凭据”，避免中断上报；列表已展示有效/已撤销状态与撤销入口。
- **结论**：维持现状；后续可在 UI 增加“切换完成后撤销旧凭据”的引导。

### 9.1 `apps/web/src/pages/workspaces/Admin.vue`

关键依赖：Vue Router（`?tab=` 深链）、Vue Query（空间列表）、`canManageWorkspace` 纯函数。

变更块：

```ts
const canManage = computed(() => canManageWorkspace(currentRole.value));
const activeTab = computed<AdminTab>(() => {
```

### 9.2 `apps/web/src/composables/useWorkspaces.ts`

职责：管理域查询与变更的单一入口；查询 key 与失效范围集中在这里。

关键依赖：`@tanstack/vue-query`、`api/workspaces`、`auth` store（用于重取 session）。

变更块：

```ts
async function invalidateWorkspaceAdmin(queryClient, workspaceId) {
  await Promise.all([
    queryClient.invalidateQueries({ queryKey: queryKeys.admin(workspaceId) }),
    queryClient.invalidateQueries({ queryKey: queryKeys.workspaces() }),
    queryClient.invalidateQueries({ queryKey: queryKeys.authSession }),
  ]);
  await refreshAuthSession();
}
```

这在做什么：成员/空间写操作后，同时刷新 admin 子树、空间列表和浏览器 session，避免切换器/成员数停在旧值；`auth/session` 不是 query，所以用 store 的 `loadSession` 补上。

检视发现：`refreshAuthSession` 吞掉错误，避免“写成功但 session 刷新失败”被展示成操作失败；代价是极端情况下切换器仍可能旧值。无实害，已写入 Note。
