## §1 一页速览

一句话：把“执行流”从**一棵会折叠、会过滤分支的节点树**，换成**一张按日志行排布、可以缩放平移的地铁线路图**，并把旧树降级为可切换视图。

- 一条 lane = 一次 agent invocation，像一条地铁线；`A1/A1.1` 是线路编号。
- 一根 bar = 一段日志行；触发事件占自己的行，两个触发之间是 `×N 无触发` 的空白段。
- 两条 lane 的 bar 在横向上重叠，就是并发；不再靠“节点并排”暗示。
- 选中一个 bad case，像在地图上插一面旗：只加粗旗杆、点亮对应 bar，不撤掉其它线路。
- 56 个子 agent 不折叠，改用“缩小看全图、放大看细节”。

## §2 架构导览

### 2.1 为什么先有纯模型，再有视图

`buildLaneModel(tree, selectedCaseId)`（`laneModel.ts:78`）不碰 DOM、不读组件状态，只做四件事：

1. **归类**：校验唯一 main、重复 agent、孤儿 parent、parent cycle；孤儿回退 main（`laneModel.ts:120`）。
2. **排序与编号**：同一父节点按触发行排序，`path = parent.path + "." + (index+1)`（`laneModel.ts:202`）；因此 main 是 `A1`，第一个子是 `A1.1`，孙是 `A1.1.1`。
3. **铺区间**：main 的事件按行切成事件 bar 与 `×N` gap bar（`laneModel.ts:378`）；子 lane 的 start 取父触发点，宽度按自身日志行数等比缩放，最长 42%。
4. **叠加标记**：BC marker 从 `anchor.agentId + anchor.eventIndex` 找触发行（`laneModel.ts:642`）；并发带取子 lane 的 min(start)–max(end)（`laneModel.ts:721`）；spawn 组按“父 lane + 父 bar”合并 trunk（`laneModel.ts:736`）。

这层是本次最值得单测的部分：所有几何断言都能在 node 环境跑，不需要浏览器。

### 2.2 视口只持有 transform

`viewport.ts` 把缩放、平移、fit、center 做成纯函数（`viewport.ts:18`–`131`）。`LaneDag.vue` 只存 `{x,y,k}` 和拖拽起点：

- 滚轮以指针为中心缩放（`LaneDag.vue:124`），范围 0.08–3。
- 指针拖拽改变 translate（`LaneDag.vue:140`）。
- fit 把整个 canvas 装进固定小窗口并居中（`LaneDag.vue:93`）。
- `locateBadCase` 把 BC marker 放到视口中心（`LaneDag.vue:233`）。

固定高度来自 `clamp(360px, 48vh, 520px)`（`LaneDag.vue:665` 起的样式与 `AgentFlow.vue:133` 的 `dagHeight` 默认值），结构树仍用 720/413。

### 2.3 选中态只有一个来源

`AgentFlow.vue:57` 用 `activeBadCaseId` 重新计算模型，`LaneDag` 用 prop 而不是模型内快照决定 `is-selected`。这样：

- 问题列表点击 → 页面 `locateBadCase` → `AgentFlow.locateBadCase`（`AgentFlow.vue:100`）→ DAG center 或树 center。
- DAG 点 BC → `select-case` → 页面更新选中 → 列表滚动。
- DAG ↔ 树切换 → `setMode`（`AgentFlow.vue:67`）只改视图，不碰选中；树挂载后按同一个 id 定位。

### 2.4 错误兜底

`AgentFlow.vue` 的 `onErrorCaptured` 记录失败视图；只有 DAG 抛错才回退树。树自身抛错时显示通用“执行流渲染失败”，避免把树的错误误报成 lane DAG 错误。这是自检时发现并修掉的一个小问题。

## §3 数据流走查

以 Session 页选 `badcase-synthetic-0001` 为例：

1. `useSessionTree` 拿到 flat `SessionTree`（agents + events + badCases）。
2. `SessionOverview.vue:256` 把 tree/problems/activeBadCaseId 交给 `AgentFlow`。
3. `AgentFlow.vue:57` 调 `buildLaneModel`：
   - main 事件 line 2 → 先产生 `×1` gap（line 1），再产生 main bar（line 2）。
   - 子 agent 通过 `toolUseId` 找到父事件 line 2，start 落在 main bar 内；宽度按子日志行数。
   - bad case anchor 为 agent `agent-s1-review-0001`、eventIndex 0 → line 2 → marker 落在 main bar 上。
4. `LaneDag` 用百分比渲染 bar，用 px 渲染 lane 行；BC marker 在独立 marker 行，选中时加粗 lead。
5. 用户点“定位”或 BC：页面调 `locateBadCase`，viewport 把 marker 的 x、主轨 y 平移到视口中心。
6. 切“结构树”：`AgentTree` 用同一个 `activeBadCaseId` 挂载，Vue Flow 的 `fitView/setCenter` 定位到对应 bad case 节点；切回 DAG 仍保持选中。

## §6 讨论点

### 6.1 lane 模型在树模式下也会计算

- **位置**：`AgentFlow.vue:57`
- **现象**：`laneModel` 是 computed，即使当前是 `tree` 模式也会随 tree/activeBadCaseId 重算。
- **问题**：61 个子 agent 时多一次 O(agents+events) 计算；当前没有可感知卡顿。
- **预判**：可改为仅 DAG 模式计算，但会让切换时的首帧多一次计算；当前不值得增加条件。
- **结论**：

### 6.2 rail 标签与 BC marker 只有两行避让

- **位置**：`laneModel.ts:642`（marker row）、`laneModel.ts:462`（rail row）
- **现象**：同一 x 附近超过两个 marker/标签时仍会叠字。
- **问题**：极端密集的 bad case/触发点会牺牲可读性；原型同样只有两行。
- **预判**：可增加行数或横向聚合，但会抬高主轨高度、压缩小窗口；先接受。
- **结论**：

### 6.3 BC 序号依赖 API 返回顺序

- **位置**：`laneModel.ts:642`
- **现象**：`index` 是 `tree.badCases` 的数组下标，仅用于显示 `BC1/BC2`。
- **问题**：API 排序变化时同一 case 的展示号会变；真实 ID 与深链不受影响。
- **预判**：展示号不是稳定身份，与原型一致；若产品要求稳定编号应在服务端给。
- **结论**：

### 6.4 没有真实时间戳

- **位置**：`laneModel.ts:378`
- **现象**：bar 长度严格按日志行比例，不是耗时。
- **问题**：读者可能误读为执行时长。
- **预判**：脚注与 tooltip 已写明“非真实耗时”；M9 有 `triggered_at` 时再替换横轴。
- **结论**：

### 6.5 大会话初始 fit 很小

- **位置**：`LaneDag.vue:93`
- **现象**：61 lane 的 canvas 高约 2580px，fit 后整体缩到 0.15 左右，需要再放大。
- **问题**：首次看到的是“缩略图”，不是可读文本。
- **预判**：符合 08 §3.3“先 fit 到全览，再用缩放查看”；若改为默认 1:1 会看不到全貌。
- **结论**：

## §9 文件级代码分析

### 9.1 `AgentFlow.vue`（A）

职责：双视图容器，默认 `dag`，按钮切 `tree`；对外暴露 `locateBadCase/locateAgent/setMode`。

关键依赖：`LaneDag`（自研 canvas）、`AgentTree`（Vue Flow）、`buildLaneModel`（纯函数）。Vue Flow 不再进入默认执行流，因此首屏不会加载它的布局逻辑。

变更块：

- `:57` computed 模型：把 tree + 选中 id 变成 lane 模型；视图只读。
- `:67` `setMode`：切视图不碰选中；切回 DAG 由 `LaneDag` 挂载后的 fit/locate 负责定位。
- `:100` `locateBadCase`：按当前视图分派到 LaneDag 或 AgentTree；视图选择写入 `he:flow-mode`，默认仍为 DAG。
- `onErrorCaptured`：记录 `failedView`，只有 DAG 失败才回退树，避免误报。

检视发现：见 §6.1。

### 9.2 `lane/laneModel.ts`（A）

职责：把 flat `SessionTree` 变成可渲染的 lane 模型。

关键依赖：无第三方；只依赖 contracts 类型。它是本次变更的“地图绘制规则书”。

变更块：

- `:78` `buildLaneModel`：唯一入口，先校验 main/重复/孤儿/环，再建 main lane 与子 lane。
- `:202` `buildChildren`：main 父节点按父 bar 分摊同触发点的兄弟（0.2–0.8）；子父节点按子日志行数比例落在父 lane 区间内。
- `:378` `buildMainBars`：事件按行排序，填 gap、合并相邻触发；输出连续覆盖 0–100 的 bar。
- `:642` `buildBadCaseMarkers`：按 anchor 解析触发行；gap 内也标在触发行，并给出最近触发点说明。
- `:721`/`:736` 并发带与 spawn 组：只用于视觉连接，不参与 bar 区间。

实现思路总结：先保证“行”是唯一横轴，再加 lane 的纵向与父子关系；所有几何在此层定死，组件不再推导。

检视发现：§6.2、§6.3、§6.4。

### 9.3 `lane/viewport.ts`（A）

为什么独立：缩放/平移是本次最容易写错的交互，抽成纯函数后可以精确断言“指针下的内容不动”“fit 居中”“locate 放大到 0.6”。
