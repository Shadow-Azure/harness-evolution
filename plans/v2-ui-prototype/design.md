# Harness Evolution V2 前端原型设计

> 可点击原型：`prototype.html`。本文只确定产品交互与迁移边界；打桩数据不进入生产代码。

## 1. 设计结论

V2 采用“全局身份 + 当前工作空间 + 空间内业务页”三层结构。顶栏保留现有 Session 错误查看和自进化两条核心导航，新增空间总览；工作空间切换器、当前用户和空间管理入口放在全局壳层。用户切换空间后，总览、Session、错误详情、自进化和对象配置都使用同一 `workspaceId`，页面不各自保存空间状态。

归因从独立前置数据变成自进化流程产物：一个 bad case 可以关联多个进化对象版本，每个对象版本产生独立归因记录。错误详情仍以 bad case 为主锚点，左栏改为可折叠的归因列表；选中某条归因只替换右侧归因内容，不改变问题描述、Session 或执行流。

## 2. 现状复用与迁移

| 现有能力 | V2 处理 | 迁移收益 |
|---|---|---|
| 用户表、管理员、登录、refresh Cookie、Bearer access token | 完整复用；新增 workspace membership 与角色鉴权，不引入公开注册 | 不重写认证状态、401 刷新和路由守卫 |
| 顶栏、亮色 token、全局三态 | 保留几何与颜色；增加空间切换器和总览入口 | 保持视觉与可访问性基线 |
| Session 列表与概览 | 保留卡片、概览和执行流；默认请求改为 `limit=10`，搜索改为 Enter 精确 root session ID | 复用现有组件和滚动记忆 |
| 错误详情、问题描述、执行流、深链 | 保留主布局；bad case 卡下增加可折叠归因子列表 | 不改变用户定位问题与证据的路径 |
| 单一 `/analysis` 视图 | 改为归因摘要集合 + 单条详情；旧视图作为兼容读取适配 | 支持多对象版本且避免复制 bad case |
| 自进化对象/版本/时间窗向导 | 保留第一步；命中预览改为 Session 关联、潜在 bad case 和缓存预览 | 保留目录、版本加载与运行创建边界 |
| 对象配置与运行详情 | 放入当前工作空间；后续 run 记录携带空间与归因快照 | 避免跨空间数据和缓存串用 |

## 3. 身份与权限

全局管理员只有一个账号，不开放注册。普通用户通过管理员创建或后续鉴权接入进入系统；接入方只需提供已验证身份与用户信息映射，业务授权仍由本服务的 membership 判定。现有 Cookie 恢复与 access token 请求链路保持不变。

| 能力 | 全局管理员 | 空间管理员 | 成员 | 只读成员 |
|---|---:|---:|---:|---:|
| 创建工作空间、设置初始额度 | ✓ | — | — | — |
| 查看有权限的空间与数据 | ✓ | ✓ | ✓ | ✓ |
| 调整当前空间额度、上报凭据 | ✓ | ✓ | — | — |
| 管理空间成员、授予空间管理员 | ✓ | ✓ | — | — |
| 配置进化对象、启动自进化 | ✓ | ✓ | ✓ | — |
| 查看 Session、bad case、归因与运行 | ✓ | ✓ | ✓ | ✓ |

全局管理员可以把任意普通用户（包括自己对应的用户身份）加入空间并任命为空间管理员；一个空间允许多个空间管理员。空间管理员的“全部操作权限”限定在该空间内，不包含创建其他空间、管理全局账号或查看未加入空间。

## 4. 信息架构与路由

```text
登录
└─ 工作空间上下文
   ├─ 空间总览
   │  └─ bad case 列表 → Session 错误详情 / 问题描述
   ├─ Session 错误查看
   │  ├─ Session 列表与概览
   │  └─ 错误详情 / 执行流 / bad case / 多条归因
   ├─ 自进化
   │  ├─ 运行列表与详情
   │  ├─ 启动向导
   │  └─ 进化对象配置
   └─ 空间管理（按权限显示）
      ├─ 空间与额度
      ├─ 成员与角色
      └─ 上报接入
```

建议生产路由增加 `/workspaces/:workspaceId` 前缀，并保留 `badCaseId`、`tab`、`agentId`、`eventIndex` 等现有 query 语义：

```text
/workspaces/:workspaceId/overview
/workspaces/:workspaceId/sessions
/workspaces/:workspaceId/sessions/:sessionId/errors?badCaseId=...&tab=problem
/workspaces/:workspaceId/evolution
/workspaces/:workspaceId/settings/{workspace,members,ingestion}
```

旧 `/sessions/**` 与 `/evolution/**` 在迁移期通过“用户最近访问且有权限的空间”重定向；无可用空间时进入空间选择页，不静默选择第一个空间。旧错误深链缺少空间时，可由 bad case/session 的唯一归属解析后重定向；一旦历史数据允许多归属，该兼容路径必须停止自动猜测。

## 5. 页面与关键交互

### 5.1 登录与空间入口

登录页只有账号、密码和登录动作，显示“由管理员开通账号”，没有注册链接。登录后恢复 Cookie 会话并读取可用空间；无权限、空间被停用和会话过期分别显示可恢复状态。空间切换器显示空间名称、角色和额度使用，切换后返回同类型页面的空间等价路由。

### 5.2 空间总览

顶部筛选包含时间范围、统计粒度（日/周/月）、`object_name` 多选和 bad case 类型。对象不选表示全部，多选表示并集；类型可查看 `self`、`discovery` 或两者。图表按时间与对象分组展示两类数量，并同步显示筛选后的总量、Session 数和对象数。

下方 bad case 列表使用独立的条件与分页状态：时间段、`object_name`、`bad_case_type` 均为可选，空值不限制。行展示 ID、标题、对象、类型、发生时间、Session 和归因数；点击整行进入对应 Session 错误详情并选中该 bad case 的“问题描述”。筛选、页码写 URL，返回总览可恢复现场。

### 5.3 Session 错误查看

默认只查询当前空间最新 10 个 root Session，不默认拉取完整树。搜索框接收完整 root session ID，Enter 后发起精确查询并替换或补充左侧结果；清空并回车恢复最新 10 条。选中 Session 后再加载概览和执行流，保留现有“打开错误详情”入口。

### 5.4 错误详情与多归因

左栏每个 bad case 是一组可折叠节点：父行保留标题、对象、类型和定位；展开后按“进化对象 · 版本”列出归因摘要，显示结论状态、运行时间和缓存标记。归因子列表独立分页，不让大量归因撑长 Session/bad case 主列表。右栏保留执行流与“问题描述 / 归因分析”双 Tab；从总览进入默认问题描述，从归因子项进入默认归因分析。没有归因时显示“启动自进化后生成”，而不是伪造未分析结论。

### 5.5 自进化启动向导

1. **选择范围**：选择已配置且启用的进化对象、版本和 bad case 时间段。
2. **关联与筛选**：后端先查时间窗内有 bad case 的 Session，再判断对象版本在哪些 Session 出现；预览同时展示关联 Session、bad case、对象触发点和 bad case 触发点。默认潜在策略为“对象自身上报的 self bad case”并集“bad case 触发点晚于该对象触发点的 bad case”。自定义策略作为带版本的可保存配置，不在前端拼接任意代码。
3. **归因与启动**：选择是否复用缓存。缓存键至少包含工作空间、bad case、对象身份、对象版本、归因策略版本和归因模型/提示词版本；命中时复用最近一次成功归因，不命中项进入新归因。预览明确“复用 / 新增 / 非该对象问题”的数量后启动。

“非该对象问题”是当前对象版本的一条归因结论，不修改 bad case 本身，也不影响该 bad case 对其他对象的潜在关系。运行详情需保留潜在集快照、缓存命中和策略版本，确保历史可重放。

### 5.6 工作空间与上报管理

全局管理员可创建空间并设置 bad case 总量上限；全局管理员和空间管理员可调整当前空间额度、管理成员和角色。成员列表展示账号、姓名、空间角色、加入时间和操作，空间管理员可新增普通成员或只读成员，并按产品授权边界任命其他空间管理员。

上报接入页展示空间专属 `POST /api/workspaces/{workspaceId}/bad-cases`、凭据创建/轮换、额度使用和请求示例。请求体沿用 `bad_cases` 领域类型，空间身份只从 URL 与服务端凭据解析，不信任 body 中的 `workspaceId`。额度在写入事务内校验；达到上限返回明确错误，前端展示额度与失败原因，不自动丢弃旧数据。

## 6. 数据与契约迁移边界

- `workspaces`：名称、状态、bad case 上限、创建信息。
- `workspace_members`：工作空间、用户、角色；唯一约束防止重复成员。
- `workspace_ingest_credentials`：只存凭据摘要，支持轮换和撤销。
- `session_families`、`bad_cases`、`evolution_targets`、`evolution_runs`：增加空间归属与必要索引。
- `bad_case_attributions`：以 bad case + 对象版本 + 策略/模型版本组织多次分析，保存结论、非对象原因、来源 run、创建时间；现有 `bad_case_analysis` 通过迁移或适配层保留读取能力。
- `evolution_run_candidates`：保存一次运行关联的 Session、潜在 bad case、触发点证据、缓存命中与策略快照。

上报 body 复用 bad case 契约，但所有读 API 必须由服务端追加工作空间约束。前端 query key 同样以 `workspaceId` 开头，切换空间时不得复用旧空间缓存。

## 7. 推荐迁移顺序

1. **空间底座**：补 membership、空间路由与数据归属；旧空间数据迁入一个明确的默认空间，旧路由重定向。
2. **上报与总览**：增加空间上报、额度和统计/分页 API；复用现有 bad case 展示组件。
3. **Session 与错误详情**：默认 10 条、精确查询和多归因集合；保留旧问题描述与执行流组件。
4. **自进化归因编排**：实现 Session 关联、触发点证据、策略版本和缓存键，再切换启动向导。
5. **权限收口**：所有读写在服务端校验空间角色，前端隐藏入口只作为体验优化；补充跨空间 403/404 和缓存隔离测试。

## 8. 原型范围

原型提供总览筛选与分页下钻、最新 10 个 Session 与回车搜索、bad case 多归因折叠/分页、三步自进化向导、空间创建/编辑/成员/上报弹窗，以及管理员/普通用户视图切换。真实权限、持久化、统计计算、接口鉴权和归因算法均不在原型中实现。
