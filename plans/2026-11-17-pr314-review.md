## §2 架构导览

### 2.1 一个 app、两个空间、四种角色

`apps/api/tests/v2_acceptance_support.py` 提供 `acceptance_api`：迁移好的 SQLite、`create_app` 的真实 lifespan、`httpx.ASGITransport`。`seed_identity` 同时插入全局用户、空间成员与 bearer；`Matrix` 把空间 A/B、四个角色、凭据与 run id 收成一份不可变事实。这里没有 mock app，权限走真实 `require_workspace_role` 依赖，因此 404/403 的差异来自产品代码而不是测试桩。

### 2.2 安全矩阵是“端点 × 角色”的笛卡尔积

`READ_PATHS` 列出 V2 的 13 个读取面（Session、bad case、归因、总览四端点、targets、runs、成员、凭据），`READ_ALLOWED` 明确每个角色能看到哪些面，`READ_MATRIX` 展开成 52 个读取断言；写面再按“viewer/member 全 403、space_admin 不能授予/编辑 space_admin、global admin 全通过”分组。表驱动让新增端点时的缺口一眼可见，代价是文件行数。

### 2.3 三处潜在数同源

`test_v2_potential_consistency.py` 只种一个 target、一个版本和一个时间窗，然后分别调用：

1. `POST /evolution/preview/potential` 的 `summary.potential` 与 `total`；
2. `GET /overview/targets` 的 `summary.potential` 与首个对象 `potential`；
3. 跑完整 `EvolutionPrepareService` 后 `evolution_run_candidates` 的 `included` 数。

三者必须都等于 `POTENTIAL`。第二个用例先跑一次归因，再用同一个 preview 断言 `reused == potential`，并在第二次 prepare 中用一个会计数的 engine 证明零调用；最后断言 `non_target` 有 probe 与 case 关联、但 `list_clusterable_probes` 不含它。这条用例是 15 §8 里“三处数量一致 + 缓存复用 + 非该对象”三条验收的合并证据。

### 2.4 迁移/重放/SSE 的证据分层

`test_fresh_sqlite_upgrades_to_head_with_v2_schema` 从 Alembic `ScriptDirectory` 取 head，不硬编码版本；`_snapshot` 反射表/列/索引，逐项断言 V2 的 workspaces 三表、`evolution_run_candidates`、`bad_case_analysis` 的 `(case, probe)` 唯一约束、`agents.tree_index` 与 `agent_events` 的 revision/triggered_at/knowledge 列。`test_mysql_upgrades...` 用同一组断言跑配置好的 MySQL，CI 通过 `test:db:mysql` 触发。

重放用例构造一个 root session：显式 Skill（tag revision）、带 tool result 的 Agent（authoritative）、不带 result 的 Agent（derived）、知识库 Read（digest）。断言三类事件、父子关系和 revision 都落库；再重放一次断言 imported=0 且行数不变。SSE 用例用 `POST /events/ticket` 取票、消费一次、再放回同一张票得到 401 `TICKET_INVALID`。

### 2.5 浏览器旅程是“同一条数据链的两端”

E2E 的 `before` 用 `fixtures:seed` + `m10_05_seed.py` 准备 demo corpus 与 `synthetic-review@synthetic-1` 触发点，然后启动带 `DeterministicGitRemote` 的真实 FastAPI 与 Vite。测试先通过 API 登录、改密、创建验收空间（quota=3）、凭据和在空间内的 target；随后在浏览器里真实登录，走上报接入 Tab、总览、Session、错误详情、向导、cluster-only run、run 详情、lane DAG 与结构树。关键数字（3 个 case、2 个 potential、quota 3/3）同时被 API 与 DOM 断言，避免“截图好看但事实不对”。

### 2.6 cluster 预览：从列表缓存到单 run 详情

`ClusterPreview` 原来 `useEvolutionRuns` 取整页列表并 `find` 当前 run；列表缓存 staleTime 30 秒且页面不轮询，cluster-only run 完成后页面仍停在 `preparing`。改为 `useEvolutionRunDetail(workspaceId, runId, { refetchInterval: runDetailRefetchInterval })`：活动 run 15 秒刷新、blocked 5 秒、终态停止。`run` 直接取详情，模板字段（target/window/status/progress）全部兼容；run 列表不再成为这个页面的隐式依赖。

## §3 数据流走查：一次 m11-05 冒烟

1. 临时目录执行 `fixtures:seed`，再写 `synthetic-review` 的 tag 与触发坐标；启动真实 FastAPI（确定性 git remote）与 Vite。
2. API 登录 admin → 改密 → 刷新 cookie；读取 `/auth/session` 拿 userId。
3. 创建 `M11-05 验收空间`（quota=3，自己为 space admin），创建凭据，创建空间内 target。
4. 浏览器匿名打开 `/workspaces/<lab>/overview` → 重定向 `/login?redirect=...`；填表登录，进入壳层。
5. 打开 `/admin?tab=ingest`，断言上报地址与至少一条凭据；截图。
6. 用凭据连续上报 3 个 case：前 3 次 201 且 `workspaceUsed=1/2/3`；重报第 1 个 200 且 used 仍为 3；第 4 个新 id 409。API 断言完成后刷新总览。
7. 总览 bad case 视角显示 3；对象视角显示 1 个对象、2 个潜在 case；Session 列表只含 1 个 Session，输入 root id 回车后 `?q=` 恢复。
8. 错误详情在 run 之前显示“尚未归因”；打开向导，选 target/version/窗口，Step2 关联 1 个 Session，Step3 2 行潜在 case，Step4 显示潜在/复用。
9. 点“仅聚类”创建 cluster-only run；轮询 API 到 completed，页面通过详情轮询自动从 preparing 变 completed。
10. 打开 run 详情：7 个 `data-step-key`，第 5 步显示 2 个问题簇；回到错误详情，归因 Tab 显示 `synthetic-review` 的 `可归因到本对象`。
11. 打开 Session 执行流：默认 lane DAG，切结构树再切回；回到总览切到 `ws-default` 断言 5 个 case，再切回验收空间并刷新断言 3。
12. 全流程收集浏览器 console/exception；除 Vue Devtools 提示外必须为空；按关键步骤截图。

## §6 讨论点

### 6.1 API 套件规模与维护成本

- **位置**：`apps/api/tests/m11-05-v2-cross-stack/test_v2_security_matrix.py:81`
- **现象**：单个测试文件 614 行、94 个表驱动用例，占本 PR 大部分新增行。
- **问题**：新增一个 V2 端点时，如果忘记同时更新 `READ_PATHS` / `READ_ALLOWED`，矩阵不会自动报警；表本身成为第二份需维护的端点清单。
- **预判**：这是验收快照而非穷举 fuzz；表驱动已经把“漏一个角色”的成本降到一行。可接受当前形态，长期可考虑从 OpenAPI 路由表生成读取面清单，或在端点注册处加契约测试。
- **结论**：待维护者决定是否在本里程碑后引入生成式矩阵。

### 6.2 E2E 与 demo fixture 的耦合

- **位置**：`tests/e2e/m11-05-v2-cross-stack.test.mjs:388`（`fixtures:seed` + `m10_05_seed.py`）
- **现象**：浏览器旅程依赖 demo corpus 的 Session/Agent/事件形状，以及 `m10_05_seed.py` 设置的 `synthetic-review@synthetic-1`。
- **问题**：未来 demo fixture 改标题或触发坐标时，E2E 会以 DOM 文本超时的方式失败，错误信息不一定指向 fixture。
- **预判**：当前用固定 `sessionId`、固定 target/version 和明确断言把耦合集中在 setup；失败时日志会带 API/Vite 输出。可接受，但应在 fixture 变更时把 E2E 当成契约。
- **结论**：暂无代码修复；维护者可在 fixture 变更流程里登记本 E2E。

### 6.3 cluster 预览用轮询而非 SSE

- **位置**：`apps/web/src/pages/evolution/ClusterPreview.vue:20`
- **现象**：run 详情页有 SSE + 15 秒 REST 兜底；cluster 预览只复用 15 秒 REST 轮询。
- **问题**：页面在活动 run 期间最多晚 15 秒看到终态；网络断开时没有 SSE 重连语义。
- **预判**：cluster 预览只关心终态、页面停留短，15 秒足够；为它新增 SSE 订阅会增加 ticket/订阅生命周期复杂度，收益低。终态后轮询停止，不会持续打点。
- **结论**：保持现状；若后续要求秒级完成提示，再引入与 run 详情一致的 SSE 订阅。

### 6.4 MySQL 用例只在 CI lane 生效

- **位置**：`scripts/run-api.mjs:19`、`test_v2_migration_replay_sse.py:173`
- **现象**：本地无 MySQL 时 18 个 mysql 用例 skip；CI 的 `mysql` job 通过 `pnpm test:db:mysql` 执行。
- **问题**：开发者在本地看不到 MySQL 迁移差异，只能等 CI；`--maxfail=1` 会让第一个 MySQL 失败遮住后续用例。
- **预判**：这是既有环境约定，不是本 PR 引入；新增用例沿用了 `HE_DB_URL`/`HE_REQUIRE_MYSQL` 约定。失败时 CI 日志有明确用例名。
- **结论**：接受；若 MySQL 失败频率升高，再拆独立 job 或加本地 docker compose。

### 6.5 冒烟截图不进入仓库

- **位置**：PR 描述与 release 资产
- **现象**：截图、smoke report、report-data 不提交仓库，只作为 PR 的临时 release 资产。
- **问题**：release 资产被清理后，后续维护者只能看到 PR 描述里的结论，无法重放当时的视觉证据。
- **预判**：这是用户明确要求“不要 git 提交代码仓”的直接结果；测试代码和断言仍在仓库，可随时重跑生成新证据。
- **结论**：接受；PR 描述写清资产位置与重跑命令。

## §9 文件级代码分析

### 9.1 `apps/web/src/pages/evolution/ClusterPreview.vue`（M）

**职责**：仅聚类 run 的预览页；只读 run 卡与状态。

**变更形态**：把 `useEvolutionRuns`（整页列表）替换成 `useEvolutionRunDetail`（单 run 快照），并把 `runDetailRefetchInterval` 传给查询。

**关键依赖**：Vue Query 的 `refetchInterval` 支持函数形式，函数拿到最新数据后返回间隔或 `false`；`runDetailRefetchInterval` 已对 `blocked/preparing/running/终态` 分支有单测，因此这里只是接线，不复制状态机。

**旧 vs 新**：

```ts
// 旧：列表缓存里找当前 run，页面不轮询
const { data } = useEvolutionRuns(workspaceId);
const run = computed(() => data.value?.running.find(...) ?? data.value?.history.find(...));

// 新：单 run 详情 + 状态驱动的轮询
const { data } = useEvolutionRunDetail(workspaceId, runId, {
  refetchInterval: runDetailRefetchInterval,
});
const run = computed(() => data.value ?? null);
```

**实现思路**：页面真正需要的不是“列表”，而是“这个 run 的最新快照”；详情端点既满足字段需求，又天然带活动/终态轮询语义。

**检视发现**：无新增缺陷；见 §6.3 的轮询 vs SSE 取舍。

### 9.2 `apps/web/src/pages/evolution/ClusterPreview.test.ts`（A）

**职责**：固定页面数据源与终态渲染。

**变更形态**：新增 138 行单测，MSW 只注册 `GET /evolution/runs/{runId}`，若页面回退到 run 列表会因 `onUnhandledRequest: "error"` 立即失败。

**关键依赖**：Vue Test Utils + Vue Query + MSW；`createAppRouter` 只用于满足 `useRoute`/`useWorkspaceId`，不渲染壳层。
