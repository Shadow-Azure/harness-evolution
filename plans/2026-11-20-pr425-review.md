## 1. 一页速览

**一句话**：让 Session 页的右栏在“内容比视口短”和“执行流分片还没到”时不提前结束，用容器填充和全高占位替代页面背景空白。

**一个比喻**：把右栏想成一只固定高度的杯子。以前杯子里只有半杯水（内容）时，杯子底部就空着；执行流分片未到时连水都没有，只剩杯口一圈标题。这个 PR 做两件事：让最后一个“问题列表”隔层涨满剩余空间；给还没到的执行流先放一个和原型同高的“占位冰格”，不让杯子看起来是空的。

**交付块**：

| 块 | 改动 | 用户可见结果 |
|---|---|---|
| 壳层 | `.session-browser` 用 `100dvh`（`100vh` 回退），补 `min-height: 0` | 文档不滚，两栏各自内部滚 |
| 右栏填充 | `.overview` / `.overview-content` 改纵向 flex，问题列表 `flex: 1 0 auto` | 低内容时列表贴住视口底 |
| 执行流占位 | async loading / error 组件 + 加载 / 失败 / 无数据统一 `.tree-loading` 720px | 首屏不再塌成标题条 |
| 回归 | 1500×837 与 1500×1100 断言并入现有 E2E | 修复前 1100 失败，修复后通过 |

**验证基线**：`pnpm lint:web`、`typecheck:web`、`test:web`、`verify:web-style`、`build`、`verify:flow`、`lint:docs`、`test:gates`、`node --test tests/e2e/m3-session-browser.test.mjs`（4/4）。修复前同一 E2E 在 1100 断言的底部间距为 108.5px，修复后 18px；执行流分片未到时修复前空白 405px，修复后 720px 占位。

## 2. 架构导览

### 2.1 壳层：谁拥有视口高度

`apps/web/src/pages/sessions/Index.vue:778` 的 `.session-browser` 是 Session 页的根。改动前已有 `height: calc(100vh - var(--shell-header-height))` 与 `overflow: hidden`；本次在同一规则内加 `100dvh` 覆盖与 `min-height: 0`（`Index.vue:783-784`）。`100vh` 先声明、`100dvh` 后声明，旧浏览器忽略不认识的单位，保留回退。

滚动归属没有改变：左栏 `.sidebar` 是 `grid-template-rows: auto minmax(0, 1fr)`，列表内部滚动；右栏 `.overview` 是 `overflow-y: auto`。`main.workspace-main` 的 `overflow: hidden` 继续兜住文档高度，所以页面本身不滚。深链错误态 `.overview` 也补了 `min-height: 0`（`Index.vue:893`），避免 grid 项的 auto 最小高度把它撑出视口。

### 2.2 右栏：把“最后一块”变成可拉伸项

`SessionOverview.vue:354` 起把 `.overview` 从普通块改成 `display: flex; flex-direction: column; min-height: 0`，`.overview-content` 从 `display: grid` 改成 `display: flex; flex: 1 0 auto; flex-direction: column; min-height: 0`（`SessionOverview.vue:371`）。关键在 `flex: 1 0 auto`：`grow=1` 让它吃到右栏剩余高度，`shrink=0` 让内容高于视口时不被压扁；`basis=auto` 保留自然高度。

最后一个子项 `.problem-list` 用 `:deep()` 设 `flex: 1 0 auto`（`SessionOverview.vue:379`）。`BadCaseList` 的根是子组件，scoped 样式用 `:deep` 才能命中；`flex-grow` 把剩余高度给列表容器，卡片的 `problem-row-card` 仍按内容高度排列，没有拉伸正文。

整体骨架 / 错误态（`.overview` 的直接子项）与 `.overview-empty` 也补了 `flex: 1 0 auto`（`SessionOverview.vue:363-368`、`597`），保证“没有选中 Session”和“概览加载中”也不会在底部留页面背景。

### 2.3 执行流：异步分片的五个状态

`SessionOverview.vue:22` 原来只有 `defineAsyncComponent(() => import(...))`。当模块还没下载完时，Vue 渲染空内容，`tree-panel` 只剩 `<header>`，这就是生产截图里“问题列表上方 405px 空白”的可复现来源。

本次把 `defineAsyncComponent` 改成带 `loadingComponent` / `errorComponent` / `delay: 0` 的对象形式（`SessionOverview.vue:44-52`）。两个组件都在脚本里用 `h()` 定义，避免新增 SFC 文件：

- `AgentFlowLoading`（`SessionOverview.vue:23`）渲染 `.tree-loading` + `LoadingSkeleton`，`data-testid="tree-loading"`。
- `AgentFlowError`（`SessionOverview.vue:36`）渲染 `.tree-loading tree-loading-error`，提示“加载失败，请刷新页面后重试”。

模板里接口加载与接口失败也包进 `.tree-loading`（`SessionOverview.vue:273-290`）；无数据继续走既有 `.tree-placeholder`。三个分支共用 `.tree-panel :deep(.tree-loading)` 的 `min-height: 720px`（`SessionOverview.vue:561`），窄屏媒体查询降到 420px（`SessionOverview.vue:629`）。

## 3. 数据流走查

1. 用户进入 `/workspaces/:wid/sessions/:sid`，`SessionsPage` 挂载；`main.workspace-main` 高度 = 视口 - 顶栏，`.session-browser` 同样高度，文档高度被锁定在视口。
2. 左栏 `useSessionList` 返回 4 个 fixture 卡片；右栏并行发起 summary / tree / bad-cases 三个 query。
3. tree 数据到达前，`treeLoading` 为真，右栏显示 720px `.tree-loading` 骨架；summary 到达后标题、统计条出现，右栏内容仍然高于视口，`.overview` 可内部滚。
4. tree 数据到达后，`tree` 为真，渲染 async AgentFlow；分片未到时 `AgentFlowLoading` 出现，仍占 720px；分片到达后 LaneDag 按 `clamp(360px, 48vh, 520px)` 渲染，右栏内容高度回落，`.overview` 的滚动范围随之收缩。
5. 问题列表数据到达后，`BadCaseList` 渲染 1 条问题卡。1500×837 下内容总高 835px，`.overview` 客户区 781px，滚到底时问题列表底边 819px，距视口底 17.75px；1500×1100 下右栏客户区 1044px，问题列表被 `flex-grow` 拉到 254.56px 高，底边 1082px，距视口底 18px。
6. 整个过程中 `document.scrollingElement.scrollHeight` 始终等于 `innerHeight`（837 / 1100），没有窗口级滚动条。

- **结论**：（留空）

### D2 1500×1100 下问题列表卡片被拉高

- **位置**：`apps/web/src/pages/sessions/components/SessionOverview.vue:379`
- **现象**：问题列表容器 `flex: 1 0 auto` 在高视口下变成一张 254px 高的白卡，单条问题卡上方只占 113px，其余是卡内空白。
- **问题**：这是否比原来的页面背景空白更差？
- **预判**：issue 的修改方案明确要求“让最后一个区块（问题列表）占满剩余高度；不要把空白留给页面背景”，且非目标只禁止拉伸问题卡正文，不禁止拉伸列表容器。视觉上白卡比灰底更像“面板”，但仍有空感；如果后续要更自然，可把剩余高度给执行流画布（需要 LaneDag 支持 flex 高度），那是另一个内容重排决策。
- **结论**：（留空）

### D3 720px 占位导致首屏高度回缩

- **位置**：`SessionOverview.vue:561`、`629`
- **现象**：低内容首屏执行流占位 720px，分片到达后 LaneDag 是 401px（48vh@837），右栏内容高度从约 1124px 回落到 835px，页面内部有一次高度回缩。
- **问题**：是否应该把占位改成与最终画布同高，避免布局跳动？
- **预判**：占位的目的就是“在不知道最终高度时保留原型量级的空间”；如果占位只有 401px，分片失败或慢时又会出现 300px 级空白，回到 issue 的症状。回缩发生在分片到达的一次性瞬间，且不改变文档滚动；接受为代价。若后续引入 CLS 预算，可再评估 `min-height` 与骨架淡出。
- **结论**：（留空）

### D4 生产整页滚动没有复现

- **位置**：PR 描述“已知限制”
- **现象**：生产截图显示窗口级滚动、两栏标题滚出视口；当前 main 的合成 Session 文档高度始终 = 视口，无法复现。
- **问题**：这是否说明本 PR 没有修复用户上报的问题？
- **预判**：本 PR 修复的是当前 main 可复现的两个缺口（异步分片塌陷 405px、高视口底部空白 108.5px）；生产截图的整页滚动仍可能是构建版本、滚动位置或别的全局样式导致。需要部署侧确认生产 commit 并采集 computed height；PR 没有声称已复现该整页滚动。
- **结论**：（留空）

### D5 右栏滚动范围与内容底边的关系

- **位置**：`SessionOverview.vue:371-379`
- **现象**：1500×837 下问题列表底边 873px，但 `.overview.scrollHeight` 是 835px，看起来像少了 38px。
- **问题**：是否有内容被裁掉？
- **预判**：835 = 内容底边相对 `.overview` 顶部的 817px + 底部 padding 18px；滚到底（scrollTop 54）后列表底边 819px，距视口底 17.75px，没有裁切。`scrollHeight` 是相对容器顶部的滚动内容高度，不是绝对坐标。
- **结论**：（留空）

## 9. 文件级代码分析

### 9.1 `apps/web/src/pages/sessions/Index.vue`

职责一句话：Session 浏览页的壳层与两栏布局。本文件只改 CSS，前身是 `main` 的 778-785 行。

旧：

```css
.session-browser {
  height: calc(100vh - var(--shell-header-height));
  overflow: hidden;
}
```

新：

```css
.session-browser {
  height: calc(100vh - var(--shell-header-height));
  height: calc(100dvh - var(--shell-header-height));
  min-height: 0;
  overflow: hidden;
}
```

这在做什么：`100dvh` 跟随移动端动态视口，避免浏览器工具栏收起时 `100vh` 比可视区高；`min-height: 0` 解除 grid 项默认的 auto 最小高度。右栏兜底 `.overview` 也补 `min-height: 0`。

实现思路：不碰全局 `body` 和 `main.workspace-main`，只在 Session 页根节点约束高度。

检视发现：无。`100dvh` 与 `100vh` 双声明是标准回退写法。

### 9.2 `apps/web/src/pages/sessions/components/SessionOverview.vue`

职责一句话：右栏的标题、统计、执行流与问题列表容器。变更是脚本（异步组件）、模板（加载/失败包层）和样式（flex 填充 + 占位）三处。

旧：

```ts
const AgentFlow = defineAsyncComponent(
  () => import("../../../components/agent-tree/AgentFlow.vue"),
);
```

新：

```ts
const AgentFlow = defineAsyncComponent({
  loader: () => import("../../../components/agent-tree/AgentFlow.vue"),
  loadingComponent: AgentFlowLoading,
  errorComponent: AgentFlowError,
  delay: 0,
});
```

这在做什么：分片下载期间渲染全高骨架，下载失败渲染失败提示；`delay: 0` 让骨架立即出现，而不是默认 200ms 内的空白。

旧：

```css
.overview { overflow-y: auto; padding: 18px 20px; }
.overview-content { display: grid; gap: 14px; }
```

新：

```css
.overview {
  display: flex;
  flex-direction: column;
  min-height: 0;
  overflow-y: auto;
  padding: 18px 20px;
}
.overview-content {
  display: flex;
  flex: 1 0 auto;
  flex-direction: column;
  gap: 14px;
  min-height: 0;
}
.overview-content > :deep(.problem-list) { flex: 1 0 auto; }
```

这在做什么：把右栏变成可分配的纵向空间；内容不足时列表容器吃剩余高度，内容超出时列表不缩、右栏滚动。

实现思路：只动容器，不动 `BadCaseList` 的卡片和正文。

检视发现：D2 的“卡内空白”是这一行 `flex: 1 0 auto` 的直接结果；D5 的滚动高度已实测无裁切。两者都不需要代码修复，留给用户拍板。

### 9.3 `tests/e2e/m3-session-browser.test.mjs`

职责一句话：Session 浏览器的真实浏览器回归。新增断言并入首个用例，位置在键盘检查之后、移动端检查之前（约 425-522 行）。

- 点击 fixture 的最小会话卡片 `10000000-0000-4000-8000-000000000004`（不整页 reload，避免 refresh cookie 轮换导致的二次登录）。
- 切到“执行序 DAG”（首个用例用 `defaultToTree` 把默认视图设为结构树，断言前必须切回 DAG，才能匹配 1100 视口的填充测量）。
- 1500×837：`documentScrollHeight === innerHeight`；`.session-browser`、`.sidebar`、`.overview` 底边 = `innerHeight`；`scrollTop=1e6` 后问题列表底边距视口底 0–24px。
- 1500×1100：`scrollTop=0`，问题列表底边距视口底 0–24px（修复前 108.5px，失败）。
- 最后保留原有的 `violations` 断言。

检视发现：没有拆成独立 `test()`，因为该文件前面的用例会消耗登录限流额度，额外 `loginCookie()` 会拿到 429；并入首个用例是当前测试设施下的最小改动。已在 issue 的验证命令里改用整文件运行。
