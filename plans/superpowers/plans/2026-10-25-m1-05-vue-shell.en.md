# Vue 3 Application Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the React bootstrap with a testable Vue 3 shell, shared data layer, design tokens, and frontend quality gates.

**Architecture:** The Vue app mounts a Pinia/root query/router assembly. `/sessions` stays the synchronous default shell page, while `/evolution` is route-level lazy and imports the Vue Flow vendor entry. A shared HTTP + query layer exposes the canonical health contract.

**Tech Stack:** Vue 3, vue-router 4, Pinia 3, @tanstack/vue-query 5, @vue-flow/core 1.x, Vite, vue-tsc, ESLint 9, Vitest/Vue Test Utils with V8 coverage.

**Spec:** [plans/fullstack-design/03-frontend-architecture.md](../../../plans/fullstack-design/03-frontend-architecture.md), [plans/fullstack-design/08-frontend-implementation.md](../../../plans/fullstack-design/08-frontend-implementation.md), `.agents/flow/issues/m1-05-web-shell.md`

## Global Constraints

- First-screen JavaScript must not contain Vue Flow.
- The non-default route must be lazy-loaded.
- `tokens.css` is the only color source; components may not hard-code colors.
- Front-end coverage floors are 80% for branches, functions, lines, and statements.
- MSW remains test-only; runtime code has no mock branch.
- PR and commits reference GitHub issue #28.

## Review Focus

- A slow or failed `/api/health` must keep the shell mounted and render a stable status, not an unhandled rejection.
- `/evolution` must remain reachable after reload and dynamically load Vue Flow.
- A missing Vue Flow vendor chunk must fail the bundle gate rather than silently passing.
- Hard-coded component colors must fail lint.
- Removing React sources must leave the cross-stack proxy healthy.
