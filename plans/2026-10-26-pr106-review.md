## §1 一页速览

一句话：Session 选中后，右栏不再显示静态占位，而是独立请求扁平 Agent 树，并在数据到达后用懒加载 Vue Flow 画出可折叠、缩放、定位的执行流。

生活化比喻：Session 列表像档案柜，详情接口是目录摘要，树接口才是打开文件夹后抽出的组织架构图；Vue Flow 是只在真正打开文件夹时才搬来的制图桌。

| 交付块 | 结论 |
|---|---|
| tree 查询和缓存键 | 正确，与 session list/detail 前缀兼容 |
| 加载、空、失败与重试 | 独立于列表和概要 |
| Vue Flow 懒加载 | 通过 build manifest 与 bundle gate |
| 四 Session 真实浏览 | 4 棵树共 8 节点，E2E 通过 |
| 缩放、折叠、键盘、定位 | 均真实浏览器通过 |
| 原型视觉 | 单层树面板、左下角图例、720px 画布，符合已实现范围 |
| 键盘焦点模型 | 有一处双重 Tab 停点，建议修复 |

## §2 架构导览

`getSessionTree()` 对 session id 做编码后请求 `/api/sessions/{sid}/tree`，不会把用户输入直接拼成未转义路径。[sessions.ts](../../apps/web/src/api/sessions.ts:51)

`queryKeys.sessionTree()` 位于 `["sessions", ...]` 前缀之下，因此现有 sync 完成后的 session 缓存失效会同时覆盖列表、详情和树。[queryKeys.ts](../../apps/web/src/api/queryKeys.ts:12)

`useSessionTree()` 复用与其他 Session 查询相同的 Vue Query 生命周期，并在无选中 Session 时禁用请求。[useSessions.ts](../../apps/web/src/composables/useSessions.ts:41)

页面把三个查询独立接入：列表失败不隐藏可用详情，详情失败不被树结果覆盖，树失败只在树面板显示重试。[Index.vue](../../apps/web/src/pages/sessions/Index.vue:66) [SessionOverview.vue](../../apps/web/src/pages/sessions/components/SessionOverview.vue:166)

`AgentTree.vue` 仍由 `defineAsyncComponent` 路径引入，生产构建把 Vue Flow 和 AgentTree 放在独立 chunk 中。[SessionOverview.vue](../../apps/web/src/pages/sessions/components/SessionOverview.vue:14)

## §3 数据流走查

### Session 首次打开

1. 列表返回后，页面自动选中首项并写入 `/sessions/:sid`。
2. detail 与 tree 各自按 selected id 查询。
3. tree 尚在加载时，右栏显示共享 skeleton，列表仍可操作。
4. tree 到货后才触发动态组件加载并创建 Vue Flow。
5. 节点集合初始化后执行 `fitView`，并保留 padding。

### 节点交互

1. Agent 节点渲染为原生 button，并暴露 `aria-pressed`。
2. Enter/Space 的浏览器默认 click 冒泡到 Vue Flow，触发 `node-select`。
3. 页面记录当前 Session 的 active Agent。
4. `locateAgent()` 用 `setCenter` 将目标节点移到视口中心，并至少保持 0.85 zoom。

### 折叠与窄屏

1. 超过 8 个兄弟节点时，纯布局层产出 collapse 节点。
2. 点击 collapse 后，页面更新 per-session expanded set。
3. 节点集合或容器尺寸变化都会等待 DOM 更新后重新 fitView。
4. 全部展开后，面板标题区提供“收起分支”恢复折叠态。

## §6 讨论点

### D1 节点存在双重 Tab 停点

**位置**：`apps/web/src/components/agent-tree/AgentTree.vue:241`、`apps/web/src/components/agent-tree/nodes/AgentNode.vue:28`

**现象**：Vue Flow 默认 `nodesFocusable=true`、`edgesFocusable=true`，每个 node/edge 外层容器会获得 `tabIndex=0`；节点内容又被改成原生 `button`，同样进入 Tab 顺序。一个节点因此有两个可达焦点，边也会依次进入 Tab 序列。

**问题**：小树尚可使用，大图展开后键盘用户需要经过大量重复 node/edge focus stop，降低执行流浏览效率，与“键盘焦点”验收目标的可用性有落差。

**预判**：保留内层 Agent button 作为唯一节点交互面；关闭 Vue Flow 外层 nodes/edges 的键盘可聚焦行为，或只关闭重复的 node focusability。增加真实 Tab 顺序断言，避免只验证脚本 `.focus()`。

**结论**：已修复（2026-10-26）。AgentTree 关闭 Vue Flow 外层 nodes/edges focusability，仅保留节点内部原生 button 与 collapse button；真实 Chrome 断言外层 node/edge 无 Tab 停点，Tab 只进入 Agent button，Enter 可选择并居中。
