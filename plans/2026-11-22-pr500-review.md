## §2 架构导览

### 2.1 滚动归属来自壳层，不是本页新造

`apps/web/src/App.vue:116-121` 把 `main.workspace-main` 固定为 `height: calc(100vh - var(--shell-header-height))`、`overflow: hidden`，文档本身不滚动；总览页 `.overview-page`、空间管理页 `.admin-page`、运行详情 `.run-detail-page` 都用“页面根节点 `height: 100%; overflow-y: auto`”接过滚动（#362、#423）。列表页此前只复用了 `.evolution-page-frame` 的页宽与内边距（`apps/web/src/styles/main.css:60-65`），根节点只有组件内的 `display: grid; gap: 14px`（`apps/web/src/pages/evolution/Index.vue:165-168`），所以内容超过 732px 后没有第二层滚动可接。

### 2.2 全宽滚动容器 + 对称内边距同时满足两个目标

新增规则在 `apps/web/src/styles/main.css:78-87`：

- `width: 100%` 让节点铺满 `main`，常显纵向滚动条画在窗口右缘，而不是 1080px 内容列的内缘；
- `padding: 20px max(24px, calc((100% - 1080px) / 2 + 24px)) 64px` 在 1408 视口给出左右各 188px 内边距，内容列左边界与修复前相同、宽度 1017px（经典 15px 滚动条）或 1032px（overlay）；
- `height: 100%` 相对 `main` 的固定高度解析，`overflow-y: auto` 让 1366px 内容落在 732px 的滚动视口内。

`left: 0` 与 `margin: 0` 覆盖 `.evolution-page-frame` 的 V1 居中补偿，避免相对定位把全宽节点再推偏。规则放在 `.workspace-main .evolution-page-frame` 两条规则之后，同特异性下由源顺序生效。

### 2.3 640px 断点跟随壳层

`apps/web/src/styles/main.css:89-96` 在 ≤640px 把根节点改回 `height: auto`、`overflow-y: visible`、`padding: 8px 24px 0`。这与 `App.vue:131-137` 的 `main.workspace-main { height: auto; overflow: visible }` 分支一致，避免内外两层滚动条；它只覆盖列表页，不影响对象配置页或其它页面。

## §3 数据流走查

1. 进入 `/workspaces/<wid>/evolution`，`Index.vue` 渲染 `section.evolution-page-frame.run-list-page`，后端返回的 `running` / `history` 分组分别渲染 3 + 5 张卡。
2. 内容高度 1366px（含 20px 上、64px 下内边距）超过 `main` 的 732px；由于根节点现在是 `overflow-y: auto`，浏览器把列表作为唯一滚动容器，`document.scrollingElement.scrollHeight === clientHeight`。
3. 鼠标在列表上滚轮：滚动事件命中 `.run-list-page`，`scrollTop` 从 0 增到 634（最大值），第 8 张历史卡底边从 1357.6px 移到 723.6px，完整进入 788px 视口。
4. 键盘 PageDown / End：先把焦点放在列表内的运行控制按钮（或卡片）上，浏览器把按键滚动作用到最近的滚动祖先，即 `.run-list-page`；`End` 到达 634。
5. 视口缩到 390×844：壳层把 `main` 切到 `height: auto; overflow: visible`，列表根节点同步回到 `height: auto; overflow-y: visible`，文档滚动承担可达性，列表自身的 `scrollHeight === clientHeight`。
6. 视口放大到 1920×1080：列表仍全宽、内容列仍 1080px 框架居中，左右内边距 444px；滚动条仍在窗口右缘。

## §6 讨论点

### D1 键盘滚动需要焦点在列表内

**位置**：`tests/e2e/m5-run-list.test.mjs:769-836`

**现象**：真实浏览器回归在发 PageDown / End 前，先把焦点放到列表内的失败徽章按钮；如果只让 `document.body` 持有焦点（刚打开页面、未点击任何元素），PageDown / End 不会滚动 `.run-list-page`，滚轮与拖动滚动条不受影响。

**问题**：issue 的验收标准把“PageDown、End 能到达最后一张卡”列为必达项。对“打开页面直接按 End”的用户，键盘滚动仍不生效；这是“页面根节点承担滚动”的壳层契约带来的浏览器行为，不是本次 CSS 的回归。

**预判**：与 #423 运行详情的处理一致——页面根节点是滚动容器，键盘滚动作用在焦点所在的滚动祖先；E2E 先点击列表内元素再按键，覆盖了这条路径。若产品要求“body 焦点下也能用 End”，需要给列表加键盘事件转发或在路由进入时把焦点移到页面容器，属于独立的行为变更，建议另开 issue。

**结论**：（留空）

### D2 经典滚动条让内容列右缘内移 15px

**位置**：`apps/web/src/styles/main.css:78-87`

**现象**：headless Chrome 经典滚动条占 15px，1408 视口下内容列宽从修复前的 1032px 变为 1017px；macOS overlay 滚动条下仍是 1032px。左边界 188px 不变。

**问题**：验收写“内容列宽度不外移”，严格测量时经典滚动条会吃掉 15px。

**预判**：这是滚动条从“不存在”变成“常显”的必然占位，issue 已明确给出 1017px 的预期；overlay 平台无变化。无实害，PR 测量表已如实列出。

**结论**：（留空）

### D3 对象配置页仍缺页级滚动

**位置**：`apps/web/src/pages/evolution/targets/Index.vue`

**现象**：对象配置页同样使用 `.evolution-page-frame`，也没有 `height` / `overflow-y`；内容超过首屏时会被 `main` 裁切。

**问题**：同壳层下还有第二个页面存在同类缺陷。

**预判**：issue 明确只修 `.run-list-page`、不顺手改对象配置页；统一两者需要独立验收与回归。保持当前边界，另开 issue 跟踪。

**结论**：（留空）

## §9 文件级代码分析

### 9.1 `apps/web/src/styles/main.css`

职责：全局布局入口，承载工作区壳层下各页面的页宽与滚动约定。变更形态 M。

```css
/* 旧：.workspace-main .evolution-page-frame 只给页宽与内边距 */
width: min(1080px, 100%);
margin: 0 auto;
padding: 20px 24px 64px;

/* 新：列表根节点全宽承担滚动，内边距保持 1080px 框架 */
.workspace-main .run-list-page {
  left: 0;
  width: 100%;
  height: 100%;
  margin: 0;
  padding: 20px max(24px, calc((100% - 1080px) / 2 + 24px)) 64px;
  overflow-y: auto;
}
```

实现思路：不改模板、不加内容容器，用同特异性但更靠后的全局规则覆盖 `.evolution-page-frame` 的页宽/居中；滚动条由全宽节点画在窗口右缘，内容列由对称 padding 保持居中。≤640px 只覆盖高度与 overflow，跟随壳层回到文档滚动。
