## §1 一页速览

一句话：生产轨迹把子 agent 的定义正文藏在“附件里的快照”，解析器以前只翻“快照”本身，现在也会拆附件，并让没有 revision 的子 agent 仍把正文哈希交给父事件。

比喻：以前邮差只查写着“快照”的信封；真实信件却套在写着“附件”的信封里，里面才是 `AGENT.md`。这次让邮差拆开附件信封，并把找到的身份证号贴到父级签收单上——即使签收单上还没有版本号。

## §2 架构导览

### 2.1 Parser 子类只负责“哪种记录算定义”

`ClaudeCodeTraceParser.consume_record` 按 `record.type` 分发；`attachment` 分支原来只提取 Skill listing digest（`claude_code.py:481-490`）。新分支只多做一件事：当 `attachment.type == "prompt_snapshot"` 时，把 `attachment.systemPrompt` 包成既有 `prompt_snapshot` 形状交给 `_record_agent_definition`。这样哈希、`definition_source`、evidence 全部复用原路径，不在 attachment 分支复制一套归一化逻辑。

### 2.2 优先级由共享状态机保证

`ParseContext.set_agent_definition`（`base.py:382-394`）已经规定：一旦来源是 `prompt_snapshot` 或 `builtin`，后续 `api-request-shape` 不能覆盖。attachment 路径传入的来源同样是 `prompt_snapshot`，所以无论 attachment 在前还是 `api-request-shape` 在前，最终身份都是 prompt snapshot；测试覆盖了更难的“shape 在前”顺序（`test_evidence.py:190-200`）。

### 2.3 树组装只补“缺 revision 也要有 hash”

`_apply_agent_revisions` 原来的门禁是 `transcript.agent_revision is None: continue`，导致“有 hash、没 `agentType`”的子 agent 完全进不了传播。现在门禁改为“revision 与 hash 都为空才跳过”（`agent_tree.py:315-317`）；事件匹配后仍优先保留显式 `tag:`，没有 revision 时继续落到最后的 `unknown` 归一（`agent_tree.py:327-344`）。也就是说，`agent_revision` 的 `agentType + isBuiltIn + body hash` 语义没有被改写，变的只是 `definition_hash` 的传播条件。

## §3 数据流走查

1. 平台返回 child envelope，`trajectory.content` 中出现 `type=attachment`、`attachment.type=prompt_snapshot`、`attachment.systemPrompt[0]`。
2. 解析器逐行 `consume_record`，命中 `attachment` 分支，把 `systemPrompt` 交给 `_record_agent_definition`；`_definition_body` 取列表首项，`definition_hash` 做归一化后 SHA-256，写入 `ctx.agent_definition_hash` 与 `definition_source=prompt_snapshot`。
3. finalize 把 hash/source 写入 `ParsedTranscript`；`agent_tree` 为 child 建节点，`_apply_agent_revisions` 找到父 `kind=agent` 事件，写入 `definition_hash`。
4. 父事件若来自显式 `agentVersion`，保留 `tag:<value>`；否则保留原 revision；仍为空时最终写 `unknown`。
5. 持久化层按 `definition_hash` 供 matcher 使用；`parser_version=8` 让已存 payload 在重放时重新归一化。

## §9 文件级代码分析

### 9.1 `apps/api/app/service/acquisition/parsers/claude_code.py`

职责：Claude Code JSONL 的 record 解释、触发事件、证据与链接。变更形态 M。

旧代码：`attachment` 分支只做 `ctx.skill_digests.update(_skill_listing_digests(attachment))`，`prompt_snapshot` 只从顶层 `record["systemPrompt"]` 取正文。

```python
# 旧
if record_type == "attachment":
    attachment = _dict(record.get("attachment"))
    if attachment:
        ctx.skill_digests.update(_skill_listing_digests(attachment))
```

新代码：在同一分支先判断 `attachment.type`，再把 `attachment.systemPrompt` 合成 `{"systemPrompt": ...}` 交给既有 `_record_agent_definition`。

```python
# 新
if record_type == "attachment":
    attachment = _dict(record.get("attachment"))
    if attachment:
        if attachment.get("type") == "prompt_snapshot":
            self._record_agent_definition(
                {"systemPrompt": attachment.get("systemPrompt")},
                "prompt_snapshot",
                ctx,
            )
        ctx.skill_digests.update(_skill_listing_digests(attachment))
```

实现思路：不新增定义解析器，只把新形状适配到旧入口；哈希、来源、evidence 与顶层路径完全一致。

检视发现：无代码缺陷。`_record_agent_definition` 对 builtin 的早返回与 `set_agent_definition` 的优先级是既有行为，新路径没有改变它。

### 9.2 `apps/api/app/service/acquisition/agent_tree.py`

职责：把 child 的 revision/hash 传播到父 `kind=agent` 事件。变更形态 M。

旧代码：`if transcript.agent_revision is None: continue`，没有 revision 就整条 child 跳过，`definition_hash` 永远到不了父事件。

新代码：条件改为 `agent_revision is None and agent_definition_hash is None` 才跳过；匹配事件时仍先保留 `tag:`，再用 child revision 补位。

```python
for transcript in transcripts:
    if transcript.agent_revision is None and transcript.agent_definition_hash is None:
        continue
    ...
    revision = event.object_revision
    if revision is None or not revision.startswith("tag:"):
        revision = transcript.agent_revision or revision
    event = replace(
        event,
        definition_hash=event.definition_hash or transcript.agent_definition_hash,
        object_revision=revision,
    )
```

实现思路：把“revision 是否可构造”与“hash 是否可传播”解耦；matcher 只需要 `definition_hash`，诊断身份仍按原语义。

检视发现：无缺陷。最终 `unknown` 归一保留，显式 tag 优先保留，父事件已有 hash 时不会被覆盖。

### 9.3 测试

`test_evidence.py:178-228` 覆盖 attachment 哈希、优先级、无正文附件；`test_object_revision.py:384-478` 覆盖无 revision 传播、正常 revision、tag 优先。所有断言都在没有生产改动时会失败（前三条依赖 parser 分支，后三条依赖 parser 与 tree 两处改动）。

检视发现：缺少“裸字符串 `systemPrompt`”的显式用例，但 `_definition_body` 已对字符串与列表分支做同一处理，属于共享路径，风险低。真实样本与向导关联仍是人工验收。
