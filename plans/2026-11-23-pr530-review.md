## §1 一页速览

**问题**：生产 `.env` 由 systemd `EnvironmentFile=` 读取；缺少 `HE_JWT_SECRET` 服务拒绝启动，缺少管理员凭据则首次部署没有可登录账号。旧模板按网络、数据、Git 等领域分组，必填与选填混排，操作者要对照 `apps/api/app/config.py` 才知道哪些不能留空。

**做法**：把模板收敛到仓库根 `.env.example`，先列 7 个必填项，再按网络、鉴权、数据库、调度、上游、Git、AI Agent、评测分组列选填项。必填项保持生效赋值，选填项默认在行首加 `#` 注释；每个变量下一行用 `# 必填｜...` 或 `# 选填｜...` 说明值、作用、默认值和约束。

**代价**：路径从 `deploy/` 移到仓库根，历史 `plans/` 快照仍可能提到旧路径；systemd 不支持行尾注释，说明只能独立成行，模板比“一行一个键”更长。

| 交付块 | 内容 |
|---|---|
| 必填 | `HE_PRODUCTION`、`HE_HOST`、`HE_DATA_DIR`、`HE_JWT_SECRET`、`HE_DB_URL`、`HE_ADMIN_USERNAME`、`HE_ADMIN_PASSWORD` |
| 选填 | 其余 `Settings` 字段，含鉴权、数据库调优、任务/SSE、上游、Git、AI Agent、评测、阶段/版本 |
| 注释 | 每个变量下一行是必填/选填说明；选填默认 `#` 注释；不写行尾注释 |
| 链接 | 部署文档、bootstrap、playbook 统一指向根模板 |

## §2 架构导览

配置只有一个事实来源：`apps/api/app/config.py` 的 `Settings`。`.env.example` 是它面向部署操作者的说明层，不参与运行时加载；运行时仍由 systemd 把 `/opt/harness/shared/.env` 注入进程。

```text
apps/api/app/config.py (Settings/默认值/校验)
        │ 人工对照
        ▼
.env.example (必填/选填 + 填写说明)
        │ 复制并填值
        ▼
/opt/harness/shared/.env
        │ systemd EnvironmentFile=
        ▼
harness-api 进程 (Settings)
```

`.env.example` 的赋值行是可直接复制的 `KEY=value`；注释行以 `#` 开头，systemd 会忽略。不能把说明写在赋值行尾，否则 systemd 会把 `#` 后的文字并入值，`HE_HOST`、`HE_DATA_DIR` 等字段会校验失败。

## §3 数据流走查

1. 操作者从仓库根拿 `.env.example`，复制到服务器 `/opt/harness/shared/.env`。
2. 填写必填段：`HE_JWT_SECRET` 用 `openssl rand -hex 32` 生成；`HE_DB_URL` 的 `CHANGE_ME` 换成 `/root/harness-mysql-password.txt` 中的密码；`HE_ADMIN_PASSWORD` 填首次登录密码。
3. 按实际接入取消选填项行首的 `#`：无上游就保持注释；启用 Git 推送取消 `HE_GIT_PUSH_TOKEN`；启用 Claude Code 取消 `ANTHROPIC_API_KEY`；同源部署取消 `HE_CORS_ORIGINS=[]`。
4. systemd 读取 `.env` 注入进程；`Settings` 按字段类型解析，空值走默认或 `None`。
5. 启动校验：`HE_JWT_SECRET` 为空直接失败；`HE_PRODUCTION=true` 时 `HE_DATA_DIR` 必须是绝对路径；`HE_DB_URL` 连不上则在数据库启动阶段失败。
6. 首次启动 `users` 表为空时，用 `HE_ADMIN_USERNAME` / `HE_ADMIN_PASSWORD` 播种管理员；已有用户后这两个值不再生效。

## §6 讨论点

1. **位置**：`.env.example:1-15`（路径与复制方式）
   **现象**：模板从 `deploy/env.production.example` 移到仓库根，旧路径删除。
   **问题**：历史 `plans/` 快照仍引用旧路径；外部书签也可能失效。
   **预判**：常驻文档、bootstrap 与 playbook 已全部改到新路径，历史 `plans/` 是过程快照且不在链接门禁范围；若维护者希望保留 `deploy/` 入口，可在根模板外再加一个转发文件，但会引入第二份路径事实。结论留维护者。

2. **位置**：`.env.example:23-24` 等每个赋值行后
   **现象**：必填/选填说明写在赋值行下一行，而不是行尾。
   **问题**：与用户“每一行在后面写清楚”的字面格式不完全一致。
   **预判**：systemd `EnvironmentFile=` 不支持行尾注释，写在行尾会让注释成为值并导致启动校验失败；独立注释行是可复制模板的必要代价。结论留维护者。

3. **位置**：`.env.example` 全量字段
   **现象**：覆盖 `Settings` 的全部字段（共 88 个赋值，含 4 个非 `HE_` 例外），包含 `HE_PHASE` / `HE_VERSION` 等内部元数据。
   **问题**：模板较长，内部调优项可能分散操作者注意力。
   **预判**：必填段在最前，选填按领域分组；全部字段可避免“配置项只在源码里”的缺口。若维护者只想保留运维常用项，可把内部调优移到独立附录。结论留维护者。
