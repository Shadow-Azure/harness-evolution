## §2 架构导览

### 2.1 RouterLink 不 import 就能用，靠的是 vue-router 的全局注册

`Index.vue` 的 import 区（`Index.vue:2-17`）没有任何 `vue-router` 引入，模板却直接写 `<RouterLink>`（`Index.vue:152`）。这不是 unplugin 的功劳：`vite.config.ts:52-55` 里 `unplugin-vue-components` 只配了 Element Plus 的 resolver（`vite.config.ts:24-42`），没配 vue-router。真正机制是 vue-router 作为插件 `app.use(router)` 安装时会把 `RouterLink`/`RouterView` 注册为**全局组件**——好比公司前台本身就认识「快递柜」这个名字，不需要每个部门再自我介绍一次。生产应用在路由入口 use 了 router，测试里也同样把 `createAppRouter()` 实例作为 plugin 传入（`Index.test.ts:53`、`:69`），所以 jsdom 下链接照常渲染成真 `<a href="/evolution">`，单测才能断言 `href`（`Index.test.ts:111`）。同仓库先例：`RunDetail.vue:375` 的返回链接同样未 import（`RunDetail.vue:10` 只引了 `useRoute/useRouter`）。

### 2.2 为什么是 `to="/evolution"` 而不是「后退」

这是本 PR 唯一像设计决策的地方（Note md:13）：`router.back()` 像电梯的「上一层」按钮——用户若是直接粘贴 URL 或新标签打开配置页，历史栈是空的，「上一层」无处可去。显式 `to="/evolution"` 则永远是「回一楼」，行为与进入路径解耦。代价：如果将来从 Session 页深链进来，点它也是回自进化页而不是回 Session——Note 已明确接受这个语义（Note md:21「单一语义」）。

### 2.3 链接放在页面骨架而非数据分支

链接位于 `<section class="evolution-page-frame">` 的第一个子元素（`Index.vue:148-158`），不在 `v-if` 数据分支里，所以空态、读取失败态都仍可见；这靠的是它在模板里先于 `header.page-intro`（`Index.vue:159`）与 `TargetTable`（`Index.vue:176`）。样式上 `.back` 用的是设计 token 变量 `--text-dim` / `--blue`（`Index.vue:203`、`:210`），过了 `verify:web-style` 的颜色源约束。

### 2.4 E2E 的就绪信号选择

返回点击后，E2E 用 `waitForDocument` 轮询两个条件的合取（`m5-target-config.test.mjs:870-875`）：路径回到 `/evolution` **且** `open-launch-wizard` 按钮存在。该按钮在 `/evolution` 页头骨架里（`apps/web/src/pages/evolution/Index.vue:63-70`），与数据加载无关（骨架屏只替换列表区），所以信号稳定；但它的语义是「自进化页就绪」借用了「向导按钮」这个业务元素，见 §6-2。

## §3 数据流走查（端到端剧本）

1. 用户在 `/evolution` 点「进化对象配置」进入配置页（E2E 剧本里是经向导提示链接 `wizard-target-config-link`，`m5-target-config.test.mjs:853-865`）。

4. 真实浏览器里 E2E 用 CDP `Runtime.evaluate` 点击该链接（`m5-target-config.test.mjs:866-869`），vue-router 接管 click 做客户端导航。
5. `waitForDocument` 轮询 CDP 直到 `location.pathname === "/evolution"` 且 `open-launch-wizard` 在文档中（`m5-target-config.test.mjs:870-875`；轮询实现 `tests/support/runtime.mjs:285-294`）。

## §6 讨论点

### 6-1 单测只断言 `href`，未驱动真实点击导航

- **位置**：`apps/web/src/pages/evolution/targets/Index.test.ts:102-115`
- **现象**：单测挂了真实 router（`Index.test.ts:53-55`），却只断言链接属性，不 `trigger("click")` 后断言 `router.currentRoute`。
- **问题**：jsdom 环境下点击 `RouterLink` 实际能完成客户端导航（vue-router 用 `history.pushState`，jsdom 支持），也就是说「点击真的导航」这一层在单测里可测而未测，目前只由 E2E 兜底。
- **预判**：属可加强而非缺陷——E2E 已覆盖真实点击（`m5-target-config.test.mjs:866-875`），本 PR 变更极小，加两行断言是锦上添花。可留给后续顺手改。
- **结论**：✅ 已采纳修复 2026-10-30——用例改为以 stub RouterLink（点击即 `$router.push(to)` 的真 `<a>`）驱动 `trigger("click")`，断言 `router.currentRoute` 落到 `/evolution`，并补 `getComponent(RouterLink).props("to")` 断言（同 `TargetConfigEntry.test.ts` 惯例）。

### 6-2 E2E 借 `open-launch-wizard` 当「自进化页就绪」信号

- **位置**：`tests/e2e/m5-target-config.test.mjs:870-875`
- **现象**：返回导航的就绪条件是 `pathname === "/evolution" && document.querySelector("[data-testid='open-launch-wizard']")`；该 testid 本义是「启动向导」按钮（`apps/web/src/pages/evolution/Index.vue:66`），不是页面就绪探针。
- **问题**：语义耦合——若将来按钮改名、加权限门控或移入数据分支，这条等待会失败，且失败信息（"target config back navigation"）不会指向真实原因。仓库其他处有更骨架级的信号可用，如本文件自己的 `waitForTargetConfigPage` 用的 `h1` 文案探针（`m5-target-config.test.mjs:130-136`）或 `data-testid='evolution-run-list'`（`apps/web/src/pages/evolution/Index.vue:56`）。
- **预判**：当前无实害——按钮在页头骨架层、不受数据/角色影响，信号稳。建议修法：合取条件改为 `pathname === "/evolution" && h1 === "自进化"` 或加 `evolution-run-list`，一行改动，可与 6-1 同批处理。
- **结论**：✅ 已采纳修复 2026-10-30——就绪探针改为 `pathname === "/evolution" && document.querySelector("h1")?.textContent === "自进化"`（`/evolution` 页 h1「自进化」位于页头骨架层，与业务按钮解耦）。

### 6-3 采集脚本是一次性脚本永久入库，无 README 说明其用途

- **位置**：`reports/2026-10-30/issue-151-back-entry/collect-before.mjs`
- **现象**：`reports/` 下采集脚本入库有充分先例（`reports/2026-10-29/issue-165-bad-case-title/collect-before.mjs`、`reports/2026-10-27/m5-03-target-config-ui/collect-smoke.mjs` 等），目录不属语料、无预算/双语门禁，本 PR 完全沿用既有惯例，合规。
- **问题**：唯一可议的是该目录历来没有 README 解释「reports/ 是各 PR 的人工采证存档、脚本是可复跑的证据链」这一定位；新访客看到 `collect-before.mjs` 名字会以为还有 `collect-after.mjs`，实际「after」证据是改后 E2E 与截图，没有独立脚本。

### 9.1 apps/web/src/pages/evolution/targets/Index.vue（M）

**职责**：进化对象配置页——列表查询、增删改启停、编辑对话框的容器页面。本 PR 变更形态 M：模板头部插入返回链接 + scoped 样式追加 `.back` 块，script 区零改动。

**关键依赖解读**：`vue-router` 是 vue 官方第一方路由库，构建期随 vendor-vue chunk 打包（`vite.config.ts:82`）、运行时全局加载。`RouterLink` 在本文件的角色是「渲染成真 `<a>` 并拦截点击做客户端导航」的声明式出口；比喻：它是路牌本身，而不是导航员——路由器（router 实例）才是导航员，路牌只声明目的地。由于 vue-router `install` 时全局注册该组件，本文件无需 import 即可在模板使用（§2.1）。

**变更代码块对照**（旧版取 `git show main:apps/web/src/pages/evolution/targets/Index.vue`）：

```
旧（main）模板开头：
<section class="evolution-page-frame target-config-page" data-testid="target-config-page">
  <header class="page-intro">          ← section 直接以页头开场，无返回口
```
```
新（本 PR）Index.vue:148-158：
<section class="evolution-page-frame target-config-page" data-testid="target-config-page">
  <RouterLink class="back" data-testid="target-config-back" to="/evolution">
    ← 返回自进化
  </RouterLink>
```
这 7 行在做三件事：① 声明式出口（`to="/evolution"` 让 vue-router 生成正确 href 并接管点击）；② 固定测试钩子（`data-testid`，供单测 `Index.test.ts:113` 与 E2E `m5-target-config.test.mjs:868` 双端定位）；③ 位置贴住 section 顶，先于页头渲染，保证任何数据状态下可见。实现思路总结：抄 RunDetail 先例（`RunDetail.vue:375-380`）的组件、位置、命名三对齐，把新交互压缩成「无新概念」的纯模板变更。

```
新（本 PR）Index.vue:202-211：
.back { color: var(--text-dim); font-size: 12px; text-decoration: none; }
.back:hover, .back:focus-visible { color: var(--blue); }
```
与 RunDetail 的 `.back` 视觉对齐（12px 灰字、hover/focus 变蓝）；特意写了 `:focus-visible` 而不止 `:hover`，键盘用户的反馈不缺位（Note md:19「键盘可达」）。颜色全部走设计 token，过了 `verify:web-style` 的颜色源门禁。

**检视发现**：无缺陷级发现。已知弱点：`.back` 样式在 targets/Index.vue 与 RunDetail.vue 各复制一份（约 8 行 CSS），第三处返回链接出现时值得抽成共享类或组件——当前两处属可接受的重复，无实害。
