## §1 一页速览

**一句话**：把错误详情从「一张错误卡 + 一条 probe 分析」换成「一个 bad case 的活页夹」——每组按对象·版本列出多条归因，每页两条，URL 记录 `case/tab/at`，详情按固定顺序展开。

**比喻**：旧页面像一张只能夹一张报告的透明文件袋；新页面像带目录的活页夹。目录（左栏）按 bad case 分组，每组翻页；抽出一页（归因 tab）能看到结论、触发点对照、推导和边界。`at` 就是页码加行号，刷新后仍能翻回同一页。

| 交付块 | 内容 |
|---|---|
| 左栏 | 折叠组、筛选 chips、2 条分页、bad case/归因深链 |
| 深链 | `case`、`tab`、`at`；`obj` 原型兼容；非法值统一 `DEEP_LINK_INVALID` |
| 详情 | 结论、分类、对象·版本、run、时间、缓存、置信度、策略、触发点、reason、reasoning、warnings、边界 |
| 空态/权限 | 尚未归因；仅管理员显示就地启动；向导浮窗预填 `focusCaseId` |
| 数据边界 | query key 以 `["ws", wid, "case", ...]` 开头，切换空间重置本地状态 |

**验证基线**：`pnpm test:web`、`typecheck:web`、`lint:web`、`verify:web-style`、`build && verify:bundle`、`verify:flow`、`test:gates`、`verify:docs`、`contract:check` 均通过；E2E `multi-attribution` 与 `m4 error detail` 通过；CI 以最终 head 为准。

## §2 架构导览

### 2.1 URL 是唯一选择源

- `parseSessionDeepLink` 在 `apps/web/src/router/deepLink.ts:222` 把 `at` 和 `obj` 规范化：`at` 只在 `tab=attr` 且存在 `case` 时有效；`obj` 只作为 `at` 未命中时的对象回落。`validQueryText` 允许对象名中的空格，但拒绝控制字符和首尾空白。
- `Index.vue:131` 的 `resolvedIndex` 按 `at → obj → 0` 推导当前归因；`Index.vue:156` 再把索引换算成左栏页码。页面不把「回落到的第一条」写回 URL，避免刷新时改变用户原始深链。
- 选中/切 tab/翻归因都走 `routeQuery`（`Index.vue:269`），统一生成 `case/tab/at`，避免组件各自拼字符串。

### 2.2 两套读取，各自明确

- 左栏组内用 `useAttributionPage`（`composables/useBadCases.ts:79`）按 `pageSize=2` 读当前页；每个展开组只关心自己的页码，缓存键含 `{page,pageSize}`。
- 详情导航用 `useAttributions`（`:121`）读 50 条全集：它先取第一页，按 `total` 有界补页。用途只有一个——定位 `at` 和计算 `N / total`，不替代左栏分页。
- 单条详情用 `useAttribution`（`:161`），只在 `effectiveAttributionId` 存在时启用；选中 case 但无归因时不会发无效详情请求。

### 2.3 组件职责

- `ErrorSidebar.vue:41` 先给完整列表编号，再过滤，保证筛选后 `BC` 编号不跳变；`:61` 在选中 case 或选中归因页变化时自动展开并同步页码。
- `CaseGroup.vue:34` 拥有单个 case 的 page query；`:122` 的计数、`:160` 的空态、`:177` 的分页都在组内闭环。
- `AttributionItem.vue:38` 用 `RouterLink` 直接指向 `case/tab/at`，不依赖父组件点击回调；满足 issue 非目标「不用整行点击代替明确链接」。
- `AttributionReport.vue:123` 之后按 08 §7.3 固定顺序渲染；`:259` 的缓存说明和 `:313` 的边界文案与原型一致。

### 2.4 权限与向导

- `Index.vue:354` 的 `openWizardFor` 先用 `canManageWorkspace` 判定 `space_admin` / `global_admin`；左栏空态和详情空态都只在权限通过时渲染按钮。
- `LaunchWizard` 直接挂在错误详情页（`Index.vue:625`），打开不改变 URL；`onLaunched`（`:365`）在启动成功后失效空间查询并跳运行详情。

## §3 数据流走查

1. 打开 `/workspaces/ws/sessions/sid/errors?case=BC&tab=attr&at=AT`。
2. `parseSessionDeepLink` 校验并得到 `badCaseId/tab/attributionId`；非法值整页 `DEEP_LINK_INVALID`。
3. `useBadCase` 校验 case 归属；跨 Session 409 → 整页「问题不属于当前 Session」。
4. `useAttributions` 拉 50 条全集，`resolvedIndex` 命中 `AT`；`useAttributionPage` 让左栏组展开到 `AT` 所在页。
5. `AttributionItem` 和 `AttributionReport` 共享同一个 `AT`：前者高亮，后者渲染详情。
6. 点「下一条」→ `AttributionReport` emit `select` → `Index.selectAttribution` 更新 `at` → 上述 4–5 重跑；左栏页码随 `selectedAttributionPage` 同步。
7. 点父行 → `routeQuery(case, "desc")` 丢掉 `at`；点「全部 bad case」→ 空 query，详情回到空态。
8. 空归因时 `AttributionReport` 显示「尚未归因」；管理员点 CTA 打开向导浮窗，URL 不变。

## §6 讨论点

### 6.1 归因计数有两套口径

- **位置**：`apps/web/src/pages/errors/components/CaseGroup.vue:122`（组徽标用分页 `total`）；`Index.vue:261`（tab 标题用 `attributionCount`）；`ProblemDescription.vue:103`（只有列表长度等于 `attributionCount` 才显示拆分）。
- **现象**：`BadCase.attributionCount` 是 distinct `(probeType, probeObject, objectVersion)`；归因列表 `total` 是可达关联行数。同一对象版本若有多条 probe 链接，组徽标可能比 tab 标题 / 描述摘要大。
- **问题**：用户会在同一页看到两个「归因数」。当前 demo 数据两者相等，未暴露；真实复用缓存的历史数据可能出现。
- **预判**：这是 m11-01 契约的两种口径，不是本 PR 能单独拍板的后端去重问题；前端已让摘要拆分只在口径一致时出现，但徽标与 tab 仍可能不一致。建议由 m11-01 owner 决定「列表是否按对象版本去重」，或由前端统一成 `attributionCount`。
- **结论**：

### 6.2 `at` 非法回落后 URL 保留旧值

- **位置**：`Index.vue:131` 的 `resolvedIndex` 与 `deepLink.ts:222`。
- **现象**：`at` 语法合法但该 case 已没有这条归因时，详情回落到第一条，地址栏仍保留旧 `at`。
- **问题**：刷新会重复回落；用户复制链接会继续带着不存在的 `at`。
- **预判**：设计明确要求「at 命中用它 → 回落第一条」，但没有说是否 canonicalize URL。自动改写会改变深链，可能影响外部引用；倾向保留现状，在详情页显示回落结果即可。
- **结论**：

### 6.3 页码 2 在页面层硬编码

- **位置**：`Index.vue:158` 的 `Math.floor(resolvedIndex.value / 2) + 1`；`CaseGroup.vue:31` 的 `pageSize = 2`。
- **现象**：两处都假设每页 2 条；未来改分页大小时需要同步改。
- **问题**：维护性风险，不是功能缺陷。
- **预判**：可以抽一个共享常量，或在 `CaseGroup` 暴露 pageSize；本 PR 不阻塞。
- **结论**：

### 6.4 Demo fixture 的 repo_url 不可达

- **位置**：`tests/e2e/support/m11_02_attribution_seed.py` 不改 evolution target；冒烟环境沿用 corpus 的 `https://example.invalid/example/skills.git`。
- **现象**：就地打开向导时 catalog 读取失败；把临时 DB 的 target 指向本地仓库后正常加载并显示 focusCase。
- **问题**：这是 demo 数据限制，不是 m11-02 代码缺陷；真实空间配置有效仓库即可。
- **预判**：保持 fixture 不动；冒烟报告记录这一限制，m10-05 已有有效 repo 的向导覆盖。
- **结论**：

### 6.5 执行流仍按选中 case 过滤

- **位置**：`Index.vue:176` 的 `flowTree`。
- **现象**：选中 case 后只保留该 case 的 finding；设计 §7.2 要求保留全部并发分支。
- **问题**：这是 m11-02 交付边界明确留给 m11-07 的行为，不是遗漏。
- **预判**：m11-07 落地 lane DAG 时一起改；本 PR 不改。
- **结论**：

## §9 文件级代码分析

### 9.1 `apps/web/src/pages/errors/Index.vue`（M）

职责：把 URL 变成选择状态，把多个 query 组合成页面，挂载向导。变更核心是删除 `useBadCaseAnalysis/useProbe`，新增 `useAttributions/useAttribution` 与 `selectedAttributionPage`。

- 检视发现：页码 2 硬编码（§6.3）。

### 9.2 `ErrorSidebar.vue`（M）

职责：筛选、展开集合、每 case 页码。旧文件只是 `BadCaseList` 的壳；新文件自己持有交互状态。

- 检视发现：无阻塞问题。

### 9.3 `CaseGroup.vue` / `AttributionItem.vue`（A）

职责：单个 case 的折叠体与单条归因链接。

- `CaseGroup` 用 `pageRequest` 在折叠时把 page 置 0，天然停掉请求；展开时按 `pageSize=2` 取页。

- 检视发现：组徽标与 tab 计数口径来自不同字段（§6.1）。

### 9.4 `AttributionReport.vue`（M）

职责：重写单条 probe 报告为多归因详情。旧文件只有 `analysis/probe` 两态；新文件有 `attribution/empty/error/loading` 四态。

- 结论横幅区分 `attributed` 与 `non_target`，后者不渲染分类 chip。

- 前后切换只 emit `select`，URL 仍由 Index 统一改；避免组件自己 `router.push`。
- 检视发现：无阻塞问题；`reportError` 对列表/详情共用一条文案，属可接受的简化。

### 9.5 `ProblemDescription.vue`（M）

职责：问题描述 tab 不再展示旧五态 chip 和单 probe report link；新增归因摘要按钮。

- 摘要只在列表长度等于 `attributionCount` 时展示拆分，避免两个口径混用。
- 保留 facts、关联对象、degraded 诊断；标题/正文两级不变。
- 检视发现：按钮文案较长，窄屏会换行；当前 340px 侧栏与详情宽度下可接受。

### 9.6 `api/badCases.ts` / `useBadCases.ts` / `queryKeys.ts`（M）

职责：新增分页列表、单条详情与全集读取。

- `getAttributionPage` 默认 `pageSize=2`，`getAttribution` 编码 case/attribution 两段路径。
- `useAttributions` 以 50 为上限补页，注释明确「只为详情导航」；`useAttribution` 在无 id 时禁用。
- query key 以 `ws` 开头，`attributionPage` 还带 `{page,pageSize}`，避免页间串数据。
- 检视发现：50 与 2 都是散落常量，后续可与 §6.3 一起收口。

### 9.7 `router/deepLink.ts` / `utils/badCaseId.ts`（M）

职责：把 `at/obj` 纳入统一校验与链接构造。

- `at` 必须与 `case` 同现，且只在 attr tab 生效；`obj` 只做兼容回落。

- 检视发现：`obj` 允许空格是刻意的（对象名可能是自然语言）；控制字符仍被拒。
