## 一页速览

**问题**：归因列表只渲染 `objectVersion`。当它只有 `digest:<sha256>` 时，71 字符版本在窄侧栏不可收缩，把对象名挤成 0 宽并压住 badge。

**做法**：API 从深链所指 run 回填 `objectRef` / `objectCommit`；前端优先显示 ref + 短 commit，只有 digest 时截断兜底。版本区可收缩，悬停/聚焦在页面上方显示完整值，旁边复制按钮复制 commit 优先、digest 兜底。

**代价**：`AttributionItem` 的根节点从 RouterLink 变成 `div` + 透明 `.attr-link`，E2E 和任何依赖根节点 `href` 的测试都要跟着改；API 查询多一次 `evolution_runs` outer join。

## 架构导览

```text
attribution list query
  probe_reports ──(last_reused_run_id ?? created_run_id)──▶ evolution_runs
        │                                                     │
        └──────────── object_ref / object_commit ◀───────────┘
                              │
                              ▼
                 AttributionItem contract
          objectVersion + objectRef + objectCommit
                              │
                              ▼
            resolveVersionLabel() → ref / commit / digest
                              │
                              ▼
   VersionLabel.vue：.ver 截断 + .ver-copy + Teleport 浮层
                              │
                              ▼
   AttributionItem.vue：透明整行链接 + 文案层 + badge 列
```

关键分层：SQL 只做一次 outer join，不写库；service 只把 `target_version` 过滤成可读 ref、把 `base_commit` 截成 7 位；前端纯函数决定回退顺序；组件只管 DOM、浮层和剪贴板。

## 数据流走查

1. `AttributionRepository._attribution_statement()`（`attributions.py:930`）在已有 probe 查询上 outer join `evolution_runs`，连接键为 `coalesce(last_reused_run_id, created_run_id)`，取 `target_version` 与 `base_commit`。
2. `AttributionReadService._item()`（`attribution.py:105`）投影 `object_ref` / `object_commit`；`_display_ref()`（`:145`）过滤 `digest:` / `provider:` 与裸 commit，`_short_commit()`（`:157`）截 7 位。
3. 契约把字段暴露为 `objectRef` / `objectCommit`（可空）；`pnpm contract:generate` 生成 OpenAPI 与 TS 类型。
4. `resolveVersionLabel()`（`versionLabel.ts:27`）的优先级：显式 ref/commit → digest → 裸 commit → 裸 ref → 未固定。
5. `VersionLabel.vue` 渲染 `.ver-ref` / `.ver-commit` / `.ver-digest`；`showTip()`（`:27`）把 `<Teleport>` 浮层定位到 `.ver` 上方，`copyVersion()`（`:76`）优先 Clipboard API，失败走 textarea 兜底。
6. `AttributionItem.vue` 用透明 `.attr-link`（`:64`）覆盖整行，文案层 `pointer-events:none` 让点击穿透到链接；`.ver-copy` 提高 z-index 并恢复 pointer-events，避免链接内嵌 button。badge 列（`:92`）改成两行堆叠 + 右下箭头，释放版本行宽度。

## 人工验收

1. 打开 Session 错误查看，展开一个归因数 ≥ 2 的 bad case；有 ref/commit 时版本显示 `ref + 短 commit`，badge 不重叠。
2. 用一份只有 digest 的归因（或 devtools 注入）确认版本截断；悬停/聚焦版本区，浮层显示完整 digest 且不被侧栏 overflow 裁剪。
3. 点复制：按钮短暂变 ✓，剪贴板为 commit（有 commit 时）或完整 digest；点击复制不应触发整行跳转。
4. Tab 顺序：整行链接 → 复制按钮；Enter 打开归因详情。
5. 窄视口（如 1100px）下对象名与版本仍不互相挤压。

## 讨论点

### 1. 显示 run 取复用 run 而非创建 run

- **位置**：`apps/api/app/db/crud/attributions.py:937`
- **现象**：连接键是 `last_reused_run_id ?? created_run_id`，与 `AttributionItem.runId` 的深链目标一致。
- **问题**：复用 run 的 `target_version` 理论上可能与创建时的 ref 不同，即使缓存键相同（body hash 相同）。
- **预判**：显示层跟随深链 run 是自洽的；若维护者要求显示“首次归因的 ref”，需要额外保存创建 run 的版本证据。结论留维护者。
- **结论**：

### 2. 裸 commit 与长分支名的判别

- **位置**：`apps/api/app/service/bad_cases/attribution.py:145`
- **现象**：7–40 位十六进制字符串被当作 commit，不再显示为 ref。
- **问题**：极少数分支名可能恰好是 7–40 位十六进制，会被误判为 commit。
- **预判**：发生率极低，且显示短 commit 仍可读；可接受。结论留维护者。
- **结论**：

### 3. 整行链接 + 复制按钮的键盘与读屏体验

- **位置**：`apps/web/src/pages/errors/components/AttributionItem.vue:64`
- **现象**：根节点是 `div`，`.attr-link` 是空内容 + `aria-label` 的透明链接，复制按钮是独立控件。
- **问题**：读屏只读链接 `aria-label` 与复制按钮标签；视觉文案被 `aria-hidden`，不会重复。需要确认链接的 `aria-label` 是否足够表达时间/缓存状态（当前包含对象名、版本、结论）。
- **预判**：可接受；如需要更完整，可把缓存/时间补进 label。结论留维护者。
- **结论**：

### 4. API 测试只覆盖 ref + commit 分支

- **位置**：`apps/api/tests/m11-01-attribution-read/test_attribution_read_api.py`
- **现象**：新增断言覆盖 `objectRef` / `objectCommit`，digest 兜底与无 run 由前端纯函数/组件测试覆盖。
- **问题**：没有 API 级 digest-only + run 缺失的组合用例。
- **预判**：显示逻辑在前端，前端测试足够；API 的 null 分支可加一条种子。无实害。结论留维护者。
- **结论**：
