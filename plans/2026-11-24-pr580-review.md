## §1 一页速览

一句话：把页面已经读到的归因行折成 `badCaseId → sessionId`，沿 `RunDetail → RunStepContent → StepClusters/StepIterations → StepCaseTable` 下传，让第 5、6 步共用来源表的 ID 重新变成带 Session 的深链。

比喻：归因表是「户口本」，来源表是「公告栏」。以前公告栏只抄了姓名（bad case），没抄住址（Session），所以贴不出可投递的链接；这次把户口本的「姓名 → 住址」对照表递给公告栏。

| 交付块 | 内容 |
|---|---|
| 数据接线 | `caseSessionMap()` + props 下传 |
| 链接语义 | `target=_blank`、`rel=noopener noreferrer`、完整 ID 的 `title`/`aria-label`、`:focus-visible` |
| 视觉 | 蓝色等宽、虚线下划线、指针、悬停实线；无映射降为 `--text-dim` |
| 防回归 | 组件/页面/conformance/E2E 四层 |

验证基线：聚焦测试 77 passed；`src/pages/evolution` 221 passed；typecheck/lint/web-style/flow/docs 通过；`m10-06` E2E 6/6（本地含 1 次既有加载竞态，单测复跑通过）。

## §3 数据流走查

1. 打开运行详情 → `attributionStep.clickable` 为真时请求 `steps/attribution`。
2. 响应 `payload.rows[]` 每行含 `badCaseId/sessionId` → `caseSessionMap()` 逐个写入，重复 case 保留首个。
3. 切到第 5 步 → `StepClusters` 展开首簇 → `StepCaseTable` 收到 `wid` + map。
4. 每行 `caseLink()` 命中 → 渲染 `<a href="/workspaces/{wid}/sessions/{sid}/errors?case={id}&tab=attr">`。
5. 用户点击 → 新窗口落到该 Session 的错误详情，`tab=attr` 选中归因分析；跨 Session 的 case 由落点页校验并显式报错。
6. 归因不可达 → map 为 `{}` → 文本分支，保留完整 `title`，无空 `href`。

## §6 讨论点

### D1 3/4 步来源走 `tab=desc`、5/6 步走 `tab=attr`，是否要统一

- **位置**：`plans/fullstack-design/08-frontend-implementation.md:827` vs `:870-871`、本 PR `:838`；`StepCaseTable.vue:28`、`StepAttribution.vue:231`。
- **现象**：同一 case 从第 4 步点来源落到「问题描述」，从第 5/6 步点来源落到「归因分析」。
- **问题**：相邻步骤核对同一条 case 时页签不同；文档读者会得到两套规则。
- **预判**：属 issue 明示非目标（沿用 `tab=attr`），当前与 `08 §11` 一致，不是缺陷；建议另案决定统一方向。
- **结论**：（留空）

### D2 `tab=attr` 不带 `at`，落点默认第一条归因

- **位置**：`RunDetail.vue:209-215`、`StepCaseTable.vue:28`、`apps/web/src/pages/errors/Index.vue:137-155`。
- **现象**：一个 case 可有多条归因，5/6 步链接只带 `case`，落点取第 0 条，未必是聚类依据的那条。
- **问题**：核对成本增加，但不影响链接可用性。
- **预判**：与 `08 §11` 的既定拼法一致；若要精确到条，可把映射值扩成 `{sessionId, attributionId}` 并追加 `&at=`，与 `StepAttribution` 对齐。建议另案增强。
- **结论**：（留空）

### D3 覆盖叙事：第 5 步的唯一接线守卫是页面级用例

- **位置**：`StepContent.test.ts:457-473` vs `RunDetail.test.ts:708-731`。
- **现象**：`StepClusters` 在 main 上已传 `wid`+map，组件级第 5 步 href 用例在 pre-fix 也能过；真正会红的是 `RunDetail.test.ts` 的页面级用例。
- **问题**：将来弱化页面级用例时，第 5 步接线可能失去守卫。
- **预判**：本 PR 已补 `RunDetailConformance` 的锚点语义断言，但仍以页面级用例为主守卫；可在后续把第 5 步接线纳入 conformance 套件。
- **结论**：（留空）
