## §6 讨论点

### D1 协议断连与无响应

**位置**：`tests/support/runtime.mjs:175`、`:183`、`:215`。

**现象**：真实Chrome关闭后，旧实现socket已CLOSED而请求仍pending；单个协议请求无期限。

**问题**：启动重试无法触发，测试等待可一直延续到全局预算耗尽。

**预判**：连接/请求有界并在所有结束路径清理pending，保留失败。

**结论**：按此修复，6项红绿回归与独立复核通过。

### D2 HTTP外层预算失效

**位置**：`tests/support/runtime.mjs:67`。

**现象**：真实TCP对端接受连接但不发headers，旧waitFor在21.5秒后仍pending，外层20秒循环无法结束单次fetch。

**问题**：只有循环截止而没有请求截止，不是真正的总预算。

**预判**：单次请求使用剩余预算内的AbortSignal。

**结论**：已修复；真实无响应TCP回归通过，既有默认预算不变。

### D3 正常产物采集阻塞业务验收

**位置**：`tests/e2e/issue-436-evolution-pause.test.mjs:182`。

**现象**：有界协议引入后，一次组合运行在刷新后暂停截图明确报Page.captureScreenshot超时，DOM状态正常、违规事件为空、清理完成。

**问题**：无图像断言且生成后删除的截图副作用阻塞默认行为验收。

**预判**：正常产物按明确请求采集，失败诊断保持；不改Chrome合法选项，不增整体预算。

**结论**：独立复核认可；默认7项和显式留图模式均通过。不声称已定位或修复Chrome内部截图挂点。

### D4 初始化失败漏清理

**位置**：issue436 E2E的Network.enable及监听注册。

**现象**：该初始化原在try/finally外，若失败可跳过page.close。

**问题**：新协议期限会正确抛错，但Chrome可能仍残留。

**预判**：移动初始化到既有try/finally内。

**结论**：已修，独立复核确认闭合；无业务断言变化。

### D5 在线门禁的陈旧结果

**位置**：`.github/workflows/ci.yml` 的 `flow-online` lane；`scripts/verify-flow-online.mjs:13-16`。

**现象**：`flow-online` 把本地 `done` 映射为远端 `CLOSED`。`gh run rerun --failed` 只重跑失败 job，不会刷新已成功的 `flow-online`；#436 在 2026-11-22T04:02Z 被重新打开后，旧 run 的 `flow-online` success 已不能代表当前事实。

**问题**：若在 `done` 与 `OPEN` 并存时合并，会把不一致带到 main，后续 PR 的在线检查也会受影响。

**预判**：维护者先关闭 #436，再推送提交触发**全新**完整 CI（不要只 rerun 失败 job），`flow-online` 才在 done↔CLOSED 下通过。

**结论**：已在本 PR 描述与检视记录中标注；通过仓库flow:sync关闭后，需要全新完整CI。
