## §1 一页速览

一句话：这个 PR 把外部问题、归因与 Probe 三张只读表接到统一 HTTP 读模型上，并让问题卡锚点与已有 Session tree 共用同一套规则。

生活化比喻：外部系统写下“哪里出了问题”和“为什么”的档案，这个 PR 像档案馆前台，把分散在三只柜子里的记录按一个一致的时点取出，再翻译成前端能直接展示的问题卡、五态标签和根因报告。

## §2 架构导览

### 2.1 HTTP 层

`apps/api/app/api/problems.py:31-122` 注册五条 GET：

- `/api/sessions/{sessionId}/bad-cases`
- `/api/sessions/{sessionId}/probes`
- `/api/bad-cases/{badCaseId}`
- `/api/bad-cases/{badCaseId}/analysis`
- `/api/probes/{probeId}`

所有端点复用中央 Bearer 门卫，并在 OpenAPI 中声明 401/403/404/409/422 的 `ErrorResponse`。case 与 analysis 共用的 `sessionId` 参数为可选、长度 1–36，用于深链归属校验。

### 2.2 单快照读取

`apps/api/app/db/crud/problems.py:68-136` 分别在同一个 `AsyncSession` 内读取：

```text
session_families
  → bad_cases
  → bad_case_analysis + probe_reports
  → agents
  → agent_events
```

Session 列表和单 case 详情使用同一快照类型；Session probe 列表使用另一条只含 probe 与反向来源的快照。这里没有 repository 写方法，也没有逐 case 查询 probe 的 N+1。

### 2.3 归并和锚点

`apps/api/app/service/bad_cases/service.py` 负责验证外部行、合并五态、生成脱敏 warning。`apps/api/app/service/problems/anchor.py:17-73` 将锚点规则抽成纯函数：

- `self + agent`：上报 Agent 本身，事件下标 −1。
- skill：上报 Agent 内同名 skill 的最后一次触发。
- `discovery + agent`：父 Agent 中匹配 `toolUseId` 的 agent 触发。
- 缺失/漂移：降级到 main，事件下标 −1，并产生稳定 warning code。

`apps/api/app/service/sessions/service.py` 与问题 API 共用同一锚点函数，避免树和问题卡出现两套语义。

### 2.4 公共契约

`apps/api/app/service/problems/schemas.py` 将问题列表/详情统一为 `BadCase`，归因使用按 `status` 判别的 RootModel：

```text
unanalyzed            → result = null
analyzed_nonissue     → result = { reason, reasoning[] }
analyzed_issue        → result = { summary }, displayState 按 attributeType 派生
```

非法状态的公共降级、身份缺失与缺失 probe 都由 service 先行处理。

## §3 数据流走查

### 场景 A：打开一个 Session 的问题列表

1. 路由验 Bearer 后调用 `ProblemService.list_for_session()`。
2. repository 在一个 session 中读 Session、全部问题、归因、probe、Agent、事件。
3. `BadCaseService` 批量合并五态，并丢弃身份字段缺失的外部行。
4. `ProblemService` 使用同一快照计算问题锚点。
5. 返回 `{items: BadCase[]}`。

### 场景 B：通过问题深链进入

1. 前端调用 `/api/bad-cases/{id}?sessionId={sid}`。
2. case 存在但 `sessionId` 不匹配时返回 `409 BAD_CASE_SESSION_MISMATCH`。
3. case 不存在返回 `404 BAD_CASE_NOT_FOUND`。
4. 成功响应同时带 `sessionId/sessionTitle/anchor/badCaseAgent`，前端无需反推。

### 场景 C：查看归因与 Probe

1. `/analysis` 返回同一 `BadCase.analysis`，没有归因行时为 `unanalyzed`。
2. 若 `analysis.probeId` 指向同会话 probe，返回五态之一。
3. `/probes/{id}` 返回完整 probe，以及经同会话与 `analyzed_issue` 双重校验的 `fromBadCases`。

## §6 讨论点

### D1 外部归因 result 漂移会让问题列表/详情直接 500

**位置**

- `apps/api/app/service/bad_cases/service.py:336-356`
- `apps/api/app/service/problems/service.py:175-183`
- `apps/api/app/service/problems/schemas.py:100-118`

**现象**

把 `badcase-synthetic-0001` 的 `analysis_result` 从合法 `{"summary": ...}` 改成 `{"not_summary": "bad"}` 后：

```text
GET /api/sessions/{sid}/bad-cases
→ 500 {"error":{"code":"INTERNAL",...}}
```

实际异常为 `analyzed_issue.result.summary: Field required`。non-issue result 缺 `reason/reasoning[]` 也走相同路径。

**问题**

m4-01 的明确约束是外部字段漂移不能把单条坏行扩散成页面故障；本 PR 在公共 DTO 边界又把已清空的 `result=None` 包成非法判别联合，导致整张问题列表和 case 详情不可用。

**预判**

应在 `ProblemService` 出站映射层把“外部状态合法但 result 形状非法”的归因统一降级为公共可表示的 `unanalyzed` 占位，保留 warning/日志；不能把 `None` 交给要求 `{summary}` 或 `{reason,reasoning[]}` 的判别联合。分析端点也应使用同一降级结果。建议优先级 P1。

**结论**

已修复（2026-10-26）。公共出口将状态虽为 analyzed、但 result 已因形状漂移被清空的归因降级为 `unanalyzed`，列表、详情和 analysis 端点返回同一占位，不再触发 500。

### D2 非法 presentation enum 的 case 被静默丢弃，详情端点随后 500

**位置**

- `apps/api/app/service/problems/service.py:135-141`
- `apps/api/app/service/problems/service.py:74-80`
- `.agents/notes/implemented/architecture/2026-10-26-external-read-models.md:13`

**现象**

把 `badcase-synthetic-0001` 的 `bad_case_type` 与 `object_type` 改为非法值：

```text
Session list: 200，但 items 从 2 条变成 1 条
GET /api/bad-cases/{caseId}: 500 INTERNAL
```

列表层只写一条日志后 `continue`；详情层先确认 `merged.items` 非空，再执行 `[0]`，最终抛 `IndexError`。

**问题**

Owning Note 要求非身份字段异常保留可读占位。当前行为既不返回占位，也没有对用户可见的降级信息，还会把“存在但字段漂移”的 case 表现成列表缺失或详情的未处理 500。

**预判**

应定义一种公共可表达的降级卡（例如明确的 drift/diagnostic 字段，锚点固定 main/-1），或至少在列表/详情统一返回结构化 degraded 占位；不能一边静默删除、一边假设后续仍能取第一项。建议优先级 P2，若产品要求外部坏行绝不消失则提升为 P1。

**结论**

已修复（2026-10-26）。非法 `badCaseType` / `objectType` 不再从列表消失：公共卡返回 `degraded=true` 与稳定 `diagnosticCode`，使用安全的 self/agent 展示占位，并把锚点固定为 main/-1；列表与详情保持一致，不再出现 IndexError。

### D3 UI 原型没有本 PR 可验收页面

**位置**

- Issue #47 非目标：错误详情 UI 属后续 issue
- `plans/fullstack-design/08-frontend-implementation.md` §7

**现象**

本 PR 没有 `apps/web/**` 或 `plans/14-15-ui-prototype/**` diff。Session 浏览器、Agent 树、亮色壳层保持原样。

**问题**

本 PR 只交付 API；错误详情页面、error sidebar 和归因 tab 仍属于后续 issue，不能拿本 PR 声称原型页完成。

**预判**

UI 检视结论应为“对已实现范围无漂移、页面验收不适用”。下一步 m4-04 必须按原型补真实页面截图和交互回归。

**结论**

待维护者确认阶段边界。
