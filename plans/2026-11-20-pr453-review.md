## §1 一页速览

**一句话**：把“Web 47 秒等 API 16 分钟”的单 job 串行流水线拆成两条并行车道，API 车道用 `pytest-xdist` 开多个 worker 并把覆盖率换成 pytest-cov 自动合并，同时把唯一会因并发负载而假的 git timeout 用例从“固定 sleep + 短超时”改成事件驱动。

**比喻**：原来一个收费站只有一条车道，47 秒能过的 Web 车排在 16 分钟的 API 车龙后面；现在两条车道并行，API 车道开 8 个收费口，并且把“必须站在门口等 4.5 秒看有没有人闯杆”的检查改成看监控回放——只要确认闸机在放行前已经关死，就不需要干等。

## §2 架构导览

### 2.1 CI lane：从“一个 job 串两套”到“两 job 并行 + 两个聚合点”

旧 `unit-tests` 在 `.github/workflows/ci.yml`（base 版本 58-81 行）同时装 Node 与 Python，`pnpm test` 用 `&&` 串 web 与 api，timeout 30 分钟。新结构：

- `unit-tests-web`（`ci.yml:58-90`）：只装 Node，`pnpm test:web`；setup 与 vitest 各记一次秒数写入 `$GITHUB_STEP_SUMMARY`。
- `unit-tests-api`（`ci.yml:92-145`）：只装 Python venv；不跑 `pnpm install`（该 job 只用 pnpm 转发 package.json 脚本，不需要 node_modules），`pnpm test:api -- -n 8 --dist worksteal` 用 `tee` 留日志，摘要里用 `awk` 截取 `slowest 25 durations` 段落折叠展示。
- `ci-ok`（`ci.yml:313-327`）：`needs` 里把 `unit-tests` 换成两个新 job，聚合逻辑不变（failure/cancelled 一票否决，skipped 放行）。

两个 job 的 timeout 分别为 10 / 15 分钟：Web 历史约 1 分钟，10 分钟足够覆盖冷启动；API 目标 8 分钟内，15 分钟给冷缓存与 runner 抖动留余量。

### 2.2 API runner：默认并发、覆盖率合并、聚焦逃生口

`scripts/run-api.mjs` 的三层设计：

1. `TEST_ARGS`（`run-api.mjs:20-25`）把 pytest-cov 与 `--durations=25` 作为所有 `test`/`test:serial` 的公共参数；`[tool.coverage.run] branch = true` 仍在 `apps/api/pyproject.toml:39-41`，所以分支覆盖口径不变。
2. `selectsWorkers`（`run-api.mjs:76-85`）只看调用方是否已给 `-n` / `--numprocesses` / `--serial`；没给就补 `-n auto`。CI 的 `pnpm test:api -- -n 8` 因此原样透传，不会叠加两个 `-n`。
3. `selectsTests`（`run-api.mjs:43-52`）用一个小型选项值表判断“是否给了测试路径”。命中时加 `--no-cov`，避免 `pnpm test:api -- tests/identity` 这种聚焦运行被整包 90% 阈值误杀——这是本次修掉的一个真实回归：pytest-cov 会读取 pyproject 的 `fail_under = 90`，不给 `--cov-fail-under` 时也会 fail。

**旧手写包装的真实行为**：旧 `test` 命令在主进程里 `Coverage().start()/report()`，`report()` 并不会像 CLI 一样按配置的 `fail_under` 抛错（本次实测聚焦 40% 仍 exit 0），所以“90% 阈值”此前只是文档；换成 pytest-cov 后才真正强制。这是行为变化，见 §6 D3。

### 2.3 计时用例：为什么固定 sleep 会假，怎么改成事件

旧用例（base 版本）用 `git alias.delayed` 起一个脚本，脚本先 `touch process-started`，再后台 `(sleep 4; touch late-side-effect) &`，manager 设 `timeout_seconds=2.0`，测试在抛错后再 `await asyncio.sleep(4.5)` 断言。并发负载下有两个墙钟竞争：

1. `git` 启动 + alias shell 初始化若晚于 2 秒，`_git` 在脚本落地前就超时，`process-started` 永远不出现——正是 issue 记录的 flake。
2. 固定 4.5 秒等待既拖慢用例，又无法证明“返回时进程组已死”，只证明了“4.5 秒内没出现副作用”。

新用例（`test_git_workspace.py:1059-1123`）：

- 注入 `runner` 直接 `_run_process((script,), cwd)`，绕过 git 启动，把被测量对象收缩为“超时 + 进程组终止”本身。
- 用 `asyncio.create_task` 启动 `manager._git`，在超时前**轮询** `process-started`（deadline 10 秒），记录 `ready_at`。
- 超时抛出后读脚本写入的 `$$`，用 `os.killpg(pgid, 0)` 轮询到 `ProcessLookupError`，直接断言“返回时整个进程组已消失”——比等待文件副作用更强。
- 再从 `ready_at` 起观察 3 秒窗口（脚本副作用预定在 +3 秒），断言 marker 始终不出现；`finally` 兜底 cancel 未完成的 task。

### 2.4 门禁与文档：让接线也被自测钉住

`scripts/gates.spec.mjs:623-716` 原来断言 CI 里存在 `run: pnpm test`；拆 job 后改为断言 `pnpm test:web`、`pnpm test:api -- -n <N>`（worker 数是调优参数，用正则）、两个新 job 都在 `ci-ok` 的 needs 里，以及 `run-api.mjs` 含 `--cov=app` / `--cov-fail-under=90` / `--durations=25`、`pyproject.toml` 含 xdist/cov。`AGENTS.md:29` 用 `test:api[:serial]` 的既有括号写法记录两个入口；`docs/development*.md` 只在日常循环加一行 `pnpm test:api:serial`，预算保持 760 不超。

## §3 数据流走查（一次 PR 触发的 CI 剧本）

1. `pull_request` 触发 `.github/workflows/ci.yml`；11 个 lane 并发启动，`unit-tests-web` 与 `unit-tests-api` 互不等待（`ci.yml:58,92`）。
2. Web job：checkout → pnpm → node → `pnpm install`（约 5 秒，缓存命中）→ `pnpm test:web`（vitest 默认 worker 池）→ 摘要写 `SETUP_SECONDS` / `WEB_SECONDS` → 结束。
3. API job：checkout → pnpm → node → Python 3.12（pip 缓存按 `apps/api/pyproject.toml`）→ venv + `pip install -e 'apps/api[dev]'` → `pnpm test:api -- -n 8 --dist worksteal`。
4. `run-api.mjs` 解析 argv：`--` 被过滤，`-n 8` 与 `--dist worksteal` 被转交（`--dist` 在 `VALUE_OPTIONS` 中，其值不会被误判为测试路径），`selectsTests` 判定无路径 → 追加 `--cov-fail-under=90` → 启动 pytest，xdist 起 8 个 worker 并按 worksteal 动态分发，pytest-cov 每 worker 写数据、主进程合并。
5. pytest 结束：`--durations=25` 打印最慢用例；`tee` 保留完整日志；摘要步骤 `awk` 截取 durations 段写入 job summary。
6. 全部 lane 结束后 `ci-ok` 读取 `needs.*.result`，`failure`/`cancelled` 即失败；分支保护只认这一个 check（`ci.yml:313-340`）。

- **位置**：`ci.yml:80-90,123-145`
- **现象**：GitHub 的 `$GITHUB_STEP_SUMMARY` 按 job 展示；Web 与 API 在不同 runner 上，摘要自然分两块。

### D3 90% 阈值从“名义”变成真正强制

- **位置**：`scripts/run-api.mjs:113-115`；`apps/api/pyproject.toml:46`
- **现象**：旧手写 `Coverage().report()` 在聚焦子集 40% 时仍 exit 0（本次实测）；新方案全量跑真正按 90% fail。

- **预判**：AGENTS.md 本来就要求“覆盖率不得低于 80%”，issue 也写明 90%；强制是修正而非破坏。建议保留，并在 Note 中记录该行为变化（已写）。
- **结论**：

### D4 本地默认 `-n auto`

- **位置**：`scripts/run-api.mjs:112`
- **现象**：10 核开发机默认 10 个 pytest worker，SQLite 临时库与真实子进程测试会争 I/O；本机 -n 4 三次 185–275 秒波动较大。
- **问题**：是否应该把本地默认改成固定值（与 CI 对齐、更可预测）？
- **预判**：`auto` 是“用满本机”的直觉默认，`test:api:serial` 是逃生口；若后续 flake 增多可再收紧。建议保留 `auto`，观察一个迭代。
- **结论**：

- **位置**：`scripts/run-api.mjs:43-52,113-115`
- **现象**：`pnpm test:api -- tests/identity` 现在带 `--no-cov`，不再打印覆盖率表。

## §9 文件级代码分析

### 9.1 `.github/workflows/ci.yml`（M）

**职责**：CI 编排。**变更形态**：替换 `unit-tests` 为两个 job，改 `ci-ok.needs`，新增两个 summary step。

**旧代码**：

```yaml
unit-tests:
  timeout-minutes: 30
  steps:
    - checkout / pnpm / node / python
    - run: pnpm install --frozen-lockfile
    - name: Python 环境
      run: venv + pip install
    - name: 单元测试
      run: pnpm test
```

**新代码**（`ci.yml:58-145`）：Web job 只装 Node，`pnpm test:web`；API job 只装 Python，`pnpm test:api -- -n 8`。两个 job 各自用 `date +%s` 记录 setup 与套件耗时写 `$GITHUB_ENV`，summary step 用 `if: always()` 保证失败时也输出已知阶段。API summary 用 `awk '/slowest [0-9]+ durations/,0'` 截 durations 段并折叠。

**为什么**：拆 job 让两个套件真正并行；去掉 API job 的 `pnpm install` 是因为该 job 不需要 node_modules（pnpm 只负责转发脚本）；`if: always()` 让失败时也能看到 setup 耗时，便于区分“环境慢”与“测试慢”。

**实现思路**：复用现有 lane 风格（每 job 自带 checkout + setup + 缓存），不引入 artifact 或跨 job 覆盖率聚合。

**检视发现**：`--durations=25` 的截取依赖 pytest 输出格式；pytest 8.4 的标题固定为 `slowest 25 durations`（本 PR 实测），若升级 pytest 改文案，摘要会静默变空——属于软可见性，无功能影响。

### 9.2 `scripts/run-api.mjs`（M）

**职责**：跨平台转发 API venv 命令。**变更形态**：删除手写 coverage `-c` 片段，新增 `TEST_ARGS` / `selectsWorkers` / `selectsTests`。

**关键依赖**：pytest-cov 是 pytest 插件（pip 安装、运行时加载），负责在 xdist 主进程合并 worker 的 `.coverage.*` 数据；pytest-xdist 负责 worker 池。两者都在 `pyproject.toml` 的 dev extra，CI 与本地共用同一入口。

**新代码**（`run-api.mjs:20-52,108-116`）：先把 argv 里的 `--` 过滤，再用两个小函数判断“是否显式指定 worker”“是否给了测试路径”；无路径时补 `--cov-fail-under=90`，有路径时补 `--no-cov`，无 `-n` 时补 `-n auto`。

**为什么**：把“全量套件门禁”和“聚焦调试”分开，避免一个阈值同时服务两种语义；`-n` 默认值让本地不必记参数，CI 又保留显式控制。

**实现思路**：`VALUE_OPTIONS` 只覆盖本仓库实际会用到的带值选项；未知的带值选项可能把值误判成路径，但后果只是聚焦运行不判阈值，偏保守。

### 9.3 `apps/api/tests/m5-09-git-candidate/test_git_workspace.py`（M）

**职责**：真实本地 git 契约。**变更形态**：只改超时用例，其余用例未动。

**旧代码**：git alias 起脚本，2 秒 manager 超时，`await asyncio.sleep(4.5)` 后断言 `process-started` 存在且 marker 不存在。

**新代码**（`test_git_workspace.py:1059-1123`）：注入 runner 直接 exec 脚本；`create_task` 跑 `_git`，轮询 `process-started` 记录 `ready_at`；`pytest.raises` 等超时；`killpg(pgid, 0)` 轮询到进程组消失；再观察 `ready_at+3.5` 的副作用窗口。

**为什么**：消除两个墙钟竞争——启动慢于超时会假失败，固定 4.5 秒既慢又不能证明返回时进程组已死。

**实现思路**：用脚本自己写 `$$` 暴露 pgid；`finally` cancel 避免 task 泄漏；断言顺序是“先证明已启动，再证明已终止，最后证明无迟到副作用”。

**检视发现**：`_run_process` 是模块私有函数，测试直接 import；这与文件里已有的 `_git` 辅助函数同属测试便利，不改变生产接口。
