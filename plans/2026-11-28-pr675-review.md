## §1 一页速览

一句话：把「仅聚类页」的网格内容从“拉满视口”改成“按内容高度从顶部排列”，并把重复的准备状态合并成一条真实进度状态。

一个比喻：页面像书架，网格默认会把每层书（页头、模式条、状态区）拉高到刚好填满柜子，书与书之间就出现很宽的缝；`align-content: start` 让书按自身高度靠上摆，空位留在最底下。

| 交付块 | 内容 | 验证 |
| --- | --- | --- |
| 布局 | `align-content: start`、1720px 内容列、移动端文档滚动 | E2E 几何 1366×768/1080、1920×1080、390×844 |
| 状态 | 页头徽标 + 单一状态区；准备/运行/失败/阻塞/中断/完成 | 组件测试 13 例 |
| 模式说明 | 橙色警告卡改为中性紧凑条，保留启动入口与禁用原因 | 组件测试 + 冒烟截图 |
| 长对象名 | chip 换行 + `title` 完整值 | 组件测试 + 390×844 E2E |
| 运行详情回归 | 根节点同步 `align-content: start` | m10-06 preparing 768/1080 几何 |

验证基线（PR 声明）：新增 E2E 在基线上失败（状态区 114.2→176.6px、模式条 126.5→188.9px），本 head 通过；`pnpm test:web` 887 passed / 1 skipped，覆盖率 92.51% 行。

## §2 架构导览

### 2.1 页面根布局（`ClusterPreview.vue#L417-L426`）

页面根节点是工作区壳层内的页级滚动容器：`display: grid`、`height: 100%`、`overflow-y: auto`，左右内边距按 `min(100%, 1720px)` 居中，滚动条留在窗口右缘。新增的 `align-content: start` 只改变“剩余高度怎么分配”，不改变滚动归属。≤640px 时 `height: auto; overflow-y: visible` 把滚动交还文档（`#L690-L704`）。

`.run-detail-page` 用同一组声明（`RunDetail.vue#L1070-L1082`），所以低内容时也有相同拉伸风险；本 PR 同步加 1 行，不碰其结构。

### 2.2 状态模型（`ClusterPreview.vue#L84-L157`）

- `statusLabel`：页面状态的中文徽标，继续优先看 `controlState`（暂停/暂停中），再看 `status`。
- `statusTone`：把状态映射到 `running/paused/blocked/completed/failed`，只用于徽标与状态区配色，不新增后端字段。
- `statusDetail`：失败/阻塞/中断、准备中、运行中、完成分别取对应文案；准备/运行/完成优先用后端真实 `progress.stageLabel`，暂停/暂停请求也保留真实进度，把暂停说明留给 `RunControl`，避免同一句话出现两遍；只有准备/运行进度为空时才回退到流程描述，不伪造百分比。
- `incompleteMessage`：失败原因只在这里取一次，避免“状态条 + 错误卡”两处措辞漂移。

### 2.3 模板结构（`ClusterPreview.vue#L289-L392`）

```text
header.detail-head
├── h1 问题聚类结果
├── span.target-chip（可换行 + title）
├── span.badge[data-testid=cluster-status]（状态徽标）
└── RunControl（暂停/继续，仅控制态存在时）
div.mode-note（中性信息条 + 启动按钮 + 禁用原因）
div.status-area[data-testid=cluster-status-detail]（唯一状态区）
├── pulse（仅准备/运行）
└── span.status-copy（progress.stageLabel 或失败原因）
completed → 输入概况 + StepClusters
```

旧的 `section.card.preparing` 与 `section.card.state-error` 已删除；失败、阻塞、中断不再另起“聚类未完成”标题。

### 2.4 样式与 token（`ClusterPreview.vue#L449-L704`）

模式条用 `--border`/`--bg-panel`/`--text-dim`，不再用 `--orange` 警告底；状态区按 tone 只改边框/浅底色，仍复用 `--blue/--orange/--red`；长 chip 用 `overflow-wrap: anywhere`，不写死宽度；移动端只调整对齐与按钮位置。

## §3 数据流走查

以准备中页面为例：

1. 路由 `/workspaces/<wid>/evolution/cluster/<rid>` 挂载页面，`useEvolutionRunDetail` 拉 `GET /runs/{rid}`；`completed=false` 时 `useEvolutionRunStep` 不请求步骤（`ClusterPreview.vue#L45-L61`）。
2. `run.progress.stageLabel`（例如「第 1/5 步 · 选择范围中…」）进入 `statusDetail`，模板只渲染一个状态区；页头徽标显示「准备中」。
3. `canLaunch` 为 false，`launchDisabledReason` 给出「聚类完成后可启动完整自进化。」，按钮 `disabled` 且 `title` 同步说明；`RunControl` 按控制态与 `canManage` 决定是否显示暂停/继续。
4. 根节点 `align-content: start` 让 back、header、mode、status 四行按内容高排列，剩余高度留在滚动容器底部；E2E 在 768/1080 两个高度比较状态区高度与相邻间距。
5. 完成后 `completed=true`，页面并行请求 `steps/range`、`steps/clusters`、`steps/attribution`，状态区显示真实「第 5/5 步 · 聚类完成」，`StepClusters` 渲染多簇，根节点滚动到最后一簇。
6. 失败/阻塞/中断时 `statusDetail` 取 `run.error.message`（中断用固定文案），状态区 `role=alert`，不再渲染第二张错误卡。

## §6 讨论点

### 6.1 完成态是否还需要独立状态行

- **位置**：`ClusterPreview.vue#L337-L341`
- **现象**：完成态页头已有「已完成」徽标，下方仍有一条「第 5/5 步 · 聚类完成」状态区。
- **问题**：这条状态区不是重复状态标签，而是唯一展示后端进度的位置；但视觉上是否值得占一整行，需要产品判断。
- **预判**：保留。删除后完成态没有任何进度来源，且准备/失败状态区会变成条件渲染，增加分支。
- **结论**：待用户拍板。

### 6.2 模式说明与原型橙色条的偏离

- **位置**：`ClusterPreview.vue#L308-L327`
- **现象**：原型 `.banner` 是橙色警告条，本实现改为中性 `--bg-panel` 条。
- **问题**：原型没有仅聚类页，橙色条是通用 banner 样式；#674 明确要求“正常模式说明不使用大面积警告卡”。
- **预判**：按 issue 验收标准执行，保留中性条；若产品希望恢复橙色，需要另开视觉决策。
- **结论**：待用户拍板。

### 6.3 运行详情同步改一行是否应拆 PR

- **位置**：`RunDetail.vue#L1082`
- **现象**：两个详情页根节点使用同一组布局声明，本 PR 同步加 `align-content: start`。
- **问题**：改动跨页面，但只有 1 行且被 m10-06 几何回归覆盖；拆分会留下一个已知同类缺陷。
- **预判**：保留在同一 PR，符合 #674 “统一详情页布局”的目标。
- **结论**：待用户拍板。

## §9 文件级代码分析

### 9.1 `apps/web/src/pages/evolution/ClusterPreview.vue`（M）

职责：仅聚类运行的路由页，负责轮询/读取运行、展示状态与聚类结果、以同一条件启动完整自进化。

关键依赖：Vue 3 `computed`/模板、Vue Query（`useEvolutionRunDetail`/`useEvolutionRunStep`）、共享组件 `RunControl`/`StepClusters`。无新增依赖。

变更代码块（状态）：

```text
旧：statusDetail 只按 preparing/running 硬编码，模板再渲染一张 preparing 卡
新：statusTone + statusDetail 统一状态映射；准备/运行取 progress.stageLabel；
    失败/阻塞/中断取 error.message；模板只保留一个 status-area
```

这在做什么：把“状态标签”和“状态详情”拆成两个单一来源，避免模板分支各自写文案。为什么这么写：后端已经给 `progress.stageLabel`，前端不应再维护第二份流程文案。

变更代码块（布局/样式）：

```text
旧：display:grid + height:100% + overflow-y:auto，无 align-content；橙色 .banner
新：同一滚动契约 + align-content:start；中性 .mode-note；target-chip 可换行
```

实现思路：只改容器对齐与呈现，不引入内层新布局；多簇滚动仍由根节点承担。

检视发现：无阻塞问题。已知弱点：完成态状态行占一整行（§6.1）；模式说明与原型橙色条不同（§6.2）。

### 9.2 `apps/web/src/pages/evolution/RunDetail.vue`（M）

职责：运行详情页，展示七步、输入、日志与阻塞/中断状态。

变更：`.run-detail-page` 增加 `align-content: start`（`#L1082`），与仅聚类页共享同一纵向契约。

为什么：两个页面使用同一组 grid + height 声明；只修一个会留下同类低内容拉伸。风险：长内容没有剩余空间，行为不变；m10-06 的 768/1080 几何与既有滚动用例覆盖。

检视发现：无。

### 9.3 `apps/web/src/pages/evolution/ClusterPreview.test.ts`（M）
