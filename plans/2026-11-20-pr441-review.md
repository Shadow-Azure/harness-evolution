## §1 一页速览

**一句话**：把 `.sr-only` 的「便利贴」从整页贴回卡片上。

`position: absolute` 的元素会找一个「定位祖先」作为自己的坐标系；找不到就退到整页（初始包含块）。`.sr-only` 本身是不可见的 1×1 辅助文本，平时无所谓；但它落在左栏列表里时，这个「整页坐标」不在列表的滚动裁剪范围内，于是它按卡片在列表里的纵向位置把整个文档撑高。生产 10 条 Session 时，最后一张卡把它顶到 y≈1830，文档从 837 变成 1895，浏览器就画出了第三条窗口滚动条。

| 交付块 | 内容 |
|---|---|
| 根因修复 | 三个容器补 `position: relative`，`.sr-only` 回到容器内并被 `overflow` 裁剪 |
| 回归 | m3 e2e：`.sr-only` 的 `offsetParent` 不能是 `body`；10 张卡片布局文档高 = 视口高 |
| 契约 | 08 §5.5 记录规则；Agent Note 记录取舍 |

验证基线（本地实测）：

- 未修复：`{"cards":10,"srOnlyInBody":10,"documentScrollHeight":1944,"innerHeight":837}`（e2e 红）
- 修复后：1500×837 与 1440×900 文档高 837/900 = 视口；`srOnlyInBody: 0`；滚动容器只有 `.session-list` 与 `.overview`
- 生产复验：部署 bundle 与本地 main 一致；页面内存注入修复后 `document` 从 1895 回到 837，`scrollY` 保持 0

## §2 架构导览

### 2.1 页面壳层与滚动职责

`App.vue` 的 `main.workspace-main` 固定视口高度并 `overflow: hidden`；Session 页 `.session-browser` 自己再算一次 `100dvh - 顶栏`，左右两栏各自 `overflow-y: auto`（[08 §5.5](../../plans/fullstack-design/08-frontend-implementation.md)）。按设计，`document.scrollingElement.scrollHeight` 应恒等于视口高度。

### 2.2 绝对定位的包含块

CSS 里 `position: absolute` 的盒子沿 DOM 往上找最近的「非 static」祖先作为包含块；如果一路没有，就用初始包含块（可以理解为整页）。`.sr-only` 的写法是 `position: absolute; width: 1px; height: 1px; clip: rect(0 0 0 0)`，它的静态位置仍然是「卡片标题行该在的地方」。

### 2.3 为什么 `overflow` 没裁剪它

`overflow: hidden/auto` 只裁剪「自己的后代」，而且是按包含块链生效的：如果元素的包含块在滚动容器之外（这里是初始包含块），滚动容器就不是它的裁剪祖先。代码里 `.session-list` 有 `overflow-y: auto`，但 `.sr-only` 的包含块在整页，于是列表的滚动条只滚卡片，`.sr-only` 留在文档坐标里，把根元素的 scrollable overflow 撑到 1895。

### 2.4 为什么之前的回归是绿的

m3 e2e 与 fixture 只有 4 条 Session（`fixtures/m2-synthetic/corpus.json` 的 `rootSessions` 长度 4）。4 张卡时最后一张的 `.sr-only` 落在 837 以内，`document` 仍是 837；`#422` 的断言只检查了文档高度，没有检查包含块，所以这个根因一直没被锁住。

## §3 数据流走查

1. 打开 `/workspaces/ws-*/sessions/<id>`：`main.workspace-main` 781px、`.session-browser` 781px、`.sidebar/.overview` 各 781px。
2. 左栏 `.session-list` 高度 607px，10 张卡片内容 1843px，内部滚动正常。
3. 每张卡片标题行的 `.sr-only` 以整页为包含块，静态 y 依次约 250、446、…、1830。
4. 根元素 `scrollHeight` 取所有后代 overflow 的并集，最后落在 y≈1830 的 `.sr-only` → `1895`。
5. 浏览器发现文档比视口高，画窗口滚动条；用户向下滚，看到两栏内容结束后的大片空白（issue 截图红框）。
6. 修复后 `.sr-only` 的包含块是 `.session-card`，它被 `.session-list` 裁剪；根元素 overflow 仍由两栏的固定高度决定，`scrollHeight` 回到 837。

## §6 讨论点

### 6.1 用 DOM 克隆模拟 10 条 Session，是否够真实？

- **位置**：`tests/e2e/m3-session-browser.test.mjs:466`
- **现象**：测试把 4 张真实卡片 `cloneNode` 成 10 张，测完移除；左栏计数标签仍显示「最新 4 / 总数 4」。
- **问题**：克隆节点没有经过 Vue 的列表渲染，但本缺陷是纯布局问题（卡片数量决定的静态位置），克隆卡片与真实卡片的 CSS/DOM 完全相同；`offsetParent` 断言与数据无关。
- **预判**：作为布局回归足够，且避免改动共享 fixture 影响其它用例的卡片计数；如果未来要覆盖真实数据路径，可另加 10 条 Session 的 fixture。
- **结论**：留空给维护者拍板

### 6.2 给 `.version-label` 加 `position: relative` 是否影响提示层？

- **位置**：`apps/web/src/pages/errors/components/VersionLabel.vue:212`
- **现象**：版本号的 `version-tip` 是 `<Teleport to="body">`，`position: fixed/absolute` 由脚本定位；`.version-label` 是 `display: flex` 的窄容器。
- **问题**：`position: relative` 会创建包含块与新的 stacking context；如果提示层仍在组件内，可能改变 z-index 参考系。
- **预判**：提示层已经 Teleport 到 body，不受组件内 stacking context 影响；冒烟未观察到提示层被裁剪或错位。
- **结论**：留空给维护者拍板

### 6.3 只审计 `.sr-only` 是否覆盖了同类风险？

- **位置**：`apps/web/src` 全局
- **现象**：仓库里 `.sr-only` 只有三处（Session 卡片、归因报告、版本号），本次全部收口。
- **问题**：其它 `position: absolute` 的辅助节点（`aria-live`、`role=status`）如果落在滚动容器内且没有定位祖先，同样会撑高文档；本次没有加全局 lint。
- **预判**：当前没有发现第四处；08 §5.5 的规则已记录，后续新增按规则检查即可，全局 lint 成本偏高。
- **结论**：留空给维护者拍板

### 6.4 生产复验依赖合并后部署

- **位置**：PR 描述「生产复验与冒烟」
- **现象**：修复已在生产页面用内存注入验证（1895 → 837），但真实部署要等 PR 合并。
- **问题**：如果部署后仍有第三条，说明还有别的逃逸源，需要重新采集 `document.scrollingElement.scrollHeight` 与滚动容器列表。
- **预判**：本次根因已用「隐藏列表 → 837」与「逐卡递减」锁死，部署后大概率消失；issue 按 bugfix milestone 保持打开，等提出人确认。
- **结论**：留空给维护者拍板

### 6.5 回归断言为什么不用 `offsetParent === null`

- **位置**：`tests/e2e/m3-session-browser.test.mjs:489`
- **现象**：断言写的是 `offsetParent === document.body`，不是 `offsetParent === null`。
- **问题**：`offsetParent` 对 `position: fixed` 元素是 `null`；`.sr-only` 是 absolute，若未来改成 fixed，`null` 断言会误绿/误红。
- **预判**：当前固定写法准确命中「包含块落到初始包含块」的根因；同时用文档高度断言兜底。
- **结论**：留空给维护者拍板

## §9 文件级代码分析

### 9.1 `SessionCard.vue`

- **职责**：左栏单张 Session 卡；包含状态点、标题、元信息、密度条与问题数。
- **变更形态**：M（`position: relative` 一行）。
- **旧代码**：`.session-card { display: grid; ... }`，无定位；`.sr-only` 的包含块落到整页。
- **新代码**：`.session-card { position: relative; display: grid; ... }`，卡片成为所有绝对定位后代的包含块。
- **为什么这么写**：卡片是列表里重复的最小单元；以卡片为边界，`.sr-only` 的静态位置就留在卡片内，列表裁剪恢复。没有改 `.sr-only` 的写法，避免影响无障碍语义与 flex 对齐。
- **实现思路总结**：给重复单元一个定位上下文，让辅助文本留在单元内。

### 9.2 `AttributionReport.vue` 与 `VersionLabel.vue`

- **职责**：错误详情页的归因结论与版本号复制提示。
- **变更形态**：M（各一行 `position: relative`）。
- **旧代码**：`.attribution`/`.version-label` 无定位；其 `.sr-only` 标题/提示落在错误详情页的滚动容器里时可能同样逃逸。
- **新代码**：各自成为 `.sr-only` 的包含块。
- **为什么这么写**：与 9.1 同一规则；两处都是滚动容器内、且 `.sr-only` 是直接子节点。
- **检视发现**：无视觉发现；`version-tip` 走 Teleport，不受 stacking context 影响（见 §6.2）。

### 9.3 `m3-session-browser.test.mjs`

- **职责**：Session 浏览器的跨栈 E2E。
- **变更形态**：M（低内容布局段之后新增 41 行）。
- **关键依赖**：Node 原生 test runner + CDP `Runtime.evaluate`；不引入新依赖。
- **变更代码块**：先克隆 6 张卡片（`data-session-id=layout-clone-*`，移除 `data-selected`），等 10 张后读 `srOnlyInBody`/`documentScrollHeight`，断言后移除克隆。
- **为什么这么写**：在现有 4 条 fixture 上造出生产的 10 条布局，不触碰共享数据；`offsetParent` 断言与卡片数量无关，是根因级锁。
- **检视发现**：克隆期间计数标签仍显示 4（§6.1）；克隆节点不进入 Vue 状态，若后续断言依赖点击克隆卡片会失效——当前只读布局，无影响。
