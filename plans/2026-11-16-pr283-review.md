## §1 一页速览

**一句话**：以前父子关系只有“连上/没连上”，现在把“凭什么连上”也写进数据：强证据、缺结果降级、弱证据合成、完全未解析四档，并且缺结果的子 Agent 仍留在树里、在节点上明确写“未返回最终报告”。

**比喻**：像户籍登记。`authoritative` 是三证齐全（父调用、回执、子档案号）；`derived` 是有父调用和子档案号但回执丢了，仍然登记但标注“待补回执”；`synthetic` 是只有邻居口供说“他住这家”；`unresolved` 是连口供都没有，先挂在主户下并记一笔待查，不能让人凭空消失。

**交付块**：

| 块 | 结果 |
|---|---|
| 关系分级 | `agent_tree` 在装配期一次算清四级证据，写入父事件 |
| 可见性 | `derived` 保留节点与父边；`unresolved` 保留节点 + 稳定诊断码 |
| 回填 | parser_version 3 触发存量 `claude-code` 重放 |
| API/UI | 沿用 `relationConfidence` DTO；节点 chip + “未返回最终报告” |
| 契约 | 无新表/新列；06 §3.4 的列第一次有写入方 |

**验证基线**：API 91% 覆盖率、Web 569 通过、SQLite/MySQL 迁移、E2E、docs/flow 门禁全绿；真实浏览器前后截图见 PR 描述。

## §2 架构导览

1. **解析层不判断关系**：`ParsedEvent` 只多一个可选字段（`parsers/base.py:85`），解析器仍然只输出“我看到了哪些触发点”。这保持了 runtime parser 的职责边界。
2. **装配层集中裁决**：`agent_tree.py:164` 从父转录的 `tool_result` block 取出已返回的工具 id；`agent_tree.py:692` 用“父事件存在 + 父 tool result 存在 + 子 metadata toolUseId 命中”给出 `authoritative`，否则 `derived`。父工具身份缺失/冲突/未知时走 `agent_tree.py:541` 的合成边，置信度分别是 `synthetic`/`unresolved`。
3. **节点不消失**：合成边仍然生成合法的父事件（带确定性 id 与 `relation_confidence`），所以未解析节点能继续参与 canonical ordering、深度计算和 UI 边。诊断码沿用 `MISSING_PARENT_TOOL_USE_ID`、`UNKNOWN_PARENT_TOOL_USE_ID`、`AMBIGUOUS_PARENT_TOOL_USE_ID`。
4. **持久化只有一处**：`acquisition_replay.py:739` 把事件字段写进 `agent_events.relation_confidence`，不新增 repository 方法，也不在 API 层重新推断。
5. **Web 只读证据**：`layout.ts:238` 从父 `SessionAgent.events` 按 `toolUseId` 找关系；`layout.ts:249` 把 `derived` 或 `interrupted/missing_report|tool_use_open` 映射为设计规定的“未返回最终报告”；`AgentNode.vue:108` 渲染 chip，`AgentNode.vue:42` 把关系与警告并入 `aria-label`，屏幕阅读器也能读到。
6. **回填机制**：`claude_code.py:248` 升到 3。关系分级是装配语义变化，旧 source_records 的 `parser_version < 3` 会进入 pending，下一次同步/重放重写整棵树。

## §3 数据流走查

以真实形状 `fixtures/m9-real-shape` 为例：

1. 主转录第 8 行有 `tool_use id=tool-agent-1`（Agent），但文件到此结束，没有对应 `tool_result`。解析器给出 `interrupted/tool_use_open` 和 `MISSING_FINAL_REPORT` 诊断。
2. 子转录 metadata 的 `toolUseId` 也是 `tool-agent-1`。`agent_tree` 在父节点 `tool_events` 中命中该事件，但 `_returned_tool_ids(main)` 不含 `tool-agent-1`，于是父事件写 `relation_confidence=derived`，子节点 `parent_agent_id=main`。
3. 重放把这条父事件写进 `agent_events`。API 的 `SessionEvent.relationConfidence` 在事件上返回 `derived`。
4. 浏览器加载 `/workspaces/ws-default/sessions/40000000-…`，`layout.ts` 在父事件上找到 `derived`，计算 `completionWarning=未返回最终报告`；节点渲染 `5 行 · 派生 · 未返回最终报告`。
5. 若父转录有 tool result，同一路径得到 `authoritative`；若只有子 metadata 的 `parentAgentId`，则父节点末尾生成合成事件并写 `synthetic`；若连父身份都没有，则合成事件写 `unresolved` 且保留 `MISSING_PARENT_TOOL_USE_ID`。

## §6 讨论点

### D1 `authoritative` 也显示 chip，是否信息过量
- **位置**：`AgentNode.vue:104`、`layout.ts:1051`
- **现象**：每个非主节点都会显示“权威/派生/合成/未解析”chip，authoritative 占多数。
- **问题**：真实大图里 chip 会重复出现，压缩了标签与触发链的视觉空间。
- **预判**：本轮保留全部 chip，理由是“展示关系证据”需要让 authoritative 也可被看见；如果后续认为噪音大，可以只保留非 authoritative，并给 authoritative 用 tooltip。
- **结论**：暂不调整，等待维护者拍板。

### D2 未解析节点结构上仍挂主 Agent
- **位置**：`agent_tree.py:655`（fallback_to_main 后接 unresolved 合成边）
- **现象**：`unresolved` 节点的 `parent_agent_id` 是主 Agent，而不是 NULL。
- **问题**：只看父链接会误以为关系已确认；树也必须保持单根才能渲染。
- **预判**：调用方应以 `relationConfidence` 判定强度，UI chip 已明示“未解析”；把节点设为无父会破坏 canonical ordering 与现有布局契约。
- **结论**：保留，文档与 Note 已写明。

### D3 非 Claude runtime 的 tool result 可见性
- **位置**：`agent_tree.py:164`
- **现象**：关系分级依赖 parser 把 `tool_result` 记录进 `blocks_outside_user_turns`；当前只有 Claude Code parser 这么做。
- **问题**：其他 runtime 即使有父调用与子 metadata，也会因为没有 result block 被判为 derived。
- **预判**：保守降级优于误报 authoritative；M9-06 的 parser 基类已提供 `record_block` 钩子，新 runtime 实现时应补 tool result 记录。本轮不扩 runtime。
- **结论**：接受为已知边界。

### D4 parser_version 升级的重放成本
- **位置**：`claude_code.py:248`
- **现象**：部署后所有存量 `claude-code` payload 会重放一次。
- **问题**：大库首次同步耗时增加。
- **预判**：这是把关系证据回填到历史会话的唯一既有机制；不升级则旧会话永远 NULL。与 M9-02 的 1→2 升级同性质。
- **结论**：接受。

### D5 合成事件会出现在父节点触发链末尾
- **位置**：`agent_tree.py:541`
- **现象**：weak/unresolved 子 Agent 会在父节点链尾多一个“合成”pill。
- **问题**：它看起来像真实 provider 事件；但若不合成，节点没有可渲染的边。
- **预判**：事件带 `relation_confidence=synthetic/unresolved`，调用方可区分；UI chip 也已标明。合成 id 确定性、可重放一致。
- **结论**：接受，Note 已记录。

## §9 文件级代码分析

### `apps/api/app/service/acquisition/parsers/base.py`（M）
- **职责**：runtime 无关的解析值与模板方法。
- **变更**：新增 `RelationConfidence` 封闭类型（`:28`），`ParsedEvent` 增加可选 `relation_confidence`（`:85`）。
- **思路**：解析器只携带事实槽位，不判断父子关系；字段默认 `None`，不改变任何现有 parser 的构造方式。
- **发现**：无。

### `apps/api/app/service/acquisition/agent_tree.py`（M）
- **职责**：把多份 ParstedTranscript 装成 canonical 树。
- **变更前**：`parent_tool` 命中即连边；缺父身份时 `append_missing_parent_event` 固定挂 main；没有关系字段。
- **变更后**：`_returned_tool_ids`（`:164`）提供 result 证据；`_with_relation`（`:173`）把置信度写回父事件；`append_synthetic_parent_event`（`:541`）接收 owner 与 confidence；匹配分支（`:692`）按 result 存在性二分。
- **思路**：一次循环里先收集 tool/result 事实，再按子节点排序处理；合成边沿用已有确定性 id 与锚点逻辑，尽量不改变 canonical ordering 的既有约束。
- **发现**：合成边插入父事件末尾后，父事件 `event_index` 仍连续；`_depths` 与 `_cycle_nodes` 不需要改动。

### `apps/api/app/service/acquisition/parsers/claude_code.py`（M）
- **职责**：Claude Code JSONL 解析器。
- **变更**：`parser_version` 2 → 3（`:248`）。
- **思路**：关系列只在树装配时产生，但存量行要重新装配；版本游标是仓库既有的触发机制。
- **发现**：所有断言 2 的测试同步更新，避免“版本升级但测试仍锁旧值”。

### `apps/api/app/db/crud/acquisition_replay.py`（M）
