## §1 一页速览

一句话：在「启动自进化」第 1 步把三个快捷胶囊与日期输入放在同一行，点选后用今天倒推出具体起止日填入输入框，同时用浅蓝选中态表示当前区间命中了哪个预设。

## §2 架构导览

### 2.1 原型状态与日期计算

`EV_WZ_RANGE_PRESETS` 只声明三个预设的 id 与中文标签；`evWzPresetRange(id)` 把 id 翻译成 `{from, to}`。近 7 天/近 30 天用 `v2DateAdd(V2_TODAY, -(days - 1))`，近半年用 `evWzDateAddMonths(V2_TODAY, -6)`。两者都从 `V2_TODAY` 出发，保证胶囊、输入框与页面演示数据在同一个「今天」上。

月末处理集中在 `evWzDateAddMonths()`：先把日期设为 1 号，移动月份，再取目标月最后一天与原始日期的较小值。因此 8 月 31 日往前 6 个月会落到 2 月最后一天，而不是 3 月 2 日。

### 2.2 点击只更新状态，不重建表单

点击处理先 `evSyncWz()` 把输入框当前值读回状态，再写入预设的 `from/to`，直接更新两个 input 的 `value` 与胶囊的 `active` / `aria-pressed`，不调用 `evRenderWizard()`。这样焦点留在被点的胶囊上，也不会因为重建 DOM 丢失日期控件的状态。

手动修改日期走 `change` 事件：`evSyncWz()` 后调用 `evWzSyncRangePresetButtons()`，用当前值反查命中项。未命中时三个胶囊都取消 `active`，不引入第四个「自定义」状态。

### 2.3 设计契约与边界

`design-v2.md` §7.4.1 与 `08` §9 Step 1 写的是同一份口径：结束日为今天（含当天）、只填值不锁定、原有校验不变、生产以浏览器当前日期计算。视觉上参考 AppSignal 与 Grafana 的时间过滤器：预设单选、当前项有明确选中态、入口保持轻量；因此没有复用总览页的实心蓝分段控件，也没有保留首版的第二行说明。Agent Note 记录被否方案：原生 date picker 快捷项、相对区间 `range=7d`、固定 180 天、额外「自定义」按钮、总览同款实心蓝分段控件。

生产 `apps/web` 的 `LaunchWizard.vue` 未改；本 PR 的交付物是原型 + 设计契约 + 决策记录。后续生产落地仍要按同一契约补组件与测试。

## §3 数据流走查

1. 打开 `harness-evolution.html?u=admin&page=evo&demo=wizard1`，`v2Boot()` 在 300ms 后调用 `evWizardOpen(null)`，`evRenderWizard()` 渲染第 1 步。
2. 用户点击「近 30 天」→ `evSyncWz()` 读取输入框 → `evWzPresetRange('30')` 算出 `2026-10-12 ~ 2026-11-10` → 写入 `wz.from/to` → 更新两个 input 与胶囊态。
3. 用户点「下一步：关联 Session」→ 原有的 `evValidateWz()` 仍按必填与 `from <= to` 校验 → `evWzStartBusy(1)` → Session 关联预览。快捷项没有进入请求体，服务端看不到它。
4. 用户手动改结束日 → `change` 事件同步状态 → `evWzSyncRangePresetButtons()` 反查；不命中任何预设时三个胶囊都不再高亮。

## §6 讨论点

### 6.1 「近半年」按自然月而不是固定 180 天

- **位置**：`plans/ui-prototype-v2/harness-evolution.html` 的 `evWzDateAddMonths()`
- **现象**：近半年从 2026-11-10 得到 2026-05-10；若按 180 天会得到 2026-05-14。
- **问题**：产品文案「近半年」可能被用户理解为 6 个自然月，也可能被理解为约 180 天；两种结果在月末边界不同。
- **预判**：按自然月更贴近中文「半年」的语义，也更容易解释月末收敛规则。Agent Note 已记录放弃固定 180 天的理由。
- **结论（2026-11-23）**：保留自然月实现。若产品后续明确要按 180 天，需同时改原型、设计文档与 Agent Note，不能只改前端常量。

### 6.2 原型日期固定为 `V2_TODAY`，生产用浏览器当前日期

- **位置**：`plans/ui-prototype-v2/harness-evolution.html` 的 `evWzPresetRange()` 与 `V2_TODAY`
- **现象**：原型点「近 30 天」总是得到 `2026-10-12 ~ 2026-11-10`，因为演示日固定；生产会随真实日期变化。
- **问题**：评审可能把截图里的 `2026-11-10` 误认为产品默认结束日。
- **预判**：这是原型数据边界，不是业务默认值。设计文档 §7.4.1 已明确「生产以浏览器当前日期计算」，页面内也标注了演示日。
- **结论（2026-11-23）**：保留固定演示日，保证截图与页面数据可重复；生产实现不得硬编码 `V2_TODAY`。

### 6.3 原型没有自动化回归测试

- **位置**：`plans/ui-prototype-v2/harness-evolution.html` 与 `plans/2026-11-23-pr536-review.md`
- **现象**：仓库没有针对静态原型的测试入口；本次用一次性 headless Chrome 脚本验证点击与日期值，截图作为证据。
- **问题**：未来修改原型可能悄悄破坏快捷项，而 CI 不会发现。
- **预判**：既有的原型改动都依赖截图与人工验收，本 PR 不新增测试基础设施；若后续生产 `LaunchWizard.vue` 落地，组件测试应覆盖同一组日期计算。
- **结论（2026-11-23）**：接受无自动化原型测试。验证记录与截图留在 issue/PR；生产实现必须补组件测试，不能复用「原型截图已验收」代替。

### 6.4 快捷项从实心分段控件改为轻量胶囊

- **位置**：`plans/ui-prototype-v2/harness-evolution.html` 的 `.wz-range-row` / `.wz-range-chip`
- **现象**：首版把三个 `.seg` 实心蓝按钮和一句长说明放在日期上方，用户反馈视觉不好看；截图里快捷行像第二条工具栏，和「下一步」主按钮抢蓝色。
- **问题**：快捷项是辅助输入，视觉权重应低于日期输入和主按钮；说明文字太长也会让表单显得吵。
- **预判**：改为与日期同一行的胶囊，选中态用浅蓝底 + 蓝色文字 + 描边，说明收成一句；日期输入仍是主要编辑面。
- **结论（2026-11-23）**：已按该方向实现，并同步 `design-v2.md`、`08` 与 Agent Note。参考 [AppSignal Date and time filter](https://appsignal.design/patterns/date-time-filter.html) 的「预设单选 + 明确选中态」与 [Grafana quick ranges](https://grafana.com/whats-new/2025-06-17-server-configurable-quick-time-ranges-for-dashboards/) 的轻量入口。
