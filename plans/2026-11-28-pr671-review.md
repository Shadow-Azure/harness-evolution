## §1 一页速览

一句话：列表根节点仍然吃满工作区高度负责滚动，但网格轨道改成按内容高度从顶部排列，空列表不再把页头、分组和空卡拉成视口高度。

比喻：原来的网格像三只等分的抽屉，抽屉里的东西少，抽屉却仍被撑满；现在抽屉只按物品高度关上，剩余的柜内空间留在最下面。

| 交付块 | 内容 |
| --- | --- |
| 生产样式 | `.workspace-main .run-list-page { align-content: start }` |
| 回归 | 0/0、0/1、1/0、1/1、3/5 × 1366×768、1366×1080、1920×1080，另加 390×844 |
| 契约 | `height: 100%; overflow-y: auto` 不变；分组标题、零计数、空提示、启动入口不变 |
| 证据 | PR 描述中的同视口前后截图、原型对照、几何测量和冒烟矩阵 |

## §2 架构导览

工作区壳层在 [App.vue:116](../apps/web/src/App.vue#L116) 把 `main.workspace-main` 固定为 `calc(100vh - header)` 并 `overflow: hidden`；列表页因此必须自己滚动。[main.css:122](../apps/web/src/styles/main.css#L122) 的 `.workspace-main .run-list-page` 用 `height: 100%; overflow-y: auto` 承担这个职责，左右 padding 保持 1080px 内容列。

同一选择器在 [main.css:129](../apps/web/src/styles/main.css#L129) 新增 `align-content: start`。CSS Grid 的默认 `align-content: normal` 在内容不足时等价于 `stretch`：三行 auto 轨道平分剩余高度，`.page-intro`、两个 `.run-group` 被拉高，`.waiting` 又作为分组网格项被 `align-items: stretch` 拉满。改为 `start` 后轨道取内容高度，剩余高度留在滚动容器底部，长列表本来就没有剩余高度，因此不受影响。

分组结构在 [RunGroup.vue:64](../apps/web/src/pages/evolution/components/RunGroup.vue#L64) 是两层网格：分组本身 `display: grid; gap: 10px`，页面再以 `gap: 14px` 排列页头与两个分组。修复只作用于外层容器，内层的 `waiting` 内边距和卡片尺寸保持原样。

## §3 数据流走查

浏览器回归的主线：`seedRuns({running, history})` 启动 Python fixture，清空并写入对应数量的合成运行 → 页面硬导航到 `/evolution?layout=...` → `useEvolutionRuns` 读取后端 `running` / `history` 分组 → `RunGroup` 渲染卡片或 `.waiting` → `snapshotExpression` 在同一个 tick 读取元素边界、计算样式和滚动量 → 断言比较两个视口的纵向指标。

fixture 的三个改动都是为这条主线服务：

- [m5_run_list_fixture.py:246](../tests/e2e/support/m5_run_list_fixture.py#L246) 按 `M5_RUN_LIST_RUNNING` / `M5_RUN_LIST_HISTORY` 截取行；默认仍是原来的 3/5，既有测试不受影响。
- [m5_run_list_fixture.py:151](../tests/e2e/support/m5_run_list_fixture.py#L151) 先删 `probe_cluster_probes` 再删 `probe_reports`，否则重复播种时外键会阻止清理。
- [m5_run_list_fixture.py:587](../tests/e2e/support/m5_run_list_fixture.py#L587) 与 [m5_run_list_fixture.py:680](../tests/e2e/support/m5_run_list_fixture.py#L680) 把 finals/events 过滤到本次选中的 run，空集时跳过插入。

## §6 讨论点

**位置**：`tests/e2e/m5-run-list.test.mjs:933` 起的新增回归。

**现象**：为了覆盖五种数据组合和四个视口，测试会执行 17 次登录，并在 API 测试环境把 `HE_LOGIN_RATE_LIMIT` 提到 1000。

**问题**：这是在测试里放宽了登录限流，而不是复用同一个会话；副作用仅限于测试进程，但会增加 fixture 与真实行为之间的配置漂移。

**预判**：可接受。浏览器每次硬导航都需要新的 refresh cookie，现有 m5 测试也采用重新登录的方式；限流只影响这个测试 API 实例，生产默认值不变。若后续用例继续增长，可考虑提取“登录一次、复用 cookie”的 helper。

**结论**：（留空）

**位置**：`tests/e2e/m5-run-list.test.mjs` 中既有 `End > PageDown` 断言。

**现象**：本机 Chrome 在 1408×788 下 PageDown 已直接滚到列表最大值（634px），End 无法再前进，既有用例在本机失败；在干净的 `main@bc570378` 上同样复现。

**问题**：该断言依赖浏览器的 PageDown 滚动量，属于既有测试的环境敏感性，与本 PR 的样式变更无关；CI 的 main 运行是该用例通过的。

**预判**：本 PR 不修改这条既有断言，避免把布局修复扩大成滚动测试重写；若 CI 在 PR 上失败，再单独评估把断言改为“End 后仍在底部”的等价形式。

**结论**：（留空）

**位置**：`apps/web/src/styles/main.css:129` 与 `RunGroup.vue` 的 `.waiting` 内边距。

**现象**：生产空卡高度约 50.6px，原型同场景约 57.4px（原型 padding 18px、虚线边框，生产 15px/16px、实线边框）。

**问题**：两者视觉细节本来就有差异，本 PR 只修纵向拉伸，没有顺手统一空卡样式。

**预判**：保持现状。统一 padding/边框属于另一个视觉对齐决定，超出 #669 的“间距不随视口膨胀”范围。

**结论**：（留空）

## §9 文件级代码分析

### `apps/web/src/styles/main.css`

职责：工作区壳层内页面框架的滚动与宽度契约。变更形态 M。

旧代码只声明 `height: 100%; overflow-y: auto`，网格默认拉伸；新代码增加 `align-content: start`，其余声明逐字不变。这样滚动容器的高度与滚动归属不动，只把剩余空间的分配方式改掉。实现思路一句话：让网格轨道按内容高度结束，剩余高度留给滚动容器底部。

检视发现：无。选择器已有 `workspace-main` 前缀，不会影响登录页或其他非工作区布局。

### `tests/e2e/m5-run-list.test.mjs`

职责：m5 自进化列表的真实浏览器回归。变更形态 M。

新增 `ensureLoginCookie` 兼容“单独跑本用例”与“整文件运行”两种密码状态；新增 `snapshotExpression` 把两组卡片数量作为等待条件，并一次采集页头内容高度、页头到分组间距、分组高度、空卡高度、卡片高度、滚动量和文档宽度。断言分两层：`assertTopAligned` 检查从顶部排列、间距范围和无横向溢出；`assertCompact` 比较 768/1080 与 1366/1920 的同一组指标，阈值 2px。末尾保留长列表滚到底和移动端文档滚动覆盖。

检视发现：调试用超时状态捕获会输出 `location.href` 与正文前 240 字，只在本用例失败时触发，不含凭据。

### `tests/e2e/support/m5_run_list_fixture.py`

职责：为 m5 列表测试写入确定性运行数据。变更形态 M。

新增数量环境变量，按状态分组截取；空集时跳过所有次级插入；重复播种前按外键顺序清理 cluster 关联；finals 与 events 过滤到选中的 run。默认 3/5 保持原行为。

检视发现：`int(os.environ.get(...))` 对非法输入会直接抛错，但这是测试辅助脚本，调用方固定传整数；可接受。
