## §2 架构导览

### 2.1 数据契约与展示映射

卡片的输入是 `BadCase`（`packages/contracts` 的生成类型，`apps/web/src/components/bad-cases/BadCaseList.vue:2`），本次消费的字段是 `title`、`reason`、`badCaseType`（`self` / `discovery`）、`objectType`、`objectName`、`metadata`、`badCaseId`、`sessionId` 与 `analysis.displayState`。

`badCaseDisplay.ts:15` 用 `STATE_PRESENTATION` 把五种归因状态映射为固定 label + tone；`:34` 的 `badCaseState` 只做查表。`:45` 的 `badCaseFactEntries` 把外部 `metadata` 转成最多 3 条 key/value：字符串原样、其它值 `JSON.stringify`、超过 72 字符截断并加省略号。它相当于一个“只开三个窗口的安检口”——外部元数据再多，也只放前三件、且每件限长，避免不可控的外部文本撑破卡片。

### 2.2 Markdown 渲染是共享基础件

`utils/markdown.ts` 不是本 PR 新增的，但它是描述正文的关键依赖：`:4` 的 `createMarkdown` 用 `markdown-it@14.1.0` 建两个单例（`:34` 带图片、`:35` 不带图片），配置 `html:false`（`:7`，原始 HTML 不生成节点）、`breaks:true`（`:6`，换行变 `<br>`）、`linkify:true`（`:8`，裸 URL 自动成链）；`:10` 在不带图片的实例上把 image 规则替换成“只输出转义后的 alt 文本”；`:20` 给所有链接补 `target=_blank` 与 `rel="noopener noreferrer"`。`renderMarkdown`（`:44`）按 `images` 选项选实例。

`BadCaseList.vue:49` 的 `reasonHtml` 只做一件事：`renderMarkdown(problem.reason, { images: false })`。它把“外部描述文本 → 安全 HTML”的决策集中在一个函数里，模板只需要 `v-html`（`:230`）。这里的“安全”不是本 PR 的推断，而是三件可核对的事实：`markdown-it` 的 `html:false`；`link_open` 统一加固；测试覆盖 `<img onerror>` 转义与 Markdown 图片降级（`BadCaseList.test.ts:209`–`:228`）。另外 `markdown-it` 14.1.0 的 `validateLink` 默认拒绝 `javascript:` / `vbscript:` / `file:` / `data:`（`node_modules/.pnpm/markdown-it@14.1.0/.../lib/index.mjs:31`–`:38`），即便外部描述里写了 `[x](javascript:...)` 也不会成链。

### 2.3 覆盖按钮：把“整卡可点”和“链接可点”拆成两层

旧非 compact 模板（`git show origin/main:...BadCaseList.vue:178`–`:230`）把标题、状态、摘要和 facts 都塞在 `<button class="problem-row">` 里，ID 深链是按钮外的兄弟节点。这个结构在只有文本时没问题，但一旦描述里出现 Markdown 链接，`<a>` 要么嵌进 `<button>`（不合规、点击还会冒泡触发选中），要么只能放弃整卡点击。

新模板把顺序翻过来：`BadCaseList.vue:189` 的 `.problem-card-content` 是普通 `div`，里面依次放 `.problem-row-head`（`:190`）、描述（`:225`）、facts（`:233`）、关联行（`:246`）；`:251` 的覆盖按钮是它的**兄弟**，绝对定位铺满卡片（`:309`–`:322`），`z-index:1`；`.problem-card-content` 设 `pointer-events:none`（`:356`–`:362`），而所有链接通过 `.problem-card-content a`（`:392`–`:396`）恢复 `pointer-events:auto` 并提到 `z-index:2`。这样点击文字落到按钮上，点击链接落到链接上，两者不是父子关系，选中动作不会被链接冒泡触发。

### 2.4 消费者与状态闭环

`SessionOverview.vue:279` 把 `problems`、`activeBadCaseId` 传给 `BadCaseList`，并监听 `select`；`selectBadCase`（`:136`–`:143`）设置 active、向父级 emit `badcase-select`、等待 `AgentFlow.locateBadCase` 把画布滚到对应节点，再调用 `BadCaseList.scrollToProblem` 把列表行滚进视野。`BadCaseList.vue:53`–`:58` 用 `getElementById` + `scrollIntoView({block:"nearest"})` 做列表侧回滚；`:60` 的 watch 在 `activeBadCaseId` 变化时触发。卡片只是这条闭环的入口，选中语义和 `aria-pressed` 没有改变。

### 2.5 流程与决策层

M14 是新增 milestone（`.agents/flow/milestones/m14-milestone.md:5`–`:13`，GitHub #22），issue #371 是它的第一个工作项（`.agents/flow/issues/m14-problem-card-description.md:5`–`:18`，`status: in-progress`）。roadmap 只增加 `m14` 的登记与一行摘要。Agent Note 记录“以原型为准”“为什么删摘要”“覆盖按钮与链接取舍”“类型徽章不跟随原型”的决策。流程文件的 i18n hash 与实测一致；scope 覆盖本 PR 全部改动路径（`apps/web/**`、`tests/e2e/**`、`plans/**`、`scripts/doc-budgets.manifest.json`、`.agents/**`）。

## §3 数据流走查

1. Session 页拉取 `bad-cases` 后，`Index.vue` 的问题列表数据经 `SessionOverview.vue:279` 进入 `BadCaseList`；`activeBadCaseId` 初始为 `null`（`SessionOverview.vue:113`）。
2. `BadCaseList.vue:109` 按 `problems` 顺序渲染 `role="listitem"`；每张卡在 `:116` 拿到 `active` 类，`:110` 的 DOM id 仍是 `problem-row-<badCaseId>`，供列表回滚使用。
3. 头部在 `:188`–`:224` 渲染 BC 编号、标题、类型徽章、对象徽章、完整 ID 深链、状态胶囊与 `degraded`；ID 深链的 `href` 来自 `badCaseDeepLink(..., "desc")`（`utils/badCaseId.ts`），点击走新窗口，不进入选中流程。
4. 描述在 `:225`–`:231` 渲染：`v-if` 先挡掉空/纯空白描述（`:227`），`reasonHtml`（`:49`）调用共享 Markdown 渲染器，`v-html` 把结果挂到 `.problem-detail.markdown`（`:230`）。原始 HTML 不会成节点；Markdown 图片被替换为 alt 文本；链接带 `target=_blank` 与 `rel`。
5. facts 在 `:233`–`:245` 由 `badCaseFactEntries` 生成 key/value chip；`metadata` 为空或没有条目时整块不渲染。关联行在 `:246`–`:248` 输出 `关联：objectType · objectName`。行尾 `定位 ↗`（`:250`）是纯装饰文本，实际点击由覆盖按钮承接。
6. 点击卡片任意非链接区域：事件目标落在 `:251` 的空按钮上，`@click` emit `select`（`:258`）。
7. `SessionOverview.selectBadCase`（`:136`）设置 active、emit `badcase-select`、调用执行流定位，再调用 `scrollToProblem`；`BadCaseList` 的 watch（`:60`）也会在 active 变化时 `scrollIntoView`。折叠分支的展开由父级 `Index.vue` 的 `badcase-select` 处理，本 PR 未改这条链路。
8. 点击描述里的链接：设计意图是链接在 `z-index:2`、`pointer-events:auto`（`:392`–`:396`），按钮在 `z-index:1`，浏览器把点击目标判给链接、选中不触发。检视时该结论只来自 DOM/CSS 推断；**补真实坐标点击时发现 scoped CSS 未命中 `v-html` 链接（`elementFromPoint` 返回 `BUTTON`）**，改为 `.problem-card-content :deep(a)` 后才成立（见 6.1 结论）。
9. 点击 ID 深链：同样在内容层，但它是 `<a target="_blank">`，不 emit `select`；单测 `BadCaseList.test.ts:323`–`:346` 覆盖了“ID 链接与选中互不影响”，但只覆盖 ID 链接，不覆盖描述链接。

## §6 讨论点

### 6.1 描述内链接与整卡覆盖缺少直接行为测试（P2，测试缺口）

- **位置**：`apps/web/src/components/bad-cases/BadCaseList.vue:251`（覆盖按钮）、`:392`–`:396`（链接提升）、`apps/web/src/components/bad-cases/BadCaseList.test.ts:323`–`:346`（只点 ID 链接）、`tests/e2e/m4-problem-cards.test.mjs:339`–`:350`（只点按钮）。
- **现象**：PR 描述把“描述里的链接不会被选中动作吞掉”列为验收项，冒烟表场景 04 的证据写的是 `m4 problem cards` E2E；但该 E2E 与单测都没有点击 `.problem-detail a`，只点击了覆盖按钮与 ID 深链。E2E 的 `row.click()` 是对空按钮的编程式点击，完全绕过了 `pointer-events` / `z-index` 的真实命中测试。
- **问题**：这条交互是本 PR 最核心的结构性取舍，却只靠“DOM 是兄弟、CSS 有 z-index”推断；未来有人把链接移回内容层或改掉 `pointer-events`，现有测试仍会全绿。反过来，若链接实际被按钮遮住，测试也发现不了。
- **预判**：这不是代码缺陷，是测试缺口。建议在本 PR 补一个真实坐标点击的描述链接 E2E（或至少单测断言 `detail` 内链接 `closest("button")` 为 null，并断言点击后没有 `select` 事件）；同时把冒烟场景 04 的证据改成实际覆盖它的用例，避免“声明有测试、实际没有”。如果维护者接受以结构审查替代行为测试，也应在 Note 里写明。
- **结论**：**已修复（2026-11-19）。** 单测补 `detail` 内链接的 `closest("button")` 为 null 与点击不触发 `select`；E2E 新增 `m4 problem cards keep description links clickable above the select button`，用 CDP `Input.dispatchMouseEvent` 在链接真实坐标点击，先以 `elementFromPoint` 断言命中 `A`，再断言 `aria-pressed` 仍为 false。该用例在修复前实测暴露了真实缺陷：scoped CSS 的 `.problem-card-content a` 不匹配 `v-html` 生成的链接，链接没有 `pointer-events:auto`，`elementFromPoint` 返回 `BUTTON`；改为 `.problem-card-content :deep(a)` 后通过。

### 6.2 完整 ID / 长对象名在 390px 有横向溢出风险（P2，潜在布局缺陷）

- **位置**：`apps/web/src/components/bad-cases/BadCaseList.vue:439`–`:445`（`.problem-no, .problem-id, .report-id { flex-shrink: 0 }`）、`:462`–`:468`（`.problem-id` 的 `overflow-wrap:anywhere`）、`:501`–`:509`（`.object-badge` 的 `white-space:nowrap`）、`tests/e2e/m4-problem-cards.test.mjs:484`–`:495`（390px 只断言页面级 `scrollWidth`）。
- **现象**：本 PR 把显示从 8 位短 ID 换成完整 `badCaseId`。`.problem-id` 虽然允许任意断行，但仍带 `flex-shrink:0`；在 flex 行里它不会被压缩，`overflow-wrap` 只影响 min-content 计算，不会让一个不可收缩的 flex item 自动变窄。`.object-badge` 则是 `white-space:nowrap`、无 `max-width`。fixture 的 ID 是 22 字符、objectName 是 `Explore` / `review-workflow`，E2E 没有覆盖长值。数据库列允许 64 字符（`apps/api/app/db/models/domain.py:297`），真实 UUID 36 字符在 390px 下约 216px，而可用内容宽度约 224px，余量只有个位数像素；任一更长的前缀 ID 或长 objectName 都可能把卡片撑破。
- **问题**：这是“从短 ID 改成完整 ID”带来的新边界，且正好是本 PR 明确要求的移动端验收点。当前 fixture 能过，不代表真实外部 ID 能过。
- **预判**：建议把 `.problem-id` 改成可收缩（`min-width:0; flex-shrink:1`）或在 `:not(.compact)` 下给 `max-width:100%; overflow:hidden; text-overflow:ellipsis`；`.object-badge` 同理加 `max-width:100%; overflow:hidden; text-overflow:ellipsis`，或允许 `overflow-wrap:anywhere`。再加一条 64 字符 ID 的 E2E/组件用例，才能把“390px 无横向溢出”从 fixture 特例变成性质。未实测复现，故标为预判而非已确认缺陷。
- **结论**：**已修复（2026-11-19）。** `.problem-id` 改为 `flex-shrink:1; min-width:0`，`.object-badge` 增加 `max-width:100%; overflow:hidden; text-overflow:ellipsis`；新增 64 字符 ID + 长 objectName 的 390px E2E。把 `.problem-id` 临时改回 `flex-shrink:0` 时该用例失败（ID 右缘 479px 超出卡片右缘 360px），确认用例有效。

### 6.5 原型 `FindingList` 把 Markdown 链接放进 `<button>`，与生产交互不一致（P3，原型/验收基线）

## §9 文件级代码分析

### `apps/web/src/components/bad-cases/BadCaseList.vue`（M）

职责：渲染 Session 页问题列表；非 compact 模板承担“描述 + 证据 + 整卡定位”，compact 模板保持旧布局。

关键依赖：`markdown-it@14.1.0`（社区包，Vite 构建期打包进 bundle，运行时不额外请求）通过 `utils/markdown.ts` 间接使用。它像一台“按说明书组装 HTML 的翻译机”：本组件只递入 `reason` 文本，翻译机负责转义、断行、链接和图片降级；组件本身不拼 HTML。测试侧依赖 Vitest + jsdom（`@vue/test-utils`），E2E 侧依赖仓库的 CDP runtime（`tests/support/runtime.mjs`），本 PR 未新增依赖。

**旧代码**（`git show origin/main:...:178`–`:230`，节选）：

```vue
<span class="problem-no">#{{ index + 1 }}</span>
<a class="problem-id" :href="badCaseDeepLink(...)"
   :aria-label="`问题 ${shortBadCaseId(problem.badCaseId)}，...`">
  {{ shortBadCaseId(problem.badCaseId) }}
</a>
<button class="problem-row" ...>
  <span class="problem-row-head">
    <strong>{{ problem.title }}</strong>
    <span class="state-chip" ...>{{ badCaseState(...).label }}</span>
  </span>
  <span class="problem-summary">{{ badCaseSummary(problem) }}</span>
  <span class="problem-meta">
    <span>{{ problem.objectType }} · {{ problem.objectName }}</span>
    <span v-for="fact in badCaseFacts(problem.metaData)">{{ fact }}</span>
    <span class="locate-copy">定位</span>
  </span>
</button>
```

这在做什么：整张卡的内容都在按钮里，按钮本身就是点击目标；ID 是按钮外的短链；第二行永远是 `badCaseSummary`。为什么当时这么写：没有描述正文，`<a>` 只有 ID 一个，放在按钮外就足以避免嵌套；按钮内全是纯文本，整卡点击最直接。

**新代码**（`:187`–`:260`，节选）：

```vue
<span class="problem-no">BC{{ index + 1 }}</span>
<div class="problem-card-content">
  <span class="problem-row-head">
    <strong>{{ problem.title }}</strong>
    <span class="type-badge" :class="problem.badCaseType">{{ problem.badCaseType }}</span>
    <span class="object-badge">{{ problem.objectName }}</span>
    <a class="problem-id" :href="badCaseDeepLink(...)">{{ problem.badCaseId }}</a>
    <span class="state-chip" ...>{{ badCaseState(...).label }}</span>
  </span>
  <div v-if="problem.reason.trim()" class="problem-detail markdown"
       data-testid="problem-card-description" v-html="reasonHtml(problem)" />
  <span v-if="badCaseFactEntries(problem.metaData).length" class="problem-facts">
    <span v-for="fact in badCaseFactEntries(problem.metaData)" :key="fact.key" class="fact-chip">
      <span class="fact-key">{{ fact.key }}</span><span class="fact-value">{{ fact.value }}</span>
    </span>
  </span>
  <span class="problem-meta">关联：{{ problem.objectType }} · {{ problem.objectName }}</span>
</div>
<span class="locate-copy">定位 ↗</span>
<button class="problem-row" :aria-label="`选择问题 ${problem.badCaseId}：${problem.title}`" ... />
```
