## §1 一页速览

这个 PR 给前后端契约装了一条“公证流水线”：FastAPI 是唯一原始发言人，先产出 OpenAPI 快照，机器再把快照翻译成 TypeScript；每次检查都重新请 FastAPI 说一遍，然后逐字和仓库里的公证文本比对。health 的 200/503 示例也不再是手写假话，而是从真实 ASGI 响应录下来的，前端编译期必须接受这两份真实录音。

| 交付块 | 用户可见效果 |
|---|---|
| OpenAPI → TS | 后端改字段，前端类型不再靠人记忆同步。 |
| `contract:check` | 生成物缺失、手改或后端漂移在构建前给出统一重生成命令。 |
| 真实 health fixture | `HealthResponse` 类型必须接受真实 200 和 503 payload。 |
| 测试与覆盖率 | CI 执行前后端单测、SQLite/MySQL、跨栈集成；双端覆盖率下限不低于 80%。 |

验证基线：本地 contract check 通过（含 `HE_VERSION=contract-probe HE_PHASE=live HE_DOCS_ENABLED=true` 污染环境）；web 30 passed/1 skipped；API 33 passed/3 skipped，coverage 93%；web statements/lines 97.11%、branches 84.53%、functions 100%；integration 3/3；gates 21/21。PR CI `build-and-docs`、`mysql`、`flow-online` 全绿。

## §2 架构导览

**契约源层。** `canonical_settings()` 在构造 Settings 前摘掉所有 `HE_*` 变量，并用 `_env_file=None` 禁读 `.env`，构造成功后恢复宿主环境（[export_openapi.py:25](../apps/api/scripts/export_openapi.py:25)）。这样 version/phase/docs 等 schema 相关值只能来自代码默认，而不是开发者 shell。`main()` 再交给 FastAPI 并递归排序 JSON 对象键（[export_openapi.py:35](../apps/api/scripts/export_openapi.py:35)）。

**翻译层。** `scripts/contract.mjs` 先调用 Python 导出快照，再调用 `openapi-typescript` 生成声明（[contract.mjs:66](../scripts/contract.mjs:66)、[contract.mjs:105](../scripts/contract.mjs:105)）。类比来看，OpenAPI 是原始公证书，`api.d.ts` 是给前端看的官方译文；译文只能由机器从公证书生成。

**真实样本层。** `export_health_fixtures.py` 不解析 OpenAPI 自行造数，而是构造两个确定性 database double 后走 `httpx.ASGITransport` 调 `/api/health`，分别接受 200/503（[export_health_fixtures.py:66](../apps/api/scripts/export_health_fixtures.py:66)）。这让 fixture 保持“录音”属性：payload、省略字段、camelCase 和状态语义都来自真实 handler。

**校验层。** `checkContracts()` 每次在临时目录重算全部产物，再与 checked-in 文本逐字比较；缺失、stale、缺 `@generated` 都会汇总成可执行的 `pnpm contract:generate` 提示（[contract.mjs:134](../scripts/contract.mjs:134)）。CLI 的 stale 场景用 `spawnSync` 实测退出码 1（[gates.spec.mjs:181](../scripts/gates.spec.mjs:181)）。

**消费层。** `index.ts` 把生成 schema alias 成 `HealthResponse` 等稳定名，并 re-export 生成 fixture（[index.ts:23](../packages/contracts/src/index.ts:23)）。Web 测试不再手写 healthy/unavailable 对象，而是导入同一 fixture 并 `satisfies HealthResponse`（[contracts.test.ts:10](../apps/web/src/contracts.test.ts:10)）。

## §3 数据流走查

1. 开发者改 FastAPI DTO，例如把 `HealthResponse.phase` 改名或新增字段。
2. 运行 `pnpm contract:generate`。Python 屏蔽本机 `HE_*` 后生成 canonical OpenAPI；Node 生成 TS；ASGI 生成真实 health JSON，并再次包装成 typed fixture 模块（[contract.mjs:112](../scripts/contract.mjs:112)）。
3. CI 运行 `pnpm contract:check`。临时目录再次生成四件产物，和仓库版本逐字比对；忘记 regenerate 时 build 前失败并提示命令（[ci.yml:48](../.github/workflows/ci.yml:48)）。
4. Web 测试导入 `healthFixtures.healthy/unavailable`。若生成类型与真实响应不兼容，`satisfies` 在编译期失败，而不是等到浏览器运行时才发现字段缺失（[contracts.test.ts:13](../apps/web/src/contracts.test.ts:13)）。
5. 跨栈测试继续通过 Vite proxy 调真实 FastAPI，验证 health 200、auth envelope 和 database 503 三条行为链（[ci.yml:46](../.github/workflows/ci.yml:46)）。

## §6 讨论点

### 1. owning Note 的产物清单落后于实现

- 位置：[2026-10-25-openapi-contract-pipeline.md:15](../.agents/notes/implemented/architecture/2026-10-25-openapi-contract-pipeline.md:15)。
- 现象：Note 说 `contract:generate` 更新“快照与生成文件”、check 比较“both”，但实现已经覆盖快照、API TS、真实 fixture JSON 和 typed fixture TS。
- 问题：决策记录与代码事实不一致，未来维护者可能低估 `contract:check` 的覆盖面。
- 预判：应更新中英 Note 和 i18n 记录，不改变决策本身。
- 结论：✅ 2026-10-25 已修复；依据 `plans/fullstack-design` 的单源契约目标，Note 必须与四产物事实一致。

### 2. generated fixture 存在 JSON 与 TS 两份产物

- 位置：[contract.mjs:92](../scripts/contract.mjs:92)、[health-fixtures.ts:7](../packages/contracts/src/generated/health-fixtures.ts:7)。
- 现象：仓库同时保存真实响应 JSON 和由 JSON 生成的 typed TS wrapper。
- 问题：是否属于必要冗余，还是可以直接生成单一 TS fixture？
- 预判：保留两份更清楚——JSON 是与语言无关的真实响应档案，TS wrapper 只解决 TypeScript JSON import 会拓宽字面量类型的问题；两者都进防漂移检查。代价是多一个生成物和一个检查分支。
- 结论：✅ 2026-10-25 决定保留；JSON 是跨语言真实响应档案，TS wrapper 解决 TypeScript JSON import 拓宽字面量的问题，两者均受防漂移检查。

### 3. `SERVICE_PHASES`/`DATABASE_DIALECTS` 只验证子集

- 位置：[index.ts:12](../packages/contracts/src/index.ts:12)、[index.ts:18](../packages/contracts/src/index.ts:18)。
- 现象：`as const satisfies readonly ServicePhase[]` 允许数组少列未来新增的 enum 值。
- 问题：跨端常量是否要在本 PR 内改成 exhaustive keyed record？
- 预判：m1-04 的验收是类型来自 OpenAPI 且无手写接口重复；常量子集问题是 m1-05 消费 shell 更合适的收紧点。当前测试已钉住完整值集合，无现行 bug。
- 结论：✅ 2026-10-25 决定转 m1-05；当前 issue 只要求类型单源和无手写接口重复，常量 exhaustive 化属于 web shell 消费边界收紧。

## §9 文件级代码分析

### `apps/api/scripts/export_openapi.py` — A

职责是生成 canonical OpenAPI。新增的 `canonical_settings()` 像“拍照前清场”：先把所有 `HE_*` 变量拿走，禁用 `.env`，拍完再放回；因此快照只反映代码默认，而不是当前 shell 的临时身份。

```python
# 旧
Settings(db_dialect=DatabaseDialect.SQLITE)
# 新
Settings(db_dialect=DatabaseDialect.SQLITE, _env_file=None)
```

前者仍会继承 `HE_VERSION`；后者配合环境摘除，`HE_VERSION=contract-probe` 不再改变 `info.version`。检视发现：无。

### `apps/api/scripts/export_health_fixtures.py` — A

职责是录制真实响应。`ContractDatabase` 不是业务存储，只是让 handler 走完整 HTTP/Pydantic 路径的确定性底座；`UnavailableContractDatabase` 只改变 `health()` 结果。这样 503 不是测试文件里的想象，而是 ASGI 响应的真实 JSON。检视发现：依赖 sibling export 脚本提供 canonical settings/canonicalize，属于小耦合，可接受。

### `apps/api/app/api/health.py` — M

`ok` 和 `service` 从带默认值改为 required，并在构造处显式传值。差异很关键：默认值会让 OpenAPI 认为字段可缺，前端因此可能写出“缺字段也合法”的分支；显式 required 让 200/503 的稳定骨架固定。检视发现：无。

### `scripts/contract.mjs` — A

职责是把“生成”和“公证”分开。`render()` 是工厂，`checkContracts()` 先渲染到 `mkdtemp` 目录再比较，失败后 `finally` 清理；不会为了 check 而污染工作树。`pathToFileURL` 也修正了 CLI 入口在 Windows 路径下的比较方式。检视发现：generated fixture 路径目前固定，只有 JSON fixture 可注入；这是为可测试性付出的少量不对称，无现行生产影响。

### `apps/web/src/contracts.test.ts` — A

旧方案会在测试里手写两个 payload；新方案导入 `healthFixtures`。当 FastAPI 和生成类型漂移时，`satisfies HealthResponse` 会在 typecheck 失败；当 handler payload 与 fixture 漂移时，`contract:check` 失败。两条路径共同防止“手写样例跟着错误类型一起改”的盲点。检视发现：无。

### 测试与门禁 — A/M

`test_openapi.py` 用子进程污染环境验证 executable workflow；`test_app.py` 钉住 required 五字段；`gates.spec.mjs` 覆盖 missing snapshot/types/fixtures 和 stale CLI nonzero。CI 在 build 前执行 contract check，测试 lane 覆盖前后端覆盖率与真实 MySQL。检视发现：无。
