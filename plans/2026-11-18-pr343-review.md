## §1 一页速览

**一句话**：把 24 个门禁/工具脚本的“我是不是被直接执行”判断，从 POSIX 专用字符串比较换成跨平台的 `isMain()`，并修掉 `verify-web-style` 在 Windows 上把盘符路径当 URL 协议的崩溃。

**一个比喻**：入口守卫像公司门禁的读卡器。POSIX 发的是正斜杠工牌，Windows 发的是反斜杠工牌；旧读卡器只认一种，于是 Windows 员工刷了卡、门没开，系统却显示“已通过”——这就是 `no-op exit 0` 的假绿。`isMain()` 先把两种工牌都换成同一种 URL 格式（`file:///...`），再比对，门才真的开。

## §2 架构导览

### 2.1 `isMain()`：唯一的入口判断

`scripts/is-main.mjs:15-21` 是全部入口的唯一判断：

```js
export function isMain(moduleUrl, entryPath = process.argv[1]) {
  if (!entryPath) return false;
  try {
    return moduleUrl === pathToFileURL(realpathSync(entryPath)).href;
  } catch {
    return false;
  }
}
```

为什么不是一句 `import.meta.url === pathToFileURL(process.argv[1]).href`：

- `realpathSync` 解决“经符号链接进入”的差异。实测 macOS 上 `node /tmp/x.mjs` 时 `process.argv[1]` 是 `/tmp/x.mjs`，而 `import.meta.url` 是 `file:///private/tmp/x.mjs`（`/tmp` 是符号链接）；不做 realpath 会误判为 false，CLI 静默退出。经 `ln -s` 的入口同样被正确识别。
- `pathToFileURL` 负责把 Windows 的 `D:\repo\scripts\x.mjs` 转成 `file:///D:/repo/scripts/x.mjs`，与 Node 的 `import.meta.url` 形态一致。
- `try/catch` 让不存在的 `argv[1]` 返回 false，而不是抛错；空 `argv[1]`（模块被 import）直接 false。

`moduleUrl` 是调用方传入的 `import.meta.url`，helper 不去猜调用者路径；这也让 `gates.spec.mjs` 能用任意 URL/路径对做单测。

### 2.2 24 个调用点

22 个旧脚本各加一行 `import { isMain } from "./is-main.mjs";`，把 ``if (import.meta.url === `file://${process.argv[1]}`)`` 换成 `if (isMain(import.meta.url))`。`contract.mjs:15,259` 与 `performance-report.mjs:8,71` 原本已是安全写法，这次一并收口，避免仓库里存在第二套入口判断。没有改任何 `main()`、参数解析或退出码。

### 2.3 `verify-web-style` 的目录枚举与文件读取

`scripts/verify-web-style.mjs:24-32`：

```js
const sourceRoot = new URL("../apps/web/src", import.meta.url);
const entries = await readdir(sourceRoot, { recursive: true, withFileTypes: true });
...
const filePath = path.join(entry.parentPath, entry.name);
const source = await readFile(pathToFileURL(filePath), "utf8");
```

关键事实（实测）：`readdir` 传 URL 时，`Dirent.parentPath` 仍是**绝对路径字符串**，不是 URL。POSIX 上以 `/` 开头，Windows 上以 `D:\` 开头。旧代码把它拼成 `${parentPath}/${name}` 再交给 `new URL(path, sourceRoot)`：以 `D:` 开头的字符串被 URL 解析器当成 `d:` 协议，抛 `ERR_INVALID_URL_SCHEME`（pr160 检视 §6-2 的 Windows 实测栈）。新代码只让 URL 解析器处理真正的 `file:` URL，路径拼接交给 `path.join`。

### 2.4 三层回归

`scripts/gates.spec.mjs:547-604`：

1. **单测**：`isMain` 对绝对、相对、含空格路径为 true，对别的路径与空值为 false；含空格样本建在真实临时目录里，验证 URL 编码不是问题。
2. **静态审计**：扫描 `scripts/*.mjs`；任何脚本不得再出现旧模板串；凡出现 `isMain(import.meta.url)` 的文件必须从 `./is-main.mjs` 导入。它防“漏改一个文件”。
3. **CLI 冒烟**：把 `is-main.mjs` 与 `verify-web-style.mjs` 复制到临时 checkout，先放一个合法 Vue 文件断言 exit 0 且打印成功行，再放一个字面色样本断言 exit 1 且报 `tokens.css`。它防“入口通了但门禁主体没跑”。

## §3 数据流走查

以 `pnpm verify:web-style` 为主角：

1. `node scripts/verify-web-style.mjs` → `process.argv[1]` 为该脚本路径。
2. `isMain(import.meta.url)`：`realpathSync(argv[1])` → `pathToFileURL(...)` → 与 `import.meta.url` 比；Windows 盘符、POSIX 符号链接都在这一步归一。
3. 进入主块：`sourceRoot = new URL("../apps/web/src", import.meta.url)`，`readdir(..., { recursive: true, withFileTypes: true })` 得到每个 `.vue` 的 `Dirent`。
4. 每个文件：`path.join(entry.parentPath, entry.name)` 得绝对路径 → `pathToFileURL` 得 `file:` URL → `readFile` 读源码。
5. `assertTokensAreOnlyColorSource`：跳过 `tokens.css`，其余出现 `#...`/`rgba(` 即抛错；CLI 以非零退出。
6. 成功路径打印 `verify-web-style: Vue components use token colors only`。

Windows 与 POSIX 的差异只落在第 2、4 步的路径→URL 归一；第 5 步的判定逻辑逐字未动。

### 6-3 [P3] `flow:sync` 每次都会重发全部状态 PATCH（既有缺陷，观察到但不在本 PR 修）

**位置**：`scripts/flow-sync.mjs:181-195`。

**现象**：执行 `pnpm flow:sync` 时输出 118 条 `→ #150 CLOSED` 之类的状态更新，但 #150 早在 2026-10-29 就已关闭；实际只有 #245 的状态变了。根因：`gh()` 返回字符串，`gh([...]).state` 恒为 `undefined`，`undefined === "CLOSED"` 恒假，于是每个 issue/milestone 都走一次幂等 PATCH。

## §9 文件级代码分析

### 9.1 `scripts/is-main.mjs`（A）

**职责**：判断调用模块是否进程入口。**依赖**：`node:fs` 的 `realpathSync`、`node:url` 的 `pathToFileURL`，都是 Node 内建，无第三方。

旧代码 vs 新代码：

```js
// 旧（22 处）：POSIX-only
if (import.meta.url === `file://${process.argv[1]}`) { ... }

// 新：所有入口共用一个判断
if (isMain(import.meta.url)) { ... }
```

实现思路（≤3 行）：先 realpath 消除符号链接差异，再转 file URL 对齐 `import.meta.url`；空了返回 false，不存在返回 false。

**检视发现**：无。`catch` 吞掉 `realpathSync` 的异常是有意为之（守卫不应因路径探测失败而崩溃）。

### 9.2 `scripts/verify-web-style.mjs`（M）

**职责**：设计 token 之外禁止字面色。**变更形态**：守卫换 helper + 文件路径 URL 化。

旧代码 vs 新代码：

```js
// 旧：Windows 盘符路径被当成 d: 协议
const path = `${entry.parentPath}/${entry.name}`;
const source = await readFile(new URL(path, sourceRoot), "utf8");

// 新：路径拼接走 path，URL 只由 file: 负责
const filePath = path.join(entry.parentPath, entry.name);
const source = await readFile(pathToFileURL(filePath), "utf8");
```

**检视发现**：错误信息里的路径仍和旧实现一样是绝对路径（旧实现 POSIX 上 `parentPath` 也是绝对路径），不是新引入的隐私/可读性变化。

### 9.3 `scripts/gates.spec.mjs`（M）

新增三段见 §2.4。`legacyGuard` 用字符串拼接构造，避免测试文件自己命中静态审计；CLI 冒烟用 `spawnSync` 起真实子进程，而不是直接 import 函数，因此能证明“入口守卫真的放行”。

**检视发现**：静态审计原先把 `gates.spec.mjs` 自己也计入 guard（它只在测试里调用 `isMain`）。已在本检视提交中跳过 spec 文件，让 guard 计数只代表真实 CLI 入口。
