## §1 一页速览

一句话：给运行详情第 2 步补上「短标签」这条数据通路，并用固定列宽把 Session 单元格从「一整面墙的 prompt」收成「门牌号 + 完整标题悬停」。

比喻：Session 行像一排门牌。原来门上直接贴了租客写的 3337 字自我介绍，门牌被撑得把隔壁三个门牌挤到墙缝；现在门上只贴短名，全文收在门后的 `title` 标签里，门框宽度固定，隔壁门牌自然回位。

交付块：

| 块 | 内容 |
|---|---|
| API | `StepSessionRow.short`；准备阶段持久化；存量行 `title[:120]` 回退 |
| Web | `short || title` 可见文本；`title` 悬停；单行省略；`table-layout: fixed` + `colgroup` |
| 回归 | API 持久化/回退、组件超长标题、E2E 几何与溢出 |
| 文档 | 05 §3.6、08 §10.1、Agent Note |
| 证据 | release `run-detail-session-step2-evidence-20261120` 的 Before/After/原型对照 |

验证基线：`pnpm test:web`、`pnpm test:api`（覆盖率 91%）、`pnpm test:e2e -- m10-06`（3/3）、`pnpm test:gates`（32/32）、`pnpm verify:docs`、`pnpm verify:flow --diff`、`pnpm contract:check`、lint/typecheck/build 均通过。

## §2 架构导览

### 2.1 数据层：准备阶段本来就有短名

`AssociatedSession` 在潜在匹配服务里同时带 `short` 与 `title`（`apps/api/app/service/evolution/potential.py` 的关联结果）；`short` 来源是 `session_families.short_title`。但准备阶段写 `stats.sessionRows` 时只挑了 `sessionId/title/objectTriggerAt/badCaseCount`（`prepare.py:189-198`），`short` 在这一步被丢掉。这里的机制像仓库拣货：货架上明明有「短名」标签，打包时却只扫了「长描述」。

修复只在快照里多写一个字段（`prepare.py:193`），不改关联算法、不重算匹配。快照是 run 的只读事实，准备完成后第 2 步只读它，所以补字段不会改变任何统计口径。

### 2.2 契约层：可选字段，读侧兜底

`StepSessionRow` 在 `stages.py:120-127` 增加 `short: str | None = None`。Pydantic 把它放在 OpenAPI 的非 required 列表，因此旧客户端与旧 run 都不受影响；`packages/contracts` 的两个文件由 `pnpm contract:generate` 生成，没有手改。

读取路径在 `_v2_session_rows`（`stages.py:791-820`）：先取持久化的 `title` 与 `short`，`short` 为空时用 `_short_label(title)` 截前 120 字符（`stages.py:786-789`）。这样 2026-11-20 之前准备的 run 不需要重新跑准备任务，符合 issue 的「不要求历史 run 重新准备」。legacy probe 行在 `_legacy_session_rows`（`stages.py:843-862`）同样给出短标签。

### 2.3 展示层：固定布局把「内容撑宽」变成「内容被裁剪」

`StepSessions.vue` 的改动集中在三处：

- 模板 `46-51`：`<colgroup>` 四列，Session 列自适应，触发点列 220px，两个计数列各 130px。
- 模板 `63-73`：可见文本 `row.short || row.title || "未命名 Session"`；`<b class="session-title" :title="row.title ?? undefined">`；Session ID 仍在下一行。
- 样式 `177-204`：`table-layout: fixed`、`min-width: 680px`、`.session-title` 单行省略；外层 `.table-scroll` 继续承接窄视口的横向滚动。

关键机制是 `table-layout: fixed`：浏览器不再根据内容计算列宽，而是按 `colgroup` 的声明分配，剩余宽度给 Session 列。长 prompt 因此只能在自己的单元格里被省略号裁掉，不能再反向挤压其它列。

### 2.4 回归层

- API：准备阶段持久化 `short`（`test_m10_04_prepare.py:206`）；阶段接口返回 `short`（`test_m10_04_stages.py:78`）；存量行回退（`test_m10_04_stages.py:93`）。
- 组件：超长标题下可见文本为短标签、`title` 属性为全文（`RunDetail.test.ts:729`）。
- E2E：真实浏览器断言首行高度、Session 列占比、四列表头宽度、表格无横向溢出（`m10-06-run-detail-v2.test.mjs:350-400`）。

## §3 数据流走查

一条端到端主线：

1. 准备阶段拿到关联结果 `AssociatedSession(session_id, short, title, ...)`。
2. `prepare.py:189-198` 把四个字段写进 `run.stats.sessionRows`，现在多一个 `short`。
3. 第 2 步接口 `_v2_session_rows` 读快照；有 `short` 用 `short`，没有就 `title[:120]`，转成 `StepSessionRow`。
4. 响应序列化为 `payload.rows[]`，`short` 和 `title` 同时在。
5. `StepSessions.vue` 用 `short` 显示、用 `title` 悬停；`table-layout: fixed` 保证四列稳定。
6. 分页、统计、排序仍读同一份快照的既有字段，不受影响。

一个具体例子：本次 fixture 的 `v2-session-1`，`title` 是 3337 字符合成 prompt，`short` 是「来源运行 A」。Before 表格首行 421.7px，Session 列 1231px；After 首行 49.9px，Session 列 919px，触发点/bad case/潜在三列 220/130/130px。V2 原型同视口首行 49.7px、表高 229.9px，与 After 基本对齐。

## §6 讨论点

### D1 回退截断的边界

- **位置**：`apps/api/app/service/evolution/stages.py:786-789`
- **现象**：存量行没有 `short` 时取 `title[:120]`。
- **问题**：120 是展示截断长度，不是语义标题；存量 run 仍会显示 prompt 前缀，且可能截断在词中间。
- **预判**：这是 issue 明确的兼容方案，避免重跑历史准备；语义标题应从上游或首条 prompt 提取，另开问题。
- **结论**：（留空）

### D2 固定列宽与窄视口

- **位置**：`apps/web/src/pages/evolution/components/StepSessions.vue:179-204`
- **现象**：`min-width: 680px` + `colgroup` 220/130/130。
- **问题**：内容容器窄于 680px 时表格横向滚动；此时 Session 列约 200px，标题只剩很短的省略号。
- **预判**：运行详情在 ≤640px 已走移动端页级滚动分支，680px 以下的横向滚动是既有 `.table-scroll` 设计的延续；不影响 1440/1500 验收。
- **结论**：（留空）

### D3 悬停范围只在标题文本

- **位置**：`apps/web/src/pages/evolution/components/StepSessions.vue:67`
- **现象**：`title` 属性加在 `<b>` 上，不在整个 `<td>` 上。
- **问题**：鼠标停在 Session ID 或单元格空白处不会出现完整标题提示。
- **预判**：与原型和启动向导的约定一致，标题文本是主要交互目标；扩大到整格会让悬停区域过大。无实害。
- **结论**：（留空）

### D4 原型多出的「对象出现」列

- **位置**：`plans/ui-prototype-v2/harness-evolution.html`（第 2 步表格）
- **现象**：原型有 5 列，实现在本次仍为 4 列。
- **问题**：视觉对照时列数不同，Session 列相对更宽。
- **预判**：issue #440 明确将列口径差异排除在根因外，本 PR 只修标题渲染；补列需要单独的信息架构确认。无实害。
- **结论**：（留空）

### D5 契约新增字段的兼容性

- **位置**：`packages/contracts/openapi.json`（`StepSessionRow.short`）
- **现象**：`short` 是非 required、可空字段。
- **问题**：旧前端忽略它即可；新前端对旧 API 仍能 `row.short || row.title` 回退。
- **预判**：双向兼容，无需版本切换。
- **结论**：（留空）

## §9 文件级代码分析

### `apps/api/app/service/evolution/prepare.py`

职责：准备阶段写 run 快照。变更形态 M。旧代码的 `sessionRows` 字典只有四个键；新代码多一个 `"short": session.short`。这是「把已存在的数据带过去」，没有新查询、没有新计算。

### `apps/api/app/service/evolution/stages.py`

职责：七步只读投影。变更三处：

- DTO `StepSessionRow` 增加 `short`（可选默认 None），让契约能表达短标签。
- `_short_label` 把标题截到 120 字符，读取侧统一兜底。
- `_v2_session_rows` 读取 `short` 并回退；`_legacy_session_rows` 从列表推导改成 for 循环，只为复用 `title` 变量算 `short`。

实现思路：写侧尽量少改，读侧兼容历史；短标签的「120」只在一个助手函数里出现。

### `apps/web/src/pages/evolution/components/StepSessions.vue`

职责：第 2 步表格组件。旧代码 `<b>{{ row.title ?? "未命名 Session" }}</b>`，表格自动布局。新代码用 `short` 优先、`title` 悬停、单行省略，并在 `<table>` 前三列之外声明 `colgroup`。固定布局是本次「止血」的核心：没有它，单行省略仍可能被长内容反向撑列。
