## 1. 一页速览

一句话：启动向导的版本字段从“只能从 tag 下拉里选”变成“下拉给 tag 建议、输入框可以填分支或 commit，提交时由服务端用 git 确认这个 ref 真的存在”。

一个比喻：原来的版本字段像只卖套餐的取餐口，你只能点菜单上的 tag；现在是一个带推荐菜单的自助窗口，你可以照着推荐点，也可以报一个菜单外的分支名或 commit 号，但厨房（服务端）会先去仓库里确认这个原料真的存在，不存在就退回第 1 步。

## 2. 架构导览

### 2.1 前端状态与交互

`LaunchWizard.vue` 仍是单一 SFC 的四步向导。新增的版本状态只有三项：`versionOpen`（建议菜单是否展开）、`versionFormatError`（本地格式错误文案）、以及沿用原有的 `targetVersion` / `versionPinned`。

- 建议列表由 `versionSuggestions` 生成：先放 `defaultRef`，再放 tag 并去重（`LaunchWizard.vue:222`）。这样分支基线不会因为不在 tag 列表里被静默替换成第一个 tag。
- 默认值由 `defaultVersion()` 选取：`defaultRef` 优先，否则第一个建议（`LaunchWizard.vue:243`）。
- `versionPinned` 是“用户已经明确选/填过”的锁：用户输入或点建议后为 true；异步的 versions 查询返回时不会覆盖用户输入。用户切对象/类型时重置。
- 建议菜单由 `versionOpen` 控制，`versionKind()` 把 `defaultRef` 标成“基线”，其余标成“tag”（`LaunchWizard.vue:254`）。点建议走 `pickVersion()`（`LaunchWizard.vue:267`），既写值又清错误。
- 点击组合框外部时由 `handleDocumentClick()` 关闭菜单（`LaunchWizard.vue:164`）；Escape 先关菜单，再按一次才关整个向导。

### 2.2 提交与校验

- `condition()` 提交前对 `targetVersion` 做 `trim()`（`LaunchWizard.vue:525`），空值仍按缺省交给后端 `defaultRef`（但本地必填校验会先拦住空输入）。
- `versionRefFormatError()` 在本地拦截明显非法的 git ref（`LaunchWizard.vue:501`）：空、超 96 字符、空白/控制字符、`..`/`@{`/`//`、`~^:?*[`、反斜杠、前导 `-`/`/`、尾随 `/`/`.`/`.lock`。
- `validateStep1()` 把格式错误写入 `fieldErrors.version`（`LaunchWizard.vue:549`）；错误文案优先展示服务端内容解析错误，其次本地格式错误。
- 真正的“仓库里是否存在”仍由服务端 `TargetContentResolver` 用 `git rev-parse --verify <ref>^{commit}` 判断；不存在返回 `TARGET_CONTENT_UNRESOLVED`（reason `ref_not_found`），前端 `handleContentUnresolved()` 把向导拉回第 1 步。这一层没有改代码，新增测试证明它接受分支和 commit，并拒绝不存在的 ref。

### 2.3 测试与证据

- 前端组件测试：分支 `defaultRef` 不在 tag 列表时仍默认选中；建议菜单内容；点建议；手输 commit/branch；提交 body 使用输入的 ref；本地格式错误；服务端 `ref_not_found` 文案。
- resolver 测试：真实本地 git 仓库中 `main` 与 `HEAD` commit 解析到同一个 body hash；`feature/does-not-exist` 返回 `ref_not_found`且不回退 tag。
- E2E：`m10-05` 仍走完整四步流程，只是版本从“选 option”变成“填 input”；截图前展开建议菜单；第二个 `m10-05` 用例专门验证缺失 ref 的 `ref_not_found` 错误。`m11-05` 同步输入方式。

## 3. 数据流走查

1. 用户打开向导，选择 `synthetic-review`；`useEvolutionTargetVersions` 请求 `GET …/targets/{id}/versions`。
2. `versionSuggestions` 合并 `defaultRef` 和 tag；`defaultVersion()` 选中 `defaultRef`（若它是分支则直接显示分支名）。
3. 用户可直接输入 `feature/foo` 或 `a3f9c21`；`onVersionInput()` 把 `versionPinned` 设为 true，后续 versions 查询更新不会覆盖。
4. 点“下一步”：`validateStep1()` 先做本地格式校验；通过后 `condition()` 带 `targetVersion` 调 `previewSessions`。
5. 服务端 `TargetContentResolver.resolve` 用 git 解析该 ref；存在则继续读 `SKILL.md`/`AGENT.md` 算 body hash；不存在返回 `TARGET_CONTENT_UNRESOLVED` / `ref_not_found`。
6. 前端 `handleContentUnresolved` 回到第 1 步，字段下方显示“该版本在仓库中不存在…”，用户改值后 watch 清错误再试。
7. 预览通过后进入第 2–4 步；最终 start 仍走同一 `condition()`，服务端再次解析 ref，避免“预览时存在、启动时已删除”的漂移。

## 6. 讨论点

### 6-1 生产 UI 最初与原型不一致（已修复）

**位置**：`LaunchWizard.vue` 版本字段与 `plans/ui-prototype-v2/harness-evolution.html` 启动向导。
**现象**：第一版生产实现用了原生 `<input list>` + `<datalist>`，没有原型里的明显下拉按钮和可见建议菜单；截图对比只能看到“普通输入框”。
**问题**：用户要求“前端 UI 按原型设计”，且原型明确是“输入 + 下拉建议”；原生 datalist 在截图和部分浏览器里不可见，验收时会被判为未对齐。
**预判**：应改成自定义组合框，保留输入自由度的同时让建议菜单可见。
**结论**：已修复（2026-11-19）。生产改为输入框 + `▾` 按钮 + `listbox` 菜单，菜单项显示 ref 与 `tag`/`基线` 标签；E2E 截图改为展开菜单后拍摄。

### 6-2 `focusCase` 的版本线索曾只接受 tag（已修复）

**位置**：`applyFocusCase()`，`LaunchWizard.vue:397`。
**现象**：原来只有 `caseData.objectVersion` 出现在 target 的 tag 列表或等于 `defaultRef` 时才采用，否则回退默认值。
**问题**：bad case 线索可能是分支或 commit；在“可输入任意 ref”后，这个限制会把线索丢掉，用户看到的是别的版本。
**预判**：线索非空就优先采用，让服务端去判断是否存在，失败再回第 1 步。
**结论**：已修复（2026-11-19）。现在 `caseData.objectVersion || defaultRef || 第一个 tag`。

### 6-3 本地格式校验与原型的规则重复（接受）

**位置**：`versionRefFormatError()`，`LaunchWizard.vue:501`。
**现象**：前端复刻了服务端 `_unsafe_ref`/git ref 规则；两处可能随需求漂移。
**问题**：重复规则增加维护成本；但如果没有本地校验，非法 ref 要等一次网络请求才报错，和原型/设计“下一步前字段级校验”不一致。
**预判**：保留本地格式校验，服务端仍是最终权威；测试覆盖两端的典型规则，后续如改规则需同步。
**结论**：接受。服务端 `ref_invalid`/`ref_not_found` 仍是权威语义，本地只做明显非法值的快速反馈。

### 6-4 建议菜单没有方向键导航（接受）

**位置**：`LaunchWizard.vue:1050` 附近组合框模板。
**现象**：菜单项是原生 `button`，可用 Tab/Enter 操作；没有 ArrowDown/ArrowUp 在选项间移动。
**问题**：严格的 ARIA combobox 期望方向键导航；原型也没有实现方向键。
**预判**：当前是原型对齐阶段，按钮可聚焦、点击可选，不阻塞主路径；后续做无障碍完善时再补。
**结论**：接受，记录为后续可选增强，不在本 PR 扩面。

### 6-5 建议菜单在 focus 时自动展开（接受）

**位置**：版本输入 `@focus="versionOpen = true"`。
**现象**：点进输入框就会展开菜单，可能遮住下方说明或错误文案。
**问题**：错误修正时菜单盖住错误提示，视觉上不够安静；但用户可直接输入，菜单也会随外部点击关闭。
**预判**：可以改成只在点 `▾` 或输入时展开；但目前“点输入框即看建议”符合组合框预期，且原型也是展开态。
**结论**：接受，暂不改。

### 9.1 `apps/web/src/pages/evolution/components/LaunchWizard.vue`（M）

**职责**：四步启动向导；本 PR 只改版本字段、校验和错误文案。
**依赖**：Vue 3 `ref/computed/watch`、TanStack Query（`useEvolutionTargetVersions`）、现有 API transport。组合框是本地 DOM + scoped CSS，没有引入新依赖。
