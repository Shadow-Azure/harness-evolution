## §1 一页速览

一句话：这个 PR 把开发机上 Claude Code 的 root/subagent JSONL 收拢成稳定的 `(root_session_id, agent_id)` payload，同时只建立未处理索引，给后续归一化留下明确入口。

生活化比喻：每个 Agent 的 JSONL 像一份已经封好的档案，`trajectory_payloads` 是档案柜，`source_records` 是“待处理清单”；这个 PR 只负责按身份把档案放进柜子、把名字写进清单，不在放档案时顺手做内容摘要。

| 交付块 | 结论 |
|---|---|
| 目录发现与身份校验 | 主路径正确；root symlink 经 CLI 解析后可绕过拒绝，见 D2 |
| JSONL 原文、hash、行数 | 原文与 hash 正确；`splitlines()` 会误切合法 Unicode 行分隔符，见 D3 |
| 事务导入与重跑 | SQLite 实测稳定；MySQL `DATETIME` 秒精度会破坏重跑零更新，见 D1 |
| 复合主键语义 | 数据库使用 `(root, agent)`；扫描器额外要求 agent 全局唯一，见 D4 |
| 隐私与 Git 卫生 | 正文不输出、本地目录未跟踪；source-root symlink 边界仍有缺口，见 D2 |
| 测试与 CI | 合成测试和本地聚合验证充分；缺 MySQL 时间往返与若干边界回归，见 D1–D5 |

## §2 架构导览

### 2.1 扫描层：目录是输入协议，不只是一个路径

`scan_local_sessions()` 先拒绝 source root 和树内 symlink，再只把顶层 `.jsonl` 当作 root transcript，并把每个 root 目录下的 `subagents/agent-*.jsonl` 与同名 `.meta.json` 精确配对（`apps/api/app/service/acquisition/local_sessions.py:261-339`）。

root 身份来自文件名；subagent 身份同时来自文件名、每行 JSONL 和 root 目录。主 Agent 的 `agent_id` 等于 root session id，子 Agent 使用 provider `agentId`，这与 [06 §3.0](plans/fullstack-design/06-database-design.md:105) 的 `(root_session_id, agent_id)` 读取键一致。

扫描器把所有 payload 先放进 `LocalSessionCorpus`，失败时尚未打开数据库（`local_sessions.py:368-391`）。这把“文件形状错误”和“数据库写一半”分开，错误分类是清楚的。

### 2.2 载荷层：正文只存一次，派生值不手填

`_read_payload()` 直接读 bytes，按原始 payload 计算 SHA-256，并拒绝空文件、非 UTF-8、空行和超过 64 MiB 的单文件（`local_sessions.py:140-157`）。总目录上限另设为 512 MiB（`local_sessions.py:29-30`、`341-343`）。

JSONL 每行通过 `object_pairs_hook` 拒绝重复键（`local_sessions.py:118-125`、`160-172`）。meta 则经过 Pydantic 封闭模型，未知字段会失败（`local_sessions.py:40-61`、`234-238`）。

### 2.3 持久层：一份 payload，一份未处理索引

`write_local_payloads()` 在单次 `database.transaction()` 中先 upsert `trajectory_payloads`，再 upsert `source_records`（`apps/api/app/db/crud/local_sessions.py:36-132`）。首次 source 索引显式写 `processed_* = NULL`，表示后续归一化仍应处理它（`local_sessions.py:95-109`）。

重跑时只更新 payload 的 source-owned 字段，以及 source index 的 `kind/source_type/line_count`；运行态列不进入更新集合（`local_sessions.py:112-125`）。这个方向正确，但时间列的比较还没有吸收 MySQL 的秒级存储语义，见 D1。

### 2.4 命令层：Node 只做桥，Python 掌握规则

`scripts/local-sessions.mjs` 固定选择 `apps/api/.venv`，把 `import|verify` 映射到 Python CLI，并默认使用 `data/harness-evolution.sqlite`（`scripts/local-sessions.mjs:8-57`）。真正的环境拒绝、扫描和写入都在 Python service 内。

CLI 只打印 `asdict` 后的聚合对象（`apps/api/app/cli.py:179-201`），错误路径由 `LocalSessionSourceError` 收敛为无路径文本。主数据流因此没有把 transcript 正文带入 stdout。

## §3 数据流走查

### 场景 A：首次导入四个真实 root session

1. `pnpm data:import:sessions` 进入 Node 桥，定位 Python 与默认 SQLite 路径（`scripts/local-sessions.mjs:28-50`）。
2. Python 先构造 `Settings`，随后 `_ensure_local_environment()` 在扫描前拒绝 production/live（`local_sessions.py:360-374`）。
3. 扫描器枚举顶层 root JSONL，验证 root 文件名是 UUID、至少一条 JSONL 声明同值 `sessionId`，把所有声明冲突视为错误（`local_sessions.py:278-297`、`184-210`）。
4. 对每个 root 的 subagents 目录生成 payload/meta 一对一映射，并检查 JSONL 中的 session/agent 身份（`local_sessions.py:300-339`）。
5. 所有文件通过后，`local_sessions.py:375-393` 建库、升级 schema，再调用一次事务写入。
6. `write_local_payloads()` 先写原文、hash、行数、meta 和 provider mtime，再建立未处理 source index（`crud/local_sessions.py:46-125`）。
7. 聚合结果是 4 roots、66 JSONL、62 subagents、66 payload/source rows；本地命令实际返回该结果。

### 场景 B：重复导入且归一化状态已经存在

1. 扫描再次产生同一组 `(root, agent)` 稳定键，原文与 mtime 未变时 payload 判定 unchanged。
2. source index 已存在，更新候选只有 `kind/source_type/line_count`；`processed_at/processed_hash/parser_version/last_sync_run_id/received_at` 不在更新集合内（`crud/local_sessions.py:86-125`）。
3. SQLite 测试先人为写入 normalized 状态，再重跑，确认 processed 三列保持不变（`test_local_session_import.py:302-388`）。
4. MySQL 上 provider mtime 含微秒而目标列是 `DATETIME` 秒精度，第一次写入会被截断；第二次比较会把同一个文件误判为 `updated_at` 变化，见 D1。

### 场景 C：源文件错误或身份不匹配

1. malformed JSON、重复 JSON key、缺 meta、孤 meta、错误 agent/session ID 都在建库前失败（`test_local_session_import.py:173-198`）。
2. 文件系统 `OSError` 被换成不带路径的 `LocalSessionSourceError`（`local_sessions.py:128-137`、`140-145`、`267-310`）。
3. production/live 在扫描和数据库创建前失败，测试确认数据库文件不存在（`test_local_session_import.py:434-444`）。
4. 但 CLI 先对 `--sessions-dir` 调用 `.resolve()`，会把 source-root symlink 解析成真实目录，之后再进入扫描器时已看不到 symlink，见 D2。

## §6 讨论点

### D1 MySQL 秒精度会让未变 payload 每次都被标记为更新

**位置**：`apps/api/app/service/acquisition/local_sessions.py:175-181`、`208,248`；`apps/api/app/db/crud/local_sessions.py:66,72-77`；`apps/api/alembic/versions/0004_domain_fixtures.py:34`

**现象**：真实本地 66 个 JSONL 的 mtime 全部带小数秒；`updated_at` 直接写入 `datetime`。SQLAlchemy 生成的 MySQL DDL 是 `DATETIME`，未指定 `fsp`。把一个 SQLite payload 的 `updated_at` 模拟成 MySQL 往返后的整秒值后，再执行同一份导入，结果为 `updated_payloads=1, unchanged_payloads=0`。

**问题**：SQLite lane 的“重复导入 0 updated”不能证明 MySQL。只要本地导入指向 MySQL，每个文件首次入库后被截断到秒，下一次导入都会因 microsecond 差异重写 payload 行，破坏 issue 的“重复输入零副作用”。

**预判**：这是双方言契约差异，优先级 P2；建议要么统一在应用层把 source timestamp 截到存储精度，要么把目标列明确升级为双方言可表达的固定精度，并用真实 MySQL 往返或可复现的秒级模拟测试锁定。

**结论**：已修复（2026-10-25）。source timestamp 在写入和比较前统一为秒精度，并新增 MySQL 往返模拟：同一文件重导为 0 updated / 5 unchanged；真实 MySQL lane 由 CI 复核。

### D2 CLI 的 `.resolve()` 绕过 source-root symlink 拒绝

**位置**：`apps/api/app/cli.py:179-189`；`apps/api/app/service/acquisition/local_sessions.py:261-276`

**现象**：service 明确规定 `source_root.is_symlink()` 时拒绝；但 CLI 在调用 service 前执行 `args.sessions_dir.resolve()`。用指向真实 session 目录的 symlink 作为 `--sessions-dir`，命令返回 0 并导入 1 个 payload，而不是拒绝。

**问题**：源代码写了两层安全语义，公共入口却把第一层消掉。后续若以 symlink 来隔离或切换数据源，实际读取目标与调用者看到的位置不一致，路径边界测试也无法代表 CLI 行为。

**预判**：P2。建议入口先检查用户传入的路径是否为 symlink，或只做不解析 symlink 的绝对化；补一条 CLI-level root symlink 回归。

**结论**：已修复（2026-10-25）。CLI 改为不跟随 symlink 的绝对化；import/verify 两个入口都在建库前拒绝 source-root symlink，且错误不包含路径。

### D3 `splitlines()` 会误切合法 JSON 字符串中的 Unicode 行分隔符

**位置**：`apps/api/app/service/acquisition/local_sessions.py:154-165`

**现象**：JSONL 使用 LF 分隔记录，但代码用 Python `str.splitlines()` 同时识别 `U+2028`、`U+2029`、`U+0085` 等字符。构造一条 message 中含字面量 `U+2028` 的合法 JSON record，扫描返回 `root transcript is not valid JSONL`。

**问题**：这些字符可以作为 JSON 字符串内容出现；Claude transcript 的用户或助手文本没有禁止它们。当前实现会把合法 transcript 拒绝，后续行数也会被错误放大。

**预判**：P2 数据兼容问题。建议只按 JSONL 的 `\n` 切分，并显式处理可选的尾随 `\r`；补 `U+2028`/`U+2029` 在字符串内的回归。

**结论**：已修复（2026-10-25）。JSONL 改为只按 LF/CRLF framing；字符串内的 U+2028、U+2029、U+0085 保留为正文，行数按真实 JSON 记录计算。

### D4 扫描器把复合键错误收紧为全局 agent_id 唯一

**位置**：`apps/api/app/service/acquisition/local_sessions.py:341`

**现象**：两个合法 root session 各自拥有相同 provider `agentId` 时，扫描返回 `duplicate agent id`。数据库主键与 `source_records` 唯一约束实际都是 `(root_session_id, agent_id)`（`apps/api/app/db/models/domain.py:25-38,57-88`）。

**问题**：provider 只承诺 agent ID 能区分同一棵树中的节点，不承诺跨 root 全局唯一；当前扫描器比落库契约更严格，会让合法复合键无法导入。

**预判**：P2/P3 兼容性风险。若允许同一 agent ID 在不同 root 复用，去重键应改为 `(root_session_id, agent_id)`，并补跨 root 同 ID 测试。

**结论**：已修复（2026-10-25）。扫描去重改为 `(root_session_id, agent_id)` 复合身份；不同 root 可复用同一 provider agent id，同 root 冲突仍拒绝。

### D5 meta 边界宽于后续 `agents` 表

**位置**：`apps/api/app/service/acquisition/local_sessions.py:49,52,59`；`apps/api/app/db/models/domain.py:148,153-154`

**现象**：导入模型接受 `agentType` 128 字符、`model` 128 字符、`taskKind` 64 字符；后续 `agents` 表对应列分别只有 64、64、32。合成探针用 65/65/33 字符均被扫描器接受。

**问题**：M2-02 只存 JSON meta 时不会立即报错，但 M2-03 归一化把同一字段写入强类型列时会遇到 MySQL 截断或拒绝，形成跨 issue 的延迟数据错误。

**预判**：P3 边界问题。建议 loader 使用目标 schema 的实际上限，或明确记录后续 normalizer 会做安全截断/拒绝。

**结论**：已修复（2026-10-25）。`agentType/model/taskKind` 的封闭 schema 上限分别收紧到 64/64/32，入库前拒绝越界值。

### D6 `verify-local` 把数据库中所有 payload 都当作本次本地语料

**位置**：`apps/api/app/service/acquisition/local_sessions.py:407-424`；`apps/api/app/db/crud/local_sessions.py:135-140`

**现象**：验证先取全表 payload/source 行数，再要求行数等于本地扫描数量。若同一个开发数据库另有 fixture、pull 或其他来源 payload，即使本地 66 个键全部存在，命令仍会报 row count mismatch。

**问题**：验证命令表达的是“数据库恰好只有本地语料”，而不是“本次本地语料的每个键都已入库”。默认脚本使用独立 SQLite 时无实害，但自定义 `HE_DB_URL` 或未来共享开发库会让合法状态误报失败。

**预判**：P3 可用性问题。可改为验证 corpus 键集合是数据库键集合的子集，并为“额外 rows 不影响本地验证”补测试；若独立数据库是硬边界，则应在 help/docs 明确拒绝共享 DB。

**结论**：已修复（2026-10-25）。`verify-local` 分别检查 payload/source 的本地键集合子集，返回本地键数量；共享库中的其他来源行不再误报。

## §9 文件级代码分析

### 扫描与导入服务

#### `apps/api/app/service/acquisition/local_sessions.py`（A）

职责：发现本地 root/subagent transcript，验证身份与边界，编排一次事务导入或数据库身份验证。

关键依赖：`json` 负责 JSONL 解码；`hashlib` 从原始 bytes 派生 SHA-256；Pydantic 对 subagent meta 做封闭校验；SQLAlchemy 只通过 CRUD 边界进入数据库。可以把这层理解为“机场安检”，先检查每份档案的封条和身份，再交给档案柜。

变更核心：

```python
content, _digest, _count, _size = _read_payload(path, label=label)
values = [json.loads(line) for line in content.splitlines()]
```

这段把 payload 原文和结构校验放在同一上层入口，确保后续 writer 只接收已验证对象；但 `splitlines()` 的换行定义比 JSONL 更宽，见 D3。

