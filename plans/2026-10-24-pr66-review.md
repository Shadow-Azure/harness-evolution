## 1. 一页速览

一句话：这个 PR 把“只会回答 health 的 TypeScript 小前台”换成了后续 SaaS 业务真正落脚的 Python/FastAPI 配电箱，同时先装好错误回执、临时门禁和 Python 质量门。

生活化比喻：旧 Fastify 壳像一间只有门铃的样板房；本 PR 保留门铃（health），换上新的水电管线（FastAPI 分层），门口加一名“未核验身份一律请回”的临时保安（401 boundary），并把未来的施工入口、验收工具和报警回执统一好。

交付块：

| 交付块 | 用户或维护者能看到什么 |
|---|---|
| 可启动 API | `pnpm dev` 同时启动 Web 与 FastAPI，health 经 Vite 代理可达。 |
| 统一失败回执 | 404、405、422、预期业务错误和未捕获异常都使用同一个 `{error:{...}}` 外形。 |
| 临时安全边界 | 身份未实现前，非公开 `/api/*` 一律 401，避免业务路由默认裸奔。 |
| Python 门禁 | ruff、strict mypy、pytest/coverage 本地与 CI 同命令。 |
| 文档开关 | 开发可看 Swagger/OpenAPI，生产可用 `HE_DOCS_ENABLED=false` 关闭。 |

## 2. 架构导览

### 2.1 组装根：先决定边界，再挂路由

`apps/api/app/main.py:13-39` 是唯一组装点。它先按 `HE_DOCS_ENABLED` 决定是否挂 `/api/docs` 与 `/api/openapi.json`，再挂鉴权边界、CORS、request context，最后注册 health router。

Starlette 的中间件是“后加入者在外层”。实测 `app.user_middleware` 顺序为 `RequestContext → CORS → AuthBoundary`，因此一个受保护请求先拿到 request ID，随后经过 CORS，再被鉴权边界拒绝。响应从内向外返回时，401 也会自动获得 `X-Request-Id`。

### 2.2 临时鉴权边界：把“未知”当成“不安全”

`apps/api/app/middleware/auth.py:18-30` 采用白名单：只有 `/api/health` 与显式开启的文档路径通过，其余 `/api/*` 都返回 401。它的价值不是完成登录，而是让 m1-06 之前的每个业务路由都默认安全。

这带来一个刻意的代价：现在 `/api/sessions` 即使尚未实现，也会返回 401 而不是 404。对用户看似“答非所问”，但内部身份落地后，这条路径会自然变成真实路由，不会出现“以为有门禁、其实裸开”的窗口。

### 2.3 错误模型：一条回执规则覆盖框架与业务

`apps/api/app/errors.py:16-24` 定义稳定错误码；`ErrorBody`/`ErrorResponse` 固定 `{error:{code,message,details}}`；`register_exception_handlers()` 把预期业务错误、HTTP 404/405、请求校验失败和未捕获异常收口到同一外形。

`INTERNAL` 被约束为 HTTP 500。非路由框架异常不会假装自己仍是 418、401 或 409，避免前端看到“内部错误码 + 外部状态码”的自相矛盾。未来预期业务错误应显式抛 `AppError`。

### 2.4 配置与 health：当前只承诺 scaffold

`apps/api/app/config.py:18-33` 从 `HE_` 命名空间读取 host、port、phase、CORS、文档开关和日志级别。`health.py:13-27` 返回 `ok/service/phase`；`ok` 用 boolean 而非 `Literal[True]`，为 m1-03 的数据库故障态保留 `false`。

### 2.5 启动脚本：pnpm 是统一入口，Python 仍是独立包

`scripts/run-api.mjs:10-53` 只做一件事：定位 `apps/api/.venv` 并把命令转发进去；`setup-api.mjs:8-48` 选 Python ≥3.12 并安装 `.[dev]`。这种设计把 Python 排除在 pnpm workspace 之外，避免 pnpm 假装能管理 pip 依赖。

## 3. 数据流走查

### 剧本 A：浏览器查询健康状态

1. 浏览器向 Vite 的 `/api/health` 发请求。
2. `apps/web/vite.config.ts:7-9` 把请求代理到 `127.0.0.1:8787`。
3. `RequestContextMiddleware` 读取或生成 request ID，写入 `request.state`。
4. `AuthBoundaryMiddleware` 发现 `/api/health` 是公开路径，放行。
5. `health()` 从 `app.state.settings.phase` 读交付阶段，并返回 `{ok,service,phase}`。
6. 响应沿中间件栈向外时写入 `X-Request-Id`。

实测输出：HTTP 200，body 为 `{"ok":true,"service":"harness-evolution","phase":"scaffold"}`。

### 剧本 B：未登录用户误入业务 API

`GET /api/sessions` 在路由匹配前被 `auth.py:23-30` 拦截，直接返回：

```json
{"error":{"code":"AUTH_REQUIRED","message":"authentication is required","details":{}}}
```

这是一条“先关门、后装修”的链路，与 m1-02 无业务路由的边界一致。

### 剧本 C：未捕获异常

路由抛出 `RuntimeError("database password=...")` 后，`errors.py:137-146` 返回 HTTP 500，body 只含 request ID，不泄露异常文本；`X-Request-Id` 同时回写。实测响应安全，但应用侧没有记录异常，详见 §6。

## 6. 讨论点

### D1. 未捕获异常只有安全响应，没有可诊断的服务端日志

**位置**：`apps/api/app/errors.py:137-146`。

**现象**：异常被 `Exception` handler 收口后，只计算 request ID 并返回 500；没有 `logger.exception` 或其他日志记录。实测注册日志捕获器后，应用侧记录数为 0，只有测试客户端自身留下一条 HTTP INFO。

**问题**：设计明确规定未捕获异常“响应不含堆栈，日志含 request_id”，并要求结构化日志。当前实现只做到前一半：用户看不到堆栈，运维人员也看不到；一旦线上 500，只剩一个 request ID，却无法用它在服务端找到对应错误。

**预判**：这是 m1-02 统一错误模型应修的错误可观测性缺口。建议记录 `logger.exception(..., extra={"request_id": ..., "method": ..., "path": ...})`，并加一个测试证明 500 会产生带 request ID 的服务端日志，同时继续断言响应不含敏感异常文本。

**结论**：已修复（2026-10-25）。未捕获异常现在以结构化 `request_id / method / path` 和异常栈写入服务端日志；响应仍只返回脱敏的 request ID，测试同时验证日志与脱敏。

### D2. `ServicePhase` 后端已有三值，跨端契约仍只允许 scaffold

**位置**：`apps/api/app/config.py:10-15`、`apps/api/app/api/health.py:26`、`packages/contracts/src/index.ts:8-9`。

**现象**：后端 `ServicePhase` 与 OpenAPI enum 是 `scaffold | demo | live`；设置 `HE_PHASE=live` 后 health 实际返回 `"phase":"live"`。共享 TypeScript 契约仍声明 `export type ServicePhase = "scaffold"`。

**问题**：仓库约定跨端字段变化先改 `packages/contracts`。当前虽然 App 只忽略 phase、没有立即运行错误，但类型系统会认为服务端不可能返回 `demo/live`。m1-04 才切 OpenAPI 生成，不代表 m1-02 可以留下已知的手写契约漂移。

**预判**：建议现在就把手写 `ServicePhase` 扩为三值，并补一个契约/配置对照测试；或者在本 issue 中只允许 `scaffold`，到 m1-03 再扩展。前一种更符合设计已经定义的三阶段模型。

**结论**：已修复（2026-10-25）。共享契约导出 `SERVICE_PHASES = scaffold/demo/live` 并由类型派生；后端测试逐字校验 FastAPI 枚举与 TS 契约同步。

### D3. README 的产品定位仍停留在 Codex-first

**位置**：`README.md:5`、`README.en.md:5`。

**现象**：README 仍说“面向 coding agent（先支持 Codex）”；全栈设计把产品定义为 coding-agent SaaS，当前明确的数据源是 Claude Code 轨迹，roadmap 已改为通用的 coding agent 叙述。

**问题**：本 PR 修改了 README“当前状态”和目录结构，却保留了与设计权威冲突的产品承诺。读者会误以为仓库下一阶段仍以 Codex 本机轨迹为首要来源。

**预判**：低成本的现状文档修复。建议改成与全栈设计和 roadmap 一致的产品定位，不在 m1-02 展开真实轨迹实现。Web 占位文案可在 m1-05 Vue 重建时统一处理。

**结论**：已修复（2026-10-25）。README 双语产品定位改为通用 coding agent，不再承诺 Codex-first。

### D4. 开发默认开放 API 文档，生产依赖运维显式关闭

**位置**：`apps/api/app/config.py:32`、`docs/development.md:12`。

**现象**：`HE_DOCS_ENABLED` 默认 `true`；设计说“开发开放、生产关闭”，实现把它变成生产部署必须主动设置 `false` 的运维约定。

**问题**：如果首次生产部署漏配环境变量，Swagger/OpenAPI 会公开。它通常只泄露接口结构、不直接泄露数据，因此当前无实害，但这是一个 fail-open 的默认值。

**预判**：可以保留为显式运维约定，也可以改成默认关闭、开发脚本注入 `HE_DOCS_ENABLED=true`。后者更安全，但会让本地命令多一层环境装配；适合在部署配置 issue 或本 PR 维护者拍板时决定。

**结论**：已修复（2026-10-25）。`HE_DOCS_ENABLED` 默认 `false`，仅 `pnpm dev` 显式开启；关闭时 `/api/docs` 与 `/api/openapi.json` 均为统一 404，避免生产 fail-open。

### D5. PR 描述里的 milestone 复选框已过时

**位置**：PR body “PR 已关联 flow milestone 与 project” 仍为 `[ ]`。

**现象**：远端 PR 已关联 M1 milestone，`gh pr view` 返回 milestone #9；Project 项未验证。

**问题**：实际状态与描述不一致，会让后续维护者误判流程尚未完成。

**预判**：只更新 PR 描述为“milestone 已关联、Project 未验证”，无需改代码。

**结论**：已修复（2026-10-25）。PR body 已更新为 M1 milestone #9 已关联、Project item 未配置，并刷新测试与覆盖率证据。

### D6. 新增要求：前后端测试与 80% 覆盖率没有形成执行门禁

**位置**：`apps/web/package.json`、`.github/workflows/ci.yml`、`scripts/route-gates.mjs`、`scripts/gates.spec.mjs`。

**现象**：本 PR 初次提交只有后端 9–12 个 ASGI 测试；Web 变更没有 App 单测，没有跨端集成测试，CI 也未执行跨栈路径。Vitest 没有 coverage provider 与阈值，路由门禁只推荐 build/docs。

**问题**：后端和前端可以各自“绿”而接口接线已断开；没有覆盖率下限时，新增主路径测试也可能掩盖大面积未执行分支。

**预判**：测试与覆盖率必须作为 PR 的交付物而不是事后建议。前端和后端单元测试都应有 80% 下限；跨栈集成测试要真实启动 FastAPI 与 Vite；CI、路由门禁和门禁自测试都要实际执行这些命令。

**结论**：已修复（2026-10-25）。Web 增加 App 成功/失败/加载单测与 Vitest 四维 80% 阈值；API 保持 90/92%；新增 Web→Vite proxy→FastAPI 集成测试及进程组清理；CI 执行前后端单测与集成测试，路由门禁与 `gates.spec.mjs` 机械校验执行接线。

## 9. 文件级代码分析

### 9.1 `apps/api/app/main.py`（A）

职责：应用组装根。关键依赖 FastAPI 是一方 Web 框架，负责路由、OpenAPI、依赖注入与 exception handlers；CORSMiddleware 来自 Starlette。可以把这里理解成配电箱：所有边界按顺序接线，业务路由只从这里进入。

旧形态是 `apps/server/src/app.ts` 中直接 `Fastify({logger:true})` 并注册 health。新形态改为可注入 `Settings` 的 `create_app()`，测试能创建互不污染的应用实例。

关键实现：

```python
docs_url = "/api/docs" if resolved_settings.docs_enabled else None
openapi_url = "/api/openapi.json" if resolved_settings.docs_enabled else None
app = FastAPI(..., docs_url=docs_url, openapi_url=openapi_url)
```

这保证关闭文档时不是“页面隐藏但 schema 仍公开”，而是两个端点都不注册。实现思路：配置先行、边界随后、路由最后。未发现新增高优先级代码缺陷。

### 9.2 `apps/api/app/errors.py`（A）

职责：把 Python 异常翻译成稳定 JSON 回执。FastAPI 是一方框架，Pydantic 负责响应形状，Starlette HTTPException 是框架路由失败的原生类型。

```json
{"error":{"code":"AUTH_REQUIRED","message":"authentication is required","details":{}}}
```

这个形状相当于统一的故障工单：前端永远读同三个字段，不必猜这次失败是 Fastify、Starlette 还是业务代码产生。`INTERNAL` 与 500 的配对是刻意约束。

发现：D1；不另发现其他缺陷。

### 9.3 `apps/api/app/middleware/auth.py`（A）

职责：身份实现前的临时安全闸。白名单是“安全清单”，不在清单内的 `/api/*` 默认拒绝。文档路径在关闭时不进入公开集合，随后由路由自然返回统一 404。

未发现缺陷。m1-06 必须替换此 middleware，而不是在其后添加真实鉴权。

### 9.4 `apps/api/app/middleware/request_context.py`（A）

职责：接受或生成 request ID，写入 `request.state` 并回写响应头。它像快递单号：用户报错时提供单号，理论上服务端能找到同号日志。

当前断点在 D1：异常 handler 读取了单号，却没有把对应异常写进日志；因此本文件与错误处理的组合尚未兑现设计语义。

### 9.5 `apps/api/app/config.py` 与 `health.py`（A）

职责：环境配置与健康契约。`Settings` 使用 pydantic-settings，`HealthResponse` 用 Pydantic v2 `extra="forbid"` 防止响应偷偷膨胀。

发现：D2、D4。

### 9.6 `apps/api/app/__main__.py`（A）

职责：`python -m app` 启动 uvicorn，dev 可带 `--reload`。它从 `HE_HOST`/`HE_PORT` 读监听地址，避免脚本里硬编码生产参数。

当前硬编码应用版本 `0.1.0` 位于 `main.py`，旧 health 契约暂不含 version；m1-03 引入 DB/version 时会统一从 Settings 取。未发现本 issue 缺陷。

### 9.7 `apps/api/tests/test_app.py`（A）

职责：用 `httpx.AsyncClient + ASGITransport` 发真实 ASGI 请求，不 mock HTTP 层。覆盖 health、OpenAPI boolean、401、404、405、422、AppError、500 脱敏、配置前缀、文档开/关。

优点：测试直接断言响应体和 header，能抓路由/中间件顺序回归。

发现：缺少 D1 的日志断言，另缺少 D2 的跨端 phase 契约断言。

### 9.8 `scripts/run-api.mjs`、`setup-api.mjs`、`dev.mjs`（A）

职责：pnpm 与 venv 之间的薄转接头。`setup-api` 选 Python ≥3.12 并建立 venv；`run-api` 转发 ruff/mypy/pytest；`dev` 并行起两个服务并转发信号。

```javascript
const processes = ["dev:api", "dev:web"].map((script) =>
  spawn(pnpm, [script], { stdio: "inherit" }),
);
```

实测 `pnpm dev`、代理请求与 Ctrl+C 关闭均正常，没有残留进程。未发现缺陷。

### 9.9 `package.json`、`pnpm-lock.yaml` 与 route gates（M/A）

旧 `dev/build/start` 指向 `@harness/server`；新命令固定到 `node scripts/*.mjs`。锁文件删除 Fastify、pino、tsup 及传递依赖。

route gate 把 Python 与 TypeScript 分开：`apps/api/**` 只推荐 Python 门禁，其他 app/package 继续推荐 build/docs。自测试固定了代表路径。未发现缺陷。

远端对应提交的两个 check 均 pass。未发现缺陷。
