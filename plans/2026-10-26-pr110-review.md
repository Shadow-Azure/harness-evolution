## §1 一页速览

一句话：这个 PR 给 Session 浏览器的“快”建立了可重复的证据，并把入口体积、Vue Flow 懒加载、61-Agent 展开、交互反馈、帧节奏和滚动位置变成可执行门禁。

| 滚动恢复 | 实现结构清晰；E2E 未断言记录值非零，也未覆盖刷新重置 |
| 报告与隐私 | fixture/local 都能清理临时目录，输出无正文与绝对路径 |

## §2 架构导览

### 2.1 静态门禁

`scripts/verify-bundle.mjs:7-11` 定义三个静态预算；`assertBundleBudgets()` 在 `:78-101` 读取入口、gzip 和带 `vendor-` 前缀的 chunk。`assertFirstScreenExcludesVueFlow()` 在 `:110-124` 检查同步 import closure，并从动态入口寻找 Vue Flow chunk。

机制优点是把“懒加载存在”和“体积不超限”拆成两个断言，避免只证明 Vue Flow 在别处，却没有证明首屏轻。

### 2.2 真实浏览器性能

`tests/e2e/m3-session-browser.test.mjs:863-1204` 用真实 FastAPI、SQLite、Vite 与 Chrome：

- 注入 PerformanceObserver 记录 long task；
- 监听 Network 记录 detail/tree 请求；
- 等四张卡出现后测量 ready；
- 点击第二张卡测量反馈；
- 在 list/overview 上记录和恢复滚动；
- 打开 61-Agent stress fixture，展开后测量节点数与耗时；
- 输出 fixture 或 local 两种来源的报告。

### 2.3 滚动记忆

`apps/web/src/utils/sessionScroll.ts:13-55` 是纯内存 Map，按 Session 保存两个面板位置。`Index.vue:316-355` 绑定真实 scroll 事件，并在路由选择变化、概览数据变化后分阶段恢复。

刷新后重置是有意的：内存实例随页面重建而清空，不污染 URL 或跨标签存储。

### 2.4 报告脚本

`scripts/performance-report.mjs:32-69` 创建临时目录、运行定向 E2E、读取 JSON，并在 `finally` 中清理。CLI 在 `:71-81` 只设置非零退出码，不提前 `process.exit()`，避免跳过清理。

## §3 数据流走查

### 场景 A：最大 Session 展开

1. `before` 阶段用 `fixtures:seed` 或 `data:import:sessions` + `data:replay:sessions` 准备数据。
2. 登录并打开 `/sessions`，四张卡先于树请求出现。
3. 用户选中 Session，detail 与 tree 各请求一次。
4. 树初始只渲染折叠节点；点击后生成 61 个 Agent。
5. E2E 记录展开耗时、长任务和滚动帧间隔；脚本输出聚合 JSON。

### 场景 B：切换 Session 后返回

1. 用户在 list 和 overview 内分别滚动。
2. scroll 事件把当前 Session 的两份 offset 存入 `SessionScrollMemory`。
3. 选择另一个 Session，旧位置已保存，新位置从 Map 读取。
4. History 前进或后退时，route 变化再次触发恢复。
5. 页面刷新会创建新 Map，因此按设计回到顶部。

### 场景 C：体积门禁

1. Vite 生成 manifest 与 asset。
2. 门禁定位同步 entry 并量 raw/gzip。
3. 从 entry 沿 `imports` 展开同步闭包，禁止 Vue Flow 出现。
4. 从 `dynamicImports` 证明 Vue Flow 仍可被动态页面到达。
5. 对带 vendor 前缀的 chunk 执行 400KB raw 上限。

## §6 讨论点

### D1 vendor 体积门禁可被改名静默绕过

**位置**：`scripts/verify-bundle.mjs:89-97`

**现象**：只有 key 或 `chunk.name` 匹配 `vendor-` 的 chunk 才进入预算；用 500KB 的 `framework.js` 做最小探针时，函数返回 `vendors:{}` 并正常通过。

**问题**：当前 Vite 配置确实生成 `vendor-vue`、`vendor-element-plus`、`vendor-vue-flow`，所以今天不会误判；但如果未来改手工分块名、拼错名称或移除配置，体积门禁会失去对象而不是直接失败。

**预判**：这是门禁自保护问题，建议要求预期的三个 vendor chunk 必须存在，或对首屏同步闭包之外的所有框架 chunk都执行预算；补“已无 vendor chunk 命中”的失败测试。优先级 P2。

**结论**：已修复（2026-10-26）。门禁要求 `vendor-vue`、`vendor-element-plus`、`vendor-vue-flow` 三个手工 vendor chunk 必须存在，同时继续逐个检查 400KB raw 上限；`framework.js` 改名探针现在因缺少预期 chunk 而失败。

### D2 滚动恢复 E2E 可能在零偏移上假绿

**位置**：`tests/e2e/m3-session-browser.test.mjs:991-1063`

**现象**：E2E 用 `Math.min(80, capacity)` 和 `Math.min(180, capacity)` 设置 scrollTop，随后只断言切换/History 后“恢复值等于保存值”，没有断言保存值大于 0。

**问题**：如果布局回归让两个面板不可滚动，保存值会全是 0，测试仍会通过，无法证明恢复逻辑真正工作。刷新后重置这一验收也只有 Agent Note 说明，没有浏览器断言。

**预判**：最小修复是断言 `secondScroll` 与 `firstScroll` 的目标偏移均为正，并在同一条真实浏览器测试里 reload 后断言两面板回到 0。优先级 P2。

**结论**：已修复（2026-10-26）。真实 Chrome 在可滚动双面板中先断言保存偏移大于 0，再验证卡片选择与 History 恢复；页面 reload 后断言两个面板最终归零。浏览器 History 的嵌套滚动恢复由 `scrollRestoration=manual` 与 Session 页首次挂载归零协调，用户滚轮后取消延迟归零。

### D3 运行时阈值和理由没有进入 owning Note

**位置**：`tests/e2e/m3-session-browser.test.mjs:938,978,1087,1109,1135,1142`、`.agents/notes/implemented/architecture/2026-10-26-session-performance.md:13`

**现象**：2500ms、200ms、34ms、350ms 等阈值只以字面量散落在 E2E；Agent Note 说明了机制，却没有记录这些预算及预留倍数。

**问题**：后续在 CI 偶发变慢时，维护者无法仅从 Note 判断阈值来自设计、实测倍数还是经验值，容易直接放宽断言而丢失决策理由。

**预判**：把阈值提成命名常量，并在 Note 的 Decision 中列出本地基线、CI 阈值和余量理由。优先级 P3。

**结论**：已修复（2026-10-26）。阈值集中到 `scripts/performance-budgets.mjs`，由 E2E 与报告共用；Agent Note 记录本地基线、CI 阈值与余量理由。

### D4 文档预算提高未在 PR 描述说明

**位置**：`scripts/doc-budgets.manifest.json:3,7,10`、PR body Summary

**现象**：`AGENTS.md` 700→720、`docs/architecture.md` 900→960、`docs/development.md` 580→600，但 PR 描述没有按文档规则说明提预算理由。

**问题**：仓库明确规定提预算须在 PR 说明。当前改动有合理事实来源，但审计者需要从实现报告或 diff 自行推导。

**预判**：在 PR body 增加一段预算调整理由即可，不必改代码。优先级 P2。

**结论**：已更新（2026-10-26）。PR 描述新增三项文档预算提升的理由：登记性能命令、阈值解释与新增架构现状，且已在搬层和压缩之后执行。

### D5 local 报告依赖外部 sqlite3 可执行文件

**位置**：`tests/e2e/m3-session-browser.test.mjs:130-143`

**现象**：local 模式通过系统 `sqlite3 -json` 找最大 Session；fixture CI 不受影响，但本地报告要求 PATH 中存在该命令。

**问题**：应用已有 Python/SQLAlchemy 数据库层，外部 CLI 让 local 模式在部分开发机上不可复现。当前无产品影响。

**预判**：可接受的本地工具依赖，但应在 development 或 report 错误里给出明确安装提示；优先级 P3。

**结论**：已修复（2026-10-26）。local 模式改用项目 Python 标准库读取 SQLite，不再依赖系统 `sqlite3` 可执行文件。
