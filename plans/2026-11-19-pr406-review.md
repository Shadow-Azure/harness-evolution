## §1 一页速览

一句话：第 2 步「Session 关联」不再把完整首条 prompt 当标题，而是复用会话列表已有的 120 字符短标题并单行省略，同时把表格改成固定列宽，让 720px 弹窗内的四列同屏；关联算法、统计与分页没有动。

比喻：像把写满整段任务的长名片塞进固定格子的名片盒——名片上只印前 120 个字的短名（超出省略），格子宽度预先定死，所以一张特别长的名片不会把旁边三格挤出去；想看完整内容，把名片抽出来看背面（鼠标悬停 `title`）。

## §2 架构导览

**短标题从哪来。** `session_families.short_title` 是 `nullable=False` 的字符串列（`apps/api/app/db/models/domain.py:120`）；采集侧在 `apps/api/app/service/acquisition/agent_tree.py:825-826` 把首条 prompt 去掉首尾空白后取前 120 字符，写入 `short_title`。所以它是“标题前缀”，不是语义摘要；会话列表早就在用它（`apps/api/app/service/sessions/service.py:73`，`SessionCard.vue:51` 用 `item.short || item.title` 并省略，`:151-159` 的具体省略样式）。这次只是把同一条字段接到第 2 步预览上。

**预览数据通路。** 预览接口从会话仓库读元数据：`PotentialRepository.list_sessions` 现在同时 `select` `short_title`（`apps/api/app/db/crud/potential.py:159-181`），映射进 `SessionMetaRecord.short_title`（`apps/api/app/db/crud/potential.py:52-58`）。关联器在 `PotentialMatcher.associated_sessions`（`apps/api/app/service/evolution/potential.py:587`）中把命中的 Session 收敛成 `AssociatedSession`，`short` 在 `:634-637` 直接取 `metas[session_id].short_title`；预览服务在 `:848-855` 再逐字段映射到 `SessionPreviewItem`（DTO 定义在 `:236-250`，`short` 在 `:240`）。路由本身没有新逻辑，只把响应模型换成了带 `short` 的版本（`apps/api/app/api/evolution_workspace.py:256-271`）。关联算法只加了字段，没有改匹配、排序或统计分支（`:624-668`）。

**契约。** `packages/contracts/openapi.json:5383-5417` 的 `SessionPreviewItem` 新增 `short`，并列入 `required`；生成的 `packages/contracts/src/generated/api.d.ts:3794-3808` 同步多出 `short: string`。这两个文件都带生成标记，本次 `pnpm contract:check` 独立通过，说明不是手改漏改。

**前端渲染与布局。** 点第 1 步「下一步」后，`goToSessions()` 调 `previewSessions` 并把响应放进 `sessionPreview`（`apps/web/.../LaunchWizard.vue:907-941`，赋值在 `:921`）。模板在 `:1746-1790`：表格加 `wz-session-table` 和 `colgroup`（`:1748-1757`），Session 单元格渲染 `item.short || item.title`（`:1776`），`title` 属性保留完整 prompt（`:1775`），短 ID 仍在下一行（`:1777`，`shortId` 在 `:630-635`）。样式在 `:2962-2991`：`table-layout: fixed`、四列 38/15/22/25、表头允许换行、标题块 `display:block` + `overflow:hidden` + `text-overflow:ellipsis` + `white-space:nowrap`。弹窗宽 720px（`:2221-2228`），`.modal-body` 左右各 18px（`:2253-2257`），所以表格可用宽度是 684px，标题列内容盒约 243.9px；这正是 PR 描述的测量值来源。窄视口仍保留 `.rep-scroll` 横向滚动兜底（`:2935-2939`）。

**为什么这能修好。** 旧布局是自动表格：`table.rep` 的 `white-space: nowrap`（`:2948-2954`）让长标题参与列宽计算，PR 实测它把表格撑到 1305.9px，再靠 `.rep-scroll` 横向滚；固定布局把“列宽”从内容手里收回到 CSS 的百分比上，标题自己的 `overflow:hidden` 只影响标题列内部，不再改变其它三列的位置。表头改回可换行，避免“该 Session 的 bad case 数”在 25% 列里把表头顶宽。

**兼容与边界。** 新字段是必填响应字段，但前端仍写 `short || title`，旧服务端缺字段时显示完整标题并同样被固定布局裁切；会话列表的标题本身没有 tooltip（`SessionCard.vue:63` 的 `:title` 只用在根会话 ID），本 PR 只给向导补了标题提示。无新增第三方依赖，改动是 Vue scoped CSS、SQLAlchemy `select` 列和 Pydantic DTO。

## §3 数据流走查

以 m10-05 seed 的长 prompt（164 字符）为例，走一条端到端主线：

1. 用户在第 1 步点「下一步」→ `goToSessions()`（`apps/web/src/pages/evolution/components/LaunchWizard.vue:907`）校验条件、`beginPreview(1, "sessions")`，然后调 `previewSessions(props.wid, { …condition(), page: 1, pageSize: 4 })`（`:913-919`）。
2. 前端客户端把请求 POST 到 `/api/workspaces/{wid}/evolution/preview/sessions`（`apps/web/src/api/evolutionRuns.ts:150-158`），响应类型是 `SessionPreviewResult`（`:153`）。
3. 路由 `preview_sessions`（`apps/api/app/api/evolution_workspace.py:256-271`）把 body 交给 `PotentialPreviewService.sessions`（`apps/api/app/service/evolution/potential.py:837-869`）。
4. `sessions` 先经 `_condition` 归一化条件，再调 `PotentialMatcher.associated_sessions`（`potential.py:587`）；后者先取窗口内 case，再 `list_sessions(session_ids)`（`:612`）。
5. 仓库按 `_QUERY_CHUNK = 500` 分块查 `session_families`（`apps/api/app/db/crud/potential.py:29-35`），`select` 出 `id, short_title, title, started_at`（`:159-181`），映射成 `SessionMetaRecord`（`:175-180`）。
6. 关联器对每个命中 Session 构造 `AssociatedSession(short=metas[session_id].short_title, title=metas[session_id].title, …)`（`potential.py:634-637`）；关联、排序、计数逻辑不变（`:624-668`）。
7. 预览服务把 `AssociatedSession` 逐字段映射为 `SessionPreviewItem`（`potential.py:848-855`），`short` 在 `:851`；分页切片在 `:858`，返回 `SessionPreviewResult`（`:859-869`）。
8. 响应经契约 `SessionPreviewItem`（`packages/contracts/openapi.json:5383-5417`）序列化；前端把结果存入 `sessionPreview.value`（`LaunchWizard.vue:921`），并 `step.value = 2`（`:927`）。
9. 模板渲染：Session 单元格的 `<b>` 文本是 `item.short || item.title`（`LaunchWizard.vue:1776`），`title` 属性是完整 prompt（`:1775`），下一行是 `#{{ shortId(item.sessionId) }}`（`:1777`）。在 684px 宽、38% 标题列、左右各 8px 内边距的约束下，标题内容盒约 243.9px；PR 实测 120 字符短标题的内容约 698px，于是 `text-overflow: ellipsis` 生效（样式 `:2986-2991`），表格总宽保持 684px（固定布局 `:2962-2964`），另外三列由 `colgroup` 的 15/22/25 分配（`:2970-2980`）。
10. 翻页走 `changeSessionPage`（`LaunchWizard.vue:945-965`），复用同一个响应类型与同一个模板；它只改 `page`，不重算关联（服务端排序稳定，PR 保持不变）。

## §6 讨论点

### D1 共享 E2E seed 改了 Session 标题，m11-05 的等待断言会超时

- **位置**：`tests/e2e/support/m10_05_seed.py:54-59`（检视时无条件把 `session_families` 的 `title` / `short_title` 改成英文长 prompt，现为 `--long-title` 显式开关）；`tests/e2e/m11-05-v2-cross-stack.test.mjs:400`（复用同一 seed）、`:707`（等待 `"技能分叉"`）；超时预算在 `tests/support/runtime.mjs:114`（20 秒）。
- **现象**：m10-05 的 seed 被 m11-05 复用，但 `short_title` 现在固定成 `LONG_TITLE[:120]`；m11-05 仍在第 2 步等 `"技能分叉"`，而这个字符串只来自同一个 Session 原来的短标题（fixture 里的 `示例技能分叉` / `示例会话三：技能分叉`）。我在临时数据目录独立跑了 `pnpm fixtures:seed` + `m10_05_seed.py`，查库确认 session `10000000-…-0003` 的 `title` 长度 164、`short_title` 长度 120，内容已是 `You are an autonomous software engineer…`。静态链路加上这次局部复现，可以判定 m11-05 在 `:707` 会等不到文本并在 20 秒后报 `timed out waiting for associated session`。
- **问题**：CI 的 e2e job 执行无参数的 `pnpm test:e2e`（`.github/workflows/ci.yml:137-139`），包含 m11-05；PR 的验证只跑了 `m10-05` 名称模式，没有覆盖这个共享 fixture 的副作用。生产行为不受影响，但全量 E2E 会红，PR 目前不能算绿。
- **预判**：这是本次 seed 改动的直接副作用，建议在本 PR 内修。最小改法是把 m11-05 的等待改成结构信号（例如存在 `[data-testid='wizard-session-title']` 行，或直接匹配新的短标签），避免再绑定具体测试文案；若希望共享 fixture 的语义保持稳定，则给 seed 加显式 `--long-title` 开关，只在 m10-05 打开，m11-05 继续用旧标题。修完后跑一次全量 `pnpm test:e2e`。
- **结论**：已在本 PR 内按“显式开关”方案修复：`m10_05_seed.py` 新增 `--long-title`（默认关闭），只有 m10-05 传该参数，m11-05 继续使用原 fixture 标题；随后全量 `pnpm test:e2e` 74/74 通过（2026-11-19）。

### D2 可见短标签仍是 prompt 前 120 字符，不是语义摘要

- **位置**：`apps/api/app/service/acquisition/agent_tree.py:825-826`（`short_title = title[:120]`）；`apps/web/.../LaunchWizard.vue:1776`（直接渲染 `short`）。
- **现象**：SWE-bench 类 Session 的首条 prompt 是整段任务描述，前 120 字符经常是 `You are an autonomous software engineer working in the repository at /testbed…` 这类模板句；在 243.9px 的标题列里再省略后，两行可能只剩相同的可见前缀，只能靠短 ID 和悬停全文区分。
- **问题**：issue #402 的期望是“可读的短标签”。本 PR 复用了会话列表既有的 `short_title`，满足“优先使用已有短标题字段”的一条，但没有解决“前缀本身不具区分度”的产品问题；改生成算法会同时影响会话列表、搜索与其它消费者，已明确不在 #404 范围。
- **预判**：作为 #404 的最小修复可以接受，且 Agent Note 已把该代价写在 Consequences；如果上线后用户仍无法区分，应在 #402 决定是否引入语义摘要、额外列或更宽标题列，而不是在本 PR 动 `short_title` 的生成。
- **结论**：

### D3 完整 prompt 只能靠原生 `title` 悬停查看，键盘与触屏不可达

- **位置**：`apps/web/.../LaunchWizard.vue:1772-1776`（`<b :title="item.title">` 不聚焦）。
- **现象**：省略后的短标签是唯一的可见文本，完整标题只存在于 `title` 属性；`<b>` 不是可聚焦元素，键盘 Tab 不会触发原生提示，触屏也没有悬停。屏幕阅读器通常只读可见文本（或对 `title` 的支持不一致）。
- **问题**：这次修复的核心价值是“标题省略 + 悬停看全文”，但“看全文”只对鼠标用户成立；issue #402 的验收只写了悬停，未要求键盘/触屏路径。仓库里 `:title=` 有 88 处，属于既有通用做法，不是本 PR 新引入的模式。
- **预判**：不阻断本次验收；若维护者认为完整标题属于关键证据，可加 `tabindex="0"` + `aria-label`，或改成点击/详情浮层；否则在 #402 记录为接受的限制即可。
- **结论**：

### D4 固定布局只裁标题列，其它列仍 `nowrap` 且没有溢出保护

- **位置**：`apps/web/.../LaunchWizard.vue:2948-2954`（所有 `th/td` 都是 `white-space: nowrap`）、`:2962-2980`（固定布局与四列百分比）、`:2986-2991`（只有 `.wz-session-title` 做 `overflow:hidden` + 省略）；E2E 只检查表头与表格横向溢出（`tests/e2e/m10-05-launch-wizard.test.mjs:411-424`）。
- **现象**：固定布局把列宽锁死，但 `td` 内容不会自动换行；如果触发点时间格式变长、字体变大，或未来某一列内容超宽，文字会画出单元格边界并压到相邻列，而不会撑开表格。当前 `formatMoment` 输出 16 字符（`LaunchWizard.vue:638-640`），在 22% 列（约 150px，内容盒约 134px）内放得下，bad case 数也是短数字。
- **问题**：当前无实害；风险在于 e2e 只验证表头位置和表格总宽，不验证每个 body 单元格的 `scrollWidth <= clientWidth`，未来改时间格式时不会报警。
- **预判**：保持现状可接受；若要加固，可给非标题单元格补 `overflow:hidden; text-overflow:ellipsis`（或允许换行），并在 e2e 里顺带断言四列 body 内容不越界。
- **结论**：
